4.3 Access Modifiers & Encapsulation

1. Definition

Access modifiers restrict which classes can read or call a member (from private inside the class out to public everywhere), while Encapsulation hides internal fields behind private modifiers and exposes validated methods.

2. Memory hook

private -> package-default -> protected -> public. Hide locators private; expose actions public.

  • Narrowest first: private (same class) < default (same package) < protected (same package + subclasses anywhere) < public (all packages).
  • Top-level class rule: outer classes allow only public or package-default (not private or protected).
  • Encapsulation = Data Hiding + Safe API: guard invariants inside setters instead of leaving fields public.

5. Code example: encapsulated Page Object hiding locators behind actions

package com.qkart.pages;

public class AuthPage {
    private final String loginEndpoint = "https://qkart-qa-web.labs.crio.do/login"; // hidden
    private int waitTimeoutSec = 10;                                               // guarded state

    public void setWaitTimeoutSec(int sec) {
        if (sec <= 0) throw new IllegalArgumentException("Timeout must be > 0");  // validation guard
        this.waitTimeoutSec = sec;
    }

    public String getLoginEndpoint() { return loginEndpoint; }                    // read-only getter
}

6. Execution flow, step by step

  1. loginEndpoint and waitTimeoutSec are marked private so tests outside AuthPage cannot corrupt them.
  2. Calling authPage.waitTimeoutSec = -5 fails to compile immediately.
  3. Callers must go through setWaitTimeoutSec(...), which rejects invalid timeouts cleanly before saving.
  4. loginEndpoint has only a public getter (no setter), making it effectively read-only outside.
  5. Other framework tests stay unaffected even if internal locators or field types change inside AuthPage.

8. Why it matters

Encapsulation localizes changes inside one class so refactoring internal representation never breaks external callers.

SDET link: This is Rule #1 of the Page Object Model (POM): keep every private final By locator private inside its Page Object class and expose only public business actions like loginAs(user, pass) to tests.

9. Quick test

Can a subclass in package tests call a protected method declared in package base? Yes — protected permits subclasses in different packages to inherit it.
