6.2 try-catch-finally, throw vs throws & try-with-resources

1. Definition

try-catch intercepts errors in narrowest-to-broadest order, finally guarantees cleanup execution, throw raises an exception while throws declares propagation, and try-with-resources auto-closes AutoCloseable streams without hiding the real crash.

2. Memory hook

Specific catch BEFORE general catch; AutoCloseable -> try(...) closes backward safely; throw = action, throws = warning!

  • Order rule: put FileNotFoundException before IOException (never superclass first!).
  • Why try-with-resources beats manual finally: if both read and close() crash, Java keeps the real read crash as primary and tucks close() under Suppressed exceptions.
  • Exception chaining: pass new FrameworkEx("msg", cause) so stack traces never lose the root line number.

3. try-with-resources Cleanup Flow

try (R1 a = ...; R2 b = ...) Lifecycle
Resources close automatically in REVERSE order (b.close() then a.close()) right after the try block.
1. Open left -> rightOpens stream a, then wrapper b
2. Run block / crashRuns test data read or throws real error
3. Auto-close right -> leftCalls b.close() then a.close() before catch runs!

4. throw vs throws & Manual finally vs try-with-resources

ConstructKey RoleTrap to Avoid

5. Code example: AutoCloseable file reader with custom unchecked wrapper

import java.io.*;
import java.nio.file.*;

class ConfigLoadException extends RuntimeException {
    ConfigLoadException(String msg, Throwable cause) { super(msg, cause); } // keeps root cause
}

public class ResourceCleanupDemo {
    static String firstLine(Path p) {
        try (BufferedReader br = Files.newBufferedReader(p)) { // auto-closes even if readLine throws!
            return br.readLine();
        } catch (IOException ex) {
            throw new ConfigLoadException("Missing config: " + p, ex); // wrap & preserve stack trace
        }
    }

    public static void main(String[] args) {
        try { firstLine(Path.of("missing.properties")); }
        catch (ConfigLoadException e) {
            System.out.println(e.getMessage() + " | Cause: " + e.getCause().getClass().getSimpleName());
        }
    }
}

6. Execution flow, step by step

  1. Files.newBufferedReader(p) opens inside the try (...) header because BufferedReader implements AutoCloseable.
  2. Whether readLine() returns a line or fails with IOException, Java closes br automatically first.
  3. Any IOException is caught cleanly and wrapped inside custom unchecked ConfigLoadException with ex passed as cause.
  4. Wait helpers can also catch two sibling exceptions in one block using pipe syntax: catch (IOException | TimeoutException e).
  5. Caller sees both the friendly context message and the root NoSuchFileException.

8. Why it matters

Leaky open streams freeze Windows files in CI runners and silent catches hide root causes across multi-layer frameworks.

9. Quick test

What happens if a method executes return true; in try and return false; in finally? false returns — and any exception thrown in try is silently lost. Never put return inside finally.
