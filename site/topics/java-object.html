Java

Object (Selenium + Interview Edition)

Definition

An object is a runtime instance of a class allocated on the Heap that bundles data (fields) and actions (methods) into a single addressable unit.

Without objects, a test script must pass loose variables (String url, String browser, String usernameInputId) to every method. Objects solve this by grouping related state and behavior into one unit (ChromeDriver, WebElement, LoginPage).

1. Class vs. Object (The Core Difference)

A class is a code template defining what fields and methods exist; it takes zero Heap memory for instance fields. An object is the physical memory block created from that class at runtime using new.

Interview Answer: "A class is a compile-time template that defines fields and methods without allocating instance memory, whereas an object is a runtime instance of a class created on the Heap that holds actual state values."

2. Runnable Code & Line-by-Line Trace (Java + Selenium Context)

class LoginPage {
    String url;                   // instance field (state) - defaults to null
    int timeout;                  // instance field (state) - defaults to 0
    boolean loaded;               // instance field (state) - defaults to false

    void open() {                 // instance method (behavior)
        loaded = true;
        System.out.println("Opened " + url + " (timeout=" + timeout + ")");
    }
}

public class Main {
    public static void main(String[] args) {
        LoginPage p1 = new LoginPage();
        System.out.println(p1.url + " | " + p1.timeout + " | " + p1.loaded);

        p1.url = "https://app.test/login";
        p1.timeout = 10;
        p1.open();

        LoginPage p2 = new LoginPage();
        p2.url = "https://staging.test/login";
        p2.open();

        System.out.println("p1 == p2 : " + (p1 == p2));

        LoginPage p3 = p1;
        p3.timeout = 30;
        System.out.println("p1.timeout : " + p1.timeout);
        System.out.println("p1 == p3 : " + (p1 == p3));
    }
}

Real Output:

null | 0 | false
Opened https://app.test/login (timeout=10)
Opened https://staging.test/login (timeout=0)
p1 == p2 : false
p1.timeout : 30
p1 == p3 : true

Step-by-Step Memory Trace:

  1. LoginPage p1 = new LoginPage();: new allocates space on the Heap at address @A1. The JVM zeroes the block (url = null, timeout = 0, loaded = false), runs the constructor LoginPage(), and stores the address @A1 in reference variable p1 on the Stack.
  2. p1.url = "..." & p1.open(): The dot (.) operator dereferences @A1, writes to its Heap fields, and runs open() against @A1's data.
  3. LoginPage p2 = new LoginPage();: Allocates a second, independent object on the Heap at @B2. p1 == p2 compares @A1 == @B2 → false.
  4. LoginPage p3 = p1;: Copies the address @A1 into p3. No new keyword = no new object. Both p1 and p3 point to @A1, so changing p3.timeout = 30 changes p1.timeout (30), and p1 == p3 is true.

Interview Answer: "The variable p1 is not the object itself; it is a reference on the Stack storing the Heap memory address of the object created by new."

3. The 3 Core Properties of Every Object

  1. State (Fields): The data values inside the object (url, timeout, driver).
  2. Behavior (Methods): The actions the object performs (open(), click(), sendKeys()).
  3. Identity (Address): What makes two objects distinct in memory even if their fields hold identical values (p1 == p2 is false).

4. == vs .equals() (Identity vs Content)

  • == (Reference comparison): Checks if two reference variables hold the exact same Heap address.
  • .equals() (Content comparison): Defined in java.lang.Object (the root parent of every Java class). By default, Object.equals() uses ==, but classes like String, Integer, and Selenium's RemoteWebElement override .equals() to compare logical identity/content.
WebElement a = driver.findElement(By.id("q")); // Heap object @E1
WebElement b = driver.findElement(By.id("q")); // Heap object @E2 (same DOM element)

System.out.println(a == b);        // false (two separate Java wrapper objects on Heap)
System.out.println(a.equals(b));   // true  (both wrap the same underlying DOM element ID)

Interview Answer: "== compares memory addresses on the Stack to see if two references point to the same Heap object, whereas .equals() compares logical equivalence when overridden (like String text or Selenium WebElement element IDs)."

5. null and NullPointerException (Boundary & Failure Case)

A reference variable without an object holds null (address 0x0). Calling any field or method using . on null throws NullPointerException (NPE) at runtime because there is no Heap object to dereference.

WebDriver driver = null;
driver.get("https://google.com"); // throws java.lang.NullPointerException

Top 3 NPE causes in Selenium Frameworks:

  1. Declaring WebDriver driver; in a test class without initializing driver = new ChromeDriver(); (or shadowing the BaseTest driver field by re-declaring WebDriver driver; in the child test class).
  2. Calling @FindBy WebElement methods before calling PageFactory.initElements(driver, this);.
  3. Passing a null driver into a Page Object constructor (new LoginPage(driver) when @BeforeMethod failed or didn't run).

6. Ways to Create an Object in Java (Types)

There are 5 ways to create an object in Java:

  1. new keyword
  2. Factory method
  3. Reflection (Constructor.newInstance())
  4. Cloning (clone())
  5. Deserialization (ObjectInputStream.readObject())

Explained in order:

  1. new keyword: Direct constructor call; allocates Heap memory immediately. Selenium usage: WebDriver driver = new ChromeDriver();, LoginPage page = new LoginPage(driver);
  2. Factory method: A static or helper method that creates and returns an object internally. Selenium usage: By locator = By.id("username"); (returns a By.ById object), PageFactory.initElements(driver, LoginPage.class);
  3. Reflection (Class.getDeclaredConstructor().newInstance()): Creates an object dynamically from its class name at runtime. SDET usage: TestNG and JUnit use reflection to instantiate your @Test classes automatically without you writing new LoginTest().
  4. Cloning (obj.clone()): Copies an existing object's fields into a new Heap instance (requires implementing Cloneable). SDET usage: Cloning baseline API request payload objects to test variations without mutating the original template.
  5. Deserialization: Reconstructs an object from a byte/JSON stream. SDET usage: Jackson / Gson deserializing API JSON responses into POJO objects (response.as(User.class) in RestAssured).

Interview Answer: "Besides the new keyword, we create objects via factory methods like By.id(), reflection (used by TestNG to instantiate test classes), cloning, and deserialization (used in RestAssured POJO mapping)."

7. Complete Selenium Usage Context

Every line of a Selenium test is object creation, reference passing, or method invocation:

// 1. Options object (holds browser configuration state)
ChromeOptions options = new ChromeOptions();
options.addArguments("--headless=new");

// 2. Browser driver object (Upcasting: interface reference -> concrete object)
WebDriver driver = new ChromeDriver(options);

// 3. Page Object (passes the driver reference into the page object's field)
LoginPage loginPage = new LoginPage(driver);

// 4. By object (factory method creates a locator object) & WebElement object
By userLocator = By.id("q");
WebElement inputBox = driver.findElement(userLocator);
inputBox.sendKeys("SDET");

// 5. Cleanup (closes browser process; Java object stays on Heap until GC collects it)
driver.quit();

Why driver.quit() doesn't delete the Java object: driver.quit() terminates the external ChromeDriver OS process and closes the browser window, but the ChromeDriver Java object remains in Heap memory (with sessionId = null) until driver goes out of scope and the Garbage Collector reclaims it. Calling driver.get() after driver.quit() throws NoSuchSessionException, not NullPointerException.

8. Must-Know Interview Q&A

Interview QuestionCrisp Interview Answer
Does a class take Heap memory?No. Only when an object is instantiated from it does the JVM allocate instance field memory on the Heap.
Why do we get NullPointerException in Page Object Model?Most commonly because driver was shadowed in the test class (WebDriver driver; re-declared locally), or PageFactory.initElements(driver, this) was omitted.
If I call driver.findElement(By.id("q")) twice, how many Java objects are created?Two separate RemoteWebElement objects on the Heap (a == b is false), though a.equals(b) is true because both reference the same DOM node.
What happens in memory after driver.quit()?The browser closes and the session ID becomes null (causing NoSuchSessionException if reused), but the Java object stays on the Heap until unreachable and collected by GC.

Self-Check

  1. LoginPage a = new LoginPage(); LoginPage b = a; — How many objects are on the Heap? (1)
  2. In Selenium, By.id("login") doesn't use new. Which object creation type is it? (Static factory method — internally it returns new By.ById("login"))
  3. If driver.quit() is called, is driver == null true? (No, driver still points to the Heap object; only its internal session is closed.)
