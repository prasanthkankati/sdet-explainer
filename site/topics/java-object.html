4.1 Class & Object (Selenium + Interview Edition)

How classes act as templates in Metaspace, how objects store state and behavior on the Heap, 5 creation mechanisms, == vs .equals(), and null safety.

A class defines fields and methods in Metaspace without allocating instance memory, whereas an object is a runtime instance created on the Heap that holds actual field values. In test automation, Page Objects, ChromeDriver, By locators, and WebElement wrappers are all Heap objects accessed via Stack reference variables.

Before you start

Prerequisite: 3.3 Essential String Methods & Regex for SDETs

Where it fits

Every Selenium test instantiates a driver object, wraps pages into Page Object classes, passes By locator objects, and invokes methods on returned WebElement objects.

Key points

  1. A class loads once into Metaspace and consumes zero instance Heap space until instantiated via new or another creation mechanism.
  2. Every object possesses three core properties: State (instance fields), Behavior (instance methods), and Identity (unique Heap memory address).
  3. == compares Stack reference addresses, whereas .equals() checks logical equivalence when overridden (for example, String text or Selenium RemoteWebElement DOM node ID).
  4. Calling a field or method on an uninitialized null reference throws java.lang.NullPointerException (NPE).
  5. Java provides exactly 5 ways to create an object: new keyword, static/helper factory methods (By.id("q")), Reflection (Constructor.newInstance() used by TestNG), Cloning (clone()), and Deserialization (used by Jackson/RestAssured).
  6. Calling driver.quit() destroys the external browser session and sets the internal session ID to null, while the Java ChromeDriver object remains on the Heap until unreachable and reclaimed by Garbage Collection.

How it works

  1. Executing LoginPage p1 = new LoginPage(); allocates Heap space at address @A1, zeroes instance fields (null, 0, false), runs the constructor, and writes @A1 into Stack variable p1.
  2. Invoking p1.open() dereferences @A1 on the Heap and mutates p1's instance state.
  3. Executing LoginPage p2 = new LoginPage(); allocates a second distinct object at @B2, making p1 == p2 evaluate to false.
  4. Executing LoginPage p3 = p1; copies address @A1 into p3 without creating a new Heap object, so edits via p3 mutate the exact same object pointed to by p1.

Demonstrating Heap object allocation, reference aliasing, and == vs .equals() behavior:

package dev.java.oop; // Declares package

class LoginPageModel { // Defines template loaded once in Metaspace
    String url; // Instance field defaults to null
    int timeout; // Instance field defaults to 0
    boolean loaded; // Instance field defaults to false

    void open() { // Instance behavior executed against target Heap object
        loaded = true; // Mutates instance state on Heap
        System.out.println("Opened " + url + " (timeout=" + timeout + ")"); // Prints object state
    } // Ends open method
} // Ends LoginPageModel class

public class ObjectLifecycleDemo { // Declares runnable class
    public static void main(String[] args) { // Main Stack frame starts
        LoginPageModel p1 = new LoginPageModel(); // Allocates Heap object #1 (@A1)
        p1.url = "https://qkart-qa-web.labs.crio.do/login"; // Writes state into @A1
        p1.timeout = 10; // Sets timeout field on @A1
        p1.open(); // Prints: Opened https://qkart-qa-web.labs.crio.do/login (timeout=10)

        LoginPageModel p2 = new LoginPageModel(); // Allocates separate Heap object #2 (@B2)
        p2.url = "https://www.selenium.dev/"; // Writes state into @B2
        p2.open(); // Prints: Opened https://www.selenium.dev/ (timeout=0)
        System.out.println("p1 == p2 : " + (p1 == p2)); // Prints: false (distinct Heap addresses)

        LoginPageModel p3 = p1; // Copies address @A1 into p3 without calling new
        p3.timeout = 30; // Mutates shared object @A1 through alias p3
        System.out.println("p1.timeout : " + p1.timeout + " | same: " + (p1 == p3)); // Prints: 30 | true
    } // Ends main method
} // Ends ObjectLifecycleDemo class

Common mistakes

  1. Shadowing a parent BaseTest driver field by re-declaring WebDriver driver; inside a child test class; @BeforeMethod initializes the parent field while the child field stays null and throws NullPointerException.
  2. Calling @FindBy WebElement methods before invoking PageFactory.initElements(driver, this);, leaving annotated proxy fields null.
  3. Expecting driver.quit() to set the Java driver variable to null; driver still points to the Heap object with a cleared session ID, throwing NoSuchSessionException on subsequent calls.
  4. Using == instead of .equals() on two WebElement objects fetched from the same DOM node via separate findElement() calls.

Interview questions

Basics

What is the difference between a class and an object in Java?
A class is a compile-time definition of fields and methods loaded into Metaspace that takes zero Heap memory for instance data. An object is a physical runtime instance allocated on the Heap via new that holds concrete values for those fields. A single LoginPage class can produce multiple independent LoginPage objects at runtime.

What are the three defining properties of every Java object?
Every object has State (values stored inside its instance fields), Behavior (methods it exposes to read or transform state), and Identity (a unique location in Heap memory distinguishing it from other objects even if field values match identically). Identity is tested via == while logical state equivalence is tested via .equals().

Name all 5 ways to create an object in Java with one SDET example each.
The 5 ways are: 1) new keyword (new ChromeDriver()), 2) Factory methods (By.id("login")), 3) Reflection (Constructor.newInstance() used internally by TestNG to instantiate @Test classes), 4) Cloning (payload.clone() for API request variations), and 5) Deserialization (Jackson/RestAssured converting JSON into a POJO via response.as(User.class)).

How it works

If you call driver.findElement(By.id("q")) twice into WebElement a and WebElement b, what do a == b and a.equals(b) return?
Each call to findElement() instantiates a fresh RemoteWebElement Java wrapper object on the Heap, so a == b returns false because they sit at distinct memory addresses. However, RemoteWebElement overrides .equals() to compare the underlying W3C DOM element ID, so a.equals(b) returns true.

What happens step by step on the Stack and Heap during LoginPage p = new LoginPage();?
First, new allocates memory on the Heap large enough for LoginPage's fields plus an object header. Next, the JVM zeroes all field slots to type defaults and executes the LoginPage() constructor body. Finally, the resulting Heap address is returned and assigned into Stack reference variable p.

What happens in memory when you call driver.quit()?
driver.quit() sends the W3C Delete Session HTTP request, terminating the external browser and driver executable processes, and clears the internal sessionId field to null. The Java ChromeDriver object itself remains on the Heap with driver != null until the reference leaves scope and Garbage Collection sweeps it.

Real situations

What are the top 3 causes of NullPointerException in Selenium Page Object frameworks?
First, declaring a duplicate WebDriver driver; field in a test subclass that shadows the initialized BaseTest.driver field. Second, accessing @FindBy fields before calling PageFactory.initElements(driver, this). Third, instantiating a Page Object inside a field initializer before @BeforeMethod has initialized driver.

Why does TestNG instantiate your @Test class without requiring you to write new LoginTest()?
TestNG inspects the compiled test classes specified in testng.xml and uses Java Reflection (getDeclaredConstructor().newInstance()) at runtime to allocate test instances automatically. This is also why TestNG requires a public no-argument constructor unless a custom IObjectFactory or dependency injector is configured.

How do RestAssured and Jackson create response POJOs without explicit new calls in your test code?
Jackson uses reflection and deserialization mechanisms to read the JSON stream, allocate a target POJO instance via its no-arg constructor (or annotated @JsonCreator), and populate fields before returning the hydrated Heap object to the test.

Troubleshooting

Why does calling driver.get(...) after driver.quit() throw NoSuchSessionException instead of NullPointerException?
Because the Java driver reference on the Stack still points to a valid ChromeDriver Heap object, the JVM invokes get() cleanly rather than throwing NPE. Inside RemoteWebDriver, Selenium detects that its internal sessionId is null and throws NoSuchSessionException: Session ID is null.

Why does creating a Page Object at field level (LoginPage login = new LoginPage(driver);) inside a Test class cause NPE during clicks?
Field initializers run during test class instantiation before @BeforeMethod launches the browser, so driver is still null when passed into LoginPage. Instantiate Page Objects inside the @Test method or lazily after @BeforeMethod sets up the driver.

Why does printing an object directly via System.out.println(user) output User@4e25154f instead of field values?
By default, classes inherit Object.toString(), which prints the class name followed by the unsigned hexadecimal hash code. Overriding toString() in your POJO or test data class outputs meaningful field details in TestNG logs.

Design choices

Why do modern Selenium frameworks instantiate Page Objects via new LoginPage(driver) passing driver in the constructor?
Injecting the active WebDriver through the Page Object constructor (Dependency Injection) ensures every Page Object operates strictly against the calling test thread's browser without relying on brittle global static fields. This makes parallel execution safe by construction.

Why should custom DTOs and Page Objects avoid exposing mutable public fields directly?
Exposing raw public fields lets external test code bypass validation or hold inconsistent object state. Keeping fields private and exposing explicit methods enforces invariants across the test suite.

When building a test payload from a template object, why is cloning or a copy constructor safer than assigning Payload copy = template;?
Simple assignment (copy = template) creates a reference alias to the identical Heap object, so modifying copy.email mutates template.email for subsequent tests. Creating a distinct Heap object via a copy constructor or clone keeps test inputs completely independent.

Quick answers

  1. Does a class declaration allocate Heap memory for instance fields? No; memory is allocated only when an object is instantiated.
  2. What are the 5 ways to create an object in Java? new keyword, Factory method, Reflection, Cloning, and Deserialization.
  3. What does == check on object variables? Heap memory address equality.
  4. What does driver.quit() set to null? The internal W3C session ID (not the Java driver variable itself).
  5. What exception is thrown when calling a method on a null reference? java.lang.NullPointerException.
  6. Why do two separate driver.findElement() calls for the same button have a.equals(b) == true? RemoteWebElement overrides .equals() to compare the underlying DOM element ID.
