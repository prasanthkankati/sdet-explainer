J5.2 Question Bank: List: ArrayList vs LinkedList (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. Compare ArrayList and LinkedList on internal structure, access speed, and memory usage.
    ArrayList uses a single contiguous Object[] array, giving O(1) indexed lookup (get(i)) and low per-element memory overhead while paying O(n) cost to shift elements when inserting or deleting in the middle. LinkedList wraps every element in a separate Node object holding prev and next references, consuming roughly 3x–4x more memory and requiring O(n) traversal for get(i) while offering O(1) insertion/removal at both ends.
  2. How does driver.findElement(By) differ from driver.findElements(By) when an element is missing?
    driver.findElement(By) expects at least one matching node and immediately throws NoSuchElementException (after any active implicit wait) if none exist. driver.findElements(By) returns a List<WebElement> containing all matching elements, or a clean empty list (size() == 0) without throwing an exception when zero elements match.
  3. Are ArrayList and LinkedList thread-safe?
    Neither is thread-safe. Concurrent structural modification from multiple threads causes lost elements or ConcurrentModificationException. For thread-safe lists across threads, use CopyOnWriteArrayList (for read-heavy listener lists) or synchronize explicitly around shared mutations.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. Explain how ArrayList grows dynamically when its internal array fills up.
    When constructed via new ArrayList<>(), Java initially shares a zero-length empty array and lazily allocates capacity 10 upon the very first add(). Once adding an 11th element overflows capacity, ArrayList.grow() computes newCapacity = oldCapacity + (oldCapacity >> 1) (1.5x growth: 10 -> 15 -> 22) and copies existing references into the newly allocated Heap array via Arrays.copyOf().
  2. Why is ArrayList faster than LinkedList even for repeated sequential scans and middle edits in practice?
    ArrayList elements sit contiguously in RAM (actually their object references sit sequentially in one array), enabling hardware CPU cache lines to prefetch adjacent slots effortlessly. LinkedList scatters individual Node objects randomly across the Heap, causing frequent CPU cache misses during pointer chasing.
  3. What is the difference between list.remove(1) and list.remove(Integer.valueOf(1)) on a List<Integer>?
    List<E> overloads remove(int index) and remove(Object o). Calling list.remove(1) invokes the primitive int overload and deletes the element at index 1, whereas calling list.remove(Integer.valueOf(1)) invokes the Object overload and removes the first occurrence of value 1.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. When writing a Selenium helper that checks whether an optional modal banner appeared without failing the test, how does List<WebElement> help?
    Use List<WebElement> banners = driver.findElements(By.id("promo-modal")); and check if (!banners.isEmpty() && banners.get(0).isDisplayed()). Notice that if implicit wait is set to 10s, findElements() still waits up to 10s when absent—so keep implicit wait at 0s and rely on explicit waits.
  2. When collecting text from 200 product cards via List<WebElement> cards, why pre-size new ArrayList<>(cards.size())?
    Passing cards.size() to the ArrayList(int initialCapacity) constructor allocates the exact array size in one shot, eliminating repeated 1.5x array copies (10 -> 15 -> 22 -> 33 -> 49 -> 73 -> 109 -> 163 -> 244) and wasted array garbage.
  3. How do you implement a FIFO test-queue or undo stack cleanly in Java?
    Although LinkedList implements Deque, the official Java documentation recommends ArrayDeque<E> for both stacks and FIFO queues because a resizable circular array beats node-per-element allocation in speed and Heap memory.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why does List<String> list = List.of("a", "b"); list.set(0, "c"); throw UnsupportedOperationException while Arrays.asList("a", "b") allows set()?
    List.of() constructs a strictly immutable unmodifiable collection introduced in Java 9 that forbids add, remove, set, and null elements. Arrays.asList() returns a fixed-size mutable wrapper backed by the original array, allowing set() while forbidding add and remove.
  2. Why does list.subList(1, 3).clear(); unexpectedly remove elements from the original parent list?
    List.subList(from, to) does NOT copy elements into a standalone new list; it returns a live backed view over a slice of the original list. Any mutation on the subList reflects directly in the parent list, and structural edits directly on the parent list afterward throw ConcurrentModificationException on the subList.
  3. Why did driver.findElements(locator).get(0).click() throw IndexOutOfBoundsException: Index 0 out of bounds for length 0?
    The page had not yet rendered the element or the locator matched zero nodes, so findElements() returned an empty list of length 0. Use WebDriverWait with ExpectedConditions.numberOfElementsToBeMoreThan(locator, 0) before calling .get(0).

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why is ArrayList the default choice over LinkedList in 95% of Java and SDET applications?
    Most lists in tests and business code are populated sequentially at the tail and iterated or indexed randomly, where ArrayList's contiguous memory layout delivers vastly higher CPU cache locality and lower memory overhead. Only choose LinkedList (or preferably ArrayDeque) when frequent O(1) insertions/deletions at both the head and tail dominate.
  2. Why should Page Objects return unmodifiable lists (List.copyOf(result)) when exposing scraped UI rows?
    Returning an unmodifiable defensive copy prevents test assertions or utility helpers from mutating Page Object internal lists inadvertently while protecting against accidental null insertions.
  3. Why was legacy Vector effectively replaced by ArrayList and CopyOnWriteArrayList?
    Synchronizing every single get() and size() method on Vector imposes unnecessary lock contention even for single-threaded usage and still fails compound check-then-act sequences (if (!v.isEmpty()) v.get(0)). Modern code uses local ArrayList for isolated threads or CopyOnWriteArrayList for concurrent shared reads.
  4. What is the default initial capacity of ArrayList?
    10 (allocated lazily on the first add).
  5. By what factor does ArrayList grow when full?
    1.5x (oldCapacity + (oldCapacity >> 1)).
  6. What is the time complexity of ArrayList.get(i) vs LinkedList.get(i)?
    O(1) for ArrayList; O(n) for LinkedList.
  7. What does driver.findElements(By) return if zero elements match?
    An empty List<WebElement> (size() == 0), never NoSuchElementException.
  8. Does List.of() allow null elements?
    No; it throws NullPointerException.
  9. Which interface allows ArrayList to signal O(1) indexed access?
    java.util.RandomAccess.
