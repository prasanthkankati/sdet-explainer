M2.3 Question Bank: Non-Functional Testing — Performance, Security, Usability & Compatibility (35 Questions)

Tier 1: Core Definitions & Classification (Q1–Q10)

  1. Q1: What is Non-Functional Testing and how does it differ from Functional Testing?
    A: Functional Testing validates WHAT the system does (business features and rules), whereas Non-Functional Testing validates HOW WELL the system performs (speed, scalability, security, usability, reliability, and cross-browser compatibility against measurable SLAs).
  2. Q2: What are the 5 main sub-types of Performance Testing?
    A: (1) Load Testing (expected normal/peak concurrent users), (2) Stress Testing (pushing beyond peak capacity to find the breaking point), (3) Spike Testing (instantaneous extreme surge/drop in traffic), (4) Endurance / Soak Testing (sustained load over 12–72 hours for memory leaks), and (5) Volume / Flood Testing (massive database record volume).
  3. Q3: What is the exact difference between Load Testing and Stress Testing?
    A: Load Testing stays *within* or *up to* the designed peak threshold (e.g., testing 5,000 users when the SLA is 5,000 users) to verify response times and throughput. Stress Testing intentionally exceeds the threshold (10,000 → 25,000 users) until the system breaks, to discover the breaking point and verify graceful degradation and auto-recovery.
  4. Q4: What is Endurance (Soak) Testing and what specific bugs does it catch?
    A: Endurance Testing applies a steady moderate load continuously for 12 to 72 hours. It catches bugs that never appear in a 15-minute load test: Java Heap memory leaks (`OutOfMemoryError`), unclosed database connections exhausting the connection pool, thread leaks, and log files filling up disk space.
  5. Q5: What is Spike Testing? Give a real-world example.
    A: Spike Testing suddenly increases concurrent users from baseline to an extreme peak in seconds and drops them back down (e.g., an e-commerce Flash Sale going live at 12:00:00 PM or concert ticket booking opening), testing whether cloud auto-scaling and request queues survive the shock.
  6. Q6: What is Volume Testing (Flood Testing)?
    A: Volume Testing evaluates system performance when the underlying database or file storage contains a huge volume of data (e.g., querying a `transactions` table seeded with 200 million rows), exposing missing SQL indexes and full-table scan locks.
  7. Q7: What is Compatibility Testing and what are its 2 version-based sub-types?
    A: Compatibility Testing verifies the software works across different browsers (Chrome, Firefox, Safari, Edge), operating systems, devices, and screen resolutions. Its 2 version sub-types are Backward Compatibility (working with older client/DB versions) and Forward Compatibility (working with upcoming OS/browser versions).
  8. Q8: What is the difference between Internationalization (`I18n`) and Localization (`L10n`)?
    A: Internationalization (`I18n`) is engineering the software architecture so it can adapt to any language/region without code changes (externalizing strings into resource bundles, supporting UTF-8). Localization (`L10n`) is translating and testing the app for one specific locale (e.g., German `de-DE`, `€` currency, `DD.MM.YYYY` dates).
  9. Q9: What is Usability Testing vs Accessibility (`a11y`) Testing?
    A: Usability Testing measures how easy, intuitive, and efficient the UI is for general users. Accessibility (`a11y`) Testing verifies that users with visual, auditory, motor, or cognitive disabilities can use the application via screen readers, keyboard-only navigation, and WCAG contrast standards.
  10. Q10: What is Recovery Testing (Failover Testing)?
    A: Recovery Testing intentionally forces hardware, network, or pod crashes (e.g., killing the primary DB node or microservice container) to verify how quickly the system recovers (`RTO`) and whether any committed data is lost (`RPO`).

Tier 2: Why / Why Not & Deep Comparisons (Q11–Q18)

  1. Q11: Why do we measure `p95` and `p99` response times in Performance Testing instead of just the "Average" response time?
    A: Averages hide severe outliers! If 90 requests take `50ms` and 10 requests take `9,500ms` (nearly 10 seconds), the average is `995ms`—which looks acceptable, even though 10% of your customers experienced a 10-second freeze. `p95` and `p99` guarantee that 95% or 99% of all users get fast responses.
  2. Q12: Why shouldn't you use Selenium WebDriver browsers to generate 10,000 concurrent users for Load Testing?
    A: Each real headless Chrome browser instance consumes ~300MB–500MB of RAM and heavy CPU; spinning up 10,000 browsers requires massive cloud infrastructure and measures client rendering overhead rather than server capacity. Protocol-level tools (JMeter, k6, Gatling) simulate 10,000 concurrent HTTP/WebSocket users from a single machine.
  3. Q13: What is the difference between Authentication (`HTTP 401`) and Authorization (`HTTP 403`) in Security Testing?
    A: Authentication (`401 Unauthorized`) verifies *identity* ("Who are you?" via login credentials/JWT). Authorization (`403 Forbidden`) verifies *permissions* ("Are you allowed to access this resource?" — e.g., a logged-in regular user trying to call `DELETE /api/admin/users/5`).
  4. Q14: What is IDOR (Insecure Direct Object Reference) and how do QA/SDETs test for it?
    A: IDOR is a critical authorization flaw where an authenticated user (`User A`) changes an ID parameter in a URL or API payload (e.g., `GET /api/orders/1002` instead of `1001`) and the server returns `User B`'s private order without checking ownership. SDETs test it by sending User A's Bearer token with User B's resource IDs and asserting `403 Forbidden` or `404 Not Found`.
  5. Q15: What is Pseudo-Localization Testing and why do SDETs run it before translations are ready?
    A: Pseudo-localization replaces English text with accented, expanded strings (e.g., `[¡¡Àccöüñt Sèttïñgs~~~!!]`) that are 30%–40% longer (simulating German/Finnish text expansion) and contain Unicode characters. It lets QA catch hardcoded strings, text truncation, and layout overflow *before* paying human translators.
  6. Q16: What is the difference between Vertical Scaling (Scale Up) and Horizontal Scaling (Scale Out) during Performance Testing?
    A: Vertical Scaling adds more CPU/RAM to a single server. Horizontal Scaling adds more server instances/pods behind a Load Balancer. Spike and Stress tests specifically validate whether Horizontal Auto-Scalers (like Kubernetes HPA) spin up new pods fast enough.
  7. Q17: Why is Compatibility Testing split into a Browser/Device Coverage Matrix instead of testing every browser version ever made?
    A: Due to Principle #2 (Exhaustive testing is impossible). QA analyzes production Google Analytics / telemetry to select the top browser + OS combinations covering 95%+ of real customer traffic (e.g., latest 2 versions of Chrome, Safari iOS, Edge, and Firefox).
  8. Q18: What is Chaos Engineering (e.g., Netflix Chaos Monkey) and how does it relate to Non-Functional Testing?
    A: Chaos Engineering is automated Reliability & Resiliency Testing in staging/production where pods, Availability Zones, or network links are intentionally injected with latency or killed to prove the distributed system survives infrastructure failures without customer downtime.

Tier 3: Real-World Tricky & Edge-Case Scenarios (Q19–Q25)

  1. Q19: Scenario: Your application passes a 1-hour Load Test with 5,000 concurrent users at `200ms` response time. In production, the server crashes every 3 days with `java.lang.OutOfMemoryError: Java heap space` under only 800 users. Why did the Load Test miss it, and which test catches it?
    A: A 1-hour Load Test is too short to fill up an 8GB JVM Heap when a small memory leak leaks only 5MB per minute. An Endurance (Soak) Test running for 24–48 hours with heap profiling alerts (`jmap` / Prometheus memory graphs) catches the gradual memory leak.
  2. Q20: Scenario: A government university portal works fine all year, but crashes every year at exactly 10:00 AM on Exam Results Day when 200,000 students refresh the page within 30 seconds. Which specific performance test was skipped?
    A: Spike Testing (testing an instantaneous 0 → 200,000 vertical jump in concurrent requests, CDN caching of static assets, and waiting-room queue throttling).
  3. Q21: Scenario: A checkout page works perfectly in Chrome and Edge, but in Safari on iPhone, clicking the "Select Delivery Date" calendar picker does nothing. What kind of bug is this and how do you automate catching it?
    A: A Cross-Browser / WebKit Compatibility defect (often caused by Safari's stricter date parsing `new Date("2026-11-13")` vs `"13/11/2026"` or WebKit CSS differences). Catch it by running Playwright (`webkit` project) or Selenium Grid + BrowserStack iOS Safari in CI/CD.
  4. Q22: Scenario: When you switch the app language from English to Arabic (`ar-SA`), the text translates properly, but the Back arrow icon and navigation menu stay on the left instead of mirroring to the right. What type of defect is this?
    A: A Localization (`L10n`) Right-to-Left (`dir="rtl"`) layout defect. Arabic and Hebrew require mirroring UI directional icons and flex/grid alignment (`dir="rtl"`), not just translating text strings.
  5. Q23: Scenario: When you type `test' OR '1'='1` into the Search box, the page returns a raw `java.sql.SQLException: syntax error near '1'` stack trace on screen. Name the 2 security vulnerabilities exposed here.
    A: (1) SQL Injection (SQLi) vulnerability (user input is concatenated directly into SQL instead of using `PreparedStatement`), and (2) Sensitive Information Exposure / Verbose Error Handling (leaking internal database/Java stack traces to the client instead of a generic error message).
  6. Q24: Scenario: During a Stress Test, when load hits 18,000 users, the payment service crashes. When you stop the test and send just 1 single user request 10 minutes later, the server still returns `503 Service Unavailable`. What failed here?
    A: Recoverability / Auto-Recovery failed (e.g., deadlocked database transactions or hung worker threads never released their locks after the stress spike ended). Stress testing specifically checks whether the system self-heals after the traffic drops.
  7. Q25: Scenario: A visually impaired user navigating your web app using only the `Tab` key gets stuck inside a promotional popup modal and cannot `Tab` to the "Close (X)" button or press `Escape`. Which non-functional test fails here?
    A: Accessibility (`a11y`) Testing (specifically WCAG 2.1 Keyboard Accessibility / Focus Trap compliance).

Tier 4: SDET, Automation (Playwright / Selenium / JMeter / k6) Application (Q26–Q30)

  1. Q26: How do you automate Accessibility (`a11y`) testing inside a Selenium Java or Playwright TypeScript framework?
    A: Integrate Deque's Axe-Core library (`com.deque.html.axecore:selenium` in Java or `@axe-core/playwright` in TS). After navigating to any page, call `new AxeBuilder(driver).analyze()` and assert `results.getViolations().isEmpty()` to catch WCAG violations automatically in CI/CD.
  2. Q27: How do you assert API response time SLAs inside RestAssured?
    A: Use RestAssured's Hamcrest matcher: `given().when().get("/api/products").then().statusCode(200).time(lessThan(500L), TimeUnit.MILLISECONDS);`.
  3. Q28: How can you use Chrome DevTools Protocol (CDP) in Selenium 4 to simulate a slow 3G mobile network (Network Compatibility Testing)?
    A: Use `DevTools devTools = ((HasDevTools) driver).getDevTools(); devTools.createSession(); devTools.send(Network.emulateNetworkConditions(false, 150, 75000, 25000, Optional.of(ConnectionType.CELLULAR3G)));` to verify loading spinners and timeout handling under high latency.
  4. Q29: How do you automate Cross-Browser & Cross-Viewport Compatibility testing in Playwright?
    A: Define multiple `projects` in `playwright.config.ts` (`Desktop Chrome`, `Desktop Firefox`, `Desktop Safari/WebKit`, `Mobile Chrome Pixel 7`, `Mobile Safari iPhone 15`) so a single test file runs across all 5 browser/device engines in parallel.
  5. Q30: How do you integrate k6 or JMeter performance tests into a Jenkins CI/CD pipeline so a slow build automatically fails the pipeline?
    A: Configure pass/fail Thresholds directly in the script (e.g., in k6: `thresholds: { http_req_duration: ['p(95)<500'], http_req_failed: ['rate<0.01'] }`). If `p95` exceeds `500ms`, the CLI exits with a non-zero exit code, automatically failing the Jenkins stage.

Tier 5: Rapid-Fire Yes/No & 1-Liner Traps (Q31–Q35)

  1. Q31: Which test checks memory leaks over 48 hours: Stress Testing or Endurance (Soak) Testing?
    A: Endurance (Soak) Testing.
  2. Q32: Why are there 18 in `I18n` and 10 in `L10n`?
    A: Because there are 18 letters between `I` and `n` in *Internationalization*, and 10 letters between `L` and `n` in *Localization*.
  3. Q33: Does Volume Testing test a huge number of concurrent users or a huge amount of data in the database?
    A: A huge amount of data in the database.
  4. Q34: Which HTTP status code indicates an Authentication failure vs an Authorization failure?
    A: `401 Unauthorized` = Authentication failure; `403 Forbidden` = Authorization failure.
  5. Q35: What does `RTO` vs `RPO` stand for in Recovery Testing?
    A: RTO (Recovery Time Objective) = max acceptable downtime duration; RPO (Recovery Point Objective) = max acceptable age/amount of data loss.
