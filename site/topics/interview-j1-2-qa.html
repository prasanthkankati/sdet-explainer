J1.2 Question Bank: JVM Architecture & Class Loader Subsystem (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. What are the four main subsystems of the JVM architecture?
    The four subsystems are the Class Loader Subsystem, the Runtime Data Areas, the Execution Engine, and the Java Native Interface (JNI). The Class Loader reads and validates bytecode, Runtime Data Areas store objects and execution state, the Execution Engine runs instructions and collects garbage, and JNI communicates with native OS libraries. Every TestNG test runs across all four subsystems simultaneously.
  2. Which three ClassLoaders ship with a standard JVM?
    The JVM uses the Bootstrap ClassLoader, Platform ClassLoader, and Application ClassLoader in top-to-bottom hierarchy. Bootstrap loads core JDK classes including java.lang.String, Platform loads extended platform modules, and Application loads your test code and third-party JARs like selenium-java. Calling String.class.getClassLoader() returns null because Bootstrap is native C/C++ code.
  3. Which JVM Runtime Data Areas are shared across threads versus created per thread?
    The Heap and Metaspace are shared across every thread inside a single JVM process. By contrast, each thread gets its own isolated JVM Stack, Program Counter (PC) Register, and Native Method Stack. This separation explains why local variables inside a test method are automatically thread-safe while shared static Heap objects cause race conditions in parallel Selenium runs.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. What happens during the three sub-phases of Linking: Verify, Prepare, and Resolve?
    Verify checks bytecode structural integrity, stack bounds, and type safety to prevent memory corruption. Prepare allocates memory for static fields and assigns their default zeroed values (0, false, or null) without running initializers. Resolve replaces symbolic class and method names in the runtime constant pool with direct memory pointers.
  2. How does the Parent Delegation Model protect Java security?
    When the Application ClassLoader receives a request to load java.lang.String, it delegates upward to Platform, which delegates upward to Bootstrap before trying the local classpath. Bootstrap immediately resolves the authentic JDK String class, ignoring any spoofed java.lang.String placed on the application classpath. This guarantees core Java APIs cannot be replaced.
  3. What is the difference between the Prepare phase and the Initialization phase for static fields?
    During Prepare, the JVM allocates space for static int timeout = 10; and sets timeout to its default 0. During Initialization, the JVM executes the actual assignment to set timeout = 10 and runs any static { } blocks in source order. Note that static final compile-time constants are inlined directly into the constant pool and do not wait for Initialization.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. A Selenium test uses JDBC to validate database rows and throws ClassNotFoundException: com.mysql.cj.jdbc.Driver. Why did compilation succeed?
    Class.forName("com.mysql.cj.jdbc.Driver") passes the class name as a String literal, so javac cannot verify at compile time whether that class exists on the classpath. At runtime, the Application ClassLoader searches the classpath JARs, fails to find the driver JAR, and throws the checked ClassNotFoundException. Adding the MySQL driver dependency to pom.xml resolves it.
  2. How does parallel TestNG execution map to the JVM's Runtime Data Areas?
    When TestNG runs 4 test methods concurrently with parallel="methods" thread-count="4", the JVM maintains 4 separate JVM Stacks and 4 PC Registers—one per worker thread. All 4 threads share the single Heap and Metaspace. Local variables like By locators inside each method stay isolated on their own Stack, whereas a single shared static WebDriver on the Heap causes threads to collide on the same browser.
  3. Where does Selenium's ChromeDriver class get loaded compared to java.lang.Object?
    java.lang.Object resides in the JDK's java.base module and is loaded by the native Bootstrap ClassLoader. org.openqa.selenium.chrome.ChromeDriver resides inside the selenium-chrome-driver.jar on the Maven test classpath, so the Application ClassLoader loads it after Bootstrap and Platform delegate back down.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why does a class throw ExceptionInInitializerError on the first test and NoClassDefFoundError on every test after?
    When a static { } initializer throws an uncaught runtime exception (for example, failing to load config.properties), the JVM aborts initialization with ExceptionInInitializerError and marks that class as erroneous in Metaspace. Any subsequent test referencing that same class cannot initialize it again and immediately fails with NoClassDefFoundError. Fixing the underlying static block exception cures both errors.
  2. What causes NoClassDefFoundError: org/openqa/selenium/WebDriver in a packaged Selenium project?
    The project compiled cleanly because the Selenium JAR was present on the compile classpath, but the JAR is absent on the runtime classpath (for example, declaring <scope>provided</scope> in pom.xml or omitting dependency JARs from a fat JAR). At runtime, the Application ClassLoader attempts to resolve WebDriver and throws NoClassDefFoundError. Ensuring runtime scope or bundling dependencies via Maven Shade fixes the issue.
  3. What causes java.lang.VerifyError when launching tests?
    VerifyError occurs during the Linking Verify phase when loaded bytecode violates JVM type rules, most commonly caused by two incompatible versions of a library JAR (Guava or ASM, for instance) on the classpath. Inspecting the build with mvn dependency:tree reveals the duplicate transitive dependency so the older version can be excluded.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why does the JVM load classes lazily instead of loading the entire classpath at startup?
    Enterprise test suites often carry dozens of third-party JARs containing tens of thousands of classes, only a fraction of which run during a given test execution. Lazy loading loads only the classes actively touched by the execution path, keeping startup latency low and Metaspace usage minimal.
  2. Why do test frameworks like TestNG and Maven Surefire sometimes create custom ClassLoaders?
    Isolated ClassLoaders allow build plugins and test runners to load specific plugin dependencies without colliding with versions used by the application under test. By maintaining separate classloader namespaces, two versions of the same library can coexist cleanly inside one JVM process.
  3. Why did Java design the Parent Delegation Model to search upward first instead of loading from the local application classpath first?
    Searching upward first guarantees that core runtime classes including java.lang.Object, String, and SecurityManager always resolve to the single canonical JDK definition. If application JARs loaded first, a misconfigured or malicious dependency JAR could redefine core language types and break type compatibility across the entire JVM.
  4. What are the 3 built-in JVM ClassLoaders?
    Bootstrap, Platform, and Application ClassLoader.
  5. What are the 3 phases of Class Loading?
    Loading, Linking (Verify, Prepare, Resolve), and Initialization.
  6. Which Runtime Data Areas are shared by all threads?
    Heap and Metaspace.
  7. Which Runtime Data Areas are created per thread?
    JVM Stack, PC Register, and Native Method Stack.
  8. What is the difference between ClassNotFoundException and NoClassDefFoundError?
    ClassNotFoundException is a checked exception on dynamic string loading; NoClassDefFoundError is an unchecked Error when a compiled dependency is missing or failed static init at runtime.
  9. Which ClassLoader loads Selenium WebDriver classes?
    The Application ClassLoader.
