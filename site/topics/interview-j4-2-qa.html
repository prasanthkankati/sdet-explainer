J4.2 Question Bank: Constructors: Default, Parameterized, Chaining & Singleton (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. What are the strict rules that distinguish a constructor from a normal method?
    A constructor must match its enclosing class name character-for-character and must declare zero return type (not even void). Constructors cannot be marked static, final, or abstract, and they are never inherited by subclasses. They execute automatically once during object creation via new.
  2. When does the Java compiler generate a default no-argument constructor, and when does it omit it?
    If a class contains zero written constructors, javac generates a hidden no-arg constructor whose access modifier matches the class and whose body simply calls super();. The moment you write any explicit constructor—for example, public LoginPage(WebDriver driver)—the compiler stops generating the implicit no-arg constructor. Any caller attempting new LoginPage() afterward fails compilation unless you declare a no-arg constructor explicitly.
  3. Why can a constructor be declared private, and where is it useful?
    Marking a constructor private prevents external classes from instantiating the class directly with new. It is used in stateless utility classes (like java.lang.Math or a WaitUtils helper with only static methods) and in the Singleton pattern (like a read-only ConfigReader) where a single shared instance is returned via getInstance().

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. Explain the execution order of constructors when ChildPage extends BasePage.
    When new ChildPage(driver) runs, the child constructor invokes super(driver) on its very first line before executing its own body. BasePage's constructor runs first (after implicitly calling Object()), initializes inherited fields, and returns control to ChildPage's remaining constructor statements. Parent fields are always ready before child constructor code runs.
  2. Why must this(...) and super(...) always be the very first statement inside a constructor?
    Guaranteeing the superclass or delegated constructor executes first ensures all parent invariants and inherited fields are initialized before the current constructor attempts to read them. Because both require position 1, a constructor can invoke at most one of them, and any constructor using this() delegates the responsibility of calling super() to the target constructor.
  3. What happens if a recursive constructor call occurs, for instance Constructor A calling this(x) which calls this()?
    Java detects direct or cyclic constructor recursion at compile time and immediately rejects the file with 'recursive constructor invocation'.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. Why do TestNG @Test classes and Jackson POJOs normally require a public no-argument constructor?
    TestNG instantiates test classes via reflection using the zero-argument constructor unless a custom object factory is configured. Similarly, Jackson deserializes JSON strings into Java objects by invoking the class's no-arg constructor first and then populating fields or setters. Adding only a parameterized constructor to a POJO without adding an explicit no-arg constructor breaks JSON deserialization.
  2. When is the Singleton pattern safe vs dangerous in a Selenium automation framework?
    Singleton is safe and beneficial for immutable, read-only resources like loading config.properties once via ConfigReader.getInstance() so tests do not re-read disk files 100 times. Singleton is dangerous for WebDriver because parallel threads would share one browser instance, leading to session collisions and NoSuchSessionException.
  3. How can a BasePage constructor enforce that every Page Object receives a non-null WebDriver?
    Inside BasePage(WebDriver driver), validate this.driver = Objects.requireNonNull(driver, "WebDriver cannot be null");. Failing immediately inside the constructor catches setup errors at the exact line of page creation rather than three steps later inside a click method.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why did adding public void LoginPage(WebDriver driver) compile without error, yet leave this.driver as null?
    Putting void before the name turns LoginPage into a standard method rather than a constructor, so new LoginPage() actually calls the compiler's implicit no-arg constructor instead. Remove void so the constructor signature reads public LoginPage(WebDriver driver).
  2. Why does class CheckoutPage extends BasePage fail to compile with 'constructor BasePage in class BasePage cannot be applied to given types'?
    BasePage defines an explicit parameterized constructor BasePage(WebDriver driver), so it no longer has a zero-arg constructor. Because CheckoutPage omitted an explicit super(driver) call, Java inserted super() implicitly and failed to find a no-arg constructor on BasePage. Declare public CheckoutPage(WebDriver driver) { super(driver); } to fix it.
  3. Why does a private-constructor Singleton break under multi-threaded parallel TestNG startup if written naively?
    A lazy Singleton checking if (instance == null) instance = new ConfigReader(); without synchronization allows two TestNG threads starting concurrently to both see null and construct two separate instances. Fix this using double-checked locking with volatile, eager static initialization, or the Bill Pugh static inner holder class.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why should constructors avoid launching browsers, navigating URLs, or calling overridable methods?
    Heavy side effects or throwing exceptions inside constructors creates partially constructed objects and couples instantiation to network timing. Moreover, calling an overridable method inside a parent constructor runs the subclass override before the subclass's own fields are initialized. Keep constructors lightweight: validate and assign fields only.
  2. Between eager initialization, synchronized getInstance(), and Bill Pugh static holder, which Singleton implementation is cleanest in Java?
    The Bill Pugh static inner holder (private static class Holder { static final ConfigReader INSTANCE = new ConfigReader(); }) or a Java enum Singleton provides guaranteed lazy loading and JVM-enforced thread safety during class initialization without synchronization lock overhead on every getInstance() call.
  3. Why is constructor injection preferred over setter injection for passing WebDriver into Page Objects?
    Constructor injection makes the driver dependency mandatory at compile time and allows marking the field private final WebDriver driver;. Setter injection allows callers to forget calling setDriver() and permits reassigning the driver midway through a test.
  4. Does a constructor have a return type?
    No; not even void.
  5. When does the compiler generate a default no-arg constructor?
    Only when the class declares zero constructors explicitly.
  6. Which statement must be first inside a constructor: this() or super()?
    Whichever is used must be line 1; both cannot appear in the same constructor.
  7. Are constructors inherited by subclasses?
    No, subclasses invoke parent constructors via super(...).
  8. How do you block external instantiation with new?
    Declare the constructor private.
  9. Why should WebDriver NOT be a global Singleton?
    Parallel test threads would overwrite and share one browser session.
