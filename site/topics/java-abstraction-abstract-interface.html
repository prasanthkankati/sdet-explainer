4.7 Abstraction: Abstract Class vs Interface

Contract design with abstract classes and interfaces, Java 8 default/static methods, Functional & Marker interfaces, and Selenium's WebDriver hierarchy.

Abstraction exposes what an object can do while hiding internal implementation details behind abstract classes or interfaces. Understanding when to choose an abstract class (shared state and partial implementation) versus an interface (pure capability contracts and multiple implementation) is foundational to Selenium's architecture and test framework design.

Before you start

Prerequisite: 4.6 Polymorphism: Overloading vs Overriding & Upcasting

Where it fits

Selenium defines SearchContext, WebDriver, WebElement, TakesScreenshot, and JavascriptExecutor as interfaces, defines By as an abstract class, and uses abstract class BasePage patterns in enterprise suites.

Key points

  1. Neither an abstract class nor an interface can be instantiated directly using new (anonymous inner classes or concrete subclasses must supply concrete bodies).
  2. An abstract class can contain both abstract methods (no body) and concrete methods, instance fields (state), constructors, and any access modifier (public, protected, package-private, private).
  3. Every field declared in an interface is implicitly public static final (constants only), and abstract interface methods are implicitly public abstract.
  4. Since Java 8, interfaces also support concrete default and static methods (plus Java 9 private helper methods) to evolve APIs without breaking existing implementations.
  5. A Functional Interface (annotated @FunctionalInterface) declares exactly one abstract method (SAM) so it can be implemented via a Lambda expression (for example, Function<WebDriver, V> in WebDriverWait).
  6. A Marker Interface declares zero methods and tags a class with metadata for the JVM or frameworks (java.io.Serializable, java.lang.Cloneable).

How it works

  1. Define pure cross-cutting contracts or capabilities as interfaces (for instance, SearchContext declaring findElement(By) and findElements(By)).
  2. Extend or implement capabilities across concrete classes without single-parent lock-in (RemoteWebDriver implements WebDriver, JavascriptExecutor, TakesScreenshot).
  3. Use an abstract class like BasePage when subclasses share protected instance state (protected final WebDriver driver;) plus mandatory abstract readiness hooks (protected abstract boolean isLoaded();).
  4. Annotate single-method contracts with @FunctionalInterface so callers can pass concise lambdas.

Modeling an abstract BasePage with a shared driver contract alongside an interface capability:

package dev.java.oop; // Declares package

import org.openqa.selenium.WebDriver; // Imports WebDriver interface

interface PageLoadCheck { // Interface contract with abstract and Java 8 default methods
    boolean isLoaded(); // Implicitly public abstract method

    default String pageStatus() { // Java 8 default method supplies reusable behavior without state
        return isLoaded() ? "READY" : "LOADING"; // Invokes implementing class's isLoaded()
    } // Ends default method
} // Ends PageLoadCheck interface

abstract class AbstractStorePage implements PageLoadCheck { // Cannot be instantiated directly with new
    protected final WebDriver driver; // Abstract class holds instance state unlike interfaces

    AbstractStorePage(WebDriver driver) { // Abstract class constructor invoked by child super()
        this.driver = driver; // Stores driver reference
    } // Ends constructor

    public String currentTitle() { // Concrete shared helper inherited by all pages
        return driver.getTitle(); // Delegates directly to active WebDriver
    } // Ends currentTitle
} // Ends AbstractStorePage

public class CartAbstractPage extends AbstractStorePage { // Concrete subclass completes contract
    public CartAbstractPage(WebDriver driver) { // Concrete constructor
        super(driver); // Invokes AbstractStorePage constructor
    } // Ends constructor

    @Override // Implements interface contract method required by AbstractStorePage
    public boolean isLoaded() { // Concrete readiness check
        return driver.getCurrentUrl().contains("/cart"); // Checks cart route
    } // Ends isLoaded
} // Ends CartAbstractPage

Common mistakes

  1. Attempting to instantiate an abstract class or interface directly (new WebDriver() or new By()); you must instantiate a concrete implementation or factory method (new ChromeDriver(), By.id("q")).
  2. Declaring an interface method without an access modifier in a class implementation and making it package-private (boolean isLoaded()); all abstract interface methods are implicitly public, so the implementing method MUST explicitly declare public.
  3. Declaring a method both abstract and final (or abstract and private / static); abstract demands subclass overriding whereas final, private, and static prohibit overriding.
  4. Adding a second abstract method to a Functional Interface; doing so breaks all lambda expressions implementing that interface and fails compilation if annotated with @FunctionalInterface.

Interview questions

Basics

Compare an abstract class and an interface across 5 core dimensions.
First, a class can extend strictly one abstract class, whereas it can implement multiple interfaces. Second, an abstract class holds instance state fields and constructors, whereas an interface holds only public static final constants and zero constructors. Third, abstract classes allow protected and private state, whereas interface abstract methods are strictly public. Fourth, both cannot be instantiated directly with new. Fifth, both support concrete helper methods via standard methods or Java 8 default methods.

Can an abstract class have zero abstract methods, or have a constructor?
Yes to both. Marking a class abstract with zero abstract methods prevents callers from instantiating the incomplete base class directly via new BasePage(driver) while allowing concrete subclasses to inherit shared code. Its constructor still exists specifically to initialize those shared fields when subclasses invoke super(driver).

What are Functional Interfaces and Marker Interfaces in Java?
A Functional Interface has strictly one abstract method (SAM)—for example, Runnable, Predicate<T>, or ExpectedCondition<T>—allowing callers to pass concise lambdas (driver -> driver.getTitle().contains("QKart")). A Marker Interface contains zero methods and marks classes with capability metadata checked at runtime via instanceof, including Serializable and Cloneable.

How it works

Why did Java 8 introduce default and static methods inside interfaces?
Before Java 8, adding a single new method to a widely implemented interface like java.util.List broke every third-party implementation class immediately at compile time. Adding default concrete methods (like Collection.stream() and List.sort()) allowed the JDK to upgrade standard interfaces cleanly without breaking legacy implementations. Interface static methods provide factory helpers directly on the contract (like Comparator.comparing()).

What happens if an interface declares int TIMEOUT = 10; without any modifiers?
Every field inside a Java interface is implicitly treated by the compiler as public static final int TIMEOUT = 10;, regardless of whether you write those modifiers explicitly. Implementing classes cannot modify that constant field.

In Selenium, explain the exact abstraction hierarchy connecting SearchContext, WebDriver, RemoteWebDriver, and ChromeDriver.
SearchContext is the top-level interface declaring findElement and findElements. WebDriver is a child interface extending SearchContext and adding browser navigation and window contracts (and WebElement also extends SearchContext). RemoteWebDriver is a concrete class implementing WebDriver plus TakesScreenshot and JavascriptExecutor, and ChromeDriver extends ChromiumDriver which extends RemoteWebDriver.

Real situations

Why is org.openqa.selenium.By designed as an abstract class instead of an interface?
By encapsulates shared locator factory methods (By.id(), By.xpath(), By.cssSelector()) alongside shared helper logic like findElement(SearchContext context) and concrete equals()/hashCode()/toString() implementations that interfaces cannot override from Object. Every locator subclass extends By and implements findElements(SearchContext).

How does TestNG's ITestListener interface leverage Java 8 default methods?
Because ITestListener provides empty default implementations for lifecycle hooks like onTestStart, onTestSuccess, and onTestFailure, your custom listener class only needs to override onTestFailure to attach failure screenshots without writing empty boilerplate overrides for seven unused hooks.

When designing a custom Page Object framework, should BasePage be an abstract class or an interface?
Make BasePage an abstract class because every Page Object shares protected instance state (protected final WebDriver driver; and protected final WebDriverWait wait;) initialized once via a constructor, which an interface cannot store.

Troubleshooting

Why does implementing PageLoadCheck fail with 'attempting to assign weaker access privileges; was public' when writing boolean isLoaded()?
In an interface, boolean isLoaded(); is implicitly public even without writing the word public. In the implementing class, omitting public assigns narrower package-private visibility, violating Java's override visibility rule. Always prefix implemented interface methods with public.

Why did adding a helper method inside an interface annotated with @FunctionalInterface break compilation?
If the added helper is an abstract method, the interface now has two abstract methods and ceases to be a Functional Interface. Making the helper either a default method or a static method leaves strictly one abstract method and compiles cleanly.

Why can you write new WebDriverWait(driver, Duration.ofSeconds(10)).until(d -> d.getTitle().equals("QKart")); without writing an anonymous class?
Wait.until(Function<? super T, V>) expects the java.util.function.Function Functional Interface. Because Function has only one abstract method (apply(T)), Java automatically compiles the lambda expression into an instance implementing that single method.

Design choices

When creating a brand-new abstraction for a test framework (for instance, a DriverProvider or SecretStore), should you start with an interface or an abstract class?
Start with an interface when defining pure behavioral capabilities because classes can implement multiple interfaces without consuming their single inheritance slot (for instance, implementing both local Docker and BrowserStack cloud providers). Reserve abstract class for tight IS-A families sharing mutable protected fields or constructor initialization logic.

Why do modern Java architectures reject empty Marker Interfaces for new code in favor of Annotations?
Marker interfaces like Serializable cannot accept configuration parameters and lock classes at compile time. Custom Java Annotations (including TestNG @Test(retryAnalyzer = ...) or JUnit @Tag("smoke")) attach structured key-value metadata cleanly to classes, methods, or fields without polluting type hierarchies.

Why are interfaces prohibited from overriding Object methods like equals(), hashCode(), or toString() as default methods?
Every class implementing an interface already inherits concrete implementations of equals, hashCode, and toString from java.lang.Object, and superclass methods always win over interface default methods. Allowing interface defaults for Object methods would create useless dead code that could never run polymorphically.

Quick answers

  1. Can an interface have instance fields or constructors? No; interface fields are implicitly public static final constants and interfaces have no constructors.
  2. Can an abstract class have a constructor? Yes, executed by subclasses via super().
  3. What is a Functional Interface? An interface with exactly one abstract method (enabling Lambda expressions).
  4. What is a Marker Interface? An empty interface with zero methods (for example, Serializable or Cloneable).
  5. What type are WebDriver, WebElement, and SearchContext in Selenium? Interfaces (whereas By is an abstract class).
  6. What methods did Java 8 allow inside interfaces? Concrete default and static methods.
