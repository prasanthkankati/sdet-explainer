4.7 Abstraction: Abstract Class vs Interface

1. Definition

Abstraction hides internal complexity behind essential operations using either an abstract class (partial blueprint that can hold state and constructors) or an interface (pure multi-implementable contract).

2. Memory hook

Abstract class = Shared base state + partial rules (1 per subclass); Interface = Pure capability contract (many allowed!).

  • Abstract class: can have instance fields, constructors (called by super()), concrete methods, and abstract methods — cannot run new directly.
  • Interface: fields are always public static final constants; classes implement unlimited interfaces (implements WebDriver, TakesScreenshot, JavascriptExecutor).
  • Java 8+ Interfaces: added default and static methods plus Single Abstract Method Functional Interfaces for lambdas.

5. Code example: abstract BasePage + TakesScreenshot capability interface

interface SnapshotCapable {                   // capability contract
    void snap(String name);
    default void logSnap(String name) { System.out.println("Snap saved: " + name); }
}

abstract class AbstractCheck {                // shared state + constructor
    protected final String url;
    AbstractCheck(String url) { this.url = url; }
    abstract boolean verify();                // subclass MUST implement
}

public class QKartCheck extends AbstractCheck implements SnapshotCapable {
    QKartCheck() { super("https://qkart-qa-web.labs.crio.do/"); }
    @Override boolean verify() { return url.contains("qkart"); }
    @Override public void snap(String n) { logSnap(n); }
    public static void main(String[] args) {
        QKartCheck c = new QKartCheck();
        System.out.println("Pass=" + c.verify());
        c.snap("checkout.png");
    }
}

6. Execution flow, step by step

  1. AbstractCheck cannot be created with new AbstractCheck(...) directly, yet supplies shared field url via its constructor.
  2. SnapshotCapable adds screenshot capability via implements plus reuses default void logSnap().
  3. QKartCheck extends one abstract base and implements the interface, fulfilling verify() and snap().
  4. Running new QKartCheck() triggers parent setup first cleanly.
  5. In real Selenium, ChromeDriver extends ChromiumDriver -> RemoteWebDriver and implements WebDriver, TakesScreenshot, and JavascriptExecutor.

8. Why it matters

Interfaces decouple your framework from concrete vendors while abstract base classes prevent copy-pasting shared state across dozens of subclasses.

SDET link: Because WebDriver, TakesScreenshot, and JavascriptExecutor are separate capability interfaces implemented by RemoteWebDriver, you safely cast ((TakesScreenshot) driver).getScreenshotAs(...) in TestNG failure listeners.

9. Quick test

Can an abstract class have zero abstract methods, or have a constructor? Yes to both — you cannot call new on it directly, and subclasses still run its constructor via super().
