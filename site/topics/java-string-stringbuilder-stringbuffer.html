3.2 String vs StringBuilder vs StringBuffer

1. Definition

String creates a brand-new Heap object on every edit, whereas StringBuilder edits an internal array in place for fast single-thread building and StringBuffer adds synchronized locks for thread safety.

2. Memory hook

Fixed text = String; Loops/JSON building = StringBuilder; Legacy thread-shared buffer = StringBuffer.

  • Why + inside loops hurts: appending 1,000 times with String += allocates ~1,000 dead intermediate String objects.
  • StringBuilder (Java 5+): fast, un-synchronized, mutable — the default pick inside test methods.
  • StringBuffer (Java 1.0): every method has synchronized overhead.

5. Code example: building a dynamic Selenium report row cleanly

public class BuilderSpeedDemo {
    public static void main(String[] args) {
        StringBuilder log = new StringBuilder(); // mutable buffer on Heap
        String[] steps = { "Open", "Login", "Checkout" };
        for (String step : steps) {
            log.append("[").append(step).append("] "); // modifies same array in place
        }
        String finalLine = log.toString();             // convert to String once when done
        System.out.println(finalLine);                 // [Open] [Login] [Checkout]
    }
}

6. Execution flow, step by step

  1. new StringBuilder() creates one small expandable byte buffer (default capacity 16 characters).
  2. Each log.append(...) writes characters straight into the tail of that single buffer.
  3. If the buffer fills up, StringBuilder doubles capacity smoothly (similar to ArrayList).
  4. No throwaway Strings get left behind per loop lap.
  5. Calling log.toString() at the end snapshots one clean immutable String.

8. Why it matters

Replacing loop concatenation with StringBuilder turns quadratic O(n^2) memory churn into linear O(n) buffer writes.

SDET link: When assembling custom HTML email summaries, dynamic XPath fragments, or large CSV/JSON payloads inside a Selenium listener or API helper, use StringBuilder inside each test method (or per-thread log).

9. Quick test

Does StringBuilder override equals() to compare text like String? No — sb1.equals(sb2) checks address equality; compare sb1.toString().equals(sb2.toString()).
