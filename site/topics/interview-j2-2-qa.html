J2.2 Question Bank: Variables, Primitive vs Reference Types & Type Casting (35 Questions)

Tier 1: Core Definitions, Variables & Primitive Rules (Q1–Q7)

  1. What is the difference between Declaration, Initialization, and Assignment?
    Declaration reserves a variable's name and data type (int count;). Initialization gives that variable its very first value (count = 0; or int count = 0;). Assignment replaces the value of an existing variable (count = count + 1;).
  2. Name all 8 primitive data types in Java and their byte sizes.
    The 4 signed integer types are byte (1 byte, -128..127), short (2 bytes), int (4 bytes), and long (8 bytes). The 2 IEEE 754 floating-point types are float (4 bytes) and double (8 bytes), followed by char (2-byte unsigned UTF-16 character, 0..65,535) and boolean (true/false).
  3. What are the key differences between primitive types and reference types?
    A primitive variable stores its exact binary value directly inside its slot (on the Stack if local, or inline in an object), can never be null, and cannot invoke methods. A reference variable stores a Heap memory address pointing to an object, defaults to null as a field, and calls methods with the dot operator.
  4. Which variable scopes receive default values from the JVM, and which do not?
    Instance variables and static class variables always receive automatic defaults (0, 0.0, '\u0000', false, or null). Local variables declared inside a method, constructor, or block never receive defaults and trigger a compile error if read before assignment.
  5. Can a boolean variable be cast to or from any numeric type like int or char?
    No. In Java, boolean represents strict logical truth values (true or false) and cannot be cast to or from any numeric type or char—attempts like (int) true or (boolean) 1 fail to compile.
  6. What is the difference between Primitive Widening and Primitive Narrowing?
    Widening implicitly converts a smaller type to a larger type with zero manual cast (byte -> short -> int -> long -> float -> double, plus char -> int). Narrowing converts a larger type to a smaller type, requires an explicit (targetType) cast, and may truncate decimals or overflow bits.
  7. Why do byte and short NOT widen implicitly to char, and vice versa?
    byte (-128..127) and short (-32,768..32,767) are signed and can hold negative values, whereas char (0..65,535) is strictly unsigned and lacks negative values. Likewise, char values above 32,767 do not fit in short, so converting between them always needs an explicit cast.

Tier 2: How It Works & Internal Promotion Mechanics (Q8–Q14)

  1. What are the outputs of (int) 3.99 and (int) -3.99?
    3 and -3. Casting a double or float to an integer in Java always truncates the fractional digits toward zero rather than rounding or flooring toward negative infinity.
  2. Why does byte c = a + b; fail to compile when a and b are byte variables?
    Binary arithmetic operators (+, -, *, /, %) apply unary/binary numeric promotion, converting any byte, short, or char operand to int before computing. Since a + b yields an int, storing it into byte c requires (byte) (a + b).
  3. Does byte b = 10; b += 5; compile without an explicit cast?
    Yes. Compound assignment operators (+=, -=, *=, /=) automatically insert an implicit narrowing cast: the compiler translates b += 5 into b = (byte) (b + 5). Be cautious because s *= 1000 will silently overflow without throwing any error.
  4. What is the output of (byte) 128 and (byte) 300?
    -128 and 44. Narrowing an int to a signed byte retains only the lowest 8 bits; 128 flips into two's-complement -128, and 300 wraps around (300 - 256 = 44).
  5. Why does byte b = 100; compile cleanly while int v = 100; byte b = v; fails?
    Java permits implicit compile-time narrowing for constant expressions whose known value fits in the target byte, short, or char range (100 fits inside -128..127). Because a non-final int variable v could hold any runtime value, the compiler demands an explicit (byte) v cast.
  6. What are the outputs of (char) 97 and int x = 'A' + 2;?
    'a' and 67. Unicode code point 97 maps to lowercase 'a' when cast to char, while 'A' + 2 promotes 'A' (ASCII/Unicode 65) to int and evaluates to 67.
  7. Why can a 64-bit long widen implicitly to a 32-bit float?
    IEEE 754 floating-point uses an exponent field capable of representing magnitudes up to roughly 3.4e38, far wider than a 64-bit long maximum (~9.2e18). Even though precision in the lower digits can be lost for huge values, Java defines long -> float as a widening conversion.

Tier 3: Real-World SDET, Selenium & Reference Casting Scenarios (Q15–Q21)

  1. When writing WebDriver driver = new ChromeDriver();, is that upcasting or downcasting, and is it checked at runtime?
    It is implicit upcasting from the concrete subtype ChromeDriver to the super-interface WebDriver. Because every ChromeDriver is guaranteed at compile time to satisfy WebDriver, upcasting is always safe and requires no runtime cast check.
  2. Why does ((TakesScreenshot) driver).getScreenshotAs(...) require an explicit cast?
    Although ChromeDriver implements TakesScreenshot, the declared reference type WebDriver does not declare getScreenshotAs. Downcasting tells the compiler to view the object as TakesScreenshot while the JVM verifies the capability at runtime using the checkcast instruction.
  3. What happens when an invalid downcast executes at runtime, and how do you prevent it?
    An invalid downcast compiles if the classes are in the same hierarchy (e.g., Dog d = (Dog) new Animal();) but throws ClassCastException at runtime. Always check with instanceof first—or use Java 16+ pattern matching if (obj instanceof Dog d).
  4. Does casting null like Object o = (String) null; throw an exception?
    No. null belongs to the null type and can be cast to any reference type (class, interface, or array) without failing, simply evaluating to null. However, calling a method on that cast reference afterward still throws NullPointerException.
  5. Why should cart price calculations on QKart avoid float or double?
    Binary floating-point types cannot represent base-10 decimals like 0.1 or 0.2 without tiny binary rounding drift (for instance, 19.99 + 0.01 yielding 19.999999999999996). Use BigDecimal initialized from strings (new BigDecimal("19.99")) or integer cents (long) in financial assertions.
  6. Why does declaring WebDriver driver = new ChromeDriver(); locally inside @BeforeMethod break @Test methods?
    Re-declaring the type creates a local variable inside @BeforeMethod that shadows the class-level instance field. When @BeforeMethod returns, the local variable vanishes off the Stack while the instance field this.driver remains its default value null, causing a NullPointerException in tests.
  7. How should you safely convert an Object holding 42 from an Excel/Jackson utility into a primitive long?
    You cannot cast (long) (Object) 42 directly or cast an Integer wrapper directly to (Long). First downcast to (Integer) obj (or (Number) obj) and then convert via unboxing or ((Number) obj).longValue().

Tier 4: Troubleshooting, Compiler Errors & Failure Modes (Q22–Q28)

  1. Why does float f = 1.0; fail to compile?
    Every un-suffixed floating-point literal in Java defaults to 64-bit double, and Java forbids implicit narrowing from double to 32-bit float. Fix it by adding the float suffix (1.0f) or explicitly casting ((float) 1.0).
  2. How do you fix 'variable timeout might not have been initialized' when compiling?
    That error occurs on a local variable whose value might remain unassigned along at least one execution path before being read. Initialize the local variable at declaration (int timeout = 10;) or ensure every if/else and try branch assigns a value.
  3. Why does int big = 1000000 * 10000; or long big = 1000000 * 10000; overflow to a negative number?
    Both literals are int values, so Java multiplies them using 32-bit signed arithmetic first—overflowing past 2,147,483,647 before assignment occurs. Suffix at least one literal with L (1000000L * 10000) to promote the multiplication to 64-bit long.
  4. Why does double z = 5 / 2; produce 2.0 instead of 2.5?
    Both 5 and 2 are int values, so integer division truncates 2.5 to 2 before widening the result to double 2.0. Making at least one operand a double literal (5 / 2.0 or (double) 5 / 2) promotes the division itself to floating point.
  5. Why does Integer x = (Integer) "hello"; fail at compile time rather than runtime?
    String is a final class that neither extends Integer nor can have subclasses implementing shared interfaces in this path. Because the compiler knows with certainty no object can ever be both a String and an Integer, it rejects the cast with an incompatible-types compile error.
  6. What happens when casting a sibling wrapper like Long l = (Long) (Object) Integer.valueOf(42);?
    Casting via Object compiles because the compiler sees a possible subtype relation, but at runtime the JVM checks the actual Heap object (an Integer) and throws ClassCastException. Sibling wrappers under Number must convert using methods like .longValue().
  7. How does type erasure with raw collections cause delayed ClassCastException bugs?
    Generic types (List<Integer>) are erased to raw List at runtime while the compiler inserts hidden (Integer) casts at read sites. Assigning a raw list containing "text" to List<Integer> emits only a warning on assignment and then throws ClassCastException when nums.get(0) executes.

Tier 5: Design Choices & Rapid-Fire Recall (Q29–Q35)

  1. Why did Java keep 8 primitive types instead of making everything an object?
    Objects incur Heap allocation overhead, object headers, garbage collection tracking, and pointer indirection on every access. Keeping 8 primitive value types lets the JVM store numbers compactly on Stack frames and in CPU registers at native speed.
  2. Why does Java forbid silent narrowing conversions for non-constant variables?
    Silent narrowing hides precision loss and upper-bit wrap-around bugs during routine code edits. Requiring explicit (type) casts makes potentially lossy conversions immediately visible in code reviews.
  3. Why prefer Java 16+ pattern matching (if (a instanceof Dog d)) over classic instanceof + cast?
    Classic checks duplicate the target type name (instanceof Dog followed by (Dog) a), creating a chance to miscast by mistake. Pattern matching verifies the type and binds the narrowed variable safely in one concise expression.
  4. Why should shared framework configuration values like base timeouts use public static final?
    Non-final static fields can be overwritten accidentally by any test thread, causing flaky cross-test contamination. Marking them final guarantees the reference/primitive stays constant after initialization.
  5. Quick recall: Can multiple variables of the same type be declared in one statement?
    Yes, separated by commas—for example, int x = 10, y = 20, z; (where z remains declared but uninitialized).
  6. Quick recall: What is the default value of a local variable vs an instance boolean field?
    Local variables have no default value (compile error if read unassigned); an instance boolean field defaults to false.
  7. Quick recall: What is the result of (int) -9.99 and (byte) 130?
    -9 (truncates toward zero) and -126 (wraps around signed 8-bit byte range).
