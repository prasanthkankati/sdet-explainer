3.1 Driver Sessions & Capabilities

Creating and terminating W3C WebDriver sessions, capability negotiation, and session-level timeouts.

A WebDriver session is a stateful connection between your Java test script and a target browser instance identified by a unique SessionId. When a session starts, the client and driver perform W3C capability negotiation to agree on browser name, platform, timeouts, and security settings.

Before you start

Prerequisite: 2.3 Using a Test Runner (TestNG & JUnit 5)

Where it fits

Session creation and capability handshake happen inside your DriverFactory every time a new test browser is launched locally or on Selenium Grid.

Key points

  1. Every WebDriver session is assigned a unique UUID SessionId accessible via ((RemoteWebDriver) driver).getSessionId().
  2. W3C standard capabilities include browserName, browserVersion, platformName, acceptInsecureCerts, pageLoadStrategy, and timeouts.
  3. Session timeouts consist of three configurable durations: script timeout (default 30s), pageLoad timeout (default 300s), and implicitWait timeout (default 0s).
  4. In Selenium 4, legacy DesiredCapabilities is replaced by strongly typed browser option classes (ChromeOptions, FirefoxOptions, EdgeOptions, SafariOptions).
  5. Setting acceptInsecureCerts(true) instructs the browser to bypass self-signed or expired SSL/TLS certificate warnings in staging environments.

How it works

  1. The test creates a typed options object such as ChromeOptions and sets W3C capabilities (like setAcceptInsecureCerts(true)).
  2. Passing the options object into new ChromeDriver(options) sends an HTTP POST /session request with alwaysMatch/firstMatch JSON payload.
  3. The driver launches the browser with the requested configuration and returns a unique SessionId and negotiated capabilities.
  4. During execution, session timeouts can be read or updated via driver.manage().timeouts().
  5. Calling driver.quit() sends HTTP DELETE /session/{sessionId} to close the browser and invalidate the SessionId.

Configuring W3C session capabilities and timeouts in Java:

package dev.selenium.drivers; // Declares package

import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.chrome.ChromeOptions; // Imports typed ChromeOptions
import org.openqa.selenium.remote.RemoteWebDriver; // Imports RemoteWebDriver for SessionId access
import org.openqa.selenium.remote.SessionId; // Imports SessionId class
import java.time.Duration; // Imports Duration for timeouts

public class SessionCapabilitiesExample { // Declares class
    public static void main(String[] args) { // Main method
        ChromeOptions options = new ChromeOptions(); // Creates typed W3C options object
        options.setAcceptInsecureCerts(true); // Accepts self-signed SSL certificates on staging
        options.setPageLoadTimeout(Duration.ofSeconds(60)); // Sets W3C pageLoad timeout to 60s

        WebDriver driver = new ChromeDriver(options); // Starts session with negotiated capabilities
        try { // Guarded block
            SessionId sessionId = ((RemoteWebDriver) driver).getSessionId(); // Retrieves unique W3C SessionId
            System.out.println("Active Session ID: " + sessionId); // Prints UUID session identifier
            driver.get("https://www.selenium.dev/"); // Navigates to Selenium homepage
        } finally { // Teardown block
            driver.quit(); // Deletes session and invalidates SessionId
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Using deprecated DesiredCapabilities directly to configure local browsers; fix by using ChromeOptions, FirefoxOptions, EdgeOptions, or SafariOptions.
  2. Setting pageLoadTimeout too low (such as 2 seconds), causing TimeoutException on normal navigation; fix by keeping pageLoadTimeout at 30 to 60 seconds.
  3. Trying to mutate ChromeOptions after passing it into new ChromeDriver(options); fix by setting all options before instantiating the driver because capabilities are immutable once a session starts.

Interview questions

Basics

What is a WebDriver session and how is it identified?
A WebDriver session is an active, stateful connection between the test client and a controlled browser instance. It is uniquely identified by a SessionId UUID generated by the driver when the session starts.

What are the three session-level timeouts in W3C WebDriver and their default values?
The three timeouts are pageLoadTimeout (default 300 seconds), scriptTimeout for asynchronous JavaScript execution (default 30 seconds), and implicitlyWait for element location (default 0 seconds).

Why was DesiredCapabilities replaced by browser Option classes in Selenium 4?
DesiredCapabilities relied on untyped string keys prone to typos. Browser Option classes like ChromeOptions and FirefoxOptions provide compile-time type safety and enforce W3C capability compliance.

How it works

How does W3C capability negotiation use alwaysMatch and firstMatch?
When starting a session, the client sends an alwaysMatch object containing capabilities that must be supported, and an optional list of firstMatch objects. The driver merges alwaysMatch with each firstMatch entry in order until it finds a valid combination, or throws SessionNotCreatedException.

Can you change browser capabilities such as acceptInsecureCerts after new ChromeDriver(options) has already been called?
No. Capabilities are negotiated only once during the POST /session handshake when the browser launches. Modifying the options object afterward has no effect on the running session.

What happens to the SessionId after driver.quit() is called?
Calling driver.quit() destroys the session on the driver server and sets the client's internal SessionId reference to null. Any further command throws NoSuchSessionException.

Real situations

How do you automate an internal QA staging site that uses a self-signed HTTPS certificate?
Call options.setAcceptInsecureCerts(true) on your ChromeOptions, FirefoxOptions, or EdgeOptions object before creating the driver so the browser bypasses the 'Your connection is not private' interstitial page.

How do you retrieve the active SessionId for logging or cloud grid video correlation?
Cast the WebDriver instance to RemoteWebDriver and call ((RemoteWebDriver) driver).getSessionId().toString(). Cloud grids like BrowserStack and Sauce Labs use this exact ID to index video recordings and logs.

When would you customize scriptTimeout in a Selenium project?
Increase scriptTimeout when calling JavascriptExecutor.executeAsyncScript() to wait for long-running client-side promises or third-party analytics callbacks.

Troubleshooting

Why does Selenium throw SessionNotCreatedException: Unrecognized capability?
W3C WebDriver rejects non-standard capability keys that lack a vendor prefix (such as goog:chromeOptions or moz:firefoxOptions). Use the official Option class methods or prefix custom vendor capabilities properly.

What causes org.openqa.selenium.TimeoutException during driver.get(url)?
The web page took longer to fire the window load event than the configured pageLoadTimeout (for example, due to a hanging third-party ad or tracking script). Increase pageLoadTimeout or switch to PageLoadStrategy.EAGER.

Why does Safari ignore setAcceptInsecureCerts(true) in some environments?
SafariDriver has stricter OS-level keychain restrictions on untrusted certificates compared to Chrome and Firefox. For Safari, install the staging root CA certificate into the macOS System Keychain.

Design choices

Why is the default implicitlyWait timeout set to 0 seconds in W3C WebDriver?
An implicit wait of 0 seconds ensures findElement() fails fast when an element is missing and allows engineers to use targeted explicit waits (WebDriverWait) without unintended timeout multiplication.

Why is RemoteWebDriver the superclass of ChromeDriver, FirefoxDriver, and EdgeDriver?
Whether a browser runs locally via a driver binary or remotely on a Selenium Grid node, both communicate over the exact same HTTP W3C WebDriver protocol implemented in RemoteWebDriver.

Why should capability configuration be centralized in a DriverFactory class?
Centralizing options in a single DriverFactory allows the entire suite to toggle headless mode, SSL acceptance, or timeouts via system properties (-Dheadless=true) without editing individual test classes.

Quick answers

  1. How do you get the current session ID? Call ((RemoteWebDriver) driver).getSessionId().
  2. What is the default pageLoadTimeout in Selenium? 300 seconds (5 minutes).
  3. What is the default implicitlyWait timeout? 0 seconds.
  4. How do you bypass SSL certificate errors? Call options.setAcceptInsecureCerts(true) before launching the driver.
  5. Are capabilities mutable after session startup? No, capabilities are negotiated once at session creation.
