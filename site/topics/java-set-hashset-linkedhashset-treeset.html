5.3 Set: HashSet vs LinkedHashSet vs TreeSet

Enforcing element uniqueness with Set, how HashSet wraps HashMap internally, insertion-ordered LinkedHashSet (getWindowHandles), and sorted TreeSet.

A Set<E> models a collection with zero duplicate elements, rejecting any insertion where an equal element already exists. Java supplies three core implementations—HashSet (fastest unordered hashing), LinkedHashSet (predictable insertion order), and TreeSet (sorted Red-Black Tree)—matching distinct ordering and performance needs.

Before you start

Prerequisite: 5.2 List: ArrayList vs LinkedList

Where it fits

Selenium's driver.getWindowHandles() returns a Set<String> (backed by LinkedHashSet preserving tab opening order), and UI deduplication checks compare list.size() against new HashSet<>(list).size().

Key points

  1. Set<E> forbids duplicate elements (e1.equals(e2)) and offers no positional index access (set.get(0) does not exist).
  2. HashSet works internally by delegating to a private HashMap<E, Object>: inserted elements become map keys paired with a single shared dummy PRESENT = new Object() constant value.
  3. HashSet offers O(1) average time for add, remove, and contains, guarantees zero predictable order, and permits strictly one null element.
  4. LinkedHashSet extends HashSet using a LinkedHashMap internally, adding a doubly-linked list across entries to preserve exact insertion order in O(1) time (returned by Selenium's driver.getWindowHandles()).
  5. TreeSet is backed by a self-balancing Red-Black Tree (TreeMap) keeping elements sorted in natural (Comparable) or custom Comparator order in O(log n) time.
  6. TreeSet forbids null elements completely (throwing NullPointerException on comparison) and throws ClassCastException if elements lack Comparable and no Comparator was provided.

How it works

  1. Call driver.getWindowHandles() after clicking a link that opens a new tab; Selenium returns a Set<String> preserving tab creation order via LinkedHashSet.
  2. Iterate the handles with an enhanced for loop (or skip the parent handle) and invoke driver.switchTo().window(handle).
  3. To assert that a product grid displays zero duplicate SKU codes, build Set<String> unique = new HashSet<>(skus); and assert unique.size() == skus.size().
  4. To retain unique entries sorted alphabetically without calling Collections.sort() afterward, collect directly into a TreeSet<>.

Detecting duplicates with HashSet, switching tabs via getWindowHandles(), and sorting unique items in TreeSet:

package dev.java.collections; // Declares package

import java.util.HashSet; // Imports unordered O(1) Set
import java.util.LinkedHashSet; // Imports insertion-ordered Set
import java.util.List; // Imports List interface
import java.util.Set; // Imports Set interface
import java.util.TreeSet; // Imports sorted Red-Black Tree Set

public class SetComparisonDemo { // Demonstrates HashSet, LinkedHashSet, and TreeSet
    public static void main(String[] args) { // Main method starts
        List<String> scrapedCategories = List.of("Electronics", "Fashion", "Electronics", "Books"); // Input with duplicate
        Set<String> hashSet = new HashSet<>(scrapedCategories); // Deduplicates in O(n); iteration order unspecified
        Set<String> insertionOrder = new LinkedHashSet<>(scrapedCategories); // Deduplicates keeping first-seen order
        Set<String> sortedUnique = new TreeSet<>(scrapedCategories); // Deduplicates and sorts alphabetically

        boolean hasDuplicates = hashSet.size() < scrapedCategories.size(); // True if list held duplicates
        System.out.println("Has duplicates: " + hasDuplicates); // Prints: true
        System.out.println("Insertion order: " + insertionOrder); // Prints: [Electronics, Fashion, Books]
        System.out.println("Sorted order   : " + sortedUnique); // Prints: [Books, Electronics, Fashion]
    } // Ends main method
} // Ends class

Common mistakes

  1. Inserting custom POJOs (like Product) into a HashSet without overriding BOTH equals() and hashCode(); two distinct Product objects with identical names produce distinct hashes and both enter the set as false non-duplicates.
  2. Trying to retrieve a specific window handle by index (driver.getWindowHandles().get(1)); Set has no get(int) method—either iterate with a loop checking !handle.equals(parent) or wrap in new ArrayList<>(handles).
  3. Inserting null into a TreeSet; TreeSet calls compareTo immediately on insertion and throws NullPointerException.
  4. Mutating a field used inside hashCode() or equals() AFTER adding an object to a HashSet; changing the object's hash leaves it stranded in the wrong bucket so set.contains(obj) and set.remove(obj) return false.

Interview questions

Basics

Compare HashSet, LinkedHashSet, and TreeSet across ordering, performance, and null handling.
HashSet provides O(1) average operations, stores one null, and makes zero ordering guarantees. LinkedHashSet also achieves O(1) average speed and allows one null while preserving exact insertion order using a linked list. TreeSet maintains sorted order in O(log n) time, forbids null completely, and compares elements via Comparable or Comparator.

Why does Set have no get(int index) method like List?
A Set represents a mathematical collection of unique values rather than a positional sequence—HashSet places elements by hash bucket rather than numeric index, and TreeSet rebalances elements dynamically. To access elements by ordinal position, convert via new ArrayList<>(set) or iterate with Iterator / streams.

Which Set implementation does Selenium's driver.getWindowHandles() return?
WebDriver specifies the return type as Set<String>, and Selenium's Java client deserializes window handles into a LinkedHashSet<String>, preserving the chronological order in which windows/tabs were returned by the browser driver.

How it works

How does HashSet work internally without duplicating hashing logic?
Inside java.util.HashSet, the constructor creates an internal private transient HashMap<E, Object> map alongside a single constant private static final Object PRESENT = new Object(). Calling set.add(e) simply executes return map.put(e, PRESENT) == null;. Because HashMap enforces unique keys, HashSet inherits uniqueness and O(1) hashing directly from HashMap.

How does TreeSet determine whether two elements are duplicates?
Unlike HashSet which relies on hashCode() and equals(), TreeSet determines equality strictly via compareTo(e) == 0 (or comparator.compare(e1, e2) == 0). If a custom Comparator returns 0 for two distinct objects (for example, comparing two products solely by identical price), TreeSet treats the second product as a duplicate and rejects it.

What does set.add(x) return when x is already present inside the set?
add(x) leaves the existing element inside the set untouched and returns boolean false rather than throwing an exception or replacing the existing element. This makes if (!seenIds.add(id)) a concise one-line duplicate detector.

Real situations

How do you reliably switch to a newly opened browser tab in Selenium using Set<String>?
Capture String parent = driver.getWindowHandle(); before clicking the external link, wait until ExpectedConditions.numberOfWindowsToBe(2) succeeds, then loop over for (String handle : driver.getWindowHandles()) and call if (!handle.equals(parent)) { driver.switchTo().window(handle); break; }. Do not rely on converting to a list and assuming index 1 is always newest across all browser versions when multiple tabs exist.

In an API test checking 500 returned order IDs for uniqueness, how do you detect and report the exact duplicate IDs?
Iterate the list with a HashSet<String> seen = new HashSet<>(); and collect any item where !seen.add(id) into a List<String> duplicates. That detects every duplicate in a single O(n) pass and logs exact offending IDs in the TestNG assertion message.

When scraping a web table of tags that must be unique AND sorted alphabetically for UI comparison, which collection avoids an extra sort step?
Collect scraped strings directly into Set<String> actual = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);, which simultaneously removes duplicates and maintains exact alphabetical ordering.

Troubleshooting

Why did adding two identical UserPOJO("qa@test.com") instances into a HashSet produce a set size of 2 instead of 1?
UserPOJO did not override hashCode() and equals(), so it inherited Object's default identity-based implementations where every new object has a unique memory hash. Overriding both equals() and hashCode() based on the email field ensures duplicate POJOs collapse cleanly to size 1.

Why did adding a custom Product class into a new TreeSet<>() throw ClassCastException: class Product cannot be cast to class java.lang.Comparable?
A no-argument TreeSet casts inserted elements to Comparable to position them inside the Red-Black Tree. Either make Product implements Comparable<Product> or pass an explicit comparator to the constructor: new TreeSet<>(Comparator.comparing(Product::getName)).

Why did inserting a single null into a TreeSet throw NullPointerException?
In Java 7+, even inserting null as the very first element into a TreeSet invokes compare(null, null) immediately to validate the comparator and throws NullPointerException. Use HashSet or LinkedHashSet when null values are valid.

Design choices

When writing a utility that checks whether a target tag exists in a collection of 10,000 items, why convert a List to a HashSet before looping?
Calling list.contains(x) scans linearly in O(n) time—meaning checking 10,000 targets against a 10,000-element list executes ~100 million comparisons (O(n^2)). Converting to a HashSet once reduces every contains() lookup to O(1) average time.

Why should custom objects stored inside a HashSet or TreeSet be immutable with respect to their equality/comparison fields?
Mutating a field after insertion breaks the structural invariant of the hash bucket or Red-Black Tree position, rendering the element unreachable for lookup or removal.

When choosing between Set.copyOf(list) and new LinkedHashSet<>(list), what trade-off applies?
Set.copyOf() produces a compact unmodifiable Set rejecting null and arbitrary mutations, though it does NOT guarantee preserving list insertion order. If insertion order matters during assertions, wrap with Collections.unmodifiableSet(new LinkedHashSet<>(list)).

Quick answers

  1. What data structure backs HashSet internally? A HashMap<E, Object> with a shared dummy PRESENT value.
  2. Which Set preserves insertion order? LinkedHashSet.
  3. Which Set maintains sorted order and what backs it? TreeSet, backed by a Red-Black Tree (TreeMap).
  4. Which Set throws NullPointerException if you add null? TreeSet.
  5. What does set.add(item) return if item is already in the set? false.
  6. What type does Selenium's driver.getWindowHandles() return? Set<String> (backed by LinkedHashSet).
