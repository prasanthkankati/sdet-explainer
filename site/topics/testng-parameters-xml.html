3.2 @Parameters & XML Suite Injection

Decoupling test configuration: injecting browser types, target environments, and timeouts via testng.xml with @Optional fallbacks.

Hardcoding environment variables (such as base URLs, browser targets, or database connection strings) inside Java test classes violates clean architecture. TestNG's @Parameters annotation provides clean, declarative dependency injection from testng.xml directly into configuration and test methods.

1. XML Declaration & Method Binding

Parameters declared with <parameter name="key" value="val" /> are mapped into Java method signatures matching annotation argument names:

<!-- In testng.xml -->
<suite name="CrossBrowserSuite">
  <parameter name="appUrl" value="https://staging.example.com" />

  <test name="ChromeRun">
    <parameter name="browser" value="chrome" />
    <classes>
      <class name="com.sdet.tests.LoginTest" />
    </classes>
  </test>
</suite>
// In Java Class
import org.testng.annotations.Parameters;
import org.testng.annotations.BeforeClass;

public class LoginTest {
    @Parameters({"browser", "appUrl"})
    @BeforeClass
    public void setup(String browser, String appUrl) {
        System.out.println("Launching " + browser + " against " + appUrl);
    }
}

2. The @Optional Fallback

If a test method is run standalone from an IDE (without testng.xml), TestNG throws a TestNGException: Parameter 'browser' is required by @Test on method but has not been marked @Optional or defined. Adding @Optional provides safe local defaults:

@Parameters({"browser"})
@BeforeMethod
public void initDriver(@Optional("chrome") String browser) {
    // If not supplied in XML, browser defaults to "chrome"
}

3. Senior SDET Interview Q&A

  1. What is the key difference between @Parameters and @DataProvider?
    @Parameters injects environment configurations from testng.xml (run once per test setup). @DataProvider injects dynamic test input data in Java memory, running the test method multiple times across different data sets.
  2. Can @Parameters inject non-String types?
    Yes! TestNG automatically converts string parameter values into Java primitives (int, boolean, long, double, etc.) based on the target method parameter type.
