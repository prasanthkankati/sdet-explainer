2.5 Arrays (1D & 2D Object[][])

Contiguous fixed-size Heap arrays, .length vs .length() vs .size(), ArrayIndexOutOfBoundsException, Arrays utilities, and TestNG @DataProvider Object[][] matrices.

An array in Java is a fixed-size, ordered container allocated as a contiguous block on the Heap that holds elements of a single declared type by zero-based index. While dynamic lists handle variable runtime counts, 1D arrays and 2D Object[][] matrices remain core structures for TestNG @DataProvider methods and Arrays utility helpers.

Before you start

Prerequisite: 2.4 Operators, Control Flow & Loops

Where it fits

Every TestNG data-driven test reads credentials and expected messages from a 2D Object[][] matrix returned by @DataProvider, and CLI arguments enter main(String[] args) as a 1D array.

Key points

  1. Every array in Java is an object allocated on the Heap whose length is permanently fixed at creation (new String[5] can never resize to 6).
  2. Arrays expose a final field arr.length (no parentheses), whereas String uses method str.length() and Collections use list.size().
  3. Accessing a negative index or an index >= arr.length throws the unchecked ArrayIndexOutOfBoundsException.
  4. Newly created arrays initialize every slot to the element type's default (0 for int[], false for boolean[], and null for object arrays like String[]).
  5. java.util.Arrays provides Arrays.toString(arr), Arrays.deepToString(matrix) for 2D arrays, Arrays.sort(arr), and Arrays.asList(arr) (which returns a fixed-size view throwing UnsupportedOperationException on .add() or .remove()).
  6. A 2D array in Java is an array of arrays (Object[][]), allowing jagged rows of different lengths and powering TestNG @DataProvider rows (each row = 1 test invocation, each column = 1 parameter).

How it works

  1. Declaring and initializing Object[][] loginCases = new Object[2][3]; allocates a 2-element outer reference array on the Heap, each pointing to a 3-slot Object[] row.
  2. Each inner row supplies one test case's parameters (username, password, expected status) to a TestNG test method.
  3. At execution, TestNG loops over row = 0 to loginCases.length - 1 and injects each row's column values into the @Test(dataProvider = ...) parameter list.
  4. Using Arrays.deepToString(loginCases) formats nested 2D arrays cleanly for logging instead of printing raw JVM hash codes.

Building a 2D Object[][] matrix for TestNG data-driven QKart login tests:

package dev.java.core; // Declares package

import java.util.Arrays; // Imports Arrays helper class

public class ArrayDataMatrixDemo { // Demonstrates 1D and 2D Object[][] arrays
    static Object[][] loginCredentials() { // Signature used by TestNG @DataProvider
        return new Object[][] { // Allocates 2D array (rows = test runs, cols = arguments)
            { "adminUser", "Pass@123", true }, // Row 0: boxed boolean true inside Object[]
            { "lockedUser", "WrongPwd", false } // Row 1: invalid credentials row
        }; // Ends 2D array initializer
    } // Ends loginCredentials

    public static void main(String[] args) { // Main method entry
        Object[][] data = loginCredentials(); // Captures 2x3 matrix reference on Stack
        System.out.println("Rows: " + data.length + ", Cols: " + data[0].length); // Prints row and col counts via .length field
        System.out.println(Arrays.deepToString(data)); // Formats nested 2D values cleanly
        String[] browsers = { "chrome", "edge", "firefox" }; // 1D array literal
        Arrays.sort(browsers); // Sorts array elements alphabetically in place
        System.out.println(Arrays.toString(browsers)); // Prints: [chrome, edge, firefox]
    } // Ends main method
} // Ends class

Common mistakes

  1. Printing an array directly via System.out.println(arr) and expecting elements; Java prints the class descriptor and identity hash code (for example, [Ljava.lang.String;@6d06d69c) unless wrapped in Arrays.toString() or Arrays.deepToString().
  2. Calling List<String> list = Arrays.asList(arr); list.add("safari");; Arrays.asList() returns a fixed-size array-backed list whose size cannot change, throwing UnsupportedOperationException.
  3. Returning mismatched column counts in a Object[][] @DataProvider compared to the @Test method's parameters; TestNG throws MethodMatcherException at runtime.
  4. Confusing arr.length with arr.length(); arrays expose a public final field with no parentheses, whereas String uses the .length() method.

Interview questions

Basics

Why are arrays fixed in size once created in Java?
The JVM allocates an array as a single contiguous memory block on the Heap so index lookup arr[i] executes in constant $O(1)$ time by computing baseAddress + i * slotSize. Growing a contiguous block in place is impossible if adjacent memory is occupied by other objects. When dynamic resizing is needed, use ArrayList, which allocates a larger array and copies elements over automatically.

Contrast .length, .length(), and .size().
arr.length is a final field on every Java array returning its fixed slot count. str.length() is a method on String returning the count of UTF-16 code units. collection.size() is a method declared by Collection and Map implementations returning the current element count.

Why does TestNG @DataProvider return Object[][] instead of String[][]?
Because java.lang.Object is the root superclass of every class and autoboxed wrapper in Java, an Object[][] matrix lets a single test row carry mixed types simultaneously—for instance, a String username, an int timeout, and a boolean expected validity flag. Using String[][] would force tedious manual parsing of integers and booleans inside every @Test.

How it works

What happens in memory when you write String[] tabs = new String[3];?
The JVM allocates an array object on the Heap large enough for 3 reference slots and initializes all 3 slots to null, because no String objects have been assigned yet. The variable tabs on the Stack holds the reference to that array object. Attempting tabs[0].length() before assigning a string throws NullPointerException.

Why does Arrays.asList(arr) throw UnsupportedOperationException on .add(), while List.of(arr) throws it on .set() too?
Arrays.asList(arr) creates a thin fixed-size wrapper directly backed by the array, so calling list.set(0, val) mutates the original array, whereas adding or removing elements is forbidden. By contrast, Java 9+ List.of(...) returns a completely unmodifiable list rejecting .add(), .remove(), .set(), and null elements. If a resizable list is required, wrap it in new ArrayList<>(Arrays.asList(arr)).

How do Arrays.equals(a, b) and a.equals(b) differ on two arrays?
Java arrays do not override Object.equals(), so a.equals(b) behaves identically to a == b and returns false for two distinct array objects even if their contents match. Calling Arrays.equals(a, b) compares lengths and pairs of elements in order (use Arrays.deepEquals(a, b) for 2D arrays).

Real situations

How do you convert a comma-separated test-data cell from Excel into a trimmed List<String>?
Call String[] parts = rawCell.split(","); to split into a fixed array, then stream or wrap it into a mutable list via new ArrayList<>(Arrays.asList(parts)). If each part needs trimming, Arrays.stream(parts).map(String::trim).collect(Collectors.toList()) produces a clean mutable list cleanly.

In a Selenium test, how do you verify an array of expected menu labels matches UI menu elements?
Extract UI texts into a List<String> using streams or a loop, and compare against Arrays.asList("Home", "Orders", "Checkout") via Assert.assertEquals(actualList, expectedList). Comparing lists directly avoids manual index loops and yields clear diff messages on TestNG failure.

Why can an Object[] array hold an integer 42 alongside a String?
When 42 is placed into an Object[] literal, the Java compiler autoboxes primitive 42 into an Integer object via Integer.valueOf(42). Because Integer inherits from Object, it fits cleanly into the Object[] slot.

Troubleshooting

What causes TestNGException: Data Provider method ... returned a null value or MethodMatcherException?
Returning an uninitialized Object[][] reference causes a null DataProvider failure, while having rows whose column count does not match the @Test method's parameter count and types throws MethodMatcherException. Verify that every row inside the Object[][] matrix matches the exact parameter count and type sequence declared on the @Test signature.

Why does int[] ids = {1, 2}; ids[2] = 3; throw ArrayIndexOutOfBoundsException?
Valid indices for a 2-element array are strictly 0 and 1. Writing to index 2 goes past the fixed Heap allocation boundary, so the JVM performs bounds checking on every access and throws ArrayIndexOutOfBoundsException immediately instead of corrupting adjacent memory.

Why did Arrays.asList(new int[]{1, 2, 3}).size() return 1 instead of 3?
Generics do not support primitive types, so Arrays.asList treats the entire int[] array as a single Object element, producing a List<int[]> of size 1. Use a boxed Integer[] array or Arrays.stream(primitiveArr).boxed().toList() instead.

Design choices

Why should Page Objects return List<String> instead of raw String[] arrays?
List<String> integrates seamlessly with Java Streams, TestNG assertions, and immutability helpers without exposing mutable fixed-length array slots. Returning List.copyOf(...) or Collections.unmodifiableList(...) also prevents callers from mutating internal Page Object state.

When is a primitive array like byte[] strictly better than List<Byte>?
When handling binary files, screenshots via OutputType.BYTES, or image buffers, List<Byte> wraps every single byte in a 16-byte Heap Byte object—inflating memory usage more than 16x. A contiguous byte[] array stores raw bytes directly with zero wrapper overhead.

Why does TestNG support Iterator<Object[]> as an alternative return type to Object[][] in @DataProvider?
When reading 5,000 test rows from a large Excel or CSV file, returning Object[][] loads every single row into Heap memory upfront before the first test begins. Returning a lazy Iterator<Object[]> streams one test row at a time into the test runner and keeps memory usage flat.

Quick answers

  1. Can a Java array resize after creation? No; use ArrayList when dynamic sizing is required.
  2. What syntax gets the number of elements in an array? arr.length (a field, without parentheses).
  3. What does System.out.println(arr) print for a String[]? Its internal class tag and hex hash code (e.g., [Ljava.lang.String;@...); use Arrays.toString(arr) instead.
  4. Which exception is thrown for an invalid array index? ArrayIndexOutOfBoundsException.
  5. Why can you not call .add() on the list returned by Arrays.asList()? It returns a fixed-size list backed directly by the original array, throwing UnsupportedOperationException on structural modifications.
  6. Which Java data structure feeds TestNG @DataProvider? A 2D array Object[][] (or Iterator<Object[]>).
