S2.1 Locators, DOM, Attributes, and Uniqueness

1. Idea

A locator is an instruction that tells Selenium which HTML element to find on a web page using By strategies. LOC is the 3-step engineering methodology used to build reliable locators: List candidates, Optimize the selector, and Check uniqueness. Every locator queries the DOM (Document Object Model) using an element's tag, attributes, text, or relative position.

2.2 How to read the DOM

  1. Open the page in Chrome.
  2. Press F12, then select the Elements tab.
  3. Press Ctrl+Shift+C (Windows) or Cmd+Shift+C (Mac), then click the element on the page. The matching line is highlighted.
  4. Read the opening tag line. It shows the tag, all attributes, and their values.
  5. Expand the parent lines above it to see its position in the tree.

2.4 The most dynamic attributes, and why

  1. Generated class names (css-1gkf44r-...): the styling library creates a new hash whenever the styles change.
  2. Generated ids (mui-1, mui-2): a counter increases when components render, so the number depends on render order.
  3. File-name attributes (src, href): uploaded asset names are UUIDs, which change with each upload.
  4. Style and state attributes (style, aria-*, value): the browser updates them as the page state changes.
  5. Position (an index such as [3]): adding or removing one item shifts every index after it.

2.5 How to know an attribute is dynamic

  • Reload the page twice and compare the values. A change means dynamic.
  • Compare two items of the same type. A pattern such as mui-1, mui-2 or a hash means dynamic.
  • Look for digits, hashes, UUIDs, or counters in the value.

2.7 Conditions to check before choosing a locator

  1. The element is in the main document (not in an iframe or Shadow DOM).
  2. The element is visible to a user.
  3. The locator matches exactly one element, or matches one element inside a stable container.
  4. The attribute is not generated (no hash, counter, or UUID).
  5. The value is the same after a reload.
  6. The value does not change with language or data (for text).
  7. The element is present in the DOM when the test looks for it.

2.8 Steps before writing any locator

  1. Open the page.
  2. Identify the target by its purpose on the page.
  3. Inspect the element in the Elements tab.
  4. Read its tag and all attributes.
  5. Check whether it is inside an iframe or Shadow DOM.
  6. Mark each attribute as stable or dynamic (Section 2.3).
  7. Reload the page and compare the values.
  8. Count matches in the Console (Section 2.10).
  9. Check that the element is visible.
  10. Choose the strategy using the priority order (Section 2.9).
  11. Write the locator.
  12. Recount. The result must be one visible match.

2.9 How to choose the best locator (priority order)

  1. data-testid (if the team provides one)
  2. Hand-written id
  3. name
  4. Stable attribute with a CSS selector (for example input[name='search'])
  5. Visible text with normalize-space() in XPath
  6. Relative XPath from a stable parent
  7. Index or position (last choice)

Rule: pick the first option that passes all conditions in Section 2.7.

4. Interview Bank

Tier 1: Definition

1. (common) What is a locator, and what does the LOC methodology stand for?
A locator is an instruction that tells Selenium which element to find on a web page using the By class. LOC stands for the 3-step methodology: List candidates, Optimize the selector, and Check uniqueness.

2. (common) What is the DOM?
The DOM is the browser's tree version of the HTML page, where each tag is a node. Selenium searches this tree, not the raw HTML file.

3. (common) What is an attribute?
An attribute is a name and value pair inside a tag, such as name="search". Most locators match one or more attributes.

4. (common) How many locator strategies does By provide?
Eight: id, name, className, tagName, linkText, partialLinkText, cssSelector, and xpath.

5. (common) What is the difference between findElement and findElements?
findElement returns the first match and throws NoSuchElementException when nothing matches. findElements returns a list, which is empty when nothing matches.

6. (common) What is a generated attribute?
It is a value that code creates at runtime, such as css-1gkf44r-MuiButtonBase-root or mui-1. It can change between page loads or releases.

7. (common) What is the difference between existence and visibility?
An element exists when it is in the DOM. It is visible when a user can see it. A hidden element can exist and still fail to be clicked.

Tier 2: Mechanics

8. (common) What do $, $$, and $x do in the console?
$ returns the first CSS match, $$ returns an array of all CSS matches, and $x returns an array of all XPath matches. Use .length on $$ or $x to count matches.

9. (common) Why is XPath text matching case-sensitive?
XPath compares strings character by character, so Add to Cart and Add to cart are different values. Use the exact case shown in the DOM.

10. (common) What does normalize-space() do?
It removes leading and trailing spaces and collapses runs of inner spaces into one. It makes " Add to cart " equal "Add to cart".

11. (advanced) Why can CSS not select a parent element?
Standard CSS selects elements from ancestors down to descendants or sideways to siblings, but it has no way to name an ancestor from its child. Use XPath parent:: or ancestor:: for that.

12. (advanced) What is a relative locator?
A relative locator finds an element by its position next to another element, using above, below, toLeftOf, toRightOf, or near. It is written as with(By.x).below(By.y).

13. (advanced) What does By.chained do?
It runs several locators in order, each one searching inside the result of the previous one. It is useful when a stable container narrows the search.

14. (advanced) What is @FindBy?
It is an annotation that declares a locator on a field in a page class. PageFactory.initElements(driver, this) fills those fields with elements.

Tier 3: Scenario

15. (common) An input's id changes on every page load. How do you locate it?
Do not use the full id. Match the stable part with [id^='prefix'] in CSS or starts-with(@id,'prefix') in XPath. If no stable part exists, locate it by name or by a stable label.

16. (common) A page has two "Add to cart" buttons. How do you pick one?
Scope the search to the product card that holds the button, then find the button inside it. If the cards have no stable attributes, use an XPath position such as (//button[normalize-space()='Add to cart'])[2] only as a last choice.

17. (advanced) You need the delete button in the row for "John Doe". How?
Use //tr[td[normalize-space()='John Doe']]//button[@title='Delete']. This finds the row that contains the name, then the delete button inside that row.

18. (common) A page has text boxes, checkboxes, and dropdowns. How do you find each type?
Match the tag and the type attribute: input[type='text'] for text boxes, input[type='checkbox'] for checkboxes, and select for dropdowns. Verify the list in the console with $$('input').map(i => i.type).

19. (advanced) A login button text changes with the language. Which locator do you avoid?
Avoid visible text: linkText, partialLinkText, and XPath text() all break when the text changes. Use button[type='submit'] or a data-testid attribute instead.

20. (common) A link contains only an icon and no text. How do you locate it?
linkText needs visible text, so it cannot match. Use the link's href with a[href='/profile'] or the icon's class.

21. (advanced) You need the price of a named product. How?
Anchor on the unique product name with //p[normalize-space()='Jenga'], then move to the next sibling with /following-sibling::p[1].

Tier 4: Debugging

22. (common) What causes NoSuchElementException?
The locator matched zero elements at the moment of the search. Common causes are a wrong locator, an element that loads later, an element inside an iframe, or an element hidden at the current window size.

23. (common) What causes StaleElementReferenceException?
The page re-rendered the element after it was located, so the stored reference points to a removed node. Locate the element again just before using it.

24. (advanced) The locator works in the DevTools console but fails in Selenium. Why?
The console searches the current document, while Selenium searches only the main document unless it switches into an iframe. Check for an iframe or Shadow DOM first.

25. (common) What causes ElementNotInteractableException on sendKeys?
The element exists but is hidden, disabled, or covered. A common cause is a hidden duplicate, such as the mobile search input on a desktop-width window.

26. (common) The test acts on the wrong element, but no exception is thrown. What do you check?
The locator probably matched several elements, and findElement returned the first. Count the matches with $$ or $x in the console.

27. (common) Why does By.className("nav-link active") fail?
By.className accepts one class name only, and a space separates two class names. Use By.cssSelector(".nav-link.active") for two classes.

28. (advanced) partialLinkText("Check") clicks "Checkout" instead of "Check Balance". Why?
partialLinkText returns the first link in document order whose text contains the substring. Use linkText("Check Balance") for the full text.

Tier 5: Design

29. (common) How do you choose between CSS and XPath?
Choose CSS for ids, classes, names, and attributes, because it is shorter. Choose XPath when you must match visible text, move to a parent, or find an element by a neighboring label.

30. (common) What is the locator priority order?
data-testid, then a hand-written id, then name, then a stable CSS attribute, then XPath with visible text, then a relative XPath from a stable parent, then an index last.

31. (common) Why should absolute XPath such as /html/body/div[2]/form/input be avoided?
It records every level of the page structure. Adding one wrapper element anywhere above it breaks the locator.

32. (advanced) Why is data-testid better than a class or id?
Developers add it for testing, and it is not changed for styling. A class or id often changes when the design changes.

33. (common) How do you check uniqueness before writing a locator?
Count the matches in the console with $$('css').length or $x('xpath').length. The count must be 1, or the element must be unique inside a stable container.

34. (common) Which attributes are the most dynamic, and why?
Generated class names, generated ids, file-name attributes in src and href, and state attributes such as style and aria-*. The browser or the code changes them when styles, render order, uploads, or page state change.

35. (common) What are the steps before writing a locator?
Open the page, inspect the element, read its attributes, check for iframe or Shadow DOM, mark each attribute as stable or dynamic, reload and compare, count matches in the console, check visibility, choose by priority, write the locator, and recount to confirm one visible match.
