M4.3 Question Bank: Defect Leakage, DRE, Density & RCA (35 Questions)

Tier 1–5 Complete Question Bank (Q1–Q35)

  1. Q1: What is the formula for Defect Removal Efficiency (DRE)?
    A: `DRE = (QA Defects / (QA Defects + Production Defects)) * 100`.
  2. Q2: What is the formula for Defect Leakage %?
    A: `Defect Leakage = (Production Defects / (QA Defects + Production Defects)) * 100` (which equals `100% - DRE`).
  3. Q3: Calculate DRE & Leakage if QA caught 190 bugs and 10 leaked to Production.
    A: Total = 200. `DRE = (190/200)*100 = 95%`; `Leakage = 5%`.
  4. Q4: What is Defect Density and why is it useful?
    A: Defects per KLOC or per Story Point; highlights unstable, high-risk modules (Defect Clustering 80/20).
  5. Q5: What is the difference between Defect Leakage and Defect Escape?
    A: Often used interchangeably; specifically, Defect Escape can refer to a bug slipping past *any* earlier phase gate (e.g., Unit → QA), while Defect Leakage specifically measures bugs escaping QA/UAT into Production.
  6. Q6: What is Defect Rejection Ratio?
    A: `(Rejected Bugs / Total Bugs Logged) * 100`. A high ratio (>10%) means QA needs clearer specs or better pre-log verification.
  7. Q7: What is the 5-Whys RCA technique?
    A: Asking "Why?" iteratively (~5 times) to trace an escaped production failure back from a code symptom to the missing requirement, test, or CI/CD process gap.
  8. Q8: What is a Fishbone (Ishikawa) Diagram?
    A: A cause-and-effect diagram grouping root causes into branches (Requirements, Code, Test Design, Test Data, Environment, Deployment).
  9. Q9: What makes an RCA "Blameless"?
    A: Focusing on fixing systems, guardrails, and automated checks rather than blaming an individual developer or tester.
  10. Q10: What are the top 4 root causes of Defect Leakage in real SDET projects?
    A: (1) QA vs Prod environment/config mismatch, (2) Missing negative/boundary test data, (3) Untested third-party API edge responses, and (4) Rushed hotfixes bypassing Regression.
  11. Q11: Why is `0%` Defect Leakage unrealistic?
    A: Principle #1 & #2: exhaustive testing is impossible, so teams target `DRE >= 95%` (Leakage `<= 5%`, with `0` Critical/Blocker leaks).
  12. Q12: What is Mean Time to Detect (MTTD) vs Mean Time to Resolve (MTTR)?
    A: MTTD = average time to discover a bug after it's introduced; MTTR = average time from detection to production fix.
  13. Q13: Scenario: Production leaked a bug because QA used a mocked Stripe payment server while Production uses live Stripe. What is the RCA action?
    A: Run an automated post-deployment synthetic smoke check against Stripe Sandbox/Canary and align mock contracts with Stripe's real OpenAPI schema.
  14. Q14: Scenario: DRE is 99%, yet customers are furious because 1 single bug corrupted 10,000 billing invoices. Why is raw bug count misleading?
    A: Unweighted DRE treats a 1px typo the same as a billing crash; always track Severity-Weighted DRE and Critical Escape Count (Target = 0).
  15. Q15: How does Shift-Left testing improve DRE?
    A: Catching ambiguities in Sprint Refinement and adding SonarQube/Unit tests catches bugs before QA even sees a build.
  16. Q16–Q35 Quick Drills: (Q16) Formula for Test Coverage %? `(Executed Tests / Total Planned Tests) * 100` or `(Covered Reqs / Total Reqs) * 100`. (Q17) What is CAPA in RCA? Corrective Action (fix current bug) + Preventive Action (stop future bugs). (Q18) When should RCA happen? Within 24–48h of a Production P1 incident. (Q19) Does adding a regression test prevent the same bug from leaking twice? Yes. (Q20) What is Defect Age? Time from `New` to `Closed`. (Q21–Q35: Environment parity via Docker/Testcontainers, Canary releases for Shift-Right detection, Feature Flags for instant rollback without hotfix, Contract Testing [Pact] to stop API schema leaks, Automated Visual Diffing [Percy/Applitools] for CSS leaks, Chaos testing for infrastructure leaks, Flaky test quarantine, Synthetic Playwright monitors in Prod, Post-mortem action item tracking in Jira, and measuring Test Effectiveness `(QA Bugs / Total Bugs)`).
