6.4 Multithreading & ThreadLocal<WebDriver> for Parallel Tests

1. Definition

Parallel threads share one Heap while keeping separate Stacks; using static WebDriver across threads collides browsers and drops sessions, whereas ThreadLocal gives every TestNG worker thread its own isolated browser slot.

2. Memory hook

Stack = per-thread private, Heap/static = shared! ThreadLocal + quit() + remove() makes parallel TestNG 100% safe.

  • Why static WebDriver crashes parallel runs: Thread-2 overwrites Thread-1's reference and calls driver.quit() mid-test (NoSuchSessionException).
  • Implement Runnable rather than extending Thread: keeps classes free to extend parent classes and run inside thread pools.
  • Always call driverPool.remove() after driver.quit(): prevents pooled TestNG worker threads from leaking old memory references.

5. Code example: production ThreadLocal WebDriver manager for TestNG

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public final class DriverManager {
    private static final ThreadLocal<WebDriver> TL = new ThreadLocal<>(); // per-thread map slot

    public static void initDriver() { TL.set(new ChromeDriver()); }     // @BeforeMethod per thread

    public static WebDriver getDriver() {                               // fast lock-free lookup
        WebDriver d = TL.get();
        if (d == null) throw new IllegalStateException("Call initDriver() first!");
        return d;
    }

    public static void quitDriver() {                                   // @AfterMethod alwaysRun=true
        try {
            if (TL.get() != null) TL.get().quit();                      // close browser cleanly
        } finally {
            TL.remove();                                                // prevent pooled thread leak!
        }
    }
}

6. Execution flow, step by step

  1. TestNG launches Thread-1 and Thread-2 when testng.xml sets parallel="methods".
  2. Each worker calls DriverManager.initDriver() inside @BeforeMethod, storing its own ChromeDriver inside that thread's ThreadLocalMap.
  3. Page Objects call DriverManager.getDriver() and fetch only the browser owned by the executing thread.
  4. When Thread-2 finishes early, TL.get().quit() terminates ONLY Thread-2's browser while Thread-1 finishes undisturbed.
  5. finally { TL.remove(); } strips the reference off the pooled thread cleanly before the next queued test arrives.

8. Why it matters

Concurrency multiplies CI speed yet introduces subtle race conditions unless shared state is either synchronized atomically or isolated per thread.

SDET link: Scaling TestNG suites cleanly with parallel="methods" on Selenium Grid requires ThreadLocal<WebDriver> (paired with local Page Object instantiation inside each @Test method) plus remove() inside @AfterMethod.

9. Quick test

What fails if two parallel threads share public static WebDriver driver and Thread A finishes first? Thread A's driver.quit() destroys the browser session while Thread B is still testing, causing NoSuchSessionException.
