3.3 Essential String Methods & Regex for SDETs

High-frequency String methods (trim vs strip, split, substring, replace vs replaceAll, String.format) and Java regex Pattern/Matcher extraction.

UI and API assertions constantly extract numbers, order IDs, prices, and tokenized labels from messy DOM strings returned by element.getText(). Mastering exact String parsing methods alongside Java's regex engine prevents silent splitting bugs and fragile substring assertions.

Before you start

Prerequisite: 3.2 String vs StringBuilder vs StringBuffer

Where it fits

Parsing product prices like "$1,299.50" on QKart, extracting dynamic OTP codes or order IDs, formatting parameterized Page Object XPaths, and validating response texts all rely on these String and regex APIs.

Key points

  1. trim() removes characters <= '\u0020' (ASCII space and control chars), whereas Java 11+ strip() uses Character.isWhitespace() to remove Unicode spaces including non-breaking spaces (&nbsp; / \u00A0).
  2. isEmpty() returns true only when length() == 0, whereas Java 11+ isBlank() returns true for empty or whitespace-only strings.
  3. substring(beginIndex, endIndex) is inclusive of beginIndex and exclusive of endIndex (throwing StringIndexOutOfBoundsException if indices fall out of range).
  4. replace(CharSequence, CharSequence) performs literal substring replacement, whereas replaceAll(String regex, String replacement) treats the first argument as a regular expression.
  5. split(String regex) splits by regex—special regex metacharacters like dot (.), pipe (|), and dollar ($) must be double-escaped inside Java string literals (split("\\.")).
  6. Pattern.compile() and Matcher extract structured substrings (for example, Order #QK-4821) without brittle fixed-offset substring() indices.

How it works

  1. Capture raw UI text via element.getText() and clean leading/trailing browser &nbsp; spaces using .strip().
  2. Remove formatting symbols ($, commas) via price.replaceAll("[^0-9.]", "") before numeric conversion.
  3. Use String.format("//button[normalize-space()='%s']", productName) to generate parameterized locators cleanly.
  4. For dynamic confirmations containing embedded IDs, compile a Pattern with capturing group ([A-Z0-9-]+) and extract via matcher.group(1).

Parsing QKart UI prices, splitting delimited strings, and extracting order IDs with regex:

package dev.java.strings; // Declares package

import java.util.regex.Matcher; // Imports regex Matcher engine
import java.util.regex.Pattern; // Imports compiled regex Pattern

public class StringRegexSdetDemo { // Demonstrates SDET string and regex operations
    public static void main(String[] args) { // Main method entry
        String rawPrice = " \u00A0$1,249.50\u00A0 "; // Includes Unicode non-breaking space from DOM
        String cleanDigits = rawPrice.strip().replaceAll("[^0-9.]", ""); // Strips Unicode spaces and non-numeric chars
        double price = Double.parseDouble(cleanDigits); // Parses 1249.50 cleanly
        System.out.println("Parsed price: " + price); // Prints: 1249.5

        String version = "4.26.0"; // Dot-separated Selenium version string
        String[] parts = version.split("\\."); // Double-escapes dot so regex matches literal '.'
        System.out.println("Major: " + parts[0] + ", Minor: " + parts[1]); // Prints: Major: 4, Minor: 26

        String toast = "Order ID: QK-90842 confirmed successfully"; // Dynamic UI toast message
        Matcher m = Pattern.compile("Order ID: ([A-Z0-9-]+)").matcher(toast); // Capturing group for ID
        String orderId = m.find() ? m.group(1) : ""; // Extracts matched group 1 if present
        System.out.println("Extracted ID: " + orderId); // Prints: QK-90842
    } // Ends main method
} // Ends class

Common mistakes

  1. Calling version.split(".") without escaping the dot; in regex, unescaped . matches every single character and returns an empty zero-length array [].
  2. Using replaceAll("$10", "$20") for literal text replacement; $ is a regex anchor/group reference in both arguments of replaceAll(), so use literal replace() instead unless regex is required.
  3. Relying on text.trim() when HTML elements contain &nbsp; (\u00A0); trim() leaves non-breaking spaces intact, causing exact assertions to fail where strip() succeeds.
  4. Calling matcher.group(1) without calling if (matcher.find()) first; calling group() prior to a successful match throws IllegalStateException: No match found.

Interview questions

Basics

What is the difference between replace() and replaceAll() in Java?
Both methods replace every matching occurrence across the entire string, NOT just the first occurrence. The real difference is that replace(CharSequence, CharSequence) matches exact literal text with zero regex parsing, whereas replaceAll(String regex, String replacement) compiles and matches a regular expression. When replacing literal substrings like "$" or "C:\path", always choose replace() for speed and safety.

How do trim() and strip() differ?
trim() dates back to Java 1.0 and only removes leading and trailing characters whose Unicode value is <= '\u0020' (ASCII space, tab, newline), missing Unicode whitespace like HTML non-breaking space (\u00A0). strip(), added in Java 11, uses Character.isWhitespace() to remove all Unicode whitespace characters cleanly.

Explain the index arguments of "Selenium".substring(1, 4).
The first index 1 is inclusive (character 'e') and the second index 4 is exclusive (stops before character 'n' at index 4), returning "ele" of length 4 - 1 = 3. If beginIndex > endIndex or either index is out of bounds, Java throws StringIndexOutOfBoundsException.

How it works

Why does "192.168.1.1".split(".") return an empty array of length 0?
split() accepts a regular expression, and an unescaped dot . is a regex wildcard matching any character. Every character becomes a delimiter, producing empty strings that split(regex) trims off the trailing end by default, leaving a 0-length array. Escaping the dot inside a Java string literal as split("\\.") or split(Pattern.quote(".")) splits into 4 octets correctly.

How do Pattern and Matcher extract a numeric order ID from "Order #QK-8421 confirmed"?
Compile Pattern p = Pattern.compile("#(QK-\\d+)"); using parentheses around QK-\\d+ to form capturing group 1. Create a matcher via Matcher m = p.matcher(text); and call m.find() to scan the text for the pattern. When find() returns true, m.group(1) returns "QK-8421".

Why does str.matches("\\d+") return false for "Order 123" even though digits exist?
Unlike JavaScript's regex test or Matcher.find(), Java's String.matches(regex) implicitly wraps the pattern as if anchored with ^...$, demanding that the entire string match the pattern. To check if digits appear anywhere inside text, use Pattern.compile("\\d+").matcher(text).find().

Real situations

In a Selenium test on QKart, product prices render as "₹1,499" or "$1,299.50". How do you assert numeric total math reliably?
Extract the price text with getText(), remove everything except digits and decimal points via text.replaceAll("[^0-9.]", ""), and pass the clean string into new BigDecimal(cleanText) or Double.parseDouble(cleanText). That avoids brittle hardcoded currency symbol removals or fixed substring(1) offsets.

How does String.format() help build dynamic XPath or CSS selectors inside a Page Object?
Define a private template like private static final String PRODUCT_CARD = "//p[normalize-space()='%s']/ancestor::div[contains(@class,'card')]"; and resolve it via By.xpath(String.format(PRODUCT_CARD, productName)). Note that if productName can contain single quotes, wrap it via an XPath quote-escaping helper.

How do you verify a Selenium page title or error message ignoring irregular spacing and casing?
Normalize whitespace using actual.strip().replaceAll("\\s+", " ") and assert with equalsIgnoreCase(expected). Collapsing runs of tabs and newlines via \\s+ prevents multi-line HTML formatting differences from causing flaky failures.

Troubleshooting

Why does matcher.group(1) throw IllegalStateException: No match found?
A Matcher starts before the beginning of the input string and holds no match state until matcher.find() or matcher.matches() returns true. Calling group() unconditionally without wrapping it inside if (matcher.find()) crashes whenever the pattern misses or find() was skipped.

What causes StringIndexOutOfBoundsException when using substring(text.indexOf(":") + 1)?
If the expected delimiter ":" is missing from the UI string, indexOf(":") returns -1; adding 1 passes 0 silently or negative offsets fail when computing end indices. Always verify int idx = text.indexOf(":"); if (idx != -1) before slicing with substring().

Why does "a,b,,".split(",") return length 2 instead of 4?
The single-argument split(regex) discards trailing empty strings by default. Passing -1 as the second limit parameter ("a,b,,".split(",", -1)) preserves all trailing empty columns, which is essential when parsing CSV test data with blank trailing cells.

Design choices

Why should repeated regex patterns inside a test helper or loop use a private static final Pattern field rather than String.replaceAll() or String.matches()?
Every invocation of String.matches(), String.split() (for multi-char regex), or String.replaceAll() recompiles the regular expression state machine from scratch. Pre-compiling once via private static final Pattern ORDER_ID = Pattern.compile(...); shares the immutable compiled Pattern safely across threads with zero repeated compilation cost.

When parsing HTML text in Selenium, when should you prefer XPath normalize-space() vs Java strip()?
Use XPath normalize-space() inside locators when matching exact DOM text that has leading/trailing HTML indentation so the selector matches directly in the browser. Use Java strip() and regex on retrieved getText() values before TestNG assertions.

Why should dynamic XPath templates created with String.format() sanitize inputs that contain single quotes?
If test data includes an apostrophe like Men's Watch inside //p[text()='%s'], the unescaped quote terminates the XPath string literal prematurely and throws InvalidSelectorException. Wrapping dynamic values in an XPath concat() helper or using a parameterized By builder prevents syntax failures.

Quick answers

  1. What does replace() use vs replaceAll()? replace() matches literal characters; replaceAll() matches regular expressions.
  2. What does strip() handle that trim() misses? Unicode whitespace including non-breaking spaces (\u00A0).
  3. How do you split a string on a literal dot .? str.split("\\.") or str.split(Pattern.quote(".")).
  4. Does String.matches(regex) check partial substrings or the entire string? The entire string.
  5. What method must return true before calling matcher.group(1)? matcher.find() (or matcher.matches()).
  6. How do you preserve trailing empty fields in split(",")? Pass -1 as the second argument: split(",", -1).
