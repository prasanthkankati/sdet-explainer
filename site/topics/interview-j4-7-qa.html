J4.7 Question Bank: Abstraction: Abstract Class vs Interface (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. Compare an abstract class and an interface across 5 core dimensions.
    First, a class can extend strictly one abstract class, whereas it can implement multiple interfaces. Second, an abstract class holds instance state fields and constructors, whereas an interface holds only public static final constants and zero constructors. Third, abstract classes allow protected and private state, whereas interface abstract methods are strictly public. Fourth, both cannot be instantiated directly with new. Fifth, both support concrete helper methods via standard methods or Java 8 default methods.
  2. Can an abstract class have zero abstract methods, or have a constructor?
    Yes to both. Marking a class abstract with zero abstract methods prevents callers from instantiating the incomplete base class directly via new BasePage(driver) while allowing concrete subclasses to inherit shared code. Its constructor still exists specifically to initialize those shared fields when subclasses invoke super(driver).
  3. What are Functional Interfaces and Marker Interfaces in Java?
    A Functional Interface has strictly one abstract method (SAM)—for example, Runnable, Predicate<T>, or ExpectedCondition<T>—allowing callers to pass concise lambdas (driver -> driver.getTitle().contains("QKart")). A Marker Interface contains zero methods and marks classes with capability metadata checked at runtime via instanceof, including Serializable and Cloneable.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. Why did Java 8 introduce default and static methods inside interfaces?
    Before Java 8, adding a single new method to a widely implemented interface like java.util.List broke every third-party implementation class immediately at compile time. Adding default concrete methods (like Collection.stream() and List.sort()) allowed the JDK to upgrade standard interfaces cleanly without breaking legacy implementations. Interface static methods provide factory helpers directly on the contract (like Comparator.comparing()).
  2. What happens if an interface declares int TIMEOUT = 10; without any modifiers?
    Every field inside a Java interface is implicitly treated by the compiler as public static final int TIMEOUT = 10;, regardless of whether you write those modifiers explicitly. Implementing classes cannot modify that constant field.
  3. In Selenium, explain the exact abstraction hierarchy connecting SearchContext, WebDriver, RemoteWebDriver, and ChromeDriver.
    SearchContext is the top-level interface declaring findElement and findElements. WebDriver is a child interface extending SearchContext and adding browser navigation and window contracts (and WebElement also extends SearchContext). RemoteWebDriver is a concrete class implementing WebDriver plus TakesScreenshot and JavascriptExecutor, and ChromeDriver extends ChromiumDriver which extends RemoteWebDriver.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. Why is org.openqa.selenium.By designed as an abstract class instead of an interface?
    By encapsulates shared locator factory methods (By.id(), By.xpath(), By.cssSelector()) alongside shared helper logic like findElement(SearchContext context) and concrete equals()/hashCode()/toString() implementations that interfaces cannot override from Object. Every locator subclass extends By and implements findElements(SearchContext).
  2. How does TestNG's ITestListener interface leverage Java 8 default methods?
    Because ITestListener provides empty default implementations for lifecycle hooks like onTestStart, onTestSuccess, and onTestFailure, your custom listener class only needs to override onTestFailure to attach failure screenshots without writing empty boilerplate overrides for seven unused hooks.
  3. When designing a custom Page Object framework, should BasePage be an abstract class or an interface?
    Make BasePage an abstract class because every Page Object shares protected instance state (protected final WebDriver driver; and protected final WebDriverWait wait;) initialized once via a constructor, which an interface cannot store.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why does implementing PageLoadCheck fail with 'attempting to assign weaker access privileges; was public' when writing boolean isLoaded()?
    In an interface, boolean isLoaded(); is implicitly public even without writing the word public. In the implementing class, omitting public assigns narrower package-private visibility, violating Java's override visibility rule. Always prefix implemented interface methods with public.
  2. Why did adding a helper method inside an interface annotated with @FunctionalInterface break compilation?
    If the added helper is an abstract method, the interface now has two abstract methods and ceases to be a Functional Interface. Making the helper either a default method or a static method leaves strictly one abstract method and compiles cleanly.
  3. Why can you write new WebDriverWait(driver, Duration.ofSeconds(10)).until(d -> d.getTitle().equals("QKart")); without writing an anonymous class?
    Wait.until(Function<? super T, V>) expects the java.util.function.Function Functional Interface. Because Function has only one abstract method (apply(T)), Java automatically compiles the lambda expression into an instance implementing that single method.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. When creating a brand-new abstraction for a test framework (for instance, a DriverProvider or SecretStore), should you start with an interface or an abstract class?
    Start with an interface when defining pure behavioral capabilities because classes can implement multiple interfaces without consuming their single inheritance slot (for instance, implementing both local Docker and BrowserStack cloud providers). Reserve abstract class for tight IS-A families sharing mutable protected fields or constructor initialization logic.
  2. Why do modern Java architectures reject empty Marker Interfaces for new code in favor of Annotations?
    Marker interfaces like Serializable cannot accept configuration parameters and lock classes at compile time. Custom Java Annotations (including TestNG @Test(retryAnalyzer = ...) or JUnit @Tag("smoke")) attach structured key-value metadata cleanly to classes, methods, or fields without polluting type hierarchies.
  3. Why are interfaces prohibited from overriding Object methods like equals(), hashCode(), or toString() as default methods?
    Every class implementing an interface already inherits concrete implementations of equals, hashCode, and toString from java.lang.Object, and superclass methods always win over interface default methods. Allowing interface defaults for Object methods would create useless dead code that could never run polymorphically.
  4. Can an interface have instance fields or constructors?
    No; interface fields are implicitly public static final constants and interfaces have no constructors.
  5. Can an abstract class have a constructor?
    Yes, executed by subclasses via super().
  6. What is a Functional Interface?
    An interface with exactly one abstract method (enabling Lambda expressions).
  7. What is a Marker Interface?
    An empty interface with zero methods (for example, Serializable or Cloneable).
  8. What type are WebDriver, WebElement, and SearchContext in Selenium?
    Interfaces (whereas By is an abstract class).
  9. What methods did Java 8 allow inside interfaces?
    Concrete default and static methods.
