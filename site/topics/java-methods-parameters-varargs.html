2.6 Methods, Parameters, Return Types & Varargs

1. Definition

A method signature combines only the method name and parameter list (ignoring return type and modifiers), and varargs (Type... args) lets a caller pass zero or more arguments packed into an array.

2. Memory hook

Signature = Name + Parameters (NOT return type!); Varargs = Last parameter only.

  • Return type is outside the signature: changing only void to int with identical parameters does not create a valid overload.
  • Parameters vs Arguments: parameters sit in the method header; arguments are the real values passed at the call site.
  • Varargs rules: a method can have only one ... parameter and it must sit at the very end.

5. Code example: method calls & varargs in a Selenium helper

public class MethodVarargsDemo {
    static boolean clickAll(String prefix, String... labels) { // '...' MUST be the final parameter
        System.out.println("Clicking " + labels.length + " items under " + prefix);
        for (String label : labels) {                           // inside body, varargs is an array
            System.out.println(" -> " + prefix + ":" + label);
        }
        return labels.length > 0;                               // boolean return for test checks
    }

    public static void main(String[] args) {
        boolean any = clickAll("Nav", "Downloads", "Documentation"); // 2 args packed as String[]
        boolean zero = clickAll("Nav");                              // 0 extra args -> empty array []
        System.out.println("Result: " + any + " / " + zero);
    }
}

6. Execution flow, step by step

  1. Calling clickAll("Nav", "Downloads", "Documentation") packs the last two Strings into new String[]{"Downloads", "Documentation"}.
  2. The JVM pushes a Stack frame containing prefix and the packed labels array.
  3. Inside clickAll, labels.length and for-each treat labels identically to an array.
  4. Calling clickAll("Nav") with zero trailing arguments passes an empty zero-length array instead of null.
  5. return pops the Stack frame and hands the boolean back to main.

8. Why it matters

Clean method signatures prevent overloading ambiguity and keep helper APIs readable without creating 5 separate method overloads just to pass 1, 2, or 3 items.

SDET link: Wait helpers and multi-select dropdown utils use varargs like selectFilters("Running", "Nike", "InStock") cleanly, while returning Page Objects (return new CartPage(driver);) enables fluent chaining.

9. Quick test

Does void send(String a) overload with int send(String a)? No — identical parameter lists with different return types fail to compile as duplicate methods.
