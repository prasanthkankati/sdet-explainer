Java Intro: JDK vs JRE vs JVM

1. Definition

Java source code is compiled by the JDK into bytecode, and the JVM (inside the JRE) loads, checks and runs that bytecode on any computer.

2. Memory hook

JDK = Make it, JRE = Run it, JVM = Do it.

  • JVM is only the engine that does the work. It cannot run alone, because it needs the library files.
  • JRE is JVM plus the library files, so it can run programs but cannot build them.
  • JDK is JRE plus the build tools, so you can write, build and run.

3. The three layers (they nest like Russian dolls)

JDK Java Development Kit: "Make it". What you install.
Everything to write, build and run. Contains the JRE plus the developer tools below.
javacCompiler. Turns Hello.java into Hello.class (bytecode).
jarPacks many .class files into one .jar (this is what Selenium ships as).
javadoc / jdb / jshellDocs generator, debugger, quick playground.
JRE Java Runtime Environment: "Run it"
Everything to run a finished program. Contains the JVM plus the library files.
Class librariesReady-made code: String, ArrayList, Math, System. Loaded by the JVM when your code uses them.
Config filesSecurity and settings files the JVM reads at startup.
JVM Java Virtual Machine: "Do it". The engine.
Loads bytecode, stores it in memory, executes it. Details on the next page.
Class LoaderBrings .class files into memory.
Memory areasHeap, Stack, Metaspace: where data lives.
Execution EngineInterpreter, JIT, Garbage Collector: runs code.

4. JRE vs JVM: the confusion fixed

JVMJRE
Is itA program (the engine)A package that contains the JVM
ContainsClass loader, memory areas, execution engineJVM + class libraries + config files
Runs Hello.class alone?No. String and System live in the libraries.Yes
JobExecutes bytecodeProvides everything needed to run

Example: your code calls new ArrayList<>(). The code for ArrayList is not in the JVM. It sits in the library files (java.base) shipped in the JRE. The JVM's class loader fetches it when needed.

5. Code example

// Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, SDET!");   // prints: Hello, SDET!
    }
}
javac Hello.java    # JDK tool: compiles to Hello.class (bytecode)
java Hello          # starts the JVM, which runs the bytecode -> Hello, SDET!

6. Step-by-step: what happens

  1. You write Hello.java (human-readable source code).
  2. javac (JDK) checks syntax and creates Hello.class (bytecode, not machine code).
  3. java Hello starts the JVM.
  4. The JVM loads Hello.class plus String and System from the libraries (JRE).
  5. The JVM checks the bytecode is safe, then runs it on your OS and CPU.

Bytecode is the same on every OS. The JVM is different per OS (Windows, Mac, Linux). That is the trick behind "write once, run anywhere".

8. Why it matters

Compile once and the same .class file runs on Windows, Mac and Linux. You install the JDK (it includes the JRE). Since Java 11 there is no separate JRE download.

SDET link: Selenium tests are Java code. You need the JDK to compile them, and JAVA_HOME must point to it so Maven, Gradle, Eclipse and IntelliJ can find it.

9. Quick test

javac -version works: you have the JDK. Only java -version works: JRE only, you can run Java but cannot compile it.
