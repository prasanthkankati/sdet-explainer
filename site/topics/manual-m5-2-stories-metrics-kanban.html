5.2 User Stories (INVEST), Acceptance Criteria, DoR vs DoD & Velocity

1. The Base: How Requirements & Quality Gates Work in Agile Jira

In Agile, requirements are written as User Stories (following the INVEST standard) paired with testable Given-When-Then Acceptance Criteria, gated by Definition of Ready (DoR) before work starts and Definition of Done (DoD) before release, and tracked via Story Points, Velocity & Burndown Charts.

2. User Story Format, INVEST & Given-When-Then Acceptance Criteria

  • Standard User Story Template: "As a [Role], I want [Action/Feature], so that [Business Value]."
  • INVEST Criteria (6 Rules of a Good User Story):
    1. I — Independent: Can be developed & tested without waiting on another story.
    2. N — Negotiable: Details can be refined collaboratively by PO, Dev & QA.
    3. V — Valuable: Delivers visible value to end-users or business.
    4. E — Estimable: Clear enough for the team to estimate Story Points.
    5. S — Small: Fits comfortably inside 1 Sprint (with time for QA & automation).
    6. T — Testable: Has exact, measurable Acceptance Criteria (e.g., "Given-When-Then").
  • BDD Acceptance Criteria (`Given - When - Then`):
    Given user has `$100` in cart → When user applies `SAVE20` → Then total updates to `$80` and discount row `-$20` displays.

3. Definition of Ready (DoR) vs Definition of Done (DoD)

ParameterDefinition of Ready (DoR)Definition of Done (DoD)
When CheckedBEFORE pulling a story into a Sprint (Planning)AFTER coding & testing, before closing a story
PurposePrevents starting vague, unready stories (Entry Gate)Guarantees production-grade quality (Exit Gate)
Checklist ExamplesClear Acceptance Criteria, UI mockups ready, API contract agreed, Story Pointed, Dependencies clearedCode peer-reviewed, Unit tests ≥80%, Manual + Automated Selenium/API tests passed, 0 S1/S2 bugs open, PO accepted

4. Story Points, Velocity, Burndown Chart & Scrum vs Kanban

  • Story Points (Fibonacci: `1, 2, 3, 5, 8, 13`): Relative effort estimate combining Complexity + Effort + Risk/Uncertainty (NOT hours!). QA participates in Planning Poker so testing & automation effort is included in the Story Points.
  • Velocity: Average number of Story Points of 100% "Done" stories a team completes per Sprint (used to forecast future capacity, never to compare two different teams).
  • Sprint Burndown Chart: Tracks Remaining Work (Story Points/Hours) on the Y-axis vs Days in Sprint on the X-axis against an ideal downward diagonal line.
  • Scrum vs Kanban:
ParameterScrumKanban
CadenceFixed 1–4 week SprintsContinuous flow (No fixed Sprints)
WIP ControlSprint Backlog commitmentExplicit WIP (Work-In-Progress) Limits per column
Key MetricVelocity & Burndown ChartLead Time & Cycle Time + Cumulative Flow
Best Use CaseProduct feature developmentProduction Support, DevOps, Bug-fix/Hotfix teams

Interview Answer: "DoR is the Entry Gate ensuring a story has clear INVEST specs and Acceptance Criteria before entering a Sprint, while DoD is the Exit Gate ensuring code, unit tests, manual QA, and automation pass before a story is closed. Story Points estimate relative complexity/effort/risk using Fibonacci numbers, Velocity measures completed points per Sprint, and Kanban uses continuous flow with WIP limits instead of fixed Sprints."
