5.5 Sorting (Comparable vs Comparator) & Iterators

1. Definition

Comparable defines one natural sort order inside a class via compareTo(o), Comparator defines unlimited external sort strategies via compare(a, b), and Fail-Fast iterators throw ConcurrentModificationException if a collection mutates mid-loop.

2. Memory hook

Comparable = 1 natural sort inside class (compareTo); Comparator = external strategy (compare); remove safely via iterator.remove()!

  • Why use Comparator instead of Comparable: lets you sort products by price, rating, or title without editing the model class.
  • Never write return p1.price - p2.price cast to int: 10.9 - 10.2 = 0.7 truncates to 0 (false tie!) or overflows on big ints — use Double.compare / Comparator.comparingDouble!
  • Fail-Fast vs Fail-Safe: ArrayList iterators check modCount and crash on concurrent edits; CopyOnWriteArrayList iterates a snapshot safely.

5. Code example: sorting QKart prices & safely pruning blank scraped strings

import java.util.*;

public class SortAndIterateDemo {
    record Product(String name, double price) {}

    public static void main(String[] args) {
        List<Product> catalog = new ArrayList<>(List.of(
            new Product("Watch", 79.99), new Product("Shoe", 49.50)
        ));
        catalog.sort(Comparator.comparingDouble(Product::price)); // external Comparator by price
        System.out.println("Sorted: " + catalog);

        List<String> tags = new ArrayList<>(List.of("NEW", "", "SALE"));
        tags.removeIf(String::isBlank);                           // safe internal Iterator removal!
        System.out.println("Cleaned tags: " + tags);              // [NEW, SALE]
    }
}

6. Execution flow, step by step

  1. Comparator.comparingDouble(Product::price) avoids integer subtraction truncation and compares doubles safely.
  2. catalog.sort(...) reorders Shoe (49.50) ahead of Watch (79.99) without changing Product.
  3. On tags, calling tags.remove("") inside an ordinary for-each loop would make modCount != expectedModCount and throw ConcurrentModificationException.
  4. tags.removeIf(String::isBlank) updates modCount cleanly through the iterator contract.
  5. Result contains only ["NEW", "SALE"] with zero runtime crash.

8. Why it matters

Knowing safe Comparator helpers and safe iteration kills subtle sorting tie bugs and mid-loop crashes.

9. Quick test

Why does for (String s : list) { if (s.isEmpty()) list.remove(s); } fail? list.remove() bumps modCount behind the hidden iterator's back, triggering ConcurrentModificationException — use removeIf() instead.
