5.6 Java 8+ Lambdas, Functional Interfaces, Streams & Optional

1. Definition

Lambdas supply compact anonymous implementations for single-abstract-method Functional Interfaces (Predicate, Function, Consumer, Supplier), Streams process collections declaratively, and Optional models nullable returns cleanly.

2. Memory hook

Predicate = test->boolean, Function = T->R, Consumer = void(T), Supplier = get()->T; Optional guards null!

  • 4 core Functional Interfaces (java.util.function): Predicate<T> (filter), Function<T,R> (map / WebDriverWait.until!), Consumer<T> (forEach), Supplier<T> (lazy default).
  • Streams are lazy & single-use: intermediate operations (filter, map) wait until a terminal operation (toList, findFirst, count) pulls data.
  • map vs flatMap: map converts 1-to-1; flatMap flattens nested collections into a single stream.

5. Code example: filtering links with Stream + Method Reference + Optional

import java.util.*;

public class StreamOptionalDemo {
    public static void main(String[] args) {
        List<String> navTexts = List.of("Downloads", "", "Documentation", "Projects");

        List<String> clean = navTexts.stream()            // start Stream pipeline
            .map(String::strip)                           // Function via Method Reference
            .filter(s -> !s.isBlank())                    // Predicate drops blank items
            .toList();                                    // Terminal triggers execution (Java 16+)

        String picked = clean.stream()
            .filter(s -> s.startsWith("Doc"))
            .findFirst()                                  // returns Optional<String>
            .orElse("Missing Doc Tab");                   // safe fallback without raw null check

        System.out.println("Clean=" + clean + " | Picked=" + picked);
    }
}

6. Execution flow, step by step

  1. navTexts.stream() creates a pipeline over the 4 source strings without mutating navTexts.
  2. .map(String::strip) trims each string (Method Reference shorthand for s -> s.strip()).
  3. .filter(s -> !s.isBlank()) supplies a Predicate dropping the empty string.
  4. Calling terminal .toList() kicks off execution and stores the 3 non-blank results.
  5. .findFirst().orElse(...) handles a potentially absent match through Optional cleanly with zero null crashes.

8. Why it matters

Streams replace nested loops and temp lists with clear step-by-step data transformations; Optional forces callers to think about absent return values.

SDET link: WebDriverWait.until(d -> d.findElement(locator)) uses Function<WebDriver, WebElement> directly, while driver.findElements(navLinks).stream().map(WebElement::getText).toList() extracts menu text cleanly in one readable pipeline.

9. Quick test

What happens if you write stream.filter(...).map(...); without a terminal operation like .toList()? Nothing executes at all because intermediate stream steps are lazy.
