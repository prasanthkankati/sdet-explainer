4.6 Polymorphism: Overloading vs Overriding & Upcasting

Compile-time Method Overloading vs runtime Method Overriding, @Override rules, Covariant return types, and Upcasting WebDriver driver = new ChromeDriver().

Polymorphism lets one interface or method name handle distinct concrete types cleanly—either at compile time by picking among overloaded parameter lists or at runtime via Dynamic Method Dispatch on an overridden child class. In Selenium, Upcasting every browser driver behind the WebDriver interface is what makes cross-browser automation possible without rewriting test steps.

Before you start

Prerequisite: 4.5 Inheritance (IS-A) vs Composition (HAS-A)

Where it fits

Every Selenium test uses Polymorphism on line 1 (WebDriver driver = new ChromeDriver(); upcasting), calls overloaded methods like driver.switchTo().frame(...), and relies on runtime overriding inside driver and Page Object subclasses.

Key points

  1. Compile-Time Polymorphism (Method Overloading) occurs inside the same class (or subclass) when multiple methods share the exact same name with different parameter lists (different count, types, or order).
  2. Runtime Polymorphism (Method Overriding) occurs when a subclass provides a specific implementation for an inherited instance method sharing the exact same name and parameter list.
  3. Overriding rules: access modifier cannot be more restrictive, checked exceptions thrown cannot be broader, and return type must match or be a covariant subtype (for example, overriding BasePage submit() to return HomePage).
  4. private, final, and static methods can NEVER be overridden; redefining a matching static signature in a subclass is compile-time Method Hiding, not overriding.
  5. Upcasting (WebDriver driver = new ChromeDriver();) assigns a child object to a parent/interface reference automatically; compile-time checks look at WebDriver while runtime calls dispatch dynamically to ChromeDriver.
  6. Downcasting (((TakesScreenshot) driver)) narrows back to a subtype explicitly and throws ClassCastException at runtime if the actual Heap object does not implement that type.

How it works

  1. Write WebDriver driver = new ChromeDriver();—the Stack variable type is interface WebDriver while the Heap object is ChromeDriver.
  2. When calling driver.get(url), javac verifies get(String) exists on the WebDriver interface.
  3. At runtime, the JVM inspects the actual Heap object (ChromeDriver / FirefoxDriver) via Dynamic Method Dispatch and runs that browser driver's overridden implementation.
  4. When invoking overloaded helpers like click(By) vs click(By, int timeoutSec), javac locks the exact method target at compile time based on the arguments supplied.

Overloading wait helpers, covariant overriding in Page Objects, and polymorphic WebDriver upcasting:

package dev.java.oop; // Declares package

import org.openqa.selenium.By; // Imports By locator
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver class
import org.openqa.selenium.firefox.FirefoxDriver; // Imports FirefoxDriver class

class BaseActionPage { // Parent page class
    protected final WebDriver driver; // Polymorphic interface reference

    BaseActionPage(WebDriver driver) { // Constructor accepts any WebDriver implementation
        this.driver = driver; // Stores upcast driver reference
    } // Ends constructor

    public BaseActionPage open(String url) { // Base method eligible for covariant override
        driver.get(url); // Dispatches dynamically to ChromeDriver or FirefoxDriver at runtime
        return this; // Returns parent page type
    } // Ends open

    public void click(By locator) { // Overloaded method #1 (1 parameter)
        driver.findElement(locator).click(); // Clicks immediately
    } // Ends click(By)

    public void click(By locator, int maxAttempts) { // Overloaded method #2 (2 parameters)
        for (int i = 0; i < maxAttempts; i++) { // Retries up to maxAttempts times
            click(locator); // Calls 1-arg overload directly
            return; // Exits once click succeeds
        } // Ends retry loop
    } // Ends click(By, int)
} // Ends BaseActionPage

public class PolymorphicLoginPage extends BaseActionPage { // Subclass overriding open
    public PolymorphicLoginPage(WebDriver driver) { // Constructor forwarding driver
        super(driver); // Calls parent constructor
    } // Ends constructor

    @Override // Compiler verifies exact override signature
    public PolymorphicLoginPage open(String url) { // Covariant return narrows BaseActionPage to child
        super.open(url); // Calls parent navigation step
        return this; // Returns child type for fluent chaining
    } // Ends override

    static WebDriver createBrowser(String name) { // Returns upcast WebDriver interface
        return "firefox".equalsIgnoreCase(name) ? new FirefoxDriver() : new ChromeDriver(); // Polymorphic factory
    } // Ends createBrowser
} // Ends PolymorphicLoginPage

Common mistakes

  1. Writing ChromeDriver driver = new ChromeDriver(); everywhere in framework signatures instead of upcasting to WebDriver driver; this locks every Page Object and listener strictly to Chrome and breaks Firefox/Edge/Grid runs.
  2. Omitting the @Override annotation when overriding equals() or a parent helper; a subtle typo in parameter types like equals(User o) silently creates an overload instead of an override, and @Override catches that bug at compile time.
  3. Expecting Dynamic Method Dispatch to apply to instance fields or static methods; fields and static methods always resolve according to the reference variable type at compile time, never the runtime Heap object.
  4. Casting ((ChromeDriver) driver) blindly inside a listener when RemoteWebDriver is returned by Selenium Grid, causing ClassCastException.

Interview questions

Basics

What is the core difference between Method Overloading and Method Overriding?
Method Overloading (compile-time polymorphism) defines multiple methods sharing the same name with different parameter types, counts, or order, resolved statically by javac. Method Overriding (runtime polymorphism) lets a subclass replace a parent's instance method with the identical signature, resolved dynamically at runtime by the JVM based on the Heap object type. Both improve API cleanliness and extensibility.

Why do we write WebDriver driver = new ChromeDriver(); instead of ChromeDriver driver = new ChromeDriver();?
Upcasting to the WebDriver interface decouples test code and Page Objects from any single browser vendor. The same driver variable can hold a ChromeDriver locally, a FirefoxDriver via CLI flag, or a RemoteWebDriver on Selenium Grid without changing a single line of Page Object code. Calling browser-proprietary methods only available on ChromeDriver is intentionally prevented unless explicitly checked.

Why is the @Override annotation considered essential even though Java does not strictly require it?
@Override instructs the compiler to prove that an annotated method actually overrides an inherited parent or interface method. Without it, misspelling a method name or using the wrong parameter type (for instance, writing public boolean equals(LoginPage p) instead of Object) silently compiles as a brand-new overload and causes subtle runtime bugs.

How it works

How does the JVM perform Dynamic Method Dispatch at runtime?
When code invokes an instance method on a polymorphic reference like driver.get(url), the bytecode emits an invokevirtual or invokeinterface instruction. At runtime, the JVM reads the class metadata pointer in the Heap object's header, looks up that class's virtual method table (vtable), and jumps directly to the subclass's overridden method body. If the Heap object is a FirefoxDriver, Firefox's implementation runs automatically.

Which methods in Java can be overloaded vs overridden?
Almost any method—including static, final, private, and constructors—can be overloaded with a different parameter list. By contrast, only non-final, non-static, non-private instance methods can be overridden. Redefining a matching static method signature in a subclass hides the parent method rather than overriding it.

What is a covariant return type and how does it help Page Object hierarchies?
Java 5 introduced covariant return types, allowing an overriding subclass method to narrow the return type to a subclass of the parent method's return type. For example, if BasePage.refresh() returns BasePage, CartPage.refresh() can override it to return CartPage directly so callers keep fluent access to cart-specific methods without manual casting.

Real situations

Name three real examples of Method Overloading inside the Selenium WebDriver API.
1) driver.switchTo().frame(int index), frame(String nameOrId), and frame(WebElement frameElement). 2) Actions.click() (clicks at current mouse coordinates) vs Actions.click(WebElement target) (moves to element and clicks). 3) Select.selectByIndex(int), selectByValue(String), and selectByVisibleText(String) (or TestNG's overloaded Assert.assertEquals signatures).

How does Method Overriding power custom Selenium ExpectedConditions?
When writing a custom wait condition, you pass an anonymous implementation or lambda overriding ExpectedCondition<Boolean>.apply(WebDriver driver). Inside WebDriverWait.until(), Selenium polls that overridden apply() method polymorphically until it returns true or times out.

When running tests against Selenium Grid with RemoteWebDriver, how do you safely take a screenshot?
RemoteWebDriver already implements TakesScreenshot, so check if (driver instanceof TakesScreenshot ts) or wrap new Augmenter().augment(driver) when needed before calling ts.getScreenshotAs(OutputType.FILE). That avoids hardcoding casts to ChromeDriver that crash on remote Grid sessions.

Troubleshooting

Why did ((ChromeDriver) driver).executeCdpCommand(...) pass locally and throw ClassCastException on Selenium Grid?
Locally, driver held a ChromeDriver instance, so the downcast succeeded. On Selenium Grid, the DriverFactory instantiated a RemoteWebDriver, which does NOT inherit from ChromeDriver, causing an immediate ClassCastException: class RemoteWebDriver cannot be cast to class ChromeDriver. Always guard downcasts with instanceof or use HasCdp / Augmenter.

Why did calling p.printVersion() on Parent p = new Child(); execute Parent.printVersion() instead of Child.printVersion()?
printVersion() was declared static in both classes. Because static methods bind at compile time to the declared reference type (Parent) rather than the Heap object type (Child), method hiding occurred instead of runtime overriding.

Why does an overloaded pair process(Object o) and process(String s) invoke process(Object) when called through a variable typed as Object x = "hello";?
Method overload selection happens strictly at compile time using the declared static types of the arguments (Object), never the runtime Heap type (String). Only overriding uses the runtime Heap type.

Design choices

Why should framework code always program to the WebDriver interface rather than concrete driver classes?
Coding against interfaces isolates tests from browser implementation changes, enables instant cross-browser switching via config flags, and supports wrapping drivers in Selenium Grid's RemoteWebDriver or EventFiringDecorator proxies transparently.

Why should you avoid creating excessive confusing overloads that take identical argument counts of convertible types (like int vs long vs Integer)?
Overloading methods with numeric promotions and boxing types forces maintainers to memorize Java's implicit overload precedence rules and risks ambiguous method call errors. Give distinct behavioral variants distinct, descriptive method names instead.

Why does Java forbid overriding private methods?
A private method is invisible outside its declaring class and represents purely internal mechanics. Allowing subclasses to intercept a parent's internal private helpers would break parent invariants silently; if a child defines a method with the same signature, Java treats it as an unrelated new method.

Quick answers

  1. Can two overloaded methods differ ONLY by return type? No; parameter lists must differ.
  2. When is Method Overloading resolved vs Method Overriding? Overloading resolves at compile time; Overriding resolves at runtime.
  3. Can a static or private method be overridden? No.
  4. What exception occurs on an invalid downcast? java.lang.ClassCastException.
  5. What is Upcasting in Selenium? WebDriver driver = new ChromeDriver(); (subclass object assigned to interface/parent variable).
  6. What does a covariant return type allow? An overriding subclass method to return a narrower subtype of the parent's return type.
