4.6 Polymorphism: Overloading vs Overriding & Upcasting

1. Definition

Polymorphism lets one method call behave differently by signature at compile time (Overloading) or by the actual Heap object type at runtime (Overriding + Upcasting).

2. Memory hook

Overloading = Same class, different params (Compile time); Overriding = Parent/Child, same signature (Runtime).

  • Upcasting runs framework magic: WebDriver driver = new ChromeDriver(); lets the entire test suite work against Chrome, Firefox, or Edge identically.
  • static and private methods NEVER override: they hide or stay local, resolved from reference type at compile time.
  • Always add @Override: lets javac catch typos in overridden method names immediately.

3. Compile-Time Overloading vs Runtime Dynamic Dispatch

Two Kinds of Polymorphism
Reference type decides WHAT methods you are allowed to call; Heap object decides WHICH override runs.
Overloading (Compile Time)driver.switchTo().frame(0)
driver.switchTo().frame("auth")
driver.switchTo().frame(webEl)
Overriding + Upcasting (Runtime)Reference: WebDriver d
Heap object: new ChromeDriver()
d.get(...) runs ChromeDriver's code!

4. Method Overloading vs Method Overriding

RuleOverloadingOverriding
Where?Same class (or subclass adds overload)Subclass rewriting Parent's method
ParametersMUST differ (count, type, or order)MUST match identically
Return typeCan differ ONLY if parameters differSame type or narrower Covariant subtype
VisibilityAny modifierCannot narrow visibility (e.g., public -> protected illegal)
Resolved when?Compile time (by reference + args)Runtime (by actual Heap object)

5. Code example: upcasting WebDriver interface & overloading helpers

interface MiniDriver {
    void open(String url);                    // contract method
}

class MiniChrome implements MiniDriver {
    @Override public void open(String url) { System.out.println("Chrome opening " + url); }
}

public class PolyDemo {
    static void waitAndClick(String locator) { waitAndClick(locator, 10); } // overload 1
    static void waitAndClick(String locator, int sec) {                     // overload 2
        System.out.println("Clicking " + locator + " wait=" + sec + "s");
    }

    public static void main(String[] args) {
        MiniDriver d = new MiniChrome();      // Upcasting: interface ref -> Chrome object
        d.open("https://www.selenium.dev/");  // Runtime dispatch picks MiniChrome.open()
        waitAndClick("#submit");              // Compile time picks overload 1 -> overload 2
    }
}

6. Execution flow, step by step

  1. Writing two waitAndClick methods with different parameters gives convenient default timeout overloading.
  2. javac resolves waitAndClick("#submit") to overload 1 before the program even runs.
  3. MiniDriver d = new MiniChrome(); stores a MiniChrome Heap instance in a MiniDriver interface variable (upcasting).
  4. At runtime, d.open(...) checks the real Heap object (MiniChrome) and dispatches dynamically to Chrome's version.
  5. Switching new MiniChrome() to new MiniFirefox() needs zero edits across any test calling d.open(...).

8. Why it matters

Polymorphism decouples caller code from concrete driver implementations so new browsers or adapters plug in without touching tests.

SDET link: WebDriver driver = new ChromeDriver(); is textbook upcasting + runtime polymorphism, while driver.switchTo().frame(int), frame(String), and frame(WebElement) (plus Actions.click() vs click(el)) are textbook overloading.

9. Quick test

What happens if a Parent static method static void run() is re-written in Child and called via Parent p = new Child(); p.run();? Parent's version runs (Method Hiding), NOT overriding, because static binds at compile time.

10. Mini glossary

TermPlain meaning
OverloadingMultiple methods sharing a name with different parameter lists
OverridingSubclass redefining an inherited parent method with identical signature
UpcastingStoring a subclass/implementation object in a parent/interface reference
Dynamic dispatchJVM choosing the overridden method at runtime based on the Heap object
Covariant returnOverriding method returning a subtype of the parent method's return type
