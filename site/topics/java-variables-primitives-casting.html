2.2 Variables, Primitive vs Reference Types & Type Casting

The 8 primitive types, Local vs Instance vs Static variable rules, reference types, and safe widening vs narrowing type conversions.

Java is a statically typed language where every variable must declare a type before use—either one of the 8 built-in primitive types holding a raw binary value or a reference type holding a pointer to a Heap object. Variable scope, default initialization, and memory location depend directly on whether the variable is declared locally inside a method, per instance on a class, or with static.

Before you start

Prerequisite: 2.1 Program Structure & main() Method Decoded

Where it fits

Test automation code relies on primitives for timeouts, counters, and boolean flags (int timeout = 10; boolean displayed;), reference variables for WebDriver and WebElement, and type casting when converting numeric UI text or downcasting driver capabilities.

Key points

  1. Java has exactly 8 primitive types: 4 integer types (byte 1B, short 2B, int 4B, long 8B), 2 floating-point types (float 4B, double 8B), 1 character type (char 2B UTF-16), and 1 boolean type (boolean).
  2. Local variables declared inside methods or blocks live on the Stack and receive no default value; reading an uninitialized local variable fails compilation immediately.
  3. Instance fields (without static) live on the Heap inside each object and receive automatic defaults (0, 0.0, '\u0000', false, or null for references); static fields are shared one copy per class.
  4. Widening casting (byte -> short -> int -> long -> float -> double) happens implicitly with zero syntax because the target range holds larger values.
  5. Narrowing casting (double -> float -> long -> int -> short -> byte) requires an explicit cast like (int) price and silently truncates decimals or overflows out-of-range bits.
  6. Every whole-number literal defaults to int (append L for long like 5000L) and every decimal literal defaults to double (append f for float like 9.99f).

How it works

  1. The JVM allocates Stack slots for local primitives when a method frame enters, requiring explicit assignment before first read.
  2. When new Object() creates an instance, the JVM zeroes all Heap instance fields to type defaults before running constructors.
  3. Assigning a smaller primitive type to a larger one (int count = 5; long ms = count;) widens automatically.
  4. Converting a wider type downward (double total = 49.99; int whole = (int) total;) forces an explicit cast and drops the fractional .99 cleanly to 49.

Comparing local vs instance vs static variables, primitive defaults, and widening vs narrowing casts:

package dev.java.core; // Declares package

public class VariablesAndCasting { // Declares demonstration class
    static int maxRetries = 3; // Static variable: single shared copy across all instances
    boolean pageReady; // Instance field: defaults to false automatically on Heap
    String baseUrl; // Reference field: defaults to null automatically on Heap

    public static void main(String[] args) { // Main Stack frame begins
        int waitSec = 10; // Local primitive: must be assigned before reading
        long waitMillis = waitSec * 1000L; // Widening int to long using L suffix
        double rawPrice = 199.95; // Decimal literal defaults to 64-bit double
        int truncatedPrice = (int) rawPrice; // Narrowing cast drops .95 leaving 199
        float taxRate = 0.18f; // Float literal requires explicit f suffix
        VariablesAndCasting run = new VariablesAndCasting(); // Object fields zero-initialized
        System.out.println(run.pageReady + " | " + run.baseUrl + " | " + truncatedPrice + " | " + waitMillis + " | " + taxRate + " | " + maxRetries); // Prints: false | null | 199 | 10000 | 0.18 | 3
    } // Main Stack frame pops
} // Ends class

Common mistakes

  1. Writing float discount = 12.5; without the f suffix; decimal literals default to double, causing a 'possible lossy conversion from double to float' compile error.
  2. Assuming int price = (int) 199.95; rounds to 200; explicit narrowing casts truncate toward zero (199), so use Math.round() when rounding is intended.
  3. Reading a local variable declared inside an if branch without assigning a fallback value on all branches; the compiler rejects it as 'variable might not have been initialized'.
  4. Performing arithmetic like byte b = 10; b = b + 1; without casting; arithmetic on byte, short, and char promotes both operands automatically to int.

Interview questions

Basics

Name all 8 primitive data types in Java and their byte sizes.
The 4 signed integer types are byte (1 byte, -128 to 127), short (2 bytes), int (4 bytes), and long (8 bytes). The 2 IEEE 754 floating-point types are float (4 bytes) and double (8 bytes). The remaining 2 types are char (2-byte unsigned UTF-16 character, 0 to 65,535) and boolean (logical true or false).

What are the key differences between primitive types and reference types?
A primitive variable stores its exact binary value directly in its variable slot (on the Stack if local, or inline inside an object on the Heap) and can never be null. A reference variable stores a memory address pointing to an object on the Heap, defaults to null when declared as a field, and supports calling methods using the dot operator.

Which variable kinds receive default values from the JVM?
Instance fields and static class fields always receive automatic default values when allocated: 0 for integer types, 0.0 for floating-point types, '\u0000' for char, false for boolean, and null for references. Local variables inside methods never receive default values and fail to compile if read prior to explicit assignment.

How it works

Why does byte a = 50; byte b = a + 1; fail to compile?
Java automatically applies binary numeric promotion to any arithmetic operation involving byte, short, or char, widening both operands to int before computing the result. Because a + 1 produces an int expression, assigning it back into a byte without an explicit cast (byte) (a + 1) fails compilation. Using compound assignment a += 1; compiles because compound operators insert an implicit narrowing cast.

What happens internally during a narrowing cast like int n = (int) 130L; or byte b = (byte) 130;?
During a narrowing primitive cast, the JVM keeps only the lower-order bits that fit in the target bit width and discards the higher-order bits. Casting 130 (binary 10000010 in 8 bits) to a signed byte interprets the leading 1 as a two's-complement negative sign bit, silently wrapping around to -126 without throwing any exception. Casting a double to int drops the fractional part toward zero.

Why can a long (8 bytes) widen implicitly to a float (4 bytes)?
Although float uses only 4 bytes of memory compared to 8 bytes for long, IEEE 754 floating-point encoding uses an exponent field that represents magnitudes up to roughly 3.4e38, far wider than long's maximum of ~9.2e18. Therefore Java classifies long -> float as a widening conversion, even though very large long values lose lower-digit precision.

Real situations

In a Selenium e-commerce test on QKart, why should currency and price calculations avoid float or double?
Binary floating-point types (float and double) cannot represent base-10 decimals like 0.1 or 0.2 exactly, causing assertions like 19.99 + 0.01 or tax sums to evaluate to 19.999999999999996. When asserting cart totals against expected prices, use java.math.BigDecimal constructed from String values (new BigDecimal("19.99")) or integer cents (long) to guarantee exact decimal equality.

Why does declaring WebDriver driver; locally inside @BeforeMethod fail to initialize the class field?
Writing WebDriver driver = new ChromeDriver(); inside @BeforeMethod declares a brand-new local variable that shadows the class-level instance field driver. Once @BeforeMethod finishes, the local variable disappears off the Stack while the instance field this.driver remains null. Then the @Test method throws NullPointerException on driver.get().

When a Selenium test calls ((TakesScreenshot) driver).getScreenshotAs(...), is that widening or narrowing reference casting?
That is a narrowing reference downcast from the super-interface WebDriver to the sibling capability interface TakesScreenshot implemented by RemoteWebDriver. Because the compiler only sees the declared type WebDriver, it requires the explicit cast and checks at runtime whether the underlying Heap object actually implements TakesScreenshot.

Troubleshooting

How do you fix 'variable timeout might not have been initialized' when compiling a helper method?
Locate the local variable inside the method and trace all conditional branches (if, else, try-catch). If any execution path skips assigning a value before the variable is read, initialize the local variable at declaration (for example, int timeout = 10;) or ensure every if-else branch assigns it.

Why does int big = 1000000 * 10000; produce a negative number instead of 10,000,000,000?
Both literals are int values, so Java computes the multiplication in 32-bit signed int arithmetic first, overflowing past Integer.MAX_VALUE (2,147,483,647) before assignment even if stored in a long. Adding the L suffix to at least one operand (1000000L * 10000) promotes the calculation to 64-bit long.

What causes double rate = 5 / 2; to evaluate to 2.0 instead of 2.5?
Dividing two int literals performs integer division first, truncating 2.5 to 2 before widening to 2.0. Making at least one operand a double literal (5.0 / 2 or (double) 5 / 2) performs floating-point division and produces 2.5.

Design choices

Why did Java keep 8 primitive types instead of making every number an object?
Wrapping every loop counter and array index in a Heap object adds object header memory overhead and pointer dereferencing on every read. Keeping 8 stack-allocatable primitive types allows the JVM to store values compactly in CPU registers and Stack frames, matching native C-like numerical speed.

Why does Java forbid silent narrowing conversions like assigning a double to an int?
Silent narrowing would hide accidental truncation bugs where decimals or upper bits vanish unnoticed during refactoring. Requiring an explicit cast forces the programmer to acknowledge potential precision loss directly at the call site.

Why should framework configuration constants like default timeouts be declared public static final rather than plain static?
Mutable static variables allow any test method to overwrite global settings mid-run, creating order-dependent flakiness across tests. Adding final locks the constant value once at class initialization so no test can mutate shared timeouts.

Quick answers

  1. How many primitive types exist in Java? Exactly 8: byte, short, int, long, float, double, char, boolean.
  2. What is the default value of a local variable? None; local variables are not default-initialized and cause a compile error if read before assignment.
  3. What is the default value of an uninitialized boolean instance field? false.
  4. Which suffix is required for a long literal? L (uppercase preferred, e.g., 30000L).
  5. What is the result of (int) 9.99? 9 (truncates toward zero, never rounds).
  6. Why should financial cart prices avoid double? IEEE 754 binary floating-point introduces decimal rounding drift; use BigDecimal instead.
