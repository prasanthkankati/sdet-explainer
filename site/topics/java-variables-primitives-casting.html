2.2 Variables, Primitive vs Reference Types & Type Casting

1. What a Variable Is

A variable is a named storage location in memory that holds a value, whose declared data type fixes what values it can store, how much memory it occupies, and which operations the compiler permits before the program runs.

A variable acts as a typed container on the JVM Stack or inside a Heap object. Because Java is a statically typed language, the javac compiler verifies every variable's type before the program executes—catching invalid assignments and incompatible conversions at compile time.

2. Basic Syntax, Word-by-Word Explanation & Naming Rules

The basic syntax is:

dataType variableName = value;

For example:

int retryCount = 3;
  • dataType (int): Tells the compiler the category of data and exact memory size (32-bit signed integer) to allocate.
  • variableName (retryCount): The identifier used to read or update that memory slot in code.
  • = (assignment operator): Copies the right-hand value into the left-hand variable (distinct from equality ==).
  • value (3): The literal, expression result, or Heap object reference stored inside the variable.
  • ; (semicolon): Terminates the statement for the compiler.

Identifier & naming rules:

  • Must begin with a letter (a–z, A–Z), dollar sign ($), or underscore (_) — never a digit (int 1retry = 3; fails to compile).
  • Cannot use a Java reserved keyword (int, class, static, boolean, null, true, false).
  • Case-sensitive (retryCount and retrycount are two separate variables); Java convention uses camelCase for variables and UPPER_SNAKE_CASE for final constants.

3. Declaration, Initialization, and Assignment

These three terms describe distinct steps in a variable's lifecycle and are frequently tested together:

  • Declaration reserves a variable name and type: int count;
  • Initialization gives the variable its very first value: count = 0; or combined on one line as int count = 0;
  • Assignment replaces the value of an already-initialized variable: count = count + 1;
int count;                  // 1. Declaration only (type and name reserved)
count = 0;                  // 2. Initialization (first value assigned)
count = count + 1;          // 3. Re-assignment (replaces 0 with 1)

int x = 10, y = 20, z;      // Declare multiple variables of the same type on one line (z is uninitialized)

final int MAX_RETRIES = 3;  // Constant variable: initialized once; MAX_RETRIES = 4 causes a compile error

4. Types of Variables by Scope (3 Categories)

Java classifies every variable into one of 3 scope types based on where it is declared:

  1. Local Variables (declared inside a method, constructor, or block)
  2. Instance Variables (non-static fields declared inside a class, one copy per object)
  3. Static Variables (class-level static fields, one shared copy per class)
Three Variable Scopes & Memory Locations
1. Local VariableStack frame; NO default value (must initialize before reading)
2. Instance VariableHeap object; defaults to 0 / 0.0 / false / \u0000 / null
3. Static VariableClass memory; one shared copy across all instances

4.1 Local Variables

Declared inside a method, constructor, or {} block. They live on the calling thread's Stack frame, are destroyed as soon as the block finishes, and receive NO default value. Reading an uninitialized local variable fails at compile time:

public void verifyLogin() {
    int attempts = 0;       // Initialized local variable on the Stack
    int uninitialized;      // Declared, but no value assigned yet
    // System.out.println(uninitialized); // COMPILE ERROR: variable uninitialized might not have been initialized
}

4.2 Instance Variables (Non-Static Fields)

Declared inside a class body (outside any method) without the static keyword. Allocated inside each Heap object when new runs, destroyed when the object is garbage-collected, and automatically initialized to default values:

public class LoginPage {
    String pageUrl;         // Instance field: defaults to null
    int maxWaitSeconds;     // Instance field: defaults to 0
    boolean isLoaded;       // Instance field: defaults to false
}

4.3 Static Variables (Class Fields)

Declared inside a class body with the static keyword. Only one shared copy exists for the entire class regardless of how many objects are created, initialized once when the class loads with the same default values as instance fields:

public class TestRunner {
    static int totalExecutedTests; // Default = 0, shared by all TestRunner instances
    public static final String DEFAULT_BROWSER = "chrome"; // Compile-time class constant
}

5. Types of Data in Java (2 Categories)

Every variable in Java has either a Primitive Type or a Reference Type:

  1. Primitive Data Types (8 built-in raw value types): byte, short, int, long, float, double, char, boolean
  2. Reference Data Types (Heap object pointers): Classes (String), Interfaces (WebDriver), and Arrays (int[], Object[][])

5.1 Primitive Data Types (All 8 Types Detailed)

Primitive variables store the actual binary value directly inside the variable slot. They are never null and have no methods:

5.2 Reference Data Types

Reference variables store a memory address (reference) pointing to an object in the Heap, or null when pointing to no object:

String env = "staging";                // Reference pointing to a String object on the Heap
int[] statusCodes = { 200, 201, 404 }; // Arrays are Heap objects even when holding primitives
WebDriver driver = new ChromeDriver(); // Interface reference pointing to a ChromeDriver Heap instance
String missing = null;                 // Holds no address; calling missing.length() throws NullPointerException

6. Must-Know Concept: Type Casting in Complete Detail

Type casting converts a value from one data type to another. Java has two broad categories:

  • Primitive casting: converting between numeric types (and char). boolean cannot be cast to or from any other primitive type.
  • Reference casting: converting between class or interface types in an inheritance hierarchy (upcasting and downcasting).
Primitive Widening Chain & Reference Casting
Widening (Implicit): byte -> short -> int -> long -> float -> double  |  char -> int -> long -> float -> double
Primitive Narrowing (Explicit)int i = (int) 9.99; (truncates toward zero)
Reference Upcast (Implicit)WebDriver d = new ChromeDriver();
Reference Downcast (Explicit)TakesScreenshot ts = (TakesScreenshot) d;

6.1 Primitive Widening (Implicit)

A smaller type converts to a larger one automatically with no explicit cast:

byte b = 10;
short s = b;     // byte -> short
int i = s;       // short -> int
long l = i;      // int -> long
float f = l;     // long -> float (may lose precision for very large 64-bit values)
double d = f;    // float -> double

The widening order is byte -> short -> int -> long -> float -> double, and char -> int -> long -> float -> double. Note that byte and short do not widen to char (because char is unsigned), and char cannot widen to short or byte.

6.2 Primitive Narrowing (Explicit Cast)

A larger type converts to a smaller one only with an explicit (type) cast in parentheses. The value may lose its fractional part or wrap around:

double d = 9.99;
int i = (int) d;        // 9: the fractional part is truncated

long big = 130L;
byte b = (byte) big;    // -126: 130 wraps into the signed byte range (-128..127)
byte over = (byte) 300; // 44: keeps lowest 8 bits (300 - 256)

int n = 65;
char c = (char) n;      // 'A'

Truncation rounds toward zero, not down toward negative infinity:

int a = (int) -9.99;    // -9 (not -10)

6.3 Casting to char and from char

char is an unsigned 16-bit type (0..65535), so casting a negative int to char wraps into a large positive Unicode value, and converting between char and short always requires an explicit cast:

char c = 'A';
int code = c;                // 65 (implicit widening char -> int)
char next = (char) (c + 1);  // 'B' (c + 1 promotes to int, requires explicit cast)
short s = (short) c;         // 65 (explicit cast required: char -> short)

6.4 Casting to and from boolean

boolean cannot be cast to any numeric type, and no numeric type can be cast to boolean:

boolean flag = true;
// int x = (int) flag;       // compile error
// boolean f = (boolean) 1;  // compile error

6.5 Casting in Arithmetic (Numeric Promotion)

Binary arithmetic operators (+, -, *, /, %) promote operands before the operation runs, so the result type is always at least int:

byte a = 10, b = 20;
// byte sum = a + b;         // compile error: a + b is promoted to int
byte sum = (byte) (a + b);   // explicit cast needed: 30

int x = 5 / 2;               // 2: integer division truncates .5
double y = 5 / 2;            // 2.0: division happens in int first, then widens to double
double z = 5 / 2.0;          // 2.5: one double operand promotes the whole expression
  • Operands smaller than int (byte, short, char) are always promoted to int.
  • If either operand is double, the result is double; otherwise float, then long, then int.

6.6 Compound Assignment Casts (+=, -=, *=, /=)

Compound assignment operators perform an implicit narrowing cast automatically:

byte b = 10;
b += 5;        // compiles: equivalent to b = (byte) (b + 5)
// b = b + 5;  // compile error: b + 5 is int

short s = 100;
s *= 1000;     // silently overflows 16-bit short without compile error

6.7 Constant Expressions and Literal Narrowing

The compiler allows narrowing without an explicit cast when the right-hand side is a compile-time constant expression whose value fits the target byte, short, or char range:

byte b = 100;          // OK: constant 100 fits in byte (-128..127)
char c = 65;           // OK: constant 65 fits in char
short s = 'A';         // OK: constant 'A' (65) fits in short
// byte bad = 200;     // compile error: 200 exceeds byte range

int value = 100;
// byte b2 = value;    // compile error: non-constant variable requires (byte) value

6.8 Reference Casting: Upcasting, Downcasting, instanceof & null

Reference casting changes how the compiler views an object; it never alters the underlying Heap object itself.

class Animal { void speak() { System.out.println("..."); } }
class Dog extends Animal { void fetch() { System.out.println("fetching"); } }

// 1. Upcasting (implicit and always safe)
Animal a = new Dog();        // upcast, implicit (like WebDriver d = new ChromeDriver())
a.speak();                   // OK
// a.fetch();                // compile error: Animal reference has no fetch() method

// 2. Downcasting (explicit and checked at runtime)
Dog d = (Dog) a;             // OK: underlying Heap object really is a Dog
d.fetch();

Animal plain = new Animal();
Dog wrong = (Dog) plain;     // compiles, but throws ClassCastException at runtime!

// 3. The instanceof check (Classic & Java 16+ pattern variable)
if (a instanceof Dog) {
    Dog safe = (Dog) a;
    safe.fetch();
}
if (a instanceof Dog dogPattern) { // Java 16+ combines check and cast
    dogPattern.fetch();
}

// 4. Unrelated types & casting null
String s = "hello";
// Integer i = (Integer) s;  // compile error: incompatible unrelated types
Object o = (String) null;    // OK: casting null to any reference type succeeds as null

SDET link: In Selenium, WebDriver driver = new ChromeDriver(); is an implicit upcast, while ((TakesScreenshot) driver).getScreenshotAs(...) and ((JavascriptExecutor) driver).executeScript(...) are explicit interface downcasts verified at runtime.

6.9 Wrapper Casting & Generics Type Erasure

You cannot cast one wrapper class directly to a sibling wrapper class or unrelated primitive; convert through wrapper methods or unboxing instead. With Generics, type parameters are erased at runtime, so raw-type casts emit an unchecked warning and fail when reading elements:

Object o = 42;             // autoboxed to Integer
int n = (Integer) o;       // cast Object to Integer wrapper, then unbox to int

Integer i = 42;
// long l = (long) i;      // compile error: Integer cannot be cast directly to long
long l = i.longValue();    // correct: convert through Number method

List raw = new ArrayList();
raw.add("text");
List<Integer> nums = raw;  // unchecked warning at compile time, no immediate error
Integer val = nums.get(0); // throws ClassCastException at runtime!

7. Summary & Mini Glossary

  • Variables: Local variables live on the Stack with no default value; Instance and Static fields receive default values.
  • Widening vs Narrowing: Widening conversions are implicit and safe; narrowing requires an explicit (type) cast and may truncate or wrap data.
  • Promotion & Compound Casts: Arithmetic promotes byte/short/char to int; compound assignments (+=) and fitting compile-time constants narrow implicitly.
  • Reference & Wrapper Casts: Reference downcasting is checked at runtime (ClassCastException) and should be guarded with instanceof; sibling wrappers convert via methods like .longValue().

8. Q&A

InterviewJ2.2 Question Bank (35 Questions) →

  • Q: What is the output of (int) 3.99 and (int) -3.99?
    3 and -3. Floating-point to integer narrowing truncates toward zero.
  • Q: Why does byte c = a + b; fail to compile when a and b are byte?
    Binary arithmetic promotes byte operands to int, so an explicit cast (byte) (a + b) is required.
  • Q: Does b += 5 compile when b is a byte?
    Yes. Compound assignment includes an implicit narrowing cast equivalent to b = (byte) (b + 5).
  • Q: What is the output of (byte) 128?
    -128. Value 128 overflows the signed 8-bit max (127) and wraps around.
  • Q: What is the output of (char) 97 and int x = 'A' + 2;?
    'a' and 67. Character arithmetic promotes 'A' (65) to int.
  • Q: Why does float f = 1.0; fail to compile?
    1.0 is a double literal; narrowing to float requires 1.0f or (float) 1.0.
  • Q: Can boolean be cast to int?
    No. boolean cannot be cast to or from any other type.
  • Q: What exception occurs for an invalid downcast, and how do you avoid it?
    ClassCastException at runtime. Guard with instanceof before downcasting.
  • Q: Is upcasting checked at runtime?
    No. Converting a subclass reference to its supertype is verified at compile time and is always safe.
  • Q: Does (String) null throw an exception?
    No. null can be cast to any reference type and evaluates to null.
