Interview

M3.1 Question Bank: Equivalence Partitioning (EP) & Boundary Value Analysis (BVA) (35 Questions)

Tier 1: Core Definitions, Formulas & Classification (Q1–Q10)

  1. Q1: Under which category of test design techniques do Equivalence Partitioning (EP) and Boundary Value Analysis (BVA) fall?
    A: They fall under **Black-Box (Specification-Based / Behavioral) Test Design Techniques** because test cases are derived directly from requirement specifications without inspecting internal code structure.
  2. Q2: What is Equivalence Partitioning (EP / ECP)?
    A: Equivalence Partitioning divides the input domain into valid and invalid classes (partitions) where every value inside a class is expected to be treated identically by the system, allowing QA to test just **1 representative value per partition**.
  3. Q3: What is Boundary Value Analysis (BVA)?
    A: Boundary Value Analysis is a black-box technique that tests the **exact edges (boundaries)** of equivalence partitions (`min-1, min, min+1` and `max-1, max, max+1`) because defects cluster heavily at range boundaries.
  4. Q4: What is the difference between 2-Value BVA and 3-Value BVA?
    A: **2-Value BVA** tests 2 points per boundary (`min-1, min` and `max, max+1` = **4 values** per range). **3-Value BVA** tests 3 points per boundary (`min-1, min, min+1` and `max-1, max, max+1` = **6 values** per range).
  5. Q5: Which ISTQB Testing Principle directly justifies why we use EP and BVA?
    A: **Principle #2: Exhaustive testing is impossible.** EP and BVA mathematically reduce thousands of redundant inputs down to 6–9 high-yield test cases.
  6. Q6: Why do bugs occur so frequently at boundaries in Java/TypeScript code?
    A: Because developers frequently make **off-by-one errors** in conditional operators—writing `<` instead of `<=`, `>` instead of `>=`, or starting array/loop indices at `1` instead of `0`.
  7. Q7: For an input field accepting integers from `1` to `100`, list the exact EP partitions and 3-Value BVA test inputs.
    A: **EP Partitions:** Invalid Low (`<= 0`, e.g., `-5`), Valid (`1..100`, e.g., `50`), Invalid High (`>= 101`, e.g., `150`). **3-Value BVA Inputs:** `{0, 1, 2, 99, 100, 101}`.
  8. Q8: Can BVA be used without first identifying Equivalence Partitions?
    A: No—boundaries are literally the **dividing lines between Equivalence Partitions**. You always identify the valid/invalid partitions first (even mentally) and then take their boundary edges.
  9. Q9: What are Invalid Equivalence Partitions beyond numeric `< min` and `> max`?
    A: Non-numeric/format partitions: **Empty/Blank (`""`)**, **Alphabetic (`"abc"`)**, **Special Characters (`"@#$"`)**, **Decimal/Float (`18.5` when integer required)**, and **Null/Whitespace (`" "`)**.
  10. Q10: What is Weak vs Robust Boundary Value Analysis?
    A: Standard BVA tests `{min-1, min, min+1, max-1, max, max+1}`. In multi-variable forms, **Single-Fault (Normal) BVA** holds all other variables at their nominal middle value while varying one variable at its boundary; **Robust/Worst-Case BVA** tests combinations where multiple variables hit extreme boundaries simultaneously.

Tier 2: Why / Why Not & Deep Comparisons (Q11–Q18)

  1. Q11: Why is 2-Value BVA (`min-1, min, max, max+1`) sometimes insufficient compared to 3-Value BVA?
    A: Suppose a developer accidentally wrote `if (age == 18 || age == 60)` instead of `if (age >= 18 && age <= 60)`. 2-Value BVA tests `{17, 18, 60, 61}`—all 4 pass! Only 3-Value BVA (`19` and `59`) or a middle EP value (`35`) exposes that all interior values fail.
  2. Q12: Why can't BVA be applied to a "Country" dropdown or "Gender" radio button?
    A: Because BVA requires an **ordered scale** (numbers, dates, times, string lengths, file sizes) where `min - 1` and `max + 1` exist. Unordered discrete sets (`{India, USA, Japan}`) have no boundary edges, so only **Equivalence Partitioning** applies.
  3. Q13: If BVA catches boundary bugs, why do we still need Equivalence Partitioning (EP)?
    A: (1) EP covers unordered discrete sets where BVA cannot be used, (2) EP tests invalid data types (`"abc"`, `"@!"`, `null`), and (3) when multiple contiguous tax/discount slabs exist, EP verifies the formula inside each slab.
  4. Q14: When a requirement has multiple contiguous slabs (e.g., Tax Slabs), how do you apply EP and BVA?
    A: Treat **every slab as its own Valid Partition** and calculate BVA at **every transition point** between slabs, plus below the lowest slab and above the highest slab.
  5. Q15: What is Output Equivalence Partitioning (Output-Domain EP)?
    A: Designing test inputs based on the **distinct output classes** the system can produce. For example, if a credit score engine outputs `REJECTED`, `SILVER_CARD`, or `PLATINUM_CARD`, you select input combinations that force the system to generate each of the 3 output classes.
  6. Q16: How do EP and BVA apply to String Length validation (e.g., Username must be 6 to 12 characters)?
    A: The ordered metric is `str.length()`. **EP:** length `3` (invalid short), length `9` (valid), length `15` (invalid long). **3-Value BVA:** strings of exact lengths **`{5, 6, 7, 11, 12, 13}`** plus `0` (empty string).
  7. Q17: How do EP and BVA apply to File Upload features (e.g., "Upload PDF/PNG up to 5 MB")?
    A: **File Format (EP):** `.pdf` (Valid), `.png` (Valid), `.exe` (Invalid), `.txt` (Invalid). **File Size (BVA around 5 MB = 5,242,880 bytes):** `0 bytes` (empty file), `1 byte`, `4.99 MB`, `5.00 MB` (exact max), and `5.01 MB` (max + 1).
  8. Q18: How do EP and BVA apply to Date/Time ranges (e.g., "Promo code valid from Jan 1, 2026 00:00:00 to Jan 31, 2026 23:59:59")?
    A: Test timestamps at exact 1-second boundaries: `Dec 31, 2025 23:59:59` (`min-1`), `Jan 1, 2026 00:00:00` (`min`), `Jan 31, 2026 23:59:59` (`max`), and `Feb 1, 2026 00:00:00` (`max+1`).

Tier 3: Real-World Tricky & Calculation Scenarios (Q19–Q25)

  1. Q19: Scenario (Classic Interview Calculation): An e-commerce cart gives: 0% discount for orders `$1–$99`, 10% discount for `$100–$499`, and 20% discount for `$500–$1000`. Orders `< $1` or `> $1000` are rejected. List all EP partitions and 2-Value BVA test points (assuming whole dollars).
    A:
    • **5 EP Partitions:** Invalid Low (`<= $0`, pick `$0`), Valid Slab 1 (`$1–$99`, pick `$50`), Valid Slab 2 (`$100–$499`, pick `$250`), Valid Slab 3 (`$500–$1000`, pick `$750`), Invalid High (`>= $1001`, pick `$1200`).
    • **BVA Cut-Points:** At `$1` (`$0, $1`), at `$99/$100` (`$99, $100`), at `$499/$500` (`$499, $500`), and at `$1000` (`$1000, $1001`) → **`{ 0, 1, 99, 100, 499, 500, 1000, 1001 }`**.
  2. Q20: Scenario: In Q19 above, what changes if the cart accepts cents (2 decimal places, e.g., `$99.99`) instead of whole dollars?
    A: The smallest unit increment ($\Delta$) is now **`0.01`**, NOT `1`! Therefore, `min - 1` at the `$100.00` boundary is **`$99.99`** (NOT `$99.00`), and `max + 1` at `$1000.00` is **`$1000.01`**! Interviewers love testing whether you adjust BVA step size to the field's precision (`0.01`).
  3. Q21: Scenario: A bank OTP field accepts a 6-digit numeric PIN (`000000` to `999999`). Why is testing `0` and `999999` as integers not enough in UI/API testing?
    A: Because a 6-digit OTP is a **fixed-length numeric string**, not an arithmetic integer! If the backend parses it as an `int`, an OTP starting with a leading zero (`"045821"`) gets truncated to `45821` (5 digits) and fails validation! Always test leading-zero boundaries (`"000000"`, `"012345"`) alongside length boundaries (`5 digits`, `6 digits`, `7 digits`).
  4. Q22: Scenario: Frontend HTML has `` which blocks typing `17` or `61` in the browser. Does that mean BVA is done?
    A: **Never!** Client-side HTML attributes (`min`, `max`, `maxlength`) can be bypassed in 2 seconds via Chrome DevTools or by calling the REST API directly via Postman/RestAssured. SDETs must execute BVA (`17` and `61`) directly against the **Backend REST API** (`POST /api/loan`) to verify server-side validation returns `400 Bad Request`.
  5. Q23: Scenario: An API pagination endpoint accepts `pageSize` (min `1`, max `100`, default `20`). What BVA inputs do you test in RestAssured?
    A: Test `pageSize` = `-1`, `0` (`min-1`), `1` (`min`), `2` (`min+1`), `99` (`max-1`), `100` (`max`), `101` (`max+1`), plus omitted parameter (verifying default `20`), `Integer.MAX_VALUE` (`2147483647`), and `"abc"`.
  6. Q24: Scenario: You test `max = 100` items in a shopping cart and it passes. What hidden boundary exists in Java backend code when multiplying `quantity * unitPrice`?
    A: **Data Type Overflow Boundary (`Integer.MAX_VALUE = 2,147,483,647`)** or floating-point precision boundary (`double` vs `BigDecimal`). Always check system-level data type boundaries alongside business boundaries.
  7. Q25: Scenario: A requirement says "Users can book up to 4 tickets per transaction." It does not mention the minimum. What are the implicit boundaries you must test?
    A: The implicit minimum for purchasing tickets is **`1`**. Therefore, the valid partition is `1..4`, and the BVA test set is **`{ -1, 0, 1, 2, 3, 4, 5 }`**.

Tier 4: SDET, Automation (Selenium / TestNG / RestAssured) Application (Q26–Q30)

  1. Q26: How do you implement EP and BVA cleanly in a Selenium + TestNG framework without writing 10 separate `@Test` methods?
    A: Write **1 parameterized `@Test(dataProvider = "bvaData")` method** and supply the EP + BVA matrix (`{input, expectedResult, expectedErrorMsg}`) via a `@DataProvider` method or an external JSON/Excel file.
  2. Q27: When automating UI tests with Selenium vs API tests with RestAssured, where should the bulk of EP and BVA permutations run?
    A: Run **all 10–15 EP/BVA boundary permutations at the Unit & RestAssured API level** (where 15 calls finish in `300 milliseconds`), and run only **2–3 representative valid/invalid checks in Selenium UI** to verify the UI error banner renders properly.
  3. Q28: How do you test the `5.01 MB` (`max + 1`) file upload boundary in Selenium without storing giant binary files in your Git repository?
    A: Generate a temporary file of exact byte length dynamically in Java before the test using `RandomAccessFile f = new RandomAccessFile(tempFile, "rw"); f.setLength(5 * 1024 * 1024 + 1);` and pass `tempFile.getAbsolutePath()` to `fileInput.sendKeys()`, deleting it in `@AfterMethod`.
  4. Q29: In TestNG, if row 3 of a 10-row BVA `@DataProvider` fails, do rows 4–10 still execute?
    A: **Yes!** Each row of a TestNG `@DataProvider` executes as an independent test invocation, so a failure at `min` (`18`) will not block testing `max` (`60`).
  5. Q30: How do you verify multiple boundary assertions inside a single test run without aborting on the first failure?
    A: Use TestNG's **`SoftAssert`** (`SoftAssert soft = new SoftAssert(); soft.assertEquals(...); ... soft.assertAll();`) so all boundary failures are collected and reported together.

Tier 5: Rapid-Fire Yes/No & 1-Liner Traps (Q31–Q35)

  1. Q31: Are EP and BVA White-Box or Black-Box techniques?
    A: Black-Box techniques.
  2. Q32: How many test cases does 2-Value BVA vs 3-Value BVA generate for a single range `[min, max]`?
    A: 2-Value BVA = 4 test cases; 3-Value BVA = 6 test cases.
  3. Q33: For a range `10.0 to 20.0` with 1 decimal place precision, what is `min - 1` and `max + 1`?
    A: `min - 1` = `9.9`; `max + 1` = `20.1`.
  4. Q34: Which technique is best for testing a dropdown of 5 payment methods: EP or BVA?
    A: Equivalence Partitioning (EP).
  5. Q35: Does `0` count as a boundary value for positive quantity fields?
    A: Yes (`0` is `min - 1` when `min = 1`).
