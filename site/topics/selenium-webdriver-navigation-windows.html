5.1 Navigation & Windows Management

Controlling browser history (back, forward, refresh), switching tabs/windows, opening newWindow(WindowType), and managing viewport dimensions.

Selenium controls browser navigation through driver.navigate() (to, back, forward, refresh) and manages multiple tabs or windows using unique opaque string identifiers called window handles. Selenium 4 introduced driver.switchTo().newWindow(WindowType.TAB) and newWindow(WindowType.WINDOW) to create and switch into new tabs or windows in a single command.

Before you start

Prerequisite: 4.4 Element Interactions

Where it fits

Window and navigation APIs are used whenever a test verifies browser history buttons, multi-tab OAuth flows, or external target='_blank' links.

Key points

  1. driver.navigate().to(url) and driver.get(url) perform the exact same W3C navigation operation; navigate() also exposes back(), forward(), and refresh().
  2. driver.getWindowHandle() returns the unique String handle of the currently focused tab/window, while driver.getWindowHandles() returns a Set<String> of all open tabs/windows.
  3. Clicking a link that opens a new tab does not automatically switch WebDriver's focus; you must call driver.switchTo().window(handle) to interact with the new tab.
  4. In Selenium 4, driver.switchTo().newWindow(WindowType.TAB) opens a new tab and automatically switches focus to it.
  5. After closing a secondary tab with driver.close(), you must explicitly call driver.switchTo().window(originalHandle) before issuing further commands, or NoSuchWindowException is thrown.

How it works

  1. Store the parent tab's handle before opening a new tab: String originalTab = driver.getWindowHandle().
  2. Either click a link that opens a new tab (and iterate driver.getWindowHandles() to switch to the handle not equal to originalTab) or call driver.switchTo().newWindow(WindowType.TAB).
  3. Perform interactions and assertions inside the newly focused tab, then call driver.close() to close only that child tab.
  4. Call driver.switchTo().window(originalTab) to return WebDriver's focus back to the parent tab.

Opening a new tab with WindowType.TAB, closing it, and switching back:

package dev.selenium.interactions; // Declares package

import org.openqa.selenium.Dimension; // Imports Dimension for window size
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WindowType; // Imports Selenium 4 WindowType enum
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver

public class NavigationWindowsExample { // Declares class
    public static void main(String[] args) { // Main method
        WebDriver driver = new ChromeDriver(); // Starts Chrome session
        try { // Guarded block
            driver.manage().window().setSize(new Dimension(1280, 800)); // Sets window dimensions
            driver.get("https://www.selenium.dev/"); // Opens parent tab
            String parentHandle = driver.getWindowHandle(); // Saves parent window handle

            driver.switchTo().newWindow(WindowType.TAB); // Opens a new tab and switches focus to it
            driver.navigate().to("https://www.selenium.dev/documentation/"); // Navigates in new tab
            System.out.println("Child Tab: " + driver.getTitle()); // Prints child tab title

            driver.close(); // Closes only the child tab
            driver.switchTo().window(parentHandle); // Switches focus back to parent tab
            driver.navigate().refresh(); // Refreshes parent tab
        } finally { // Teardown block
            driver.quit(); // Closes all remaining windows and terminates driver
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Clicking a target='_blank' link and immediately calling findElement() for an element on the new tab without calling driver.switchTo().window(newHandle); fix by switching window handles first.
  2. Calling driver.close() on a child tab and forgetting to call driver.switchTo().window(parentHandle), which throws NoSuchWindowException on the next command; fix by always switching back to a valid handle.
  3. Relying on index order in driver.getWindowHandles() assuming it is sorted across all browsers; fix by filtering out known parent handles (!handle.equals(parentHandle)).

Interview questions

Basics

Is there any functional difference between driver.get(url) and driver.navigate().to(url)?
No. In Selenium's Java bindings, driver.navigate().to(url) simply calls driver.get(url) internally. The navigate() interface exists to group history actions like back(), forward(), and refresh().

What is the difference between getWindowHandle() and getWindowHandles()?
getWindowHandle() returns a single String representing the currently focused browser tab or window. getWindowHandles() returns a Set<String> containing the handles of all tabs and windows open in the current session.

How do you open a new tab and switch to it in Selenium 4?
Call driver.switchTo().newWindow(WindowType.TAB). It opens a new blank browser tab and automatically switches WebDriver's active context into that new tab.

How it works

Does WebDriver automatically switch focus when a test clicks a link that opens a new browser tab?
No. Even though the new tab appears in the foreground visually on screen, WebDriver's internal command context remains bound to the original tab until you explicitly call driver.switchTo().window(newTabHandle).

How do you wait for a second window or tab to finish opening after clicking a link?
Use an explicit wait: new WebDriverWait(driver, Duration.ofSeconds(10)).until(ExpectedConditions.numberOfWindowsToBe(2)), and then iterate through driver.getWindowHandles() to switch to the new handle.

What happens if you call driver.close() on a child tab and then immediately call driver.getTitle()?
Selenium throws NoSuchWindowException: target window already closed, because WebDriver's focus is still pointing to the closed child tab. You must call driver.switchTo().window(parentHandle) first.

Real situations

How do you test two different user roles (such as Admin and Customer) simultaneously in Selenium?
Note that two tabs opened inside the same ChromeDriver instance share cookies and session storage. To isolate cookies for two concurrent users, either instantiate two separate WebDriver instances or use WebDriver BiDi BrowsingContext user contexts.

How do you verify a responsive mobile layout on desktop Chrome without changing device emulation?
Use driver.manage().window().setSize(new Dimension(375, 812)) to resize the browser viewport to mobile dimensions and verify mobile menu visibility.

What happens to PageElement references when driver.navigate().refresh() is called?
Refreshing the page destroys and recreates the entire DOM tree. Any WebElement variable located before refresh() becomes invalid and throws StaleElementReferenceException if used afterward.

Troubleshooting

Why does driver.switchTo().window() sometimes fail to find the new tab right after element.click()?
Opening a new OS window or tab is asynchronous. If getWindowHandles() is called a few milliseconds before the browser registers the new tab, the Set still has size 1. Always wait with ExpectedConditions.numberOfWindowsToBe(2) first.

What causes NoSuchWindowException during a test run?
Either the test called driver.close() on the active tab without switching back to another open tab, or an application script called window.close() on a popup window while Selenium was still trying to interact with it.

Why does driver.manage().window().maximize() fail in headless Linux CI pipelines?
Headless environments often lack a desktop window manager to define screen dimensions. Pass --window-size=1920,1080 in ChromeOptions instead of calling maximize().

Design choices

Why does getWindowHandles() return a java.util.Set<String> instead of a List<String>?
Every window handle in a session is guaranteed to be unique, and the W3C specification does not mandate a strict chronological ordering across all browser engines, making Set the appropriate collection type.

When should you use WindowType.TAB versus WindowType.WINDOW?
Use WindowType.TAB for standard multi-tab workflows since it uses less OS window-management overhead. Use WindowType.WINDOW when testing multi-window positioning or side-by-side drag/drop.

Why should a multi-window helper method always record the initial handle before performing the click?
Storing String parent = driver.getWindowHandle() before the action provides a deterministic reference so the test can reliably close child popups and restore focus to the parent page.

Quick answers

  1. Are driver.get() and driver.navigate().to() identical? Yes, navigate().to() delegates directly to driver.get().
  2. What does getWindowHandles() return? A Set<String> of all open window/tab handles in the session.
  3. How do you open a new tab in Selenium 4? Call driver.switchTo().newWindow(WindowType.TAB).
  4. What must you do after calling driver.close() on a popup tab? Call driver.switchTo().window(parentHandle) to restore focus.
  5. Which ExpectedCondition waits for a new tab to open? ExpectedConditions.numberOfWindowsToBe(2).
