J5.1 Question Bank: Collections Hierarchy & Generics (Type Safety) (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. What is the difference between Collection and Collections in Java?
    java.util.Collection<E> is an interface extended by List, Set, and Queue that defines core container behaviors like add(), remove(), size(), and iterator(). java.util.Collections is a non-instantiable utility class containing static helper methods like sort(), reverse(), shuffle(), and unmodifiableList(). One is a data-structure contract; the other is an algorithm helper class.
  2. Draw the core Collections Framework hierarchy and explain why Map stands apart.
    Iterable<E> is implemented by Collection<E>, which splits into three main sub-interfaces: List<E> (ordered, duplicates allowed), Set<E> (unique elements), and Queue<E> (FIFO/priority processing). Map<K, V> sits in its own hierarchy because each entry pairs a key with a value rather than storing standalone single elements compatible with Collection.add(E).
  3. What are Generics in Java and what problem did Java 5 solve by adding them?
    Generics allow classes, interfaces, and methods to accept types as parameters—like List<WebElement> instead of untyped List. Before Java 5, a list accepted anything descending from Object, causing accidental insertions of wrong types to compile cleanly and fail later with ClassCastException during iteration. Generics catch type mismatches immediately during compilation.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. What is Type Erasure and how does it affect Java bytecode?
    During compilation, javac verifies all generic type constraints, inserts explicit casts wherever elements are read, and then strips the generic type parameters—replacing unbounded <T> with Object and bounded <T extends Number> with Number. Consequently, at runtime both ArrayList<String> and ArrayList<Integer> share the identical compiled ArrayList.class in Metaspace. This preserved backward compatibility with pre-Java 5 bytecode.
  2. Explain the PECS rule (? extends T vs ? super T) for generic wildcards.
    PECS stands for Producer Extends, Consumer Super. Use List<? extends Number> when reading values produced by a list (every read guarantees at least a Number, though adding elements is forbidden because the exact subtype could be Integer or Double). Use List<? super Integer> when writing Integer objects into a consumer list (it safely accepts List<Integer>, List<Number>, or List<Object>).
  3. Why does Java forbid creating generic arrays like new T[10] or new ArrayList<String>[5]?
    Arrays carry and enforce their exact component type at runtime (throwing ArrayStoreException on mismatch), whereas generic type arguments are erased at compile time. Mixing reified arrays with erased generics would allow type pollution that breaks array runtime guarantees.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. Why can you NOT pass a List<ChromeDriver> into a method expecting List<WebDriver>?
    Even though ChromeDriver extends WebDriver, Java Generics are invariant: List<ChromeDriver> is NOT a subtype of List<WebDriver> (otherwise the method could insert a FirefoxDriver into a ChromeDriver list). Changing the method signature to accept List<? extends WebDriver> allows passing lists of any specific driver subtype safely.
  2. How do generic utility methods simplify custom Selenium wait and API deserialization wrappers?
    A generic REST helper like public <T> T postAndParse(String endpoint, Object body, Class<T> responseType) returns the exact deserialized POJO type without forcing every test to write manual casts. Notice how passing the explicit Class<T> token works around Type Erasure so Jackson knows which target POJO class to instantiate at runtime.
  3. When reading config lists or product grids from Selenium, why declare variables as List<String> names = new ArrayList<>(); instead of ArrayList<String>?
    Programming to the interface (List) decouples calling code from the concrete implementation. Later switching from ArrayList to LinkedList or CopyOnWriteArrayList requires changing only the single new expression without touching method parameters or return types.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. What causes 'heap pollution' warnings when mixing varargs with generics like T... items?
    Because varargs internally builds an array T[] and generic arrays are non-reifiable after Type Erasure, calling a generic varargs method emits an unchecked generic array creation warning. When the method strictly reads the array safely without exposing the raw array reference, annotate it with @SafeVarargs on final or static methods.
  2. Why did Collections.emptyList().add("QKart") throw UnsupportedOperationException?
    Factory helpers like Collections.emptyList(), Collections.singletonList(), and Java 9+ List.of() return immutable collections that reject structural modification. Instantiate new ArrayList<>() whenever elements will be added dynamically at runtime.
  3. Why did two overloaded methods validate(List<String>) and validate(List<Integer>) fail to compile?
    After Type Erasure, both parameter signatures reduce identically to validate(List) in the bytecode descriptor. The Java compiler rejects both overloads with 'name clash: both methods have the same erasure'.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why did Java design Map outside the Collection interface hierarchy?
    All Collection implementations manage single elements via uniform operations like add(E), contains(Object), and iterator() over elements. A Map associates two independent types (key and value), where insertion takes two arguments put(K, V) and iteration splits into keys, values, or entry pairs. Keeping Map separate preserves clean, non-bloated contracts.
  2. Why did Java choose Type Erasure rather than full runtime reified generics (like C#)?
    Type Erasure ensured binary compatibility with millions of lines of pre-Java 5 unparameterized code and allowed non-generic callers to interoperate with newly generified standard collections without needing duplicate collection classes in the JVM.
  3. Why should framework return types avoid raw List or List<Object>?
    Returning untyped containers shifts casting errors onto callers and loses IDE auto-completion. Strongly typed generic DTOs or interfaces catch data mismatches immediately at compile time.
  4. Does Map extend the Collection interface?
    No; Map is a separate root interface in java.util.
  5. What is the difference between Collection and Collections?
    Collection is an interface; Collections is a static utility class.
  6. What does Type Erasure do at compile time?
    Verifies generic types, inserts casts, and strips type arguments from runtime bytecode.
  7. Can you create List<int>?
    No; use wrapper type List<Integer>.
  8. What is the wildcard rule PECS?
    Producer Extends (? extends T for reading), Consumer Super (? super T for writing).
  9. What interface sits above Collection enabling enhanced for-each loops?
    java.lang.Iterable<T>.
