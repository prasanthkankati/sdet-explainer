J3.2 Question Bank: String vs StringBuilder vs StringBuffer (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. Compare String, StringBuilder, and StringBuffer in one concise overview.
    String is immutable and stored in the String Constant Pool or Heap, making every edit allocate a new object. StringBuilder is mutable and unsynchronized, giving the fastest performance for single-threaded loops. StringBuffer is also mutable, with synchronized methods that guarantee thread-safety at a slight locking cost.
  2. When should you choose StringBuilder instead of String?
    Choose StringBuilder whenever text is assembled iteratively across a loop, conditional branch sequence, or dynamic query/XPath generator. For fixed constants or a single "Hello " + name expression outside loops, plain String stays cleaner and equally fast because the compiler optimizes single-expression concatenation automatically.
  3. Why did Java 5 introduce StringBuilder when StringBuffer already existed?
    In real Java programs, over 99% of string-building buffers live strictly as local variables inside one method and are never shared between threads. Paying synchronization lock acquisition and release cost on every single append() call in StringBuffer wasted CPU cycles, so Java 5 added StringBuilder as a drop-in unsynchronized replacement.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. Why does String res = ""; for (int i=0; i<1000; i++) res += i; harm Heap performance?
    Because String is immutable, each res += i iteration allocates a new internal concatenation buffer, copies all existing characters from res plus the new digits, produces a brand-new Heap String, and abandons the previous String as garbage. Over 1,000 iterations, this generates roughly 1,000 dead Heap strings and copies characters quadratically. Using a single StringBuilder performs all appends in one array.
  2. How does StringBuilder grow its capacity when appended text exceeds initial capacity?
    An empty new StringBuilder() allocates an initial backing array of 16 characters (new StringBuilder("abc") allocates 3 + 16 = 19). When an append() exceeds capacity, StringBuilder computes a new capacity of (oldCapacity * 2) + 2 (or exact required length if larger) and copies contents via Arrays.copyOf(). Passing an estimated capacity like new StringBuilder(512) avoids intermediate array copies altogether.
  3. Does sb.toString() share the backing array with StringBuilder?
    No; calling sb.toString() allocates a fresh immutable String with a copy of the active characters (from index 0 to sb.length()). Subsequent sb.append() mutations on the StringBuilder never affect the previously returned String.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. In a Selenium WebTable test, how should you collect and compare text from 500 table rows?
    Create a local StringBuilder inside the extraction method, loop through row elements calling sb.append(row.getText()).append('|'), and return sb.toString(). Keeping the StringBuilder local ensures every TestNG parallel thread gets its own isolated buffer on its own Stack frame without needing StringBuffer.
  2. When building a shared multi-threaded custom logger buffer accessed concurrently by 4 TestNG threads, which mutable class avoids garbled text?
    If multiple threads genuinely append to one shared mutable buffer instance, choose StringBuffer (or a thread-safe queue/logger like SLF4J/Log4j2) so concurrent append() calls serialize cleanly without corrupting character indices. However, using ThreadLocal<StringBuilder> or Log4j2 appenders scales better under heavy concurrency.
  3. How do you check whether a UI string is a palindrome during an SDET coding interview?
    Normalize case and characters first, then pass the string into new StringBuilder(cleaned).reverse().toString().equals(cleaned), or scan inward with two index pointers (left and right) for zero extra Heap allocation.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why did new StringBuilder("OK").equals(new StringBuilder("OK")) return false in a unit test?
    Neither StringBuilder nor StringBuffer overrides Object.equals() or hashCode(), so equals() falls back to reference identity (==). Always convert both buffers via .toString() or compare via Java 11 sb1.compareTo(sb2) == 0.
  2. Why did a shared static StringBuilder reportBuffer throw ArrayIndexOutOfBoundsException during parallel TestNG runs?
    StringBuilder provides zero thread synchronization; when two worker threads append concurrently, one thread reads an outdated internal count field while another expands the buffer, causing index corruption or out-of-bounds failures. Make the buffer local to each method or replace it with a thread-safe structure.
  3. What happens if you pass null directly into new StringBuilder((String) null) vs sb.append((String) null)?
    Passing null into the new StringBuilder(String) constructor throws NullPointerException immediately because it calls str.length(). By contrast, calling sb.append((String) null) safely appends the literal four characters "null" without throwing.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why does modern Java (Java 11+) use StringJoiner or String.join(", ", list) instead of manual StringBuilder loops for comma-separated text?
    Manual loops building delimited lists require clumsy trailing-comma checks (if (i > 0) sb.append(", ")). String.join(", ", list) and Collectors.joining(", ") handle delimiters cleanly in one readable call using StringJoiner internally.
  2. Why should public method signatures return String rather than StringBuilder?
    Returning a mutable StringBuilder exposes an internal buffer that callers could accidentally mutate downstream, violating encapsulation. Convert to an immutable String via toString() at the method boundary.
  3. When is StringBuffer legitimately preferred over StringBuilder today?
    Only when maintaining legacy APIs expecting a StringBuffer parameter (including older java.util.regex.Matcher methods prior to Java 9) or sharing a single mutable text accumulator directly across threads without external locking.
  4. Which class is fastest for single-threaded string concatenation in loops?
    StringBuilder.
  5. What makes StringBuffer thread-safe?
    Its mutation methods are declared synchronized.
  6. What is the default initial capacity of new StringBuilder()?
    16 characters.
  7. How does StringBuilder.equals() compare two instances?
    By reference identity (==), because it does not override Object.equals().
  8. What happens when calling new StringBuilder((String) null)?
    Throws NullPointerException.
  9. What does sb.append((String) null) append?
    The four characters "null".
