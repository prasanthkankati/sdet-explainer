4.2 Constructors: Default, Parameterized, Chaining & Singleton

1. Definition

A constructor runs automatically at object creation to initialize fields (having no return type and matching the class name), this()/super() chain constructors across the class hierarchy, and private constructors enforce a Singleton.

2. Memory hook

Same name as class + ZERO return type! Add any constructor and the free compiler default disappears.

  • Compiler default rule: Java supplies a zero-arg constructor ONLY if you write zero constructors yourself.
  • this(...) vs super(...): whichever is used MUST sit on line 1 inside a constructor — never both on the same constructor.
  • private constructor: blocks outsiders from calling new, used for Math-style utility classes or Singletons.

5. Code example: Page Object super() chaining + thread-safe Singleton

class BasePage {
    protected final String url;
    BasePage(String url) { this.url = url; }          // removes no-arg default constructor!
}

class QKartHomePage extends BasePage {
    QKartHomePage() { this("https://qkart-qa-web.labs.crio.do/"); } // delegates via this()
    QKartHomePage(String url) { super(url); }         // super() MUST be line 1
}

final class ConfigSingleton {
    private static volatile ConfigSingleton instance; // safe double-checked field
    private ConfigSingleton() {}                      // blocks external 'new ConfigSingleton()'
    public static ConfigSingleton getInstance() {
        if (instance == null) {
            synchronized (ConfigSingleton.class) {
                if (instance == null) instance = new ConfigSingleton();
            }
        }
        return instance;
    }
}

6. Execution flow, step by step

  1. Declaring BasePage(String url) removes Java's invisible zero-arg default constructor.
  2. Calling new QKartHomePage() invokes this(...) on line 1, jumping to QKartHomePage(String url).
  3. Line 1 of QKartHomePage(String url) calls super(url) to initialize BasePage.url first.
  4. In ConfigSingleton, the private constructor refuses new ConfigSingleton() from outside classes.
  5. Double-checked locking ensures only one shared instance ever builds across concurrent threads.

8. Why it matters

Guarantees every object starts in a valid state instead of half-initialized fields crashing later with NPEs.

SDET link: Every Selenium Page Object takes WebDriver via its constructor (public LoginPage(WebDriver driver) { super(driver); }) so no test can ever accidentally instantiate a driverless Page Object.

9. Quick test

What breaks if you write public void LoginPage()? Java compiles it as an ordinary method named LoginPage instead of a constructor, so new LoginPage() never runs it.
