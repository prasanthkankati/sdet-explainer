4.2 Relative Locators

Finding elements spatially using RelativeLocator.with(By) and above(), below(), toLeftOf(), toRightOf(), and near().

Introduced in Selenium 4, Relative Locators (formerly Friendly Locators) allow you to find elements based on their visual, spatial position relative to other known elements on the page. They use the browser's JavaScript getBoundingClientRect() API to calculate coordinates for above, below, toLeftOf, toRightOf, and near.

Before you start

Prerequisite: 4.1 Locators (All 8 Traditional Strategies)

Where it fits

Relative locators are used in Page Objects when target inputs or buttons lack unique attributes of their own but sit next to a stable label or heading.

Key points

  1. Entry point is RelativeLocator.with(By.tagName("...")) from org.openqa.selenium.support.locators.RelativeLocator.
  2. The five spatial methods are above(), below(), toLeftOf(), toRightOf(), and near().
  3. near() locates elements within a default Euclidean pixel distance of 50px (or a custom pixel radius passed as an argument).
  4. Multiple spatial constraints can be chained together, such as with(By.tagName("button")).below(emailInput).toRightOf(cancelBtn).
  5. Relative locators execute client-side bounding box math via getBoundingClientRect(), so responsive layout shifts can change spatial relationships.

How it works

  1. Import static org.openqa.selenium.support.locators.RelativeLocator.with.
  2. Locate or specify the anchor reference element (for example, By.id("password") or an existing WebElement).
  3. Build the RelativeBy query using with(By.tagName("input")).above(By.id("password")).
  4. Pass the resulting RelativeBy locator into driver.findElement(), which executes a bundled JavaScript function in the browser using getBoundingClientRect() to sort candidates by proximity.

Using RelativeLocator.with() to find elements by spatial relationship:

package dev.selenium.elements; // Declares package

import org.openqa.selenium.By; // Imports By class
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import static org.openqa.selenium.support.locators.RelativeLocator.with; // Static import for with()

public class RelativeLocatorsExample { // Declares class
    public static void main(String[] args) { // Main entry point
        WebDriver driver = new ChromeDriver(); // Starts Chrome session
        try { // Guarded block
            driver.get("https://www.selenium.dev/selenium/web/web-form.html"); // Loads web form
            WebElement passwordField = driver.findElement(By.name("my-password")); // Locates known reference element
            WebElement textAbovePassword = driver.findElement( // Finds input spatially above password
                with(By.tagName("input")).above(passwordField) // Chains with(By) and above(WebElement)
            ); // Completes lookup
            textAbovePassword.sendKeys("Found via RelativeLocator"); // Types into located input
            System.out.println("Input name: " + textAbovePassword.getAttribute("name")); // Prints matched input name
        } finally { // Teardown block
            driver.quit(); // Closes browser
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Using relative locators without a fixed browser viewport size, causing elements that are toRightOf() on desktop to wrap below() on narrow mobile viewports; fix by setting --window-size=1920,1080.
  2. Using RelativeLocator when a simple, direct By.id or By.cssSelector is available; fix by reserving RelativeLocator for elements that genuinely lack unique attributes.
  3. Passing a broad tag like By.tagName("div") to with(), which matches outer wrapper containers; fix by passing the specific leaf tag such as By.tagName("input") or By.tagName("button").

Terms to know

TermMeaning
RelativeLocatorA Selenium 4 support class that locates elements based on visual proximity to other DOM elements.
RelativeByThe specialized By subclass returned by RelativeLocator.with(By) that supports spatial chaining.
getBoundingClientRect()The native DOM JavaScript method that returns an element's x, y, width, height, top, right, bottom, and left viewport coordinates.
near()A RelativeBy method that matches elements within 50 pixels (by default) of the reference element.

Interview questions

Basics

What are Relative Locators in Selenium 4 and what are the five spatial methods?
Relative Locators find elements based on their visual layout position relative to an anchor element rather than solely by DOM hierarchy. The five spatial methods are above(), below(), toLeftOf(), toRightOf(), and near().

What is the default pixel distance used by the near() relative locator?
By default, near() searches for candidate elements within 50 pixels of the reference element's bounding box. You can also pass a custom distance in pixels, such as near(element, 100).

Which package provides RelativeLocator in Selenium Java?
RelativeLocator is located in org.openqa.selenium.support.locators.RelativeLocator, and its entry method with(By) is typically imported statically.

How it works

How does Selenium calculate whether one element is above() or toRightOf() another element?
Selenium injects a pre-compiled JavaScript atom into the browser that calls element.getBoundingClientRect() on all candidate elements and the anchor element, comparing their top, bottom, left, and right pixel coordinates and sorting matches by center-to-center distance.

Can you pass a By locator instead of a WebElement into above() or below()?
Yes. All five spatial methods are overloaded to accept either a resolved WebElement reference or a By locator directly, such as with(By.tagName("input")).below(By.id("email-label")).

How does chaining multiple spatial methods work in RelativeLocator?
When you chain methods like with(By.tagName("button")).below(formHeader).toRightOf(cancelButton), Selenium intersects the candidate sets so only buttons that satisfy both coordinate conditions are returned.

Real situations

When is RelativeLocator better than an XPath sibling axis in a real project?
Sometimes two elements appear side-by-side visually via CSS Grid or Flexbox, even though they live in completely separate branches of the HTML DOM tree. RelativeLocator finds them visually by screen coordinates where XPath sibling axes fail.

Why can responsive web design break tests that rely on toLeftOf() or toRightOf()?
On a narrow window (such as 800x600 in unconfigured headless mode), CSS Flexbox or Grid wraps horizontal columns into a vertical stack, moving an element from toRightOf() to below(). Always lock the viewport to 1920x1080.

How do you click the 'Delete' button corresponding to a specific user row in a grid layout without table tags?
Locate the user's label element first, then call driver.findElement(with(By.tagName("button")).toRightOf(userLabel)).click().

Troubleshooting

Why did RelativeLocator return the wrong element when multiple inputs existed below a label?
above() and below() sort all matching candidates by Euclidean proximity to the reference element and return the closest one. If another input is slightly closer diagonally, chain a second constraint like .near() or use a more specific By inside with().

Why does RelativeLocator fail to match an element that is further down the page outside the current scroll view?
getBoundingClientRect() computes coordinates relative to the layout, but if a virtualized table only renders rows when scrolled into view, the target node is not in the DOM yet. Scroll the anchor into view first.

What happens if the anchor element passed to below(By.id("missing")) does not exist?
Selenium throws NoSuchElementException because it cannot resolve the reference anchor element's bounding rectangle.

Design choices

Should RelativeLocators replace standard CSS and ID locators across a framework?
No. Standard ID and CSS selectors are faster and immune to visual CSS layout shifts. RelativeLocators should be used selectively when target elements lack semantic attributes.

Why did Selenium 4.2+ expand RelativeLocator.with() to accept any By locator instead of only By.tagName()?
Allowing any By locator (such as with(By.cssSelector("button.action-btn")).toRightOf(anchor)) lets engineers filter candidates by CSS class or attribute before applying coordinate math.

What is the performance overhead of RelativeLocator compared to By.id()?
Both execute in a single round-trip HTTP call because Selenium sends the entire JavaScript coordinate filter in one payload, though evaluating getBoundingClientRect() on many candidates takes slightly more browser CPU than a direct ID lookup.

Quick answers

  1. What is the entry method for Relative Locators? RelativeLocator.with(By) (statically imported).
  2. What are the 5 Relative Locator methods? above(), below(), toLeftOf(), toRightOf(), and near().
  3. What is the default pixel radius of near()? 50 pixels.
  4. Which browser API powers Relative Locators? The DOM element.getBoundingClientRect() JavaScript method.
  5. Can you chain multiple Relative Locator directions? Yes, e.g., with(By.tagName("button")).below(el1).toRightOf(el2).
