2.3 Using a Test Runner (TestNG & JUnit 5)

Integrating Selenium WebDriver with TestNG and JUnit 5 for lifecycle hooks, assertions, and parallel execution.

Selenium WebDriver automates browsers but does not include a test runner, assertion library, or reporting engine. In Java automation frameworks, engineers pair Selenium with TestNG or JUnit 5 to manage setup and teardown lifecycles, validate expected outcomes with assertions, and execute test suites in parallel.

Before you start

Prerequisite: 2.2 Write Your First Selenium Script

Where it fits

The test runner orchestrates the entire execution lifecycle around Selenium commands in local IDE runs and CI/CD pipelines.

Key points

  1. TestNG (@BeforeMethod, @Test, @AfterMethod) and JUnit 5 (@BeforeEach, @Test, @AfterEach) manage browser startup and teardown automatically.
  2. Initializing a fresh WebDriver instance before each test method and quitting it afterward ensures strict test isolation.
  3. Hard assertions (Assert.assertEquals) abort the test method immediately on failure, whereas SoftAssert collects multiple failures before reporting.
  4. Never store a shared static WebDriver field across parallel tests; use instance fields per test or ThreadLocal<WebDriver>.
  5. Maven Surefire Plugin executes TestNG (testng.xml) and JUnit 5 test classes from the command line via mvn test.

How it works

  1. The test runner invokes the @BeforeMethod (or @BeforeEach) setup method before a @Test method starts.
  2. The setup method initializes a new ChromeDriver instance so the test begins with a clean browser profile and empty cookies.
  3. The test runner executes the @Test method, which performs Selenium actions and calls Assert.assertEquals() to verify UI state.
  4. Whether the @Test passes or throws an AssertionError, the test runner guarantees execution of @AfterMethod to call driver.quit().

TestNG lifecycle with Selenium 4 WebDriver:

package dev.selenium.runner; // Declares package

import org.openqa.selenium.By; // Imports By locator class
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver class
import org.testng.Assert; // Imports TestNG Assert utility
import org.testng.annotations.AfterMethod; // Imports teardown annotation
import org.testng.annotations.BeforeMethod; // Imports setup annotation
import org.testng.annotations.Test; // Imports test annotation

public class WebFormTest { // Declares TestNG test class
    private WebDriver driver; // Declares instance-level WebDriver field

    @BeforeMethod // Runs before every @Test method
    public void setUp() { // Setup method
        driver = new ChromeDriver(); // Starts a clean Chrome session
        driver.get("https://www.selenium.dev/selenium/web/web-form.html"); // Opens target application URL
    } // Ends setup

    @Test // Marks method as an executable test case
    public void shouldSubmitWebFormSuccessfully() { // Test method
        driver.findElement(By.name("my-text")).sendKeys("Selenium 4"); // Enters text into input
        driver.findElement(By.cssSelector("button")).click(); // Clicks submit button
        String actualMessage = driver.findElement(By.id("message")).getText(); // Reads confirmation banner
        Assert.assertEquals(actualMessage, "Received!"); // Verifies actual text matches expected text
    } // Ends test method

    @AfterMethod(alwaysRun = true) // Runs after every @Test even if assertions fail
    public void tearDown() { // Teardown method
        if (driver != null) { // Null check guard
            driver.quit(); // Closes browser and terminates driver process
        } // Ends guard
    } // Ends teardown
} // Ends class

Common mistakes

  1. Creating the browser in @BeforeSuite or @BeforeClass and sharing one browser state across 20 tests; fix by initializing a fresh session in @BeforeMethod so a failure in test 1 never corrupts test 2.
  2. Omitting alwaysRun = true on @AfterMethod in TestNG group runs, causing teardown to be skipped; fix by annotating @AfterMethod(alwaysRun = true).
  3. Using SoftAssert without calling softAssert.assertAll() at the end of the @Test method; fix by always invoking assertAll() as the final line of the test.

Terms to know

TermMeaning
Test RunnerA framework (such as TestNG or JUnit 5) that discovers, schedules, executes, and reports on annotated test methods.
Test IsolationThe principle that each test method runs independently with its own clean browser session and state.
Hard AssertionAn assertion that immediately throws an AssertionError and halts the current test method when a check fails.
SoftAssertA TestNG class that records assertion failures without halting execution until assertAll() is called.

Interview questions

Basics

Why do we need TestNG or JUnit 5 when working with Selenium?
Selenium only provides browser automation APIs. TestNG and JUnit 5 provide test discovery, @BeforeMethod/@AfterMethod lifecycle hooks, assertion methods, data-driven execution, parallel thread management, and HTML/XML test reports.

What is the difference between @BeforeClass and @BeforeMethod in TestNG?
@BeforeClass runs once before the first test method in the current class, whereas @BeforeMethod runs before every single @Test method in the class. Creating WebDriver in @BeforeMethod guarantees every test starts with a clean browser.

What is the difference between Assert.assertEquals() and SoftAssert in TestNG?
Assert.assertEquals() is a hard assertion that throws AssertionError immediately on mismatch and stops the test method. SoftAssert records failures and continues executing subsequent checks until softAssert.assertAll() is called at the end of the test.

How it works

Does @AfterMethod still execute if an assertion fails or NoSuchElementException is thrown inside @Test?
Yes. TestNG and JUnit 5 guarantee that @AfterMethod / @AfterEach teardown hooks execute even when the @Test method terminates abnormally with an exception or AssertionError, ensuring driver.quit() always runs.

What is the parameter order difference between TestNG Assert.assertEquals and JUnit 5 Assertions.assertEquals?
In TestNG, the signature is Assert.assertEquals(actual, expected, message). In JUnit 5, the signature is Assertions.assertEquals(expected, actual, message). Swapping them produces confusing failure logs.

How does Maven execute TestNG or JUnit 5 Selenium tests from the command line?
Maven uses the maven-surefire-plugin during the mvn test phase to scan src/test/java for @Test classes or execute a configured testng.xml suite file.

Real situations

Why is declaring public static WebDriver driver dangerous when running tests in parallel?
A static field is shared by all threads in the JVM. When two parallel threads overwrite the same static driver variable, commands from both tests interleave in one browser window and cause race conditions. Use ThreadLocal<WebDriver> instead.

Why should you add alwaysRun = true to @BeforeMethod and @AfterMethod in TestNG?
When filtering tests by TestNG groups (such as groups = {"smoke"}), TestNG skips lifecycle hooks that do not belong to that group unless alwaysRun = true is specified. Without it, driverremains null and throws NullPointerException.

How do you capture a screenshot automatically only when a Selenium @Test method fails?
In @AfterMethod, accept an ITestResult result parameter, check if (!result.isSuccess()), cast driver to TakesScreenshot, capture the screenshot bytes, and then call driver.quit().

Troubleshooting

Why did a test pass in TestNG even though a SoftAssert check failed?
The engineer forgot to call softAssert.assertAll() at the end of the @Test method. Without assertAll(), SoftAssert collects the failures in memory but never throws the aggregated AssertionError.

What causes NullPointerException on driver.get() inside a @Test method?
Either the @BeforeMethod setup was skipped (for example, missing alwaysRun = true during group execution), or the test class re-declared WebDriver driver = new ChromeDriver() as a local variable inside setUp() instead of assigning it to the class field.

Why does mvn test report 'No tests were executed' even though @Test methods exist?
Ensure the test class filename ends with Test.java (such as LoginTest.java), or explicitly point maven-surefire-plugin to your testng.xml suite file.

Design choices

Why is starting a new browser per @Test method preferred over sharing one browser across an entire test class?
Browser sessions accumulate cookies, localStorage tokens, and open modals. Starting a fresh browser in @BeforeMethod guarantees each test is atomic, repeatable, and immune to cascading failures from earlier tests.

Where should assertions live: inside Page Object classes or inside @Test classes?
Assertions should live inside @Test classes, while Page Object classes return page state (such as getErrorMessageText()). Keeping assertions in test classes preserves separation of concerns.

When should you use TestNG @DataProvider instead of writing multiple @Test methods?
Use @DataProvider when the exact same UI workflow (such as login validation) must be verified with multiple input combinations (invalid password, locked user, empty fields).

Quick answers

  1. Which TestNG annotation runs before each test method? @BeforeMethod runs before every @Test method.
  2. Which JUnit 5 annotation runs after each test method? @AfterEach runs after every @Test method.
  3. Why use alwaysRun = true on @AfterMethod? Guarantees driver.quit() runs even when filtering by TestNG groups.
  4. What must be called at the end of a SoftAssert test? softAssert.assertAll() must be called to throw collected failures.
  5. How do you isolate WebDriver across parallel threads? Store the WebDriver instance inside a ThreadLocal<WebDriver> container.
