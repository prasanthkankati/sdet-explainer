9.1 Automated Driver & Browser Management

How the built-in Rust binary Selenium Manager resolves driver executables, downloads Chrome for Testing (CfT), caches binaries, and handles corporate proxies.

Selenium Manager is the official command-line binary tool bundled directly inside selenium-java (since Selenium 4.6) that automates browser and driver management out of the box. Written in Rust for cross-platform speed, it automatically detects the browser version installed on the host machine, downloads the matching driver binary into ~/.cache/selenium, and can even download standalone browser binaries (such as Chrome for Testing) when requested.

Before you start

Prerequisite: 8.2 Log & Network Interception with BiDi

Where it fits

Selenium Manager runs transparently behind the scenes every time new ChromeDriver(), FirefoxDriver(), or EdgeDriver() is called without a manual driver path.

Key points

  1. Selenium Manager is bundled inside selenium-java for Windows, Linux, and macOS—zero extra Maven dependencies or manual downloads are required.
  2. It acts as an automatic fallback: if webdriver.chrome.driver is not set and chromedriver is not on the system PATH, Selenium Manager resolves and downloads the driver automatically.
  3. Downloaded drivers and browsers are cached locally in ~/.cache/selenium (or %USERPROFILE%\.cache\selenium on Windows) alongside a selenium-manager.json metadata file.
  4. If you specify a browser version via options.setBrowserVersion("130") (or "beta", "dev", "canary"), Selenium Manager automatically downloads both the matching Chrome for Testing (CfT) browser binary and its ChromeDriver!
  5. In corporate networks behind a proxy or offline firewall, Selenium Manager is configured via environment variables (SE_PROXY, SE_CACHE_PATH, SE_OFFLINE) or JVM system properties.

How it works

  1. Browser Discovery: When new ChromeDriver() is called, Selenium Manager executes OS-specific shell/registry commands to detect the installed Chrome version (e.g., 130.0.6723.91).
  2. Cache Check: It checks ~/.cache/selenium to see if a compatible chromedriver (major version 130) is already cached locally.
  3. Driver Download: If not cached, it queries the official Chrome for Testing (CfT) JSON endpoints (or Mozilla/Edge repositories), downloads the matching driver zip, extracts it to ~/.cache/selenium, and sets its executable permission.
  4. Session Binding: It returns the absolute binary path to ChromeDriverService, which launches the driver session seamlessly.

Using Selenium Manager for automatic driver resolution and version-pinned browser testing:

package dev.selenium.manager; // Declares package

import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.chrome.ChromeOptions; // Imports ChromeOptions

public class SeleniumManagerExample { // Declares class
    public static void main(String[] args) { // Main method
        // Case 1: Zero-config automatic driver resolution for installed Chrome
        WebDriver defaultDriver = new ChromeDriver(); // Selenium Manager resolves matching chromedriver
        try { // Guarded block
            defaultDriver.get("https://www.selenium.dev/"); // Navigates to Selenium site
            System.out.println("Default Title: " + defaultDriver.getTitle()); // Prints page title
        } finally { // Teardown block
            defaultDriver.quit(); // Closes default session
        } // Ends finally

        // Case 2: Requesting a specific browser version (downloads Chrome for Testing + driver)
        ChromeOptions options = new ChromeOptions(); // Creates ChromeOptions
        options.setBrowserVersion("stable"); // Requests stable channel Chrome for Testing
        WebDriver versionedDriver = new ChromeDriver(options); // Selenium Manager resolves browser & driver
        try { // Guarded block
            versionedDriver.get("https://www.selenium.dev/documentation/selenium_manager/"); // Opens docs
            System.out.println("Versioned Title: " + versionedDriver.getTitle()); // Prints title
        } finally { // Teardown block
            versionedDriver.quit(); // Closes versioned session
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Leaving an old hardcoded System.setProperty("webdriver.chrome.driver", "C:/old/chromedriver.exe") in the codebase, which overrides and bypasses Selenium Manager and causes SessionNotCreatedException when Chrome auto-updates; fix by deleting System.setProperty.
  2. Still adding io.github.bonigarcia:webdrivermanager to pom.xml in Selenium 4.6+ projects; fix by removing it and letting built-in Selenium Manager handle drivers.
  3. Having an outdated chromedriver binary sitting in C:\Windows\System32 or /usr/local/bin on the system PATH, which Selenium checks before invoking Selenium Manager; fix by removing stale driver binaries from system PATH folders.

Interview questions

Basics

What is Selenium Manager and when was it introduced?
Selenium Manager is the built-in CLI tool (written in Rust and bundled inside selenium-java starting in Selenium 4.6) that automatically discovers, downloads, and caches matching browser drivers and browser binaries without any manual configuration.

Where does Selenium Manager store downloaded driver binaries on your machine?
By default, it stores all downloaded drivers, browsers, and metadata inside the ~/.cache/selenium directory (or %USERPROFILE%\.cache\selenium on Windows).

Do you still need System.setProperty("webdriver.chrome.driver", ...) or WebDriverManager in Selenium 4?
No. Both manual System.setProperty paths and third-party WebDriverManager dependencies are obsolete in modern Selenium 4 because Selenium Manager handles driver resolution natively.

How it works

In what order does Selenium look for a browser driver before invoking Selenium Manager?
First, Selenium checks if a JVM system property (such as webdriver.chrome.driver) or DriverService executable path was explicitly set. Second, it checks if the driver binary exists on the OS PATH. If neither is found, it invokes Selenium Manager.

What happens if you set options.setBrowserVersion("128") on a machine that only has Chrome 130 installed?
Selenium Manager detects that Chrome 128 is not installed locally, automatically downloads both the standalone Chrome for Testing (CfT) v128 browser binary and ChromeDriver v128 into ~/.cache/selenium, and launches the test on Chrome 128.

How long does Selenium Manager keep cached driver metadata before checking for patch updates?
Selenium Manager stores a Time-To-Live (TTL) timestamp (default 3600 seconds / 1 hour) in ~/.cache/selenium/selenium-manager.json so repeated test runs do not make redundant network requests on every single test.

Real situations

How do you configure Selenium Manager in a corporate CI environment that requires an outbound HTTP proxy?
Either set the environment variable SE_PROXY=http://proxy.company.com:8080 on the CI agent, or configure a Proxy object on ChromeOptions via options.setProxy(proxy).

How do you run Selenium Manager in an air-gapped CI environment with zero internet access?
Pre-install the browser and matching driver on the CI image's system PATH (or pre-populate the SE_CACHE_PATH directory) and set the environment variable SE_OFFLINE=true.

How can you test your web app against next month's upcoming Chrome release before it ships to users?
Call options.setBrowserVersion("beta") or options.setBrowserVersion("dev") on ChromeOptions. Selenium Manager automatically downloads the beta Chrome for Testing binary and matching driver.

Troubleshooting

Why did my test still fail with 'This version of ChromeDriver only supports Chrome version 114' even on Selenium 4.26?
Because Selenium checks system properties and the OS PATH before calling Selenium Manager! You either have an old System.setProperty("webdriver.chrome.driver", ...) in your code or an old chromedriver.exe sitting in a folder on your system PATH. Delete both.

How do you enable debug logging for Selenium Manager to diagnose a download or proxy failure?
Set the environment variable SE_DEBUG=true or enable fine logging for the org.openqa.selenium.manager.SeleniumManager logger to print the exact CLI commands and network responses.

What happens if the CI container's home directory is read-only and ~/.cache/selenium cannot be created?
Set the environment variable SE_CACHE_PATH=/tmp/selenium-cache to point Selenium Manager to a writable directory.

Design choices

Why did the Selenium team build Selenium Manager in Rust instead of Java, Python, and C# separately?
Selenium supports five official language bindings (Java, Python, C#, Ruby, JS). Writing one fast, self-contained native Rust binary allows all five languages to share the exact same driver resolution engine.

Why is Chrome for Testing (CfT) better for automation than standard consumer Google Chrome?
Consumer Chrome auto-updates silently in the background, which historically broke test pipelines mid-run, and consumer Chrome cannot be downloaded by specific historical version numbers. CfT provides version-pinned, non-auto-updating binaries.

Why does Selenium Manager act as a fallback rather than overriding explicit driver paths?
Acting as a fallback preserves backward compatibility for enterprise environments or custom embedded browsers that intentionally supply a custom-built driver binary.

Quick answers

  1. What language is the Selenium Manager binary written in? Rust (bundled natively inside selenium-java).
  2. Where is the default Selenium Manager cache folder? ~/.cache/selenium (or %USERPROFILE%\.cache\selenium on Windows).
  3. Which env var configures a proxy for Selenium Manager? SE_PROXY.
  4. Which env var changes the cache folder path? SE_CACHE_PATH.
  5. How do you auto-download Chrome Beta for testing? Call chromeOptions.setBrowserVersion("beta").
