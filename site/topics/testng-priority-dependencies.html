TestNG

2.2 Priority, dependsOnMethods & enabled Attribute

Controlling test execution sequence, conditional dependency cascades, and skipping vs soft failure semantics.

By default, TestNG executes test methods in arbitrary or alphabetical order. In real-world enterprise suites, test engineers must control sequencing, disable deprecated tests, or establish hard dependencies between transactional workflows.

1. The priority Attribute

Assigns numerical precedence to @Test methods. Lower numbers execute first (e.g. priority 0 runs before priority 1). Negative priorities are valid and run before priority 0.

public class PriorityTest {
    @Test(priority = -1)
    public void setupEnvironment() { /* Runs first */ }

    @Test(priority = 0)
    public void loginTest() { /* Runs second */ }

    @Test(priority = 1)
    public void createProjectTest() { /* Runs third */ }
}

2. Dependency Mapping: dependsOnMethods

When Method B depends on Method A, TestNG guarantees Method A runs first. If Method A fails, Method B is skipped (marked as SKIP, not FAIL), avoiding false-negative noise:

public class DependencyTest {
    @Test
    public void createUser() {
        // If this throws AssertionError...
        Assert.assertTrue(apiCreateUser(), "User creation API failed");
    }

    @Test(dependsOnMethods = {"createUser"})
    public void updateUserSettings() {
        // ...This method is automatically SKIPPED, not executed
        openSettingsPage();
    }
}

3. The enabled Attribute

Setting @Test(enabled = false) instructs the compiler and runner to completely ignore the test during suite execution. It does not appear in test counts or reports.

4. Senior SDET Interview Q&A

  1. What is the difference between priority and dependsOnMethods?
    priority only influences execution order—if priority 1 fails, priority 2 will still run. dependsOnMethods enforces a hard conditional dependency: if the upstream method fails, downstream methods are automatically skipped.
  2. What does alwaysRun = true do when combined with dependsOnMethods?
    It forces the dependent method to execute even if the parent method failed. Frequently used for cleanup routines like deleteUserSession().
