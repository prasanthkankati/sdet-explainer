8.2 Log & Network Interception with BiDi

Streaming console.log and uncaught JavaScript exceptions with LogInspector, intercepting HTTP traffic with Network, and handling Basic Auth.

With WebDriver BiDi enabled, Selenium 4 provides high-level Java APIs to observe and control internal browser activity in real time. LogInspector captures console logs (console.log, console.error) and uncaught JavaScript page exceptions, while the BiDi Network module intercepts HTTP requests/responses and injects Basic Authentication credentials automatically.

Before you start

Prerequisite: 8.1 WebDriver BiDi Architecture & Setup

Where it fits

BiDi listeners are registered in @BeforeMethod or inside specialized test methods to fail tests automatically on uncaught JS errors or to authenticate against protected endpoints.

Key points

  1. LogInspector (org.openqa.selenium.bidi.module.LogInspector) subscribes to browser console logs via onConsoleEntry() and uncaught JS errors via onJavaScriptException().
  2. LogInspector implements AutoCloseable and should be closed in teardown (or via try-with-resources) to unsubscribe WebSocket listeners.
  3. Network (org.openqa.selenium.bidi.module.Network) intercepts traffic via onBeforeRequestSent(), onResponseCompleted(), and addIntercept().
  4. HTTP Basic Authentication popups are handled cleanly via network.onAuthRequired() or ((HasAuthentication) driver).register(UsernameAndPassword.of(user, pass)).
  5. Capturing uncaught JavaScript exceptions during UI regression runs catches silent frontend React/Angular crashes that do not throw a WebDriver exception.

How it works

  1. Enable BiDi on the browser options via options.enableBiDi() and launch the driver.
  2. Instantiate LogInspector(driver) inside a try-with-resources block (or close it in @AfterMethod).
  3. Register callbacks with logInspector.onConsoleEntry(...) and logInspector.onJavaScriptException(...) to collect logs into a thread-safe CopyOnWriteArrayList.
  4. Trigger the UI actions in the browser and assert on the captured console messages or zero JS exceptions.

Capturing console logs and uncaught JavaScript errors with BiDi LogInspector:

package dev.selenium.bidi; // Declares package

import org.openqa.selenium.By; // Imports By locator class
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.bidi.log.ConsoleLogEntry; // Imports ConsoleLogEntry model
import org.openqa.selenium.bidi.log.JavascriptLogEntry; // Imports JavascriptLogEntry model
import org.openqa.selenium.bidi.module.LogInspector; // Imports W3C BiDi LogInspector
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.chrome.ChromeOptions; // Imports ChromeOptions
import java.util.List; // Imports List interface
import java.util.concurrent.CopyOnWriteArrayList; // Imports thread-safe list for async callbacks

public class BiDiFeaturesExample { // Declares class
    public static void main(String[] args) { // Main method
        ChromeOptions options = new ChromeOptions(); // Creates ChromeOptions
        options.enableBiDi(); // Enables W3C WebDriver BiDi WebSocket

        WebDriver driver = new ChromeDriver(options); // Starts BiDi-enabled Chrome session
        List<ConsoleLogEntry> consoleLogs = new CopyOnWriteArrayList<>(); // Thread-safe list for console logs
        List<JavascriptLogEntry> jsExceptions = new CopyOnWriteArrayList<>(); // Thread-safe list for JS errors

        try (LogInspector logInspector = new LogInspector(driver)) { // Opens auto-closeable LogInspector
            logInspector.onConsoleEntry(consoleLogs::add); // Subscribes to all console.* entries
            logInspector.onJavaScriptException(jsExceptions::add); // Subscribes to uncaught JS exceptions

            driver.get("https://www.selenium.dev/selenium/web/bidi/logEntryAdded.html"); // Loads BiDi test page
            driver.findElement(By.id("consoleLog")).click(); // Clicks button that logs to console
            driver.findElement(By.id("jsException")).click(); // Clicks button that throws JS Error

            System.out.println("Console logs captured: " + consoleLogs.size()); // Prints captured log count
            System.out.println("JS exceptions captured: " + jsExceptions.size()); // Prints captured exception count
        } finally { // Teardown block
            driver.quit(); // Closes browser and WebSocket
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Using a standard non-thread-safe ArrayList inside async BiDi callbacks (onConsoleEntry / onResponseCompleted), which can cause ConcurrentModificationException because WebSocket events arrive on a background thread; fix by using CopyOnWriteArrayList or CompletableFuture.
  2. Asserting on the consoleLogs list zero milliseconds after click() before the async WebSocket frame arrives; use WebDriverWait or CompletableFuture.get(5, TimeUnit.SECONDS) to await the event.
  3. Using URL credentials (https://user:pass@site.com) on modern browsers that block embedded credentials in sub-resource requests; fix by using HasAuthentication or BiDi Network auth handlers.

Interview questions

Basics

How do you capture browser console.log and console.error messages in Selenium 4?
Enable BiDi with options.enableBiDi(), instantiate new LogInspector(driver), and register a callback via logInspector.onConsoleEntry(entry -> System.out.println(entry.getText())).

How do you detect uncaught JavaScript exceptions thrown by the web application during a Selenium test?
Use LogInspector.onJavaScriptException(entry -> ...). Whenever the page throws an uncaught TypeError or ReferenceError in the browser console, the callback receives a JavascriptLogEntry with the message and stack trace.

How do you handle an HTTP Basic Authentication dialog in Selenium 4?
Cast driver to HasAuthentication and register credentials before navigating: ((HasAuthentication) driver).register(UsernameAndPassword.of("admin", "secret")); driver.get("https://...");.

How it works

Why should lists that collect BiDi events use CopyOnWriteArrayList instead of ArrayList?
BiDi WebSocket callbacks execute asynchronously on a background listener thread while your @Test method runs on the main test thread. CopyOnWriteArrayList prevents ConcurrentModificationException when iterating or asserting on the list.

How do you wait deterministically for a single BiDi console log or network event in a test?
Create a CompletableFuture<ConsoleLogEntry> future = new CompletableFuture<>(); pass future::complete to logInspector.onConsoleEntry(future::complete), trigger the click, and call ConsoleLogEntry entry = future.get(5, TimeUnit.SECONDS).

How do you restrict HasAuthentication credentials so they are only sent to a specific domain?
Use the overloaded register(Predicate<URI>, Supplier<Credentials>) method, such as ((HasAuthentication) driver).register(uri -> uri.getHost().contains("staging.example.com"), UsernameAndPassword.of("user", "pass")).

Real situations

How can a QA team automatically fail any UI test if the application logs a HTTP 500 response in the background?
Register a BiDi Network.onResponseCompleted listener in @BeforeMethod that records any response where response.getStatus() >= 500, and assert in @AfterMethod that the error list is empty.

Why is LogInspector preferred over the legacy driver.manage().logs().get(LogType.BROWSER) API?
The legacy LogType.BROWSER API was never part of the W3C standard, did not work in Firefox, and required polling. BiDi LogInspector is an official W3C standard that streams logs in real time across Chrome, Firefox, and Edge.

How do you filter ConsoleLogEntry events to capture only console.error messages?
Either pass a FilterBy.logLevel(LogLevel.ERROR) to onConsoleEntry, or check if (entry.getLevel() == LogLevel.ERROR) inside your consumer lambda.

Troubleshooting

Why was my consoleLogs list still empty immediately after clicking the button that calls console.log()?
WebSocket frames arrive asynchronously a few milliseconds after the click command returns. Wrap your assertion in new WebDriverWait(driver, Duration.ofSeconds(5)).until(d -> !consoleLogs.isEmpty()).

Why did LogInspector throw BiDiException when running on Firefox or Chrome?
You forgot to call options.enableBiDi() on FirefoxOptions or ChromeOptions before instantiating the driver.

What happens if LogInspector or Network is not closed at the end of a test?
If the browser session remains open across multiple operations, unclosed listeners continue firing callbacks and accumulating objects in memory. Always close them via try-with-resources or in @AfterMethod.

Design choices

Why did LogInspector and Network implement AutoCloseable in Java?
Implementing AutoCloseable allows engineers to scope event interception cleanly to a specific try (LogInspector inspector = new LogInspector(driver)) { ... } block, automatically unsubscribing the listener on exit.

When should you use BiDi Network interception vs a dedicated API test in RestAssured?
Use RestAssured to test backend API contracts directly. Use BiDi Network interception in Selenium when you need to verify how the frontend UI reacts to a slow network, a 503 error, or specific API payloads.

Why is registering HasAuthentication better than embedding https://user:pass@host in the URL?
Modern browsers strip embedded URL credentials when fetching sub-resources (XHR/fetch requests) for security, causing AJAX calls to fail with 401. HasAuthentication supplies credentials on every challenge automatically.

Quick answers

  1. Which class captures console logs and JS errors in Selenium 4 BiDi? org.openqa.selenium.bidi.module.LogInspector.
  2. Which method subscribes to uncaught JS errors? logInspector.onJavaScriptException(consumer).
  3. Which interface handles HTTP Basic Auth popups? HasAuthentication via ((HasAuthentication) driver).register(UsernameAndPassword.of(u, p)).
  4. Which thread-safe List should hold async BiDi events? CopyOnWriteArrayList (or synchronize with CompletableFuture).
  5. Which BiDi module monitors HTTP status codes? org.openqa.selenium.bidi.module.Network.
