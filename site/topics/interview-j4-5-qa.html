J4.5 Question Bank: Inheritance (IS-A) vs Composition (HAS-A) (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. What are the types of inheritance supported for classes in Java?
    Java supports Single inheritance (B extends A), Multilevel inheritance (C extends B where B extends A), and Hierarchical inheritance (both B and C extend A). Multiple inheritance of classes (C extends A, B) and hybrid combinations involving multiple parent classes are forbidden at compile time.
  2. What is the difference between IS-A (Inheritance) and HAS-A (Composition)?
    IS-A expresses specialization using extends—for example, ChromeDriver IS-A RemoteWebDriver. HAS-A expresses ownership or delegation through instance fields—for example, LoginPage HAS-A WebDriver and HeaderComponent. Inheritance links classes statically at compile time, whereas Composition lets classes assemble modular pieces flexibly.
  3. What is the implicit root parent class of every Java class?
    Every class that does not explicitly write extends SomeParent implicitly extends java.lang.Object. Because of this single root hierarchy, every Java object supports toString(), equals(), hashCode(), and getClass().

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. Explain the Diamond Problem and why Java forbids multiple class inheritance.
    Suppose classes B and C both extend A and override A.connect() differently, and class D tried to extend both B and C. When D invokes connect() without overriding it, the compiler cannot decide whether to run B.connect() or C.connect(), and duplicate state fields from A create memory ambiguity. Forbidding multiple class inheritance eliminates this ambiguity at the language level.
  2. How does Java resolve the Diamond Problem when a class implements two interfaces that share the same Java 8 default method signature?
    Because interfaces carry no mutable instance state fields, Java allows implementing multiple interfaces (implements InterfaceA, InterfaceB). If both interfaces supply a default method with the identical signature, compilation fails unless the implementing class overrides that method explicitly—choosing one parent default via InterfaceA.super.methodName() or writing a fresh implementation.
  3. Does a child object inherit the parent's private fields in memory?
    When a child object is created on the Heap, space is allocated for ALL instance fields declared in both the parent and child classes, including the parent's private fields. However, Java access rules forbid the child class from referencing those private fields by name directly—the child interacts with them strictly through the parent's protected or public constructors and methods.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. In a Selenium framework for https://qkart-qa-web.labs.crio.do/, how should you share the top search/cart header across HomePage, CheckoutPage, and ProfilePage?
    Use Composition (the Page Component pattern): build a dedicated HeaderComponent class encapsulating the search bar, login button, and cart badge, and store a private final HeaderComponent header inside each Page Object that renders that header. Avoid putting header locators on BasePage, because pages like a standalone CheckoutFrame or ErrorPage might not render a header at all.
  2. Why is class CheckoutTest extends LoginTest an anti-pattern in TestNG frameworks?
    Extending one concrete test class from another couples test setup, annotations, and state across unrelated suites, breaking atomic test independence and preventing safe parallel test execution. Both CheckoutTest and LoginTest should extend a minimal BaseTest (or use TestNG listeners/composition) and seed login state via cookies or APIs.
  3. How does Selenium itself combine Inheritance and Interfaces in ChromeDriver?
    ChromeDriver extends ChromiumDriver which extends RemoteWebDriver (IS-A class inheritance sharing W3C command execution code), while RemoteWebDriver implements multiple capability interfaces (WebDriver, TakesScreenshot, JavascriptExecutor) and composes a CommandExecutor (HAS-A).

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why does a massive BaseTest god-class slow down and break CI maintenance?
    When BaseTest contains Excel helpers, API clients, UI login steps, DB clients, and 15 @BeforeMethod checks, every test suite loads unnecessary state and a minor refactor to one helper triggers recompilation and regression risks across hundreds of unrelated tests. Decompose utilities into small composable classes injected only where needed.
  2. Why does class PageA extends BasePage, RetryHelper fail to compile?
    Java permits at most one class after extends. Convert shared helper contracts into interfaces or compose a private final RetryHelper retryHelper; instance field inside PageA.
  3. Why did a parent class variable inside a child test return null when both classes declared WebDriver driver;?
    Declaring a field with the same name in a subclass does NOT override the parent's field; it hides (shadows) it as a second distinct Heap slot. Methods defined in the parent still read the parent slot while child methods read the uninitialized child slot. Remove the duplicate field declaration in the subclass.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why does Effective Java advise 'Favor composition over inheritance'?
    Inheritance exposes parent implementation details to subclasses and locks the design permanently at compile time; changing a non-private parent method can break child overrides unexpectedly. Composition interacts strictly through stable public contracts and lets you swap implementations (for example, swapping a mock config reader or headless vs grid driver strategy) cleanly.
  2. When IS inheritance genuinely the right choice in a test automation framework?
    Use inheritance strictly when a genuine IS-A relationship holds and the base class is explicitly designed for extension—for example, BasePage holding shared WebDriverWait click/type wrappers for Page Objects, or BaseTest holding standardized TestNG @BeforeMethod/@AfterMethod driver lifecycle setup.
  3. Why should classes not designed for subclassing be marked final or avoid protected hooks?
    Keeping classes non-inheritable by default prevents external tests from extending utility or concrete Page Object classes in unintended ways that violate internal invariants.
  4. How many classes can one Java class extend directly?
    At most 1 class.
  5. How many interfaces can one Java class implement?
    Unlimited (separated by commas).
  6. What is the root superclass of every Java class?
    java.lang.Object.
  7. Why does Java forbid multiple class inheritance?
    To eliminate the Diamond Problem ambiguity over inherited implementations and state.
  8. Which design relationship does Composition represent?
    HAS-A (holding helper objects as fields).
  9. How should shared UI widgets like Headers and Footers be modeled in Selenium?
    Via Composition using Page Component classes rather than bloating BasePage.
