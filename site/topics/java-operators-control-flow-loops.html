2.4 Operators, Control Flow & Loops

Short-circuit boolean guards (&& vs &), ternary expressions, modern switch expressions, and loop control with break and continue.

Operators and control-flow statements govern branching, retry logic, and element iteration inside every automation helper. Understanding short-circuit evaluation order, switch fall-through traps, and loop termination prevents null dereferences and subtle off-by-one defects.

Before you start

Prerequisite: 2.3 Wrapper Classes, Autoboxing & Integer Cache (-128 to 127)

Where it fits

Null-safe DOM checks (el != null && el.isDisplayed()), browser factory switch selection, and iterating over List<WebElement> product cards in QKart rely directly on short-circuit operators and loop control.

Key points

  1. Short-circuit operators && and || skip evaluating the right-hand operand whenever the left-hand operand already determines the boolean result.
  2. Single & and | evaluate both sides unconditionally on booleans (and act as bitwise operators on integers), breaking null guards if misused.
  3. The ternary operator condition ? exprIfTrue : exprIfFalse evaluates to a single expression value and works cleanly for inline defaults like timeouts or headless flags.
  4. Traditional switch statements fall through into subsequent case blocks unless terminated by break or return; Java 14+ arrow switch expressions (case "chrome" -> ...) eliminate fall-through completely.
  5. while checks the condition before the first iteration (0+ times), whereas do-while executes the body once before checking the condition (1+ times).
  6. break exits the enclosing loop immediately, continue skips the remainder of the current iteration and advances to the next check, and labeled break outer; exits nested loops.

How it works

  1. An incoming browser name string enters an arrow switch expression that maps "chrome", "firefox", or "edge" without needing break.
  2. Inside a search loop over product cards, an if (card == null || !card.isDisplayed()) continue; statement short-circuits safely and skips hidden items.
  3. Once the matching product card is located and clicked, break; exits the loop immediately rather than scanning remaining DOM elements.
  4. For polling loops requiring at least one initial check before evaluating continuation, do { ... } while (...) runs once prior to checking the exit predicate.

Using short-circuit guards, Java 14+ arrow switch, and break/continue over Selenium results:

package dev.java.core; // Declares package

import java.util.List; // Imports List interface

public class ControlFlowDemo { // Demonstrates operators and loop control
    static String resolveBrowserFlag(String browser) { // Method returning CLI flag via switch expression
        return switch (browser.toLowerCase()) { // Modern arrow switch prevents fall-through
            case "chrome", "edge" -> "--headless=new"; // Multiple labels share one branch without break
            case "firefox" -> "-headless"; // Firefox headless argument
            default -> throw new IllegalArgumentException("Unsupported browser: " + browser); // Explicit guard
        }; // Semicolon closes switch expression
    } // Ends resolveBrowserFlag

    public static void main(String[] args) { // Main execution entry
        List<String> titles = List.of("", "QKart Shoe", "QKart Watch"); // Sample product list
        String found = null; // Holds matched title
        for (String title : titles) { // Enhanced for-each iterates elements sequentially
            if (title == null || title.isBlank()) { // Short-circuit OR skips blank check when null
                continue; // Skips blank entry and moves to next element
            } // Ends skip check
            if (title.contains("Shoe")) { // Checks target keyword
                found = title; // Stores matched product title
                break; // Stops scanning remaining products immediately
            } // Ends match check
        } // Ends for-each loop
        String status = (found != null) ? found : "MISSING"; // Ternary assigns fallback value
        System.out.println(resolveBrowserFlag("chrome") + " | " + status); // Prints: --headless=new | QKart Shoe
    } // Ends main method
} // Ends class

Common mistakes

  1. Forgetting break; in a classic case "chrome": switch block; execution falls through into case "firefox": and overwrites or launches the wrong driver.
  2. Using & instead of && in if (el != null & el.isEnabled()); Java still calls el.isEnabled() when el is null and throws NullPointerException.
  3. Writing an assignment = inside an if condition on booleans (if (isAdmin = true)); this assigns true and always enters the branch—always use == or write if (isAdmin) directly.
  4. Writing a for (int i = 0; i <= items.size(); i++) boundary condition; valid indices stop at size() - 1, so <= throws IndexOutOfBoundsException.

Interview questions

Basics

What is the difference between && and & in Java?
When applied to booleans, && (logical short-circuit AND) evaluates the left expression first and skips the right expression completely if the left side is false. Single & evaluates both sides unconditionally and also functions as a bitwise AND operator on integers. For null checks like driver != null && driver.getTitle().contains("QKart"), only && prevents NullPointerException.

How do while and do-while loops differ?
A while loop evaluates its boolean condition before entering the loop body, meaning the body executes zero times if the condition starts out false. A do-while loop runs its body first and evaluates the condition at the bottom, guaranteeing at least one execution. Pagination helpers often use do-while to inspect page 1 before checking if a Next button is enabled.

What is the difference between break and continue inside a loop?
break terminates the enclosing loop entirely and resumes execution at the first statement after the loop. continue aborts only the current pass through the loop body and jumps immediately to the next iteration's update/condition check. Neither keyword exits the enclosing method itself—use return for that.

How it works

Explain operator precedence pitfalls between !, &&, and ||.
Unary negation ! binds tightest, && binds tighter than ||, and assignment = binds last. Writing a || b && c evaluates as a || (b && c) even if the author intended (a || b) && c. Adding explicit parentheses around compound boolean checks prevents subtle logic defects.

How do Java 14+ arrow switch expressions eliminate fall-through bugs?
With arrow labels (case "chrome" -> new ChromeDriver();), only the single expression or block to the right of the arrow executes, and control exits the switch automatically without needing break. Comma-separated labels (case "chrome", "chromium" -> ...) handle shared branches cleanly. If a switch expression assigns to a variable, the compiler also enforces exhaustiveness via default.

How does a labeled break outer; behave inside nested loops?
By placing a label like outer: directly above an outer for loop, a nested inner loop can execute break outer; to exit both loops simultaneously instead of only escaping the inner loop. This removes the need for awkward boolean exit flags when scanning a 2D HTML table for a target cell.

Real situations

In Selenium, when should you choose an index-based for (int i = 0; ...) loop over an enhanced for-each loop?
Use enhanced for-each when reading every element sequentially without needing its position, including collecting text from List<WebElement> product titles. Choose a classic indexed for loop when you need the numeric row/column index to construct a dynamic XPath like //tr[" + (i + 1) + "]/td[3] or to avoid StaleElementReferenceException by re-fetching elements by index.

How does short-circuit || help in fallback locator or retry checks?
In isVisible(primaryLocator) || isVisible(fallbackLocator), if the primary locator succeeds and returns true, Java skips evaluating isVisible(fallbackLocator) completely. This prevents paying an unnecessary implicit or explicit wait timeout on the fallback locator when the primary locator already matched.

Why does String flag = headless ? "--headless=new" : ""; keep Page Object setup concise?
The ternary operator assigns a conditional configuration value in a single expression without declaring an uninitialized mutable variable beforehand. It allows marking the target variable final immediately at declaration.

Troubleshooting

Why did a DriverFactory switch (browser) pass Chrome into FirefoxDriver initialization?
In a classic colon-syntax switch statement, omitting break; at the end of case "chrome": causes execution to fall straight into case "firefox":, overwriting the driver variable. Converting the factory to a modern arrow switch expression makes fall-through syntactically impossible.

Why does for (int i = 0; i <= rows.size(); i++) crash on the final iteration?
Zero-based Java collections and arrays index valid elements from 0 up to size() - 1. Using <= attempts to access index rows.size() on the last pass and throws IndexOutOfBoundsException. Always use strict < (i < rows.size()).

Why does passing null into switch (browser) throw NullPointerException?
Classic and standard switch statements call browser.hashCode() internally during dispatch, crashing immediately if the selector expression is null. Either validate Objects.requireNonNullElse(browser, "chrome") beforehand or use a Java 21 case null -> branch.

Design choices

Why should complex nested if-else chains in DriverFactory or test helpers be replaced with switch expressions or early returns?
Deeply nested if-else ladders increase cyclomatic complexity and make missing edge cases hard to spot in code reviews. Early-return guard clauses flatten nesting, while Java 14+ switch expressions enforce exhaustive handling at compile time.

Why should you avoid nesting multiple ternary operators inside a single expression?
While single ternary expressions (a ? b : c) improve readability for simple defaults, chaining nested ternaries creates dense, error-prone precedence puzzles. Replace multi-branch ternary expressions with an if-else or switch expression.

Why should a loop checking dynamic page state include a maximum iteration or timeout bound?
Unbounded while (true) or while (!ready) loops hang a CI pipeline indefinitely if an AJAX call fails or a spinner freezes in the DOM. Always bound polling loops with a maximum attempt count or Duration deadline (preferring Selenium's built-in WebDriverWait).

Quick answers

  1. Which operator skips the right side when the left side is false? && (short-circuit logical AND).
  2. Which operator skips the right side when the left side is true? || (short-circuit logical OR).
  3. How many times does a do-while loop execute at minimum? At least 1 time.
  4. What happens when break is omitted in a classic switch case? Execution falls through into the next case block.
  5. How do you exit both outer and inner loops at once in Java? Use a labeled break labelName; statement.
  6. Does Java 14+ arrow syntax (case "x" -> ...) fall through? No, fall-through is impossible with arrow labels.
