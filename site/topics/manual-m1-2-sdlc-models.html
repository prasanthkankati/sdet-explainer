1.2 SDLC Models: Waterfall, V-Model, Iterative, Spiral & Agile

1. The Base: What is SDLC and Why Does It Exist?

The Software Development Life Cycle (SDLC) is the structured engineering framework that defines the exact sequence of phases—Requirement Gathering, System Design, Coding, Testing, Deployment, and Maintenance—used to turn a business idea into working production software.

The Problem It Solves: Without a defined SDLC, developers start writing code before business rules are agreed upon ("Cowboy Coding"), QA receives unstable code drops with zero documentation or test servers, and nobody knows when a feature is ready for customers. SDLC establishes clear phase handoffs, deliverables, and quality gates across the entire engineering team.

Core Document Terminology & Their Properties (Defined First):

  • 1. BRS (Business Requirement Specification): High-level document written by the Business Analyst describing WHAT the business/customer needs and WHY (e.g., "Support UPI and Apple Pay checkout to increase conversion by 15%").
  • 2. SRS (System Requirement Specification): Detailed technical specification translating the BRS into HOW the system must behave—exact input fields, validation rules, API error codes, and response times.
  • 3. Agile User Story & Acceptance Criteria: In Agile projects, giant BRS/SRS documents are replaced by bite-sized User Stories ("As a <role>, I want <feature>, so that <value>") paired with testable Acceptance Criteria (exact pass/fail rules QA verifies).
  • 4. HLD (High-Level Design) vs LLD (Low-Level Design):
    • HLD (Macro Architecture): System-wide blueprint created by Architects showing microservices, cloud infrastructure, message queues, and databases.
    • LLD (Micro Component Design): Detailed blueprint showing exact Java class names, method signatures, SQL table columns, and REST API JSON payloads.

3. Classification Tree: How SDLC Models Split

Different projects have different requirement stability and risk profiles (e.g., a fixed-spec NASA spacecraft vs a fast-changing e-commerce app). Based on how and when the 6 phases are executed, SDLC models split into 2 families (5 core models):

  1. Sequential Models (Phases run in one big pass): 1. Waterfall Model, 2. V-Model
  2. Incremental & Evolutionary Models (Software is built in repeated cycles): 3. Iterative & Incremental Model, 4. Spiral Model, 5. Agile Model
SDLC MODELS Classified by Execution Flow & Requirement Flexibility
FAMILY A: SEQUENTIAL MODELS Requirements are locked up front; entire product is delivered at the end.
• 1. Waterfall Model (Linear step-by-step)
• 2. V-Model (Verification paired with Validation)
FAMILY B: INCREMENTAL / CYCLICAL MODELS Product is built, tested, and delivered in repeated increments/loops.
• 3. Iterative & Incremental (Module by module)
• 4. Spiral Model (Risk-driven loops)
• 5. Agile Model (1–4 week Sprints — Industry Standard)

4. Each SDLC Model Defined & Explained in Order

① Waterfall Model (Linear Sequential Model)

  • Definition: Each phase must 100% finish and freeze before the next phase begins (Requirements → Design → Coding → Testing → Deployment). There is no overlapping or going backward.
  • How QA works in Waterfall: QA only enters at Phase 4 (after 100% of coding is finished). If a requirement bug was introduced in Month 1, QA discovers it in Month 9 when fixing it requires rewriting the architecture (10x–100x cost).
  • In what exact cases we use it: Short, small projects where requirements are 100% clear, fixed, and guaranteed not to change (e.g., migrating a static legacy report).

② V-Model (Verification and Validation Model)

  • Definition: An extension of Waterfall where every Left-Side Development (Verification) phase is directly paired with a Right-Side Testing (Validation) phase, forming a V-shape with Coding at the bottom vertex.
  • How QA works in V-Model: QA starts on Day 1. While architects write a design document on the left side, QA simultaneously reviews it (Static Verification) and writes the corresponding test cases for the right side (Dynamic Validation):

③ Iterative & Incremental Model

  • Definition: Instead of building the entire application in one giant pass, the system is divided into smaller functional modules built across repeated mini-SDLC cycles (Cycle 1 builds & tests Login; Cycle 2 adds & tests Search + runs Regression on Login; Cycle 3 adds & tests Checkout).
  • In what exact cases we use it: Large enterprise systems where core requirements are known, so high-priority modules can be delivered early and refined over cycles.

④ Spiral Model (Risk-Driven Model)

  • Definition: Combines iterative prototyping with formal risk analysis. Every loop of the spiral passes through 4 quadrants: (1) Determine Objectives, (2) Identify & Resolve Risks (Build Prototype), (3) Develop & Test, (4) Plan Next Iteration with Customer.
  • In what exact cases we use it: High-budget, high-risk R&D, defense, aerospace, or first-of-a-kind financial trading engines where technical feasibility is uncertain up front.

⑤ Agile Model (Scrum / Kanban — Modern Industry Standard)

  • Definition: Breaks the product into small user-centric features (User Stories) delivered in fixed time-boxes called Sprints (typically 2 weeks). Each sprint is a complete mini-SDLC producing a working, tested, potentially shippable product increment.
  • How QA & SDET work in Agile: QA is embedded inside the development team from Day 1 of the sprint. Manual testing, API testing, and Selenium/Playwright UI automation happen inside the same sprint ("In-Sprint Automation"), while CI/CD pipelines run automated regression on every code push.
  • In what exact cases we use it: Almost all modern SaaS, e-commerce, banking apps, mobile apps, and cloud platforms where requirements evolve rapidly with market feedback.

Interview Answer: "In Waterfall, testing happens only at the end after coding completes. In the V-Model, every development stage is paired with a testing stage designed in parallel (LLD to Unit, HLD to Integration, SRS to System, BRS to UAT). In Agile, development, manual testing, and Selenium/API automation happen together inside short 2-week sprints with continuous CI/CD delivery."

// Phase 3 (Coding): Build Page Object while Developer codes the feature

    private final WebDriver driver;
    private final By payButton = By.id("pay-now-btn");

    public PaymentPage(WebDriver driver) { this.driver = driver; }
    public void submitPayment() { driver.findElement(payButton).click(); }
}

7. Self-Check

  1. In the V-Model, which testing level pairs directly with HLD (High-Level Design) and which pairs with LLD (Low-Level Design)? (HLD → Integration Testing; LLD → Unit Testing)
  2. Which SDLC model explicitly dedicates a quadrant of every cycle to Risk Analysis and Prototyping? (Spiral Model)
  3. Why does Regression Testing grow after every cycle in Iterative and Agile models? (Because each new sprint/iteration adds features on top of previous increments, requiring automated regression to ensure old features didn't break.)
