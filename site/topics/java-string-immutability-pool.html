3.1 String Immutability & String Constant Pool

1. Definition

A Java String cannot be changed once created, and literal strings share one reused slot inside the String Constant Pool on the Heap while new String() always allocates a separate Heap object.

2. Memory hook

Literals share the Pool; new String() buys a fresh Heap box; == checks address, .equals() checks letters.

  • Immutable + final: modifying a String always creates a new String object rather than overwriting old characters.
  • Pool reuse: two "QA" literals point to the exact same pooled object to save memory.
  • intern(): moves or fetches the matching pooled reference for a runtime String.

5. Code example: literal pooling vs new String() and immutability

public class StringPoolDemo {
    public static void main(String[] args) {
        String s1 = "Selenium";                   // created once in String Pool
        String s2 = "Selenium";                   // reuses exact same Pool object
        String s3 = new String("Selenium");       // forces separate Heap object outside Pool

        System.out.println(s1 == s2);             // true (same address in Pool)
        System.out.println(s1 == s3);             // false (Pool != normal Heap)
        System.out.println(s1.equals(s3));        // true (same characters)

        s1.concat(" 4");                          // new String("Selenium 4") created & dropped!
        System.out.println(s1);                   // still "Selenium" (immutable)
    }
}

6. Execution flow, step by step

  1. The first literal "Selenium" creates one pooled object inside the Heap's String Constant Pool.
  2. s2 = "Selenium" finds the matching entry already in the pool and assigns the identical reference to s2.
  3. new String("Selenium") bypasses the pool reference and allocates an extra non-pooled Heap object referenced by s3.
  4. s1 == s3 compares memory addresses and prints false, while s1.equals(s3) checks characters and prints true.
  5. Calling s1.concat(" 4") without saving its return value leaves s1 untouched at "Selenium".

8. Why it matters

Immutability keeps String keys safe in HashMap (cached hashcode), thread-safe across parallel threads without locking, and safe for DB/URL credentials.

SDET link: driver.getTitle() and element.getText() construct runtime Strings on the Heap outside the literal pool, so writing if (driver.getTitle() == "QKart") fails! Always compare UI text using .equals(...) or TestNG Assert.assertEquals.

9. Quick test

Why does String s = "hi"; s.toUpperCase(); System.out.println(s); still print hi? Because Strings are immutable and the returned uppercase String was not assigned back to s.
