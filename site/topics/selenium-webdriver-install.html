2.1 Install Selenium Library

Setting up the Selenium Java client library in Maven (pom.xml) or Gradle (build.gradle) projects.

Installing the Selenium library means adding the official org.seleniumhq.selenium:selenium-java dependency to your Java build tool. Once declared in Maven or Gradle, the build tool automatically downloads the WebDriver APIs, browser-specific driver classes, and the built-in Selenium Manager binary.

Before you start

Prerequisite: 1.1 About Selenium & Components

Where it fits

Dependency configuration is the very first setup step in any Java test automation repository before writing page objects or test classes.

Key points

  1. The official Maven coordinates for Selenium 4 in Java are groupId org.seleniumhq.selenium and artifactId selenium-java.
  2. Selenium 4 requires a minimum of Java 11 at both compile time and runtime.
  3. Adding selenium-java pulls transitive dependencies for Chrome, Firefox, Edge, Safari, RemoteWebDriver, and Selenium Manager automatically.
  4. You should never mix different versions of individual selenium-* sub-artifacts (such as selenium-chrome-driver and selenium-api) in the same pom.xml.
  5. In Selenium 4.6+, third-party driver managers like WebDriverManager are no longer required because Selenium Manager is bundled inside selenium-java.

How it works

  1. The engineer creates a standard Maven or Gradle Java project with JDK 11 or newer configured.
  2. The engineer declares org.seleniumhq.selenium:selenium-java inside the dependencies block of pom.xml or build.gradle.
  3. Maven or Gradle queries Maven Central, resolves the dependency tree, and downloads the JAR artifacts to the local ~/.m2 or ~/.gradle cache.
  4. The IDE indexes the downloaded JARs, making org.openqa.selenium.* packages available for import in Java test classes.

Maven pom.xml configuration for Selenium 4 and TestNG:

<project xmlns="http://maven.apache.org/POM/4.0.0"> <!-- Root Maven POM element -->
    <modelVersion>4.0.0</modelVersion> <!-- POM model version required by Maven -->
    <groupId>dev.selenium.qa</groupId> <!-- Organization package identifier -->
    <artifactId>selenium-automation-suite</artifactId> <!-- Project module name -->
    <version>1.0.0</version> <!-- Project build version -->
    <properties> <!-- Central properties block for versions -->
        <maven.compiler.source>21</maven.compiler.source> <!-- Sets Java source compatibility to JDK 21 -->
        <maven.compiler.target>21</maven.compiler.target> <!-- Sets bytecode target to JDK 21 -->
        <selenium.version>4.26.0</selenium.version> <!-- Centralizes the Selenium 4 version -->
    </properties> <!-- Ends properties block -->
    <dependencies> <!-- Starts dependency declarations -->
        <dependency> <!-- Declares the umbrella Selenium Java library -->
            <groupId>org.seleniumhq.selenium</groupId> <!-- Official Selenium group ID -->
            <artifactId>selenium-java</artifactId> <!-- Umbrella artifact including all drivers -->
            <version>${selenium.version}</version> <!-- Resolves version from properties -->
        </dependency> <!-- Ends Selenium dependency -->
    </dependencies> <!-- Ends dependencies block -->
</project> <!-- Ends Maven POM -->

Common mistakes

  1. Declaring both selenium-java and older individual artifacts like selenium-chrome-driver with mismatched versions; fix by declaring only selenium-java.
  2. Running Selenium 4 on JDK 8; fix by upgrading JAVA_HOME and maven.compiler.release to JDK 11, 17, or 21.
  3. Placing selenium-java under <dependencyManagement> without adding it to <dependencies>; fix by placing it directly in the <dependencies> section so JARs are added to the classpath.

Interview questions

Basics

What are the exact Maven coordinates to install Selenium in a Java project?
You add the dependency with groupId org.seleniumhq.selenium and artifactId selenium-java inside your pom.xml file. This single umbrella dependency pulls all supported browser driver bindings and Selenium Manager automatically.

What is the minimum Java version required to compile and run Selenium 4?
Selenium 4 requires a minimum of Java 11. Attempting to compile or run Selenium 4 classes on Java 8 results in an UnsupportedClassVersionError because the library bytecode is compiled for class file version 55.0.

Do you need to download chromedriver.exe manually after installing selenium-java?
No. Starting in Selenium 4.6, Selenium Manager is bundled directly inside selenium-java and automatically detects your installed browser version and downloads the matching driver binary on the fly.

How it works

What transitive dependencies are included when you add selenium-java to pom.xml?
Adding selenium-java automatically resolves selenium-api, selenium-support, selenium-remote-driver, selenium-chrome-driver, selenium-firefox-driver, selenium-edge-driver, selenium-safari-driver, and the native Selenium Manager binaries.

Where does Maven store the downloaded Selenium JAR files on your machine?
Maven caches all downloaded JAR artifacts inside the local repository located at ~/.m2/repository/org/seleniumhq/selenium/. Subsequent builds reuse these cached JARs without re-downloading them from Maven Central.

How do you centralize the Selenium version across a multi-module Maven framework?
Define a custom property such as <selenium.version>4.26.0</selenium.version> inside the parent pom.xml <properties> block and reference it via ${selenium.version}. This ensures every submodule upgrades in lockstep by changing a single line.

Real situations

Should you set the Maven scope of selenium-java to compile or test?
If your Page Object classes and driver factory live in src/main/java, keep the default compile scope so main classes can import WebDriver. If all framework and test classes live strictly inside src/test/java, you can use <scope>test</scope>.

How do you upgrade Selenium in a CI/CD project without breaking existing tests?
Update the <selenium.version> property in pom.xml, run mvn dependency:tree to verify no transitive version conflicts exist, and execute the smoke test suite on CI before merging.

Why do enterprise teams use a corporate artifact repository like Nexus or Artifactory for selenium-java?
Enterprise CI runners often block direct outbound internet access to Maven Central for security. An internal Nexus or Artifactory server proxies and caches verified selenium-java JARs inside the corporate firewall.

Troubleshooting

How do you fix java.lang.NoClassDefFoundError: org/openqa/selenium/WebDriver?
This error occurs when selenium-java is missing from the runtime classpath or was declared with <scope>test</scope> while being referenced by code in src/main/java. Fix it by removing <scope>test</scope> or running mvn test-compile.

How do you diagnose a NoSuchMethodError inside internal Selenium classes after an upgrade?
NoSuchMethodError indicates a dependency version collision where an older transitive selenium-api or Guava JAR overrides the newer version on the classpath. Run mvn dependency:tree -Dverbose to locate the conflicting dependency and exclude the older transitive artifact.

What causes UnsupportedClassVersionError (class file version 55.0) when running a Selenium test?
Class file version 55.0 corresponds to Java 11, meaning your IDE or Maven runner is executing with a JDK 8 runtime. Update your project SDK and JAVA_HOME environment variable to JDK 11, 17, or 21.

Design choices

Why is declaring the single selenium-java artifact preferred over declaring individual browser driver artifacts?
Declaring selenium-java guarantees that selenium-api, selenium-remote-driver, selenium-support, and all browser driver classes share the exact same release version. Mixing individual artifacts frequently causes binary incompatibility exceptions.

Why did Selenium 4 replace the Apache HttpClient / OkHttp transport layer with the built-in Java 11+ HttpClient?
By adopting the standard java.net.http.HttpClient introduced in Java 11, Selenium reduced external third-party library conflicts, added native HTTP/2 and WebSocket support for BiDi, and shrank the dependency footprint.

Why should you remove io.github.bonigarcia:webdrivermanager when migrating to modern Selenium 4?
Selenium Manager is natively integrated into Selenium 4 and performs driver and browser discovery automatically as a fallback whenever a driver session starts. Removing external driver managers eliminates redundant network checks and extra third-party dependencies.

Quick answers

  1. What is the Maven artifactId for Selenium? selenium-java under groupId org.seleniumhq.selenium.
  2. What is the minimum JDK version for Selenium 4? Java 11 (JDK 17 or 21 recommended for production).
  3. Does selenium-java include Select and Actions classes? Yes, selenium-support is pulled automatically as a transitive dependency.
  4. How do you inspect version conflicts in Maven? Run mvn dependency:tree from the project root.
  5. Is WebDriverManager needed in Selenium 4.6+? No, built-in Selenium Manager resolves drivers automatically.
