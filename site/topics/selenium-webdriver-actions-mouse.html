7.1 Mouse Actions

Simulating complex pointer gestures with the Actions API: moveToElement (hover), contextClick (right-click), doubleClick, dragAndDrop, and clickAndHold.

The Selenium Actions class implements the W3C WebDriver Actions API to simulate low-level hardware input devices (mouse pointer, keyboard, touch/pen, and scroll wheel). Mouse actions allow tests to hover over dropdown menus (moveToElement), right-click context menus (contextClick), double-click elements (doubleClick), and drag-and-drop items across the viewport.

Before you start

Prerequisite: 6.3 FluentWait Configuration

Where it fits

The Actions class is used in Page Objects whenever an interaction requires hovering, right-clicking, double-clicking, or dragging elements.

Key points

  1. Every Actions chain MUST end with .perform() (which internally calls .build().perform()) to transmit the action sequence to the browser.
  2. moveToElement(WebElement) moves the virtual mouse pointer to the in-view center of the element, triggering CSS :hover and mouseover events.
  3. contextClick(WebElement) performs a right-click on the target element; doubleClick(WebElement) performs a rapid double left-click.
  4. dragAndDrop(source, target) presses and holds on source, moves to target, and releases the mouse button (equivalent to clickAndHold(source).moveToElement(target).release()).
  5. If a pointer movement target lies outside the current browser viewport bounds, the driver throws MoveTargetOutOfBoundsException.

How it works

  1. Instantiate Actions actions = new Actions(driver).
  2. Chain one or more pointer gestures such as actions.moveToElement(menu).pause(Duration.ofMillis(200)).click(submenu).
  3. Call .perform() at the end of the chain to compile the composite Action and send the W3C /actions payload to the driver.
  4. The browser executes the low-level pointer ticks sequentially in real time.

Performing hover, right-click, double-click, and drag-and-drop with Actions:

package dev.selenium.actions; // Declares package

import org.openqa.selenium.By; // Imports By locator class
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.interactions.Actions; // Imports Actions API class

public class MouseActionsExample { // Declares class
    public static void main(String[] args) { // Main method
        WebDriver driver = new ChromeDriver(); // Starts Chrome session
        try { // Guarded block
            driver.get("https://www.selenium.dev/selenium/web/mouse_interaction.html"); // Loads mouse test page
            Actions actions = new Actions(driver); // Creates Actions builder bound to driver

            WebElement hoverable = driver.findElement(By.id("hover")); // Locates hover target
            actions.moveToElement(hoverable).perform(); // Moves mouse to center of element and executes

            WebElement clickable = driver.findElement(By.id("clickable")); // Locates input target
            actions.contextClick(clickable).perform(); // Performs right-click on element
            actions.doubleClick(clickable).perform(); // Performs double-click on element

            WebElement draggable = driver.findElement(By.id("draggable")); // Locates drag source
            WebElement droppable = driver.findElement(By.id("droppable")); // Locates drop target
            actions.dragAndDrop(draggable, droppable).perform(); // Drags source onto target and releases
        } finally { // Teardown block
            driver.quit(); // Closes browser
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Chaining actions.moveToElement(menu).click(subMenu) and forgetting to call .perform() at the end, which does nothing at all and throws no error; fix by always ending with .perform().
  2. Moving the OS physical mouse cursor across the monitor while a headed test runs, which can interfere with native hover states; run in headless mode or keep the physical cursor outside the browser window.
  3. Calling moveToElement() on an element that is scrolled far below the viewport without scrolling it into view first, which throws MoveTargetOutOfBoundsException.

Interview questions

Basics

What is the difference between calling build() and perform() on the Actions class?
build() compiles the chained actions into a composite Action object without executing it. perform() internally calls build().perform() and immediately executes the actions. In everyday tests, calling .perform() alone is sufficient.

How do you hover over a navigation menu to reveal a dropdown in Selenium?
Instantiate Actions actions = new Actions(driver); locate the menu WebElement, and call actions.moveToElement(menuElement).perform().

How do you perform a right-click and a double-click in Selenium?
Use new Actions(driver).contextClick(element).perform() for a right-click, and new Actions(driver).doubleClick(element).perform() for a double-click.

How it works

How does element.click() differ from new Actions(driver).click(element).perform()?
WebElement.click() uses the W3C Element Click endpoint, which automatically scrolls the element into view and checks interactability. Actions.click(element) uses the W3C Actions endpoint, moving the virtual mouse pointer to the element's current viewport coordinates and clicking without auto-scrolling.

What sequence of primitive actions does dragAndDrop(source, target) execute internally?
It executes clickAndHold(source), moves the pointer to the center of target via moveToElement(target), and releases the mouse button via release().

How do you insert a brief delay inside an Actions chain (for example, holding a drag for 500ms)?
Chain .pause(Duration.ofMillis(500)) between clickAndHold(source) and moveToElement(target) before calling .perform().

Real situations

How do you move a horizontal price range slider by 80 pixels to the right?
Locate the slider handle WebElement and call new Actions(driver).dragAndDropBy(sliderHandle, 80, 0).perform().

Why does dragAndDrop(source, target) sometimes fail on HTML5 draggable elements, and how do you fix it?
Some HTML5 drag-and-drop libraries require a small initial pointer movement or pause after mousedown to register the drag start. Chain clickAndHold(src).pause(Duration.ofMillis(200)).moveByOffset(5, 5).moveToElement(tgt).release().perform().

How do you click at a specific pixel offset from the center of a <canvas> element?
Call new Actions(driver).moveToElement(canvas, offsetX, offsetY).click().perform(). Note that in W3C Selenium 4, offsets in moveToElement(el, x, y) are calculated from the center of the element, not the top-left corner.

Troubleshooting

What causes MoveTargetOutOfBoundsException when using Actions.moveToElement()?
Unlike WebElement.click(), Actions.moveToElement() does not automatically scroll off-screen elements into the viewport. Call new Actions(driver).scrollToElement(element).moveToElement(element).perform() first.

Why did my Actions hover line execute with zero errors, yet the dropdown menu never opened?
First, verify you called .perform() at the end of the chain. Second, if the submenu renders asynchronously on hover, wait for ExpectedConditions.visibilityOfElementLocated(subMenuBy) before clicking the submenu.

Why did moveToElement(element, 10, 10) click a different spot after upgrading from Selenium 3 to Selenium 4?
In legacy Selenium 3 (JSON Wire Protocol), offsets were measured from the top-left corner (0,0) of the element. In W3C Selenium 4, offsets are measured from the in-view center point of the element.

Design choices

Should you use Actions.click(element) for every button click in your framework?
No. Standard WebElement.click() is preferred for normal buttons and links because it automatically scrolls the element into view and performs full W3C hit-testing.

Why is creating a new Actions(driver) instance per interaction recommended over storing a single Actions field?
An Actions instance maintains an internal queue of input ticks. Creating a fresh new Actions(driver) per method guarantees no leftover pointer state from an earlier failed action.

How do you explicitly reset all depressed mouse buttons and modifier keys if an action fails mid-chain?
Cast driver to Interactive and call ((Interactive) driver).resetInputState().

Quick answers

  1. What method must terminate every Actions chain? .perform() must be called to execute the queued actions.
  2. Which Actions method hovers over an element? actions.moveToElement(element).perform().
  3. Which Actions method right-clicks an element? actions.contextClick(element).perform().
  4. Where are (x, y) offsets measured from in Selenium 4 moveToElement(el, x, y)? From the center point of the element.
  5. What exception occurs if moveToElement targets an off-screen element? MoveTargetOutOfBoundsException (scroll to the element first).
