5.4 Map: HashMap Internal Working & equals/hashCode Contract

HashMap put/get bucket mechanics, load factor 0.75 resizing, Java 8 Red-Black Tree treeification at threshold 8, equals/hashCode contract, and ConcurrentHashMap.

A Map<K, V> associates unique keys to values, and HashMap is Java's most frequently asked interview data structure because its performance hinges on hashing, collision handling, and the equals()/hashCode() contract. Knowing how buckets resize, treeify in Java 8+, and behave under concurrency explains both O(1) lookups and thread-safety hazards.

Before you start

Prerequisite: 5.3 Set: HashSet vs LinkedHashSet vs TreeSet

Where it fits

Configuration properties maps, Excel row-to-map TestNG DataProviders, API header/query parameter maps, and JSON object parsing all rely directly on HashMap, LinkedHashMap, and ConcurrentHashMap.

Key points

  1. HashMap starts with a default initial capacity of 16 buckets (power of 2) allocated lazily on the first put() and a default load factor of 0.75 (resizing to 2x capacity when size exceeds threshold 16 * 0.75 = 12).
  2. Bucket index calculation mixes upper bits via (h = key.hashCode()) ^ (h >>> 16) and computes (table.length - 1) & hash (fast bitwise AND replacing modulo).
  3. When two distinct keys map to the same bucket (a hash collision), nodes form a linked list; in Java 8+, once a single bucket reaches TREEIFY_THRESHOLD = 8 (and table length >= 64), that bucket converts into a balanced Red-Black Tree, improving worst-case lookup from O(n) to O(log n).
  4. If a bucket drops back down to UNTREEIFY_THRESHOLD = 6 during removals or resizing, the tree converts back into a linked list.
  5. The equals() & hashCode() Contract: If a.equals(b) is true, then a.hashCode() == b.hashCode() MUST be true; unequal objects MAY share the same hash code (collision).
  6. HashMap allows 1 null key and multiple null values (not thread-safe); Hashtable is legacy-synchronized forbidding any null; ConcurrentHashMap uses fine-grained CAS + bucket-level locking forbidding null keys and values.

How it works

  1. On map.put(key, value), HashMap checks if key == null (routing straight to bucket 0); otherwise it computes perturbed hash(key) and bucket index (n - 1) & hash.
  2. If the bucket slot is empty, it inserts a new Node<K, V> directly.
  3. If the bucket is occupied (collision), it walks the linked list or Red-Black Tree checking node.hash == hash && (node.key == key || key.equals(node.key)): if matched, it overwrites the old value and returns it; if absent, it appends the new node.
  4. If the linked chain length hits 8 (and total table capacity is at least 64), treeifyBin() converts the bucket into a Red-Black Tree.
  5. On map.get(key), HashMap locates the exact same bucket via hash(key), compares key equality via equals(), and returns the matching value or null.

Implementing equals/hashCode properly on a key class and iterating entries safely via entrySet():

package dev.java.collections; // Declares package

import java.util.HashMap; // Imports HashMap implementation
import java.util.Map; // Imports Map interface
import java.util.Objects; // Imports Objects.equals and Objects.hash

final class EnvKey { // Custom immutable Map key class
    private final String env; // Immutable field participating in hashCode and equals
    private final String browser; // Second immutable key field

    EnvKey(String env, String browser) { // Constructor initializes immutable key fields
        this.env = env; // Assigns environment name
        this.browser = browser; // Assigns browser name
    } // Ends constructor

    @Override // Overrides Object.equals per HashMap contract
    public boolean equals(Object o) { // Checks logical equivalence of two keys
        if (this == o) return true; // Short-circuits same Heap address
        if (!(o instanceof EnvKey other)) return false; // Rejects null or unrelated types
        return Objects.equals(env, other.env) && Objects.equals(browser, other.browser); // Compares fields
    } // Ends equals

    @Override // Always override hashCode whenever equals is overridden
    public int hashCode() { // Guarantees equal EnvKey instances produce identical bucket hashes
        return Objects.hash(env, browser); // Computes consistent hash from exact equals fields
    } // Ends hashCode
} // Ends EnvKey class

public class HashMapInternalsDemo { // Demonstrates custom key contract and entrySet iteration
    public static void main(String[] args) { // Main method starts
        Map<EnvKey, String> urls = new HashMap<>(); // Capacity 16, load factor 0.75
        urls.put(new EnvKey("qa", "chrome"), "https://qkart-qa-web.labs.crio.do/"); // Stores entry
        String target = urls.get(new EnvKey("qa", "chrome")); // New EnvKey matches same bucket + equals -> found
        for (Map.Entry<EnvKey, String> entry : urls.entrySet()) { // Efficient single-lookup iteration
            System.out.println("Resolved URL: " + entry.getValue()); // Prints: Resolved URL: https://qkart-qa-web.labs.crio.do/
        } // Ends entrySet loop
        System.out.println("Lookup match: " + target); // Prints QKart URL cleanly
    } // Ends main method
} // Ends class

Common mistakes

  1. Overriding equals() on a key class while forgetting to override hashCode(); two logically equal keys hash to different buckets so map.get(new Key("a")) returns null.
  2. Using mutable objects as HashMap keys and mutating fields after put(); the key remains trapped inside its original hash bucket and becomes unreachable.
  3. Iterating a Map via for (String k : map.keySet()) { val = map.get(k); } instead of map.entrySet(); looking up map.get(k) repeats hashing for every key, whereas entrySet() reads keys and values together in one pass.
  4. Assuming map.get(k) == null guarantees the key is absent; the key could be explicitly mapped to a null value—always check map.containsKey(k).

Interview questions

Basics

Explain the equals() and hashCode() contract and why breaking it breaks HashMap.
The contract states two rules: 1) If a.equals(b) is true, then a.hashCode() MUST equal b.hashCode(). 2) Having identical hashCode() values does NOT force a.equals(b) to be true (collisions are allowed). If you override equals() without hashCode(), two equal keys land in different buckets, making map.get(key) return null because it searches the wrong bucket.

Compare HashMap, LinkedHashMap, and TreeMap.
HashMap delivers O(1) average lookup with unpredictable iteration order and permits 1 null key. LinkedHashMap preserves insertion order (or LRU access order) via an internal doubly-linked list across entries at O(1) speed. TreeMap stores entries sorted by key inside a Red-Black Tree in O(log n) time and throws NullPointerException on a null key.

Why is ConcurrentHashMap preferred over Hashtable and Collections.synchronizedMap()?
Hashtable and synchronizedMap() lock the entire map object on every get() and put(), serializing all parallel threads into a single bottleneck. ConcurrentHashMap allows lock-free concurrent reads (via volatile reads) and restricts write locking to just the single bucket head node using CAS and fine-grained synchronized blocks.

How it works

Trace every step of map.put("env", "qa") inside HashMap.
First, if the internal bucket table is still null, HashMap allocates 16 buckets. Next, it computes "env".hashCode(), perturbs upper bits with h ^ (h >>> 16), and finds the bucket index using (16 - 1) & hash. If the bucket is empty, it creates a Node; if occupied, it traverses the chain/tree checking equals() to update an existing key or append a new node, doubling table capacity when size crosses 12.

What changed in HashMap collision handling in Java 8?
In Java 7 and earlier, all colliding entries inside one bucket lived in a singly linked list, causing worst-case get() lookup to degrade to O(n) under heavy hash collisions or denial-of-service attacks. Java 8 converts any bucket chain reaching TREEIFY_THRESHOLD = 8 (provided total table capacity is at least MIN_TREEIFY_CAPACITY = 64; otherwise it resizes first) into a balanced Red-Black Tree, bounding worst-case bucket lookup to O(log n).

Why did Java choose a default load factor of 0.75 instead of 0.5 or 1.0?
A low load factor like 0.5 wastes half the bucket array in empty slots and triggers frequent expensive table resizes. A high load factor like 1.0 fills every slot densely, increasing collision chain lengths and slowing down lookups. Empirical analysis established 0.75 as the optimal balance between space overhead and minimal hash collisions.

Real situations

How do SDETs solve the classic 'count frequency of every character or word in a string' interview program using HashMap?
Iterate through characters or split words and update counts cleanly in one line using Java 8's map.merge(ch, 1, Integer::sum) or map.put(ch, map.getOrDefault(ch, 0) + 1). Using getOrDefault or merge avoids verbose containsKey null branches.

In a parallel TestNG framework caching API auth tokens across test threads by role name, which map should you use?
Use ConcurrentHashMap<String, String> alongside atomic tokens.computeIfAbsent(role, r -> fetchToken(r)). That prevents race conditions when two parallel threads simultaneously request the first token for the same role, and avoids ConcurrentModificationException during concurrent updates.

When mapping Excel column headers to cell values per test row, why choose LinkedHashMap over HashMap?
LinkedHashMap preserves the exact left-to-right column order from the spreadsheet, making failure logs and serialized test reports deterministic and readable.

Troubleshooting

Why did storing test threads' data in a non-synchronized HashMap cause an infinite loop (100% CPU) in Java 7 or lost updates in Java 8?
Concurrent put() calls resizing a standard HashMap across parallel threads can overwrite bucket pointers simultaneously, corrupting entries or (in Java 7) forming cyclic linked-list pointers during rehash. Never share an unsynchronized HashMap across writing threads—use ConcurrentHashMap instead.

Why did concurrentMap.put("token", null) throw NullPointerException when HashMap allowed it?
In a concurrent map, if map.get(key) returned null, a caller could never tell whether the key was absent or mapped to null because another thread could delete the key between containsKey() and get(). To prevent ambiguous race checks, ConcurrentHashMap strictly forbids both null keys and null values.

Why does a HashMap fail to find a custom ByWrapper key even though both instances print identical fields?
Either hashCode() was omitted (sending lookups to a different bucket), equals() was overloaded with the wrong parameter type (missing @Override), or a mutable field inside the key changed after insertion.

Design choices

Why does HashMap require bucket table capacity to always be a power of 2 (16, 32, 64)?
When table length n is a power of 2, n - 1 has all binary lower bits set to 1 (for example, 15 = 0b1111). Computing (n - 1) & hash produces the identical remainder as hash % n using a single CPU bitwise AND instruction instead of slower integer division.

Why does HashMap store keys via Immutable types like String or Integer by default in real projects?
Immutable keys never change fields after insertion, cache their hashCode() safely, and eliminate bucket corruption defects caused by post-insertion mutation.

When writing a custom LRU cache for test fixtures or mock API responses, how does LinkedHashMap build one effortlessly?
Calling new LinkedHashMap<>(16, 0.75f, true) enables access-order mode and overriding removeEldestEntry(Map.Entry eldest) { return size() > maxEntries; } automatically evicts the least recently accessed entry on every insertion.

Quick answers

  1. What are HashMap's default initial capacity and load factor? Capacity 16, load factor 0.75 (resize threshold 12).
  2. At what bucket chain length does Java 8 HashMap treeify into a Red-Black Tree? 8 nodes (when table capacity is at least 64).
  3. Can ConcurrentHashMap store null keys or null values? No; either throws NullPointerException.
  4. Which method iterates both keys and values in a single lookup? map.entrySet().
  5. What happens if two objects have a.equals(b) == true but different hashCode() values? Violates the contract; HashMap fails to find keys on get().
  6. Which Map preserves insertion order? LinkedHashMap.
