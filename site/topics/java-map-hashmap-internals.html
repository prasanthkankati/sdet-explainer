5.4 Map: HashMap Internal Working & equals/hashCode

1. Definition

HashMap hashes each key to compute a bucket index inside an array (default 16 slots, 0.75 load factor), chaining collisions per bucket (treeifying at 8 nodes in Java 8+) and relying strictly on the hashCode/equals contract.

2. Memory hook

Equal objects MUST share the same hashCode! Default 16 buckets, 0.75 resize, treeifies at 8!

  • Bucket formula: index = hash & (capacity - 1) maps a key into array slot 0..15.
  • Collision rule (Java 8+): colliding nodes form a linked list, then convert into a Red-Black Tree once bucket chain length hits 8 (and capacity >= 64).
  • Contract rule: if a.equals(b) is true, a.hashCode() == b.hashCode() MUST be true — or HashMap.get() checks the wrong bucket!

3. Inside HashMap Bucket Lookup & Resizing

map.put(key, value) Flow
Use immutable keys like String or Integer so hashes never change while inside the Map.
1. Compute Hashhash(key.hashCode()) spreads bits across array slots
2. Pick BucketLands on slot i; if occupied, walk chain comparing keys via equals()
3. Resize / TreeifySize > 16 * 0.75 = 12 doubles array to 32; 8+ collisions -> Red-Black Tree

5. Code example: pairing QKart user test data safely with Map & overriding equals/hashCode

import java.util.*;

public class HashMapContractDemo {
    static final class ItemKey {
        final String sku;
        ItemKey(String sku) { this.sku = sku; }
        @Override public int hashCode() { return Objects.hash(sku); } // MUST match equals!
        @Override public boolean equals(Object o) {
            return (o instanceof ItemKey k) && Objects.equals(sku, k.sku);
        }
    }

    public static void main(String[] args) {
        Map<ItemKey, Double> prices = new HashMap<>();
        prices.put(new ItemKey("SHOE-01"), 49.99);
        Double p = prices.get(new ItemKey("SHOE-01")); // finds 49.99 ONLY because hashCode+equals match!
        System.out.println("Price = " + p);
    }
}

6. Execution flow, step by step

  1. Calling prices.put(new ItemKey("SHOE-01"), 49.99) computes Objects.hash("SHOE-01") to pick bucket slot i.
  2. When looking up with a brand-new new ItemKey("SHOE-01") instance, get() computes the identical hash to land on the same slot i.
  3. Inside slot i, equals() compares "SHOE-01" strings and returns 49.99.
  4. Had hashCode() not been overridden, the two objects would hash to different buckets and get() would wrongly return null!
  5. Once entries pass 12 (75% of 16), HashMap doubles capacity to 32 and rehashes keys.

8. Why it matters

O(1) key-value lookup underpins caches, config tables, and object deduplication — yet breaking the hashCode/equals pair creates invisible ghost keys.

SDET link: Framework configs load into Map<String, String>, Excel rows map column header -> value per row via LinkedHashMap (keeping sheet column order!), and parallel test caches require ConcurrentHashMap instead of unsynchronized HashMap.

9. Quick test

What happens if two objects satisfy a.equals(b) == true but return different hashCode() integers? HashMap.get(b) searches a different bucket and fails to find key a!
