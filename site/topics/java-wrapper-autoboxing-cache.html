2.3 Wrapper Classes, Autoboxing & Integer Cache (-128 to 127)

1. Definition

Wrapper classes wrap each of the 8 primitives inside an immutable Heap object so Generics and Collections can hold them, while Integer caches objects from -128 to 127 — breaking == above 127.

2. Memory hook

Primitive -> Object = Boxing; -128..127 is reused; beyond 127 always use .equals()!

  • 8 Wrapper classes: Byte, Short, Integer, Long, Float, Double, Character, Boolean.
  • Autoboxing / Unboxing: compiler automatically inserts Integer.valueOf(x) and obj.intValue().
  • Trap: unboxing a null Wrapper throws NullPointerException.

5. Code example: the 127 vs 200 Integer == trap and parseInt

import java.util.*;

public class WrapperCacheDemo {
    public static void main(String[] args) {
        Integer a = 100, b = 100;     // compiler calls Integer.valueOf(100) -> cached
        Integer x = 200, y = 200;     // outside -128..127 -> two distinct Heap objects!
        System.out.println("100 == : " + (a == b));       // true (same cached object)
        System.out.println("200 == : " + (x == y));       // FALSE! different addresses
        System.out.println("200 eq : " + x.equals(y));    // true (compares 200 == 200)

        int qty = Integer.parseInt("3");                  // string UI badge -> primitive int
        System.out.println("Qty = " + qty);
    }
}

6. Execution flow, step by step

  1. Java loads IntegerCache once at startup containing objects for -128 through 127.
  2. Integer a = 100 autoboxes using Integer.valueOf(100) and points both a and b to slot 100 in the cache.
  3. Integer x = 200 misses the cache and runs new Integer(200) twice, leaving x and y at different Heap addresses.
  4. x == y compares addresses and returns false, whereas x.equals(y) compares numeric values and returns true.
  5. Integer.parseInt("3") turns webpage text directly into a raw int without creating an unneeded wrapper.

8. Why it matters

Java collections use Generics that require object types, making wrappers unavoidable — yet confusing == with .equals() on HTTP status codes like 200 vs 200 causes flaky tests.

9. Quick test

Why is Integer x = 200; Integer y = 200; x == y false while Integer a = 50; Integer b = 50; a == b is true? Only -128..127 is cached; 200 allocates two distinct Heap objects.
