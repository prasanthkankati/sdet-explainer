4.1 Locators (All 8 Traditional Strategies)

Locating DOM elements using By.id, By.name, By.className, By.tagName, By.linkText, By.partialLinkText, By.cssSelector, and By.xpath.

A locator is a query mechanism encapsulated in the org.openqa.selenium.By class that instructs WebDriver how to find HTML elements in the DOM. Selenium provides eight traditional locator strategies, and engineers apply the LOC methodology (List candidates, Optimize selector, Check uniqueness) to choose resilient selectors.

Before you start

Prerequisite: 3.3 RemoteWebDriver & Service Classes

Where it fits

Locators are defined as private final By fields inside Page Object classes and passed to findElement(By) or findElements(By) during test execution.

Key points

  1. The 8 traditional By strategies are id, name, className, tagName, linkText, partialLinkText, cssSelector, and xpath.
  2. Under the W3C WebDriver specification, By.id, By.name, and By.className are internally converted into CSS selector queries before transmission.
  3. driver.findElement(By) returns the first matching WebElement or throws NoSuchElementException if zero matches exist.
  4. driver.findElements(By) returns a List<WebElement> of all matching elements, or an empty list (size 0) if none match, never throwing NoSuchElementException.
  5. Passing compound class names with spaces (such as By.className("btn btn-primary")) throws InvalidSelectorException; use By.cssSelector(".btn.btn-primary") instead.

How it works

  1. Follow the LOC methodology: List candidate attributes in DevTools, Optimize the selector for stability, and Check uniqueness (1 of 1 match).
  2. Construct a By object using one of the eight static factory methods on org.openqa.selenium.By.
  3. Pass the By object to driver.findElement(By) to retrieve a single WebElement or driver.findElements(By) to retrieve a List<WebElement>.
  4. The browser driver evaluates the selector against the live DOM and returns the unique element reference ID.

Demonstrating traditional locators and findElement vs findElements:

package dev.selenium.elements; // Declares package

import org.openqa.selenium.By; // Imports By locator factory
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import java.util.List; // Imports List collection

public class LocatorsExample { // Declares class
    public static void main(String[] args) { // Main method
        WebDriver driver = new ChromeDriver(); // Starts Chrome session
        try { // Guarded block
            driver.get("https://www.selenium.dev/selenium/web/web-form.html"); // Opens form page
            WebElement byId = driver.findElement(By.id("my-text-id")); // 1. Finds input by unique ID
            WebElement byName = driver.findElement(By.name("my-password")); // 2. Finds password input by name
            WebElement byCss = driver.findElement(By.cssSelector("button[type='submit']")); // 3. Finds button by CSS
            WebElement byXpath = driver.findElement(By.xpath("//a[normalize-space()='Return to index']")); // 4. Finds link by XPath
            List<WebElement> inputs = driver.findElements(By.tagName("input")); // 5. Finds all input tags as a List
            System.out.println("Total inputs found: " + inputs.size()); // Prints count of matching inputs
        } finally { // Teardown block
            driver.quit(); // Closes browser cleanly
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Passing multiple space-separated classes into By.className("form-control input-lg"), which throws InvalidSelectorException; fix by using By.cssSelector(".form-control.input-lg").
  2. Using fragile absolute XPaths like /html/body/div[2]/div[1]/form/input[1]; fix by writing relative XPaths anchored to stable attributes.
  3. Using findElement() to check if an optional popup is absent, which wastes implicit wait time and throws NoSuchElementException; fix by checking driver.findElements(By...).isEmpty().

Interview questions

Basics

What are the eight traditional locator strategies in Selenium?
The eight strategies on the By class are By.id(), By.name(), By.className(), By.tagName(), By.linkText(), By.partialLinkText(), By.cssSelector(), and By.xpath().

What is the difference between driver.findElement() and driver.findElements()?
findElement() returns the first matching WebElement or throws NoSuchElementException if none is found. findElements() returns a List<WebElement> containing all matches, or an empty list (size 0) if no element matches, without throwing an exception.

What does the LOC methodology stand for when creating locators?
LOC stands for List candidates (inspecting available DOM attributes), Optimize selector (choosing the shortest, most stable attribute like id or data-testid), and Check uniqueness (verifying the selector matches 1 of 1 in browser DevTools).

How it works

How does W3C WebDriver handle By.id(), By.name(), and By.className() under the hood?
The W3C WebDriver specification defines only five wire-level locator strategies: css selector, link text, partial link text, tag name, and xpath. Selenium's Java client automatically converts By.id("foo") to By.cssSelector("#foo") and By.name("bar") to By.cssSelector("*[name='bar']").

Why does By.className("btn btn-success") throw InvalidSelectorException?
By.className() expects a single class token without spaces. When spaces are present, Selenium throws InvalidSelectorException: Compound class names not permitted. Join multiple classes with dots in By.cssSelector(".btn.btn-success").

How do CSS attribute substring selectors (^=, $=, *=) work for dynamic IDs?
input[id^='user_'] matches an id starting with 'user_', input[id$='_input'] matches an id ending with '_input', and input[id*='login'] matches an id containing 'login' anywhere in the value.

Real situations

When must you use XPath instead of CSS Selector?
Use XPath when you need to locate an element by its exact visible text on non-anchor tags (such as //button[normalize-space()='Add to cart']) or when traversing upward in the DOM to a parent or ancestor node (such as //input[@id='email']/ancestor::div[@class='form-group']).

How do you verify that an error banner is NOT present on the page without throwing an exception?
Call List<WebElement> banners = driver.findElements(By.id("error-banner")) and assert Assert.assertTrue(banners.isEmpty()). Because findElements() returns an empty list on zero matches, no exception is thrown.

How do you scope an element search inside a specific parent container or table row?
First locate the parent WebElement (such as WebElement row = driver.findElement(By.id("row-1"))), and then call row.findElement(By.cssSelector(".delete-btn")) on that WebElement instead of on driver.

Troubleshooting

Why does a child XPath like row.findElement(By.xpath("//td")) search the entire page instead of just inside row?
In XPath, a leading // always searches from the root of the HTML document, even when called on a child WebElement. Prefix the expression with a dot (row.findElement(By.xpath(".//td"))) to scope it strictly to the current element context.

What causes InvalidSelectorException when writing an XPath or CSS selector?
It is caused by syntax errors such as unclosed square brackets, mismatched quotes, or using invalid XPath axis names. Always test the selector in Chrome DevTools (Ctrl+F in Elements panel) before running the test.

Why does By.linkText() fail even though the text looks identical on screen?
CSS rules like text-transform: uppercase can display lowercase DOM text as uppercase on screen, or leading/trailing whitespace may exist in the HTML. Inspect the raw DOM text or use XPath normalize-space().

Design choices

What is the recommended priority order for choosing locators in an enterprise framework?
Prioritize unique static IDs (By.id) and dedicated test attributes (data-testid / data-qa via By.cssSelector) first, followed by By.name, semantic By.cssSelector, and finally relative By.xpath when text or upward traversal is required.

Why are absolute XPaths (/html/body/div[3]/div[2]/button) banned in production automation?
Any minor UI layout change—such as wrapping a banner in a new <div>—shifts the hierarchy and breaks every absolute XPath on the page. Relative selectors anchored to semantic attributes survive layout refactoring.

Why should locators be stored as By fields rather than WebElement fields when not using PageFactory?
Storing By objects keeps Page Objects lightweight and resolves the fresh WebElement from the DOM at the exact moment an action method is called, reducing StaleElementReferenceException.

Quick answers

  1. How many traditional locator strategies exist on By? Eight: id, name, className, tagName, linkText, partialLinkText, cssSelector, and xpath.
  2. What does findElements() return when nothing matches? An empty List<WebElement> (size 0), never throwing NoSuchElementException.
  3. How do you match multiple classes in CSS? Chain them with dots: By.cssSelector(".btn.btn-primary").
  4. How do you scope an XPath search inside a parent WebElement? Start the XPath with a dot: parent.findElement(By.xpath(".//span")).
  5. Which CSS operator matches a prefix? The ^= operator (e.g., input[id^='prefix_']).
