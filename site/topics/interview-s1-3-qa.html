Tier 1: Core Definitions, Class Hierarchy & Lifecycle (Q1–Q7)

  1. What is ChromeOptions in Selenium WebDriver?
    ChromeOptions is a capability configuration class in Selenium Java (extending ChromiumOptions and MutableCapabilities) that aggregates command-line launch arguments, user preferences, and W3C capabilities to configure Google Chrome prior to session initialization.
  2. Where does ChromeOptions sit in the Selenium class hierarchy?
    It extends ChromiumOptions<ChromeOptions>, which extends AbstractDriverOptions<DO>, which extends MutableCapabilities, which implements Capabilities.
  3. What happens if you modify a ChromeOptions instance after instantiating ChromeDriver?
    It has zero effect on the running browser. ChromeOptions are evaluated strictly at startup during operating system process creation; runtime options cannot be dynamically mutated after the session begins.
  4. What is the fundamental difference between driver.close() and driver.quit()?
    driver.close() closes only the currently focused browser tab or window, leaving the driver executable and session alive. driver.quit() terminates all open windows, invalidates the session, and kills the background chromedriver.exe process.
  5. What W3C command is dispatched when driver.close() is executed?
    It dispatches the W3C Close Window command via an HTTP DELETE request to /session/{session id}/window.
  6. What W3C command is dispatched when driver.quit() is executed?
    It dispatches the W3C Delete Session command via an HTTP DELETE request to /session/{session id}.
  7. What is MutableCapabilities and why does ChromeOptions inherit from it?
    MutableCapabilities is a thread-safe map-like structure for storing arbitrary W3C capabilities. ChromeOptions inherits from it so it can be passed anywhere a generic Capabilities interface is expected, such as RemoteWebDriver.

Tier 2: Deep Comparisons & Mechanical Trade-Offs (Q8–Q14)

  1. Why is calling driver.close() in teardown considered a catastrophic anti-pattern?
    Because close() does not terminate the chromedriver.exe operating system daemon. In automated CI/CD pipelines executing hundreds of tests, orphaned driver processes accumulate in memory, eventually causing server OutOfMemory crashes.
  2. What is the difference between PageLoadStrategy NORMAL, EAGER, and NONE?
    NORMAL waits for the window load event (all images, scripts, and stylesheets downloaded); EAGER unblocks as soon as DOM parsing completes at DOMContentLoaded; NONE unblocks immediately after the initial HTTP navigation request is dispatched.
  3. How does --headless=new differ from the legacy --headless argument?
    --headless=new (introduced in Chrome 109) utilizes the authentic desktop Chrome Blink rendering engine without a visible display, ensuring 100% feature parity. The old --headless used an alternate, stripped-down headless browser implementation that had documented layout and extension differences.
  4. What is the difference between addArguments() and setExperimentalOption()?
    addArguments() passes command-line flags to the Chrome executable during OS process startup (e.g. --start-maximized). setExperimentalOption() writes configuration settings into Chrome's JSON user preferences file (e.g. download folder locations and notification permissions).
  5. How does setAcceptInsecureCerts(true) compare to the argument --ignore-certificate-errors?
    setAcceptInsecureCerts(true) is an official W3C WebDriver standard capability properly scoped to the session. --ignore-certificate-errors is an aggressive Chromium CLI switch that globally disables all SSL validation and can mask real security bugs.
  6. What occurs if you call driver.getTitle() after driver.close() when two tabs were open?
    Selenium throws NoSuchWindowException: no such window: target window already closed because WebDriver does not automatically switch focus to the remaining tab; you must explicitly call driver.switchTo().window(handle).
  7. What occurs if you call driver.getTitle() after driver.quit()?
    Selenium throws NoSuchSessionException: Session ID is null. Using WebDriver after calling quit()? because the automation session was destroyed.

Tier 3: Arguments, Prefs & Docker Headless Flags (Q15–Q21)

  1. Why is the --no-sandbox flag required when running Chrome in Docker?
    Docker containers typically execute as the root user. Chrome's operating system security sandbox refuses to run with root privileges and will immediately crash the browser process on launch unless --no-sandbox is supplied.
  2. Why is --disable-dev-shm-usage mandatory in containerized CI/CD pipelines?
    Docker assigns a default shared memory size of only 64MB to /dev/shm. Modern websites quickly exceed 64MB of RAM during rendering, causing Chrome to crash with session deleted because of page crash. This flag forces Chrome to use the larger /tmp disk partition.
  3. Why must you specify --window-size=1920,1080 during headless test execution?
    In headless mode without a physical monitor, Chrome defaults to a small resolution (typically 800x600). This causes responsive websites to collapse into mobile navigation drawers or hamburger menus, causing standard desktop locators to fail with ElementNotInteractableException.
  4. How do you block notification popups using Chrome preferences?
    Populate the preference key profile.default_content_setting_values.notifications with integer value 2 (which represents Block) inside the prefs dictionary passed to options.setExperimentalOption("prefs", map).
  5. How do you set a custom file download directory in ChromeOptions?
    Add prefs.put("download.default_directory", "/custom/download/path") and prefs.put("download.prompt_for_download", false) to the experimental prefs map.
  6. What problem does --remote-allow-origins=* resolve?
    Chrome 111 introduced strict WebSocket origin checks for security. When Selenium connects to the Chrome DevTools Protocol (CDP), the connection was rejected with ConnectionFailedException unless --remote-allow-origins=* was provided.
  7. Why should you never use --disable-web-security in enterprise test automation?
    It disables the browser's Same-Origin Policy and Cross-Origin Resource Sharing (CORS) rules. Tests will pass in automation that will fail for real users in production, concealing critical security defects.

Tier 4: SDET Code, Popups & Multi-Window Switching (Q22–Q28)

  1. When is it appropriate to call driver.close() inside a test method?
    When a user interaction opens a child window or popup tab. You switch to the child tab, verify its contents, execute driver.close() to dismiss it, and switch back to the parent window handle.
  2. How do you switch back to the main window after closing a popup?
    Store the main window handle using String parent = driver.getWindowHandle() before the popup opens. After closing the popup with driver.close(), invoke driver.switchTo().window(parent).
  3. Why should ChromeOptions never be declared as a public static field in a framework?
    Static variables are shared across all executing threads. In parallel test runs, multiple threads would concurrently modify the same options object, causing race conditions and unpredictable browser configurations.
  4. What is the purpose of options.setBinary("/path/to/chrome")?
    It allows the tester to specify an explicit path to a non-standard Chrome installation, such as a custom enterprise build, beta channel, or Chrome for Testing executable.
  5. How do you automatically download PDF files instead of viewing them in Chrome?
    Inject prefs.put("plugins.always_open_pdf_externally", true) into the prefs map of ChromeOptions.
  6. How do you load a custom browser extension (.crx) into a ChromeDriver session?
    Use options.addExtensions(new File("/path/to/extension.crx")) before starting the session.
  7. What is the expected result if you call driver.quit() inside a try block without finally?
    If any assertion or command inside the try block throws an exception, the execution skips driver.quit(), leaving the browser window open and the driver executable running in RAM. Always place quit() inside a finally block or TestNG @AfterMethod.

Tier 5: Rapid-Fire Yes/No & 1-Liner Traps (Q29–Q35)

  1. Does driver.close() release the TCP communication port used by ChromeDriver?
    No. Only driver.quit() releases the TCP loopback port.
  2. Can you add arguments to ChromeOptions as a chained call?
    Yes. options.addArguments("flag1").addArguments("flag2") returns the same ChromeOptions instance.
  3. Does ChromeOptions support incognito mode?
    Yes, via options.addArguments("--incognito").
  4. Can you use ChromeOptions when instantiating a RemoteWebDriver?
    Yes. RemoteWebDriver(url, options) directly accepts ChromeOptions because it implements Capabilities.
  5. Does PageLoadStrategy.NONE wait for document.readyState to become interactive?
    No. NONE does not wait for any document ready state; it returns immediately after navigation starts.
  6. Will setting driver = null terminate the background chromedriver process?
    No. Nullifying the Java reference only makes the variable eligible for garbage collection; the external chromedriver.exe operating system process continues running until killed or quit.
  7. What is the default PageLoadStrategy in Selenium WebDriver?
    PageLoadStrategy.NORMAL.
