3.1 Black-Box Techniques: Equivalence Partitioning (EP) & Boundary Value Analysis (BVA)

1. The Base: What is a Test Design Technique and Why Do We Need It?

A Test Design Technique is a systematic mathematical method for selecting a small, high-yield set of test inputs from an infinite pool of possible inputs so that maximum defects are caught with minimum test cases.

The Problem It Solves: Suppose a banking app has an "Age" input field that accepts customers aged `18` to `60`. A tester could type `18, 19, 20, 21 ... 60`, plus negative numbers `-5, 0, 1, 2 ... 17`, plus `61, 62 ... 999`. Testing all integers takes thousands of test cases (violating Principle #2: Exhaustive testing is impossible), while picking 2 random numbers (`25` and `40`) misses the exact edge bug where a developer wrote `if (age > 18)` instead of `if (age >= 18)`. Test Design Techniques solve this mathematically.

2. Core Terms & Their Properties Defined First (Black-Box vs White-Box vs Grey-Box)

Before learning EP and BVA, understand the 3 families of Test Design Techniques classified by whether the tester sees internal source code:

  • 1. Black-Box Testing (Specification-Based / Behavioral): Designing test cases strictly from external requirements (`SRS` / `User Stories`) by feeding inputs and checking outputs without looking at internal source code.
    • 5 Core Black-Box Techniques: (1) Equivalence Partitioning (EP), (2) Boundary Value Analysis (BVA), (3) Decision Table Testing, (4) State Transition Testing, (5) Use Case Testing.
  • 2. White-Box Testing (Structure-Based / Glass-Box / Clear-Box): Designing test cases by inspecting internal Java/TS source code (`if/else` branches, `for` loops, method paths) to achieve Statement Coverage and Branch/Decision Coverage.
  • 3. Grey-Box Testing (Experience + Contract-Based): Combining Black-Box execution with knowledge of internal database schemas, REST API JSON contracts, and browser DevTools network logs.

4. Technique 1 & Technique 2 Defined & Explained in Order

â‘  Technique 1: Equivalence Partitioning (EP / Equivalence Class Partitioning — ECP)

  • Definition: Dividing the input domain of a software program into Equivalence Classes (Partitions) such that every value inside a given partition is processed identically by the codeâ€”meaning if 1 value in the partition passes (or fails), all other values in that same partition will also pass (or fail).
  • Core Rule of EP: Pick exactly 1 representative value from the center of each Valid Partition and each Invalid Partition.
    • For `Age 18..60`: 3 test cases total → `10` (Invalid Low), `35` (Valid Middle), `75` (Invalid High).
  • In what exact cases we apply EP:
    1. Numeric ranges (Age, Transfer Amount, Item Quantity).
    2. Discrete non-numeric sets/dropdowns where BVA does not apply (e.g., User Role = `{Admin, Member, Guest}` or Card Type = `{Visa, MasterCard}`).

â‘¡ Technique 2: Boundary Value Analysis (BVA — 2-Value vs 3-Value BVA)

  • Definition: Testing the exact boundary edges between valid and invalid equivalence partitions because developers most frequently introduce off-by-one defects (writing `<` instead of `<=`, or `>` instead of `>=`) at the boundary edges.
  • The 2 Standard Forms of BVA (ISTQB Standard):
    1. 2-Value BVA (4 Boundary Points per range): Tests the boundary value itself and the closest invalid neighbor:
      { min - 1, min, max, max + 1 } → For `18..60`: `{ 17, 18, 60, 61 }`.
    2. 3-Value BVA (6 Boundary Points per range — Complete Industry Standard): Tests the boundary value plus one step on both sides:
      { min - 1, min, min + 1, max - 1, max, max + 1 } → For `18..60`: `{ 17, 18, 19, 59, 60, 61 }`.
  • Why 3-Value BVA (`min+1`, `max-1`) is needed: If a developer accidentally coded `if (age == 18 || age == 60)`, then 2-Value BVA `{17, 18, 60, 61}` would pass `18` and `60` while `19` and `59` fail! Adding `min+1` and `max-1` catches this immediately.

Interview Answer: "Equivalence Partitioning divides inputs into valid and invalid groups where all values in a group behave the same, so we test 1 representative value per group. Boundary Value Analysis tests the exact edges of those groups (`min-1, min, min+1` and `max-1, max, max+1`) because off-by-one bugs (`<` vs `<=`) happen at boundaries."

6. Real Runnable Java & TestNG Code Trace: Catching an Off-By-One Bug with BVA

Look at how a developer's tiny `< 60` typo passes Equivalence Partitioning (`age = 35`), passes `min` (`age = 18`), and is caught immediately by BVA at `max = 60`:

public class LoanEligibilityValidator {
    // REQUIREMENT: Eligible if age is between 18 and 60 (inclusive)
    public static boolean isEligible(int age) {
        // DEFECT: Developer wrote '< 60' instead of '<= 60'
        return age >= 18 && age < 60;
    }

    public static void main(String[] args) {
        int[][] testMatrix = {
            // { inputAge, expected (1=true, 0=false) }
            { 10, 0 }, // EP Invalid Low
            { 35, 1 }, // EP Valid Middle
            { 75, 0 }, // EP Invalid High
            { 17, 0 }, // BVA min - 1
            { 18, 1 }, // BVA min
            { 19, 1 }, // BVA min + 1
            { 59, 1 }, // BVA max - 1
            { 60, 1 }, // BVA max  <-- CATCHES THE '< 60' BUG!
            { 61, 0 }  // BVA max + 1
        };

        for (int[] row : testMatrix) {
            int age = row[0];
            boolean expected = row[1] == 1;
            boolean actual = isEligible(age);
            String status = (actual == expected) ? "PASS" : "FAIL (BUG CAUGHT!)";
            System.out.printf("Age: %2d | Expected: %-5b | Actual: %-5b | %s%n",
                age, expected, actual, status);
        }
    }
}

7. Self-Check

  1. A password field requires 8 to 16 characters. What are the 6 BVA length values (3-Value BVA) you must test? (`7, 8, 9` and `15, 16, 17` characters.)
  2. Why did `Age = 35` (EP) miss the `age < 60` bug in the code trace above while `Age = 60` (BVA) caught it? (Because off-by-one operator errors (`<` vs `<=`) only manifest at the exact boundary edge `60`, never in the middle of the partition.)
  3. Can you apply BVA to a dropdown containing `{India, USA, UK}`? (No â€” unordered discrete sets have no numeric/sequential boundary; use Equivalence Partitioning.)
