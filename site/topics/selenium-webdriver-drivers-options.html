3.2 Browser Options & Page Load Strategy

Customizing browser startup arguments, headless execution, user preferences, and PageLoadStrategy (NORMAL, EAGER, NONE).

Browser Options classes (ChromeOptions, FirefoxOptions, EdgeOptions, SafariOptions) configure both W3C capabilities and vendor-specific browser settings. They control how the browser launches, including headless mode, window dimensions, file download directories, and the PageLoadStrategy that governs when driver.get() returns control to the script.

Before you start

Prerequisite: 3.1 Driver Sessions & Capabilities

Where it fits

Browser Options are configured in your framework's driver initialization layer before launching local or CI/CD headless browser sessions.

Key points

  1. PageLoadStrategy.NORMAL (default) waits for the full page and all stylesheets, images, and subframes (document.readyState === 'complete').
  2. PageLoadStrategy.EAGER waits only until the initial HTML document is parsed and DOMContentLoaded fires (document.readyState === 'interactive'), skipping slow images/stylesheets.
  3. PageLoadStrategy.NONE returns immediately after the initial HTML response starts downloading, requiring explicit waits for all elements.
  4. In Chrome 109+, modern headless mode is enabled via options.addArguments("--headless=new").
  5. Vendor-specific preferences such as default download directories are configured via options.setExperimentalOption("prefs", prefsMap) in Chromium browsers.

How it works

  1. Instantiate ChromeOptions (or FirefoxOptions/EdgeOptions) before creating the driver.
  2. Call options.setPageLoadStrategy(PageLoadStrategy.EAGER) or NORMAL to define when navigation commands complete.
  3. Call options.addArguments(...) to pass command-line flags such as --headless=new and --window-size=1920,1080.
  4. Pass the configured options object into new ChromeDriver(options) so the browser starts with those flags and preferences.

Configuring ChromeOptions with headless mode, window size, and PageLoadStrategy:

package dev.selenium.drivers; // Declares package

import org.openqa.selenium.PageLoadStrategy; // Imports PageLoadStrategy enum
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.chrome.ChromeOptions; // Imports ChromeOptions
import java.util.HashMap; // Imports HashMap for browser prefs
import java.util.Map; // Imports Map interface

public class BrowserOptionsExample { // Declares class
    public static void main(String[] args) { // Main entry point
        ChromeOptions options = new ChromeOptions(); // Creates ChromeOptions instance
        options.setPageLoadStrategy(PageLoadStrategy.EAGER); // Returns once DOMContentLoaded fires
        options.addArguments("--headless=new"); // Enables modern Chromium headless mode
        options.addArguments("--window-size=1920,1080"); // Sets fixed desktop viewport resolution

        Map prefs = new HashMap<>(); // Creates preferences map
        prefs.put("download.prompt_for_download", false); // Disables save-as dialog prompt
        options.setExperimentalOption("prefs", prefs); // Attaches custom user prefs to ChromeOptions

        WebDriver driver = new ChromeDriver(options); // Launches Chrome with configured options
        try { // Guarded execution
            driver.get("https://www.selenium.dev/"); // Navigates using EAGER page load strategy
            System.out.println("Loaded: " + driver.getTitle()); // Outputs page title
        } finally { // Cleanup block
            driver.quit(); // Terminates browser and driver
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Running headless tests without specifying --window-size=1920,1080, which defaults to a small viewport (800x600) and hides desktop menus behind mobile hamburger icons; fix by explicitly setting window size.
  2. Using PageLoadStrategy.NONE without explicit waits, causing immediate NoSuchElementException; fix by pairing NONE or EAGER with WebDriverWait.
  3. Using driver.manage().window().maximize() inside headless Linux Docker containers where no window manager exists; fix by passing --window-size=1920,1080 in ChromeOptions.

Terms to know

Interview questions

Basics

What are the three PageLoadStrategy modes in Selenium 4?
The three modes are PageLoadStrategy.NORMAL (waits for the full load event including images and stylesheets), PageLoadStrategy.EAGER (waits only for DOMContentLoaded when HTML is parsed), and PageLoadStrategy.NONE (returns immediately after navigation starts).

How do you run Chrome in headless mode in Selenium 4?
Create a ChromeOptions instance, call options.addArguments("--headless=new"), and pass options into new ChromeDriver(options). For Firefox, use firefoxOptions.addArguments("-headless").

Why is --headless=new preferred over the legacy --headless flag in Chrome?
In Chrome 109+, --headless=new runs the exact same unified browser rendering binary as headed Chrome, supporting extensions and Downloads accurately, whereas legacy --headless ran a separate stripped-down implementation.

How it works

How does PageLoadStrategy.EAGER affect driver.get() execution time?
Under EAGER, driver.get() finishes as soon as document.readyState reaches interactive (DOMContentLoaded). It does not wait for heavy images, fonts, or slow external analytics scripts, significantly reducing navigation wait times.

How are ChromeOptions serialized when sent to ChromeDriver?
Selenium packages standard W3C settings at the top level of the capabilities JSON and nests Chromium-specific arguments, extensions, and prefs inside the vendor-prefixed goog:chromeOptions object.

How do you configure Chrome to automatically download files to a custom directory without showing a Save dialog?
Create a Map with "download.default_directory" set to your absolute folder path and "download.prompt_for_download" set to false, then pass it via options.setExperimentalOption("prefs", prefs).

Real situations

Why do tests that pass locally in headed Chrome often fail with ElementNotInteractableException in CI headless mode?
Headless browsers in CI default to a small 800x600 viewport, causing responsive web pages to collapse desktop navigation bars into mobile hamburger menus. Adding --window-size=1920,1080 in ChromeOptions fixes the viewport.

Which flags are required when running Chrome inside a Linux Docker container?
Pass --headless=new, --no-sandbox, and --disable-dev-shm-usage. In Docker, the default /dev/shm shared memory partition is only 64MB, which causes Chrome tabs to crash unless --disable-dev-shm-usage redirects shared memory to /tmp.

How do you test a web application using a specific Chrome user profile or browser extension?
Use options.addArguments("user-data-dir=/path/to/profile") to load an existing profile, or options.addExtensions(new File("extension.crx")) to install a packaged Chrome extension at startup.

Troubleshooting

Why does Chrome crash with 'session not created: DevToolsActivePort file doesn't exist' in Linux CI?
Chrome crashed immediately on launch because it ran as the root user in a container without sandboxing support or ran out of /dev/shm memory. Add --no-sandbox and --disable-dev-shm-usage to ChromeOptions.

Why did switching to PageLoadStrategy.NONE cause immediate NoSuchElementException on the first findElement()?
PageLoadStrategy.NONE returns control to Java before the HTML body has even finished downloading. Every element lookup after driver.get() must be wrapped in an explicit WebDriverWait.

How do you suppress the 'Chrome is being controlled by automated test software' infobar?
Call options.setExperimentalOption("excludeSwitches", Collections.singletonList("enable-automation")) on your ChromeOptions instance.

Design choices

When should an architect choose PageLoadStrategy.EAGER over PageLoadStrategy.NORMAL?
Choose EAGER when testing e-commerce or media sites where slow third-party ad networks or high-resolution product images delay the window.onload event for 20+ seconds even though the interactive DOM is ready in 1 second.

Why should headless mode be controlled via a Maven CLI property (-Dheadless=true) rather than hardcoded?
Developers need headed browsers locally to visually debug test steps, while CI/CD pipelines need headless browsers for speed and headless Linux agents. Reading System.getProperty("headless") supports both seamlessly.

Why is setting a fixed window size (--window-size=1920,1080) better than driver.manage().window().maximize()?
maximize() depends on the host monitor's physical resolution, which varies across developer laptops and CI virtual displays. A fixed 1920x1080 viewport guarantees identical responsive breakpoints everywhere.

Quick answers

  1. What is the default PageLoadStrategy? PageLoadStrategy.NORMAL (waits for document.readyState === 'complete').
  2. Which PageLoadStrategy waits only for DOMContentLoaded? PageLoadStrategy.EAGER (document.readyState === 'interactive').
  3. What argument enables modern headless mode in Chrome? options.addArguments("--headless=new").
  4. Why add --disable-dev-shm-usage in Docker? Prevents Chrome tab crashes caused by Docker's small 64MB /dev/shm memory limit.
  5. How do you set a 1080p viewport in headless Chrome? options.addArguments("--window-size=1920,1080").
