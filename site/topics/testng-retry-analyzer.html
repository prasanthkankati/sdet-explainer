5.2 IRetryAnalyzer & Automatic Flaky Test Retries

Mitigating UI flakiness: implementing IRetryAnalyzer, max retry bounds, and dynamic injection via IAnnotationTransformer.

Web applications frequently encounter transient network spikes, animation delays, and race conditions that cause automated tests to fail intermittently. TestNG provides the IRetryAnalyzer interface to automatically re-execute failed tests before marking the final build as failed.

1. Real-Time Project Structure: Where Retry Logic Lives

Flaky test retries are managed across two interconnected classes in the retry package, dynamically bound at runtime via XML:

sdet-test-framework/
├── testng.xml                            # 📍 Binds transformer: 
└── src/test/java/com/sdet/
    ├── retry/
    │   ├── RetryAnalyzer.java            # 📍 Implements IRetryAnalyzer (max retry bounds check)
    │   └── AnnotationTransformer.java    # 📍 Implements IAnnotationTransformer (injects retry into all @Test)
    └── tests/CheckoutTest.java           # Automatically retried on transient DOM/network failures

2. Implementing IRetryAnalyzer

package com.sdet.retry;

import org.testng.IRetryAnalyzer;
import org.testng.ITestResult;

public class RetryAnalyzer implements IRetryAnalyzer {
    private int retryCount = 0;
    private static final int MAX_RETRY_COUNT = 2; // Retry at most twice

    @Override
    public boolean retry(ITestResult result) {
        if (retryCount < MAX_RETRY_COUNT) {
            retryCount++;
            System.out.println("[RETRYING TEST]: " + result.getName() + " (Attempt " + retryCount + ")");
            return true; // TestNG re-executes the test method
        }
        return false; // Stop retrying; mark test as FAILED
    }
}

2. Dynamic Injection via IAnnotationTransformer

Manually adding @Test(retryAnalyzer = RetryAnalyzer.class) to hundreds of methods is error-prone. Use IAnnotationTransformer to automatically attach the retry analyzer to all tests across the framework:

package com.sdet.retry;

import org.testng.IAnnotationTransformer;
import org.testng.annotations.ITestAnnotation;
import java.lang.reflect.Constructor;
import java.lang.reflect.Method;

public class RetryTransformer implements IAnnotationTransformer {
    @Override
    public void transform(ITestAnnotation annotation, Class testClass, Constructor testConstructor, Method testMethod) {
        annotation.setRetryAnalyzer(RetryAnalyzer.class);
    }
}

3. Senior SDET Interview Q&A

  1. Is relying heavily on IRetryAnalyzer an anti-pattern?
    Yes, when used as a crutch to mask bad locators, missing explicit waits, or race conditions. Retries should only catch genuine external flakiness (e.g. transient 502 Bad Gateway or third-party payment gateway latency). Retried tests must be tagged and tracked as technical debt.
  2. How does TestNG report retried tests in standard HTML reports?
    Intermediate failures are categorized under the Retried / Skipped section, and only the final attempt determines whether the test is marked as Pass or Fail in the test summary.
