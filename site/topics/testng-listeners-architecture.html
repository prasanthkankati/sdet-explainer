5.1 Listeners Architecture: ITestListener & ISuiteListener

AOP event interception: capturing failures, auto-capturing screenshots, and driving ExtentReports/Allure pipelines.

Listeners in TestNG implement the Observer pattern. They allow automation architects to intercept test events (start, success, failure, skip, suite start/finish) and execute cross-cutting concerns without polluting test logic with reporting boilerplate.

1. Core Listener Interfaces

InterfaceInterception ScopePrimary Use Case
ITestListenerIndividual test methods and resultsCapturing screenshots on failure, logging pass/fail to HTML reports.
ISuiteListenerSuite start and suite finishInitializing reporting engines (ExtentReports), global database teardowns.
IInvokedMethodListenerBefore & after every method (config + test)Logging method execution duration, thread ID monitoring.
IAnnotationTransformerRuntime annotation transformationDynamically injecting retry analyzers without modifying test source code.

2. Implementation Example: Screenshot on Failure

package com.sdet.listeners;

import org.testng.ITestListener;
import org.testng.ITestResult;
import org.openqa.selenium.OutputType;
import org.openqa.selenium.TakesScreenshot;
import com.sdet.core.BaseTest;

public class TestFailureListener implements ITestListener {
    @Override
    public void onTestFailure(ITestResult result) {
        String testName = result.getMethod().getMethodName();
        System.err.println("[TEST FAILED]: " + testName);

        // Capture base64 screenshot from ThreadLocal driver
        TakesScreenshot ts = (TakesScreenshot) BaseTest.getDriver();
        String base64Screenshot = ts.getScreenshotAs(OutputType.BASE64);

        // Attach to ExtentReports or Allure
        ReportingManager.logFailure(testName, result.getThrowable(), base64Screenshot);
    }
}

3. Senior SDET Interview Q&A

  1. Where should you register listeners for production test execution?
    In testng.xml under <listeners><listener class-name="..."/></listeners>. While @Listeners works at the class level, registering in XML ensures global application across all test classes.
  2. How does ITestContext differ from ITestResult?
    ITestResult contains metadata about a single test method (status, exception, execution time). ITestContext contains suite and test-level data, including all passed, failed, and skipped tests, start/end timestamps, and injected XML attributes.
