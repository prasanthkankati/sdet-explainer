J5.5 Question Bank: Sorting (Comparable vs Comparator) & Fail-Fast Iterators (21 Questions)

Tier 1: Core Definitions, Classification & Theory (Q1–Q3)

  1. Compare Comparable and Comparator in Java.
    Comparable<T> lives in java.lang, is implemented inside the target class itself via compareTo(T o), and defines the single natural order of that class (used by Collections.sort(list)). Comparator<T> lives in java.util, is defined externally via compare(T o1, T o2) or lambdas, and lets you define unlimited independent sort strategies (sort by price, sort by rating, sort by date) without modifying the domain class.
  2. What is the difference between a Fail-Fast iterator and a Fail-Safe iterator?
    A Fail-Fast iterator (used by ArrayList, HashSet, and HashMap) detects structural changes made outside the iterator during traversal and immediately throws ConcurrentModificationException. A Fail-Safe iterator (used by CopyOnWriteArrayList and ConcurrentHashMap) iterates safely without throwing that exception because it operates over a cloned snapshot or weakly consistent concurrent buckets.
  3. What return values must compareTo(o) and compare(o1, o2) follow?
    Both methods return a negative integer if the first object is ordered before the second, 0 if both are equal in sort rank, and a positive integer if the first object comes after the second. Always delegate to wrapper helpers like Integer.compare(x, y) and Double.compare(x, y) instead of manual subtraction to prevent overflow bugs.

Tier 2: How It Works & Internal Mechanics (Q4–Q6)

  1. How does an ArrayList iterator detect modification and throw ConcurrentModificationException?
    ArrayList maintains a counter field modCount incremented on every structural edit (add, remove, clear). When list.iterator() creates an iterator (including implicitly in every for-each loop), the iterator snapshots expectedModCount = modCount. Calling list.remove() directly updates modCount without updating expectedModCount, so the next call to iterator.next() detects the mismatch and immediately throws ConcurrentModificationException—even on a single thread!
  2. Why does calling iterator.remove() succeed without throwing ConcurrentModificationException?
    When you call it.remove() on the iterator itself, the iterator deletes the last returned element from the underlying list AND synchronizes expectedModCount = modCount internally. Note that you must call it.next() before calling it.remove(), otherwise it throws IllegalStateException.
  3. How does CopyOnWriteArrayList avoid ConcurrentModificationException internally?
    Every write operation (add, set, remove) acquires a lock, copies the entire internal array into a fresh modified array, and atomically swaps the backing array reference. Any active iterator holds the immutable snapshot reference from when the loop started, so reads never lock and never throw ConcurrentModificationException—at the expense of copying the array on writes.

Tier 3: Real-World SDET & Selenium Scenarios (Q7–Q9)

  1. How do you write a Selenium UI test verifying that a product table sorted properly by Price Low-to-High?
    Scrape all price cells from the UI into List<Double> actual = elements.stream().map(e -> Double.parseDouble(e.getText().replaceAll("[^0-9.]", ""))).toList();. Build a mutable copy List<Double> expected = new ArrayList<>(actual); Collections.sort(expected);, and assert Assert.assertEquals(actual, expected). Copying first guarantees you never compare a sorted list against itself.
  2. In a multi-column sort requirement (sort products by category ascending, then price descending, with nulls last), how does Java 8 Comparator write this cleanly?
    Chain Comparator.comparing(Item::category, Comparator.nullsLast(String::compareToIgnoreCase)).thenComparing(Comparator.comparingDouble(Item::price).reversed()). This reads cleanly and guards against missing price or category fields without throwing NullPointerException.
  3. How do you safely strip blank entries from a scraped List<String> in one line in Java 8+?
    Call list.removeIf(s -> s == null || s.isBlank());. Internally ArrayList.removeIf() shifts matching items in a single linear O(n) pass using a bitset and increments modCount once, running faster and cleaner than manual iterator loops.

Tier 4: Troubleshooting, Exceptions & Failure Modes (Q10–Q12)

  1. Why did a single-threaded for (WebElement el : rows) { if (el.getText().isEmpty()) rows.remove(el); } throw ConcurrentModificationException?
    The exception name misleads newcomers into thinking multiple threads are required. Removing an element directly from rows inside an enhanced for-each loop violates the hidden Iterator's modCount invariant on the very same thread. Replace the loop with rows.removeIf(el -> el.getText().isEmpty()) or an explicit Iterator.
  2. Why did Collections.sort(actualPrices) pass an assertion comparing actualPrices to itself even when the UI table was completely unsorted?
    Collections.sort(list) mutates the list in place and returns void. Writing List<Double> sorted = actualPrices; Collections.sort(sorted); creates an alias pointing to the identical Heap list, so both variables point to the sorted list afterward! Always allocate new ArrayList<>(actualPrices) before sorting.
  3. Why did return o1.price - o2.price cast to int inside a Comparator put $10.90 equal to $10.20?
    Truncating 10.90 - 10.20 = 0.70 to int evaluates to 0, falsely reporting two unequal prices as equal! Always use Double.compare(o1.price, o2.price) instead of subtracting.

Tier 5: Design Choices & Rapid-Fire Recall (Q13–Q21)

  1. Why did Java design standard collections like ArrayList and HashMap with Fail-Fast iterators rather than making all iterators Fail-Safe?
    Cloning an entire array or map on every loop would create massive memory overhead and hide subtle concurrency bugs where iterations operate on stale data. Fail-Fast checks cost a single integer comparison per step and catch structural modification defects immediately during testing.
  2. When building a custom framework entity (like TestCaseResult), when should it implement Comparable vs relying on Comparator?
    Implement Comparable only when the type has one unmistakable, universal natural order (like alphabetical String or chronological LocalDate). When items can legitimately sort by timestamp, duration, status, or module name depending on the report view, expose named Comparator constants instead.
  3. When should you choose CopyOnWriteArrayList over ArrayList?
    Choose CopyOnWriteArrayList strictly for small collections that are read constantly across parallel threads and mutated rarely—for instance, registering custom test execution listeners at startup and notifying them concurrently during tests.
  4. Which method does Comparable define vs Comparator?
    Comparable defines compareTo(T o); Comparator defines compare(T o1, T o2).
  5. What exception does a Fail-Fast iterator throw when a list is modified mid-loop?
    ConcurrentModificationException.
  6. Name two safe ways to remove items from an ArrayList while iterating.
    iterator.remove() or list.removeIf(predicate).
  7. Which collections have Fail-Safe iterators?
    CopyOnWriteArrayList and ConcurrentHashMap.
  8. Does Collections.sort(list) return a new list?
    No; it sorts the target list in place and returns void.
  9. Why should numeric comparators use Integer.compare() instead of a - b?
    To avoid integer overflow bugs and decimal truncation.
