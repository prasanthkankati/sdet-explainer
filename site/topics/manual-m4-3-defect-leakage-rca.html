4.3 Defect Leakage, Defect Escape & Root Cause Analysis (RCA)

1. The Base: Why Do QA Teams Measure Defect Metrics & Perform RCA?

Defect Metrics (DRE, Defect Leakage, Defect Density) mathematically measure how effective our QA testing process was at catching bugs before release, while Root Cause Analysis (RCA) investigates WHY an escaped bug slipped into Production so we fix the process gap permanently.

The Problem They Solve: Saying "Testing went well this sprint" is an opinion. If QA caught 95 bugs and only 5 reached Production (`95% DRE`), testing was strong; if QA caught 10 bugs and customers reported 15 bugs (`40% DRE`), our test coverage or CI/CD gates have a serious hole that needs RCA.

2. Core Formulas Defined & Calculated Step by Step

  1. Defect Removal Efficiency (DRE): Percentage of total defects caught by QA before Production release.
    DRE (%) = [ Defects Caught by QA / (Defects Caught by QA + Defects Found in Production) ] × 100
    Example: QA found `95` bugs; customers found `5` bugs → `DRE = (95 / 100) * 100 = 95%`.
  2. Defect Leakage % (Defect Escape Rate): Percentage of total defects that escaped QA and reached Production/UAT.
    Defect Leakage (%) = [ Production Defects / (QA Defects + Production Defects) ] × 100 = 100% - DRE
    Example: `(5 / 100) * 100 = 5%` Leakage.
  3. Defect Density: Number of confirmed defects per unit size of software (e.g., per 1,000 Lines of Code `KLOC` or per Module/Story Point) â€” identifies Defect Clustering (80/20) hotspots.
    Defect Density = Total Confirmed Defects in Module / Size of Module (KLOC or Story Points)
  4. Defect Rejection Ratio: `(Rejected Bugs / Total Logged Bugs) * 100` â€” measures QA test accuracy and requirement understanding.

3. Root Cause Analysis (RCA): 5-Whys & Fishbone (Ishikawa)

Whenever a High/Critical Defect escapes to Production, QA & Engineering conduct a Blameless Post-Mortem RCA using two standard tools:

  • 1. The 5-Whys Technique (Drilling down from Symptom to Process Fix):
    1. Why did checkout fail in Production? → Because coupon `SAVE20` threw a `NullPointerException` when cart subtotal was `$0`.
    2. Why did the code throw NPE? → Because `discount.getAmount()` was called without a null check.
    3. Why didn't Unit/QA tests catch it? → Because QA only tested `$100` carts, not `$0` gift-card carts.
    4. Why wasn't `$0` in the Test Cases? → Because Acceptance Criteria didn't mention boundary `$0` subtotal.
    5. Root Fix: Add BVA checklist to Sprint Refinement + add automated regression test for `$0` cart in CI/CD.
  • 2. Fishbone (Ishikawa) Diagram: Categorizes causes into branches (Requirements, Code, Test Coverage, Test Data, Environment/Config, CI/CD) to make sure no contributing factor is missed.

Interview Answer: "DRE is `(QA Defects / (QA + Prod Defects)) * 100` and Defect Leakage is `100% - DRE`. When a critical bug escapes to production, we run a blameless 5-Whys RCA to fix both the code bug and the missing test/process gate, then add a permanent automated regression test."

4. In Selenium & SDET Automation

  • Closing Escaped Defects Permanently: Every production escape identified during 5-Whys RCA must produce a permanent Selenium/API regression test (e.g., asserting $0 gift-card checkout in CI) so the same defect can never leak twice.
  • Tracking Suite Effectiveness: High DRE correlates directly with deterministic Selenium assertions, explicit WebDriverWait conditions, and isolated test data rather than brittle Thread.sleep() waits.
