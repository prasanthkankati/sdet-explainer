Playwright

1.1 Playwright Introduction, Key Features, TS vs JS & Setup

1. What is Playwright?

Playwright is an open-source Node.js library and test automation framework developed by Microsoft (released in 2020) for automating modern web browsers and end-to-end testing.

Interview Answer: "Playwright Test is an end-to-end test framework for modern web apps created by Microsoft. It bundles a test runner, auto-waiting assertions, isolated browser contexts, parallelization, and rich tooling. It natively supports Chromium, WebKit, and Firefox across Windows, Linux, and macOS in both headless and headed modes, with built-in mobile emulation for Chrome (Android) and Mobile Safari."

Core Facts to Know:

  • Developer & Year: Created by Microsoft and open-sourced in 2020.
  • Primary Use Case: Built mainly for fast, reliable end-to-end (E2E) testing of modern single-page applications (React, Angular, Vue, Next.js).
  • API Testing Included: Beyond UI browser automation, Playwright includes native support for testing backend REST APIs and validating microservices via APIRequestContext without extra libraries.
  • Technology Foundation: It is a Node.js library that executes outside the browser while communicating over high-speed native debugging protocols.

2. Playwright Architecture & The Restaurant Analogy

To understand how Playwright communicates with browser processes at runtime, examine the Restaurant Analogy:

Role in AnalogyPlaywright ComponentReal Technical Function

Waiter 🍽️Playwright APIReceives your test instructions, serializes them, and passes them to the communication channel.
Communication Line 📡WebSocket ConnectionA single, persistent, bi-directional pipe streaming JSON messages via Chrome DevTools Protocol (CDP) or native browser socket pipes.

3. Real Browsers vs. Rendering Engines

A fundamental concept in Playwright is that it automates browser rendering engines, not branded consumer browsers:

  • Chromium, Firefox, and WebKit are rendering browser engines (the underlying layout and JavaScript execution cores).
  • Branded consumer browsers are developed on top of these rendering engines:
    • Chromium Engine: Powers Google Chrome, Microsoft Edge, Brave, Vivaldi, and Opera.
    • WebKit Engine: Powers Apple Safari (macOS and iOS).
    • Gecko Engine: Powers Mozilla Firefox.

When you run tests in Playwright, it downloads and launches dedicated, pinned builds of Chromium, Firefox, and WebKit. This guarantees tests run deterministically against the core layout engines without interference from personal user extensions, auto-updates, or custom browser skins.

4. Playwright vs. Selenium WebDriver

A direct architectural comparison between the two leading automation frameworks:

Architecture DimensionPlaywrightSelenium WebDriver
Communication ProtocolSingle, persistent, bi-directional WebSocket (CDP / BiDi socket). Zero HTTP polling.Stateless HTTP request-response roundtrips over W3C WebDriver wire protocol.
Driver ExecutablesZero driver management. Directly controls browser engine binaries via native internal pipes.Requires intermediate driver executables (ChromeDriver, GeckoDriver, msedgedriver).
Execution SpeedExtremely fast (sub-millisecond command execution over WebSocket).Slower due to network roundtrips for every findElement and interaction.
Auto-WaitingBuilt-in automatic actionability checks (visible, stable, enabled, clickable) before every action.No built-in auto-waiting. Requires explicit WebDriverWait and ExpectedConditions loops.
Session IsolationLightweight BrowserContext (creates fresh incognito profile in ~5–10ms with zero memory bloat).Cold browser boots. Running a new session requires launching a brand-new OS browser process.
Shadow DOMPierces open Shadow DOM automatically without special syntax or JavaScript executors.Requires complex custom JavaScript traversal (getShadowRoot()).
Network & APIBuilt-in network interception, API mocking (page.route), and direct REST API testing.Requires external proxy tools (Browsermob) or complex BiDi DevTools listener scripts.

  2. Install VS Code: Download and install Visual Studio Code (code.visualstudio.com).

cd playwright-tests

7. Playwright Installation & Version Check

Initialize Playwright in your project folder using the official scaffolding command:

# Install Playwright test runner and scaffolding
npm init playwright@latest

After installation completes, verify the installed Playwright version:

# Check Playwright CLI version
npx playwright --version
# Example output: Version 1.50.0

9. Running Tests: Headless vs. Headed Execution

Playwright offers flexible test execution modes from the command line:

1. Headless Mode (Default Execution)

By default, Playwright runs tests in headless mode—the browser runs entirely in memory without opening a visible graphical window, making execution fast and ideal for CI/CD servers:

# Run all tests headlessly across Chromium, Firefox, and WebKit
npx playwright test

# Run a specific test file headlessly
npx playwright test ./tests/example.spec.ts

2. Headed Mode (Visual Browser Window)

To watch the browser window execute actions visually for debugging, pass the --headed flag:

# Run a specific test file with visible browser window
npx playwright test ./tests/example.spec.ts --headed

# Run tests on a single browser engine with visible window
npx playwright test --project=chromium --headed

3. Interactive UI Mode & Reports

# Launch interactive UI Mode (time-travel debugging, watch mode, locator playground)
npx playwright test --ui

# Open the auto-generated HTML test report
npx playwright show-report

11. JavaScript vs. TypeScript in Test Automation

Understanding static vs. dynamic typing in automation suites:

JavaScript (Dynamically Typed)

Variables can change types at runtime without strict compiler verification:

let age = 30;       // Number
let name = "John";  // String
age = "thirty";     // Valid in JS — variable mutated from Number to String without compile error

TypeScript (Statically Typed)

Superset of JavaScript that enforces strict type contracts at compile time:

let age: number = 30; // Strictly typed as number
let name: string = "John";
age = "thirty";       // COMPILE ERROR: Type 'string' is not assignable to type 'number'

Why Use TypeScript for Playwright?

  • ECMAScript Standard: Compiles down to standard JavaScript executing on any Node.js runtime.
  • Catches Errors Early: Identifies invalid locator arguments and broken method calls inside VS Code before running tests.
  • Full IntelliSense: Displays available methods, arguments, and return types for Page, Locator, and Expect.

12. Installing & Managing Dedicated Browser Binaries

# Install default browser binaries (Chromium, Firefox, WebKit)
npx playwright install

# Install browsers AND operating system dependencies (required for Linux CI / Docker)
npx playwright install --with-deps

Browser Binary Cache Locations:

  • Windows: %USERPROFILE%\AppData\Local\ms-playwright
  • macOS: ~/Library/Caches/ms-playwright
  • Linux: ~/.cache/ms-playwright

13. Updating Playwright

# Update @playwright/test to latest version
npm install -D @playwright/test@latest

# Download matching new browser binaries and dependencies
npx playwright install --with-deps
