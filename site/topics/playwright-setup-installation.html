Playwright

1.1 Setup for Playwright Testing (Node.js, npm init, Config & First Test)

Playwright Test is an end-to-end test framework for modern web apps. It bundles test runner, assertions, isolation, parallelization and rich tooling. Playwright supports Chromium, WebKit and Firefox on Windows, Linux and macOS, locally or in CI, headless or headed, with native mobile emulation for Chrome (Android) and Mobile Safari.

Playwright was created specifically to accommodate the needs of end-to-end testing. Playwright supports all modern rendering engines including Chromium, WebKit, and Firefox. Test on Windows, Linux, and macOS, locally or on CI, headless or headed with native mobile emulation.

1. Installing Playwright

Get started by installing Playwright using your preferred package manager. Run the following command in your terminal:

# Recommended: Initialize via npm
npm init playwright@latest

# Alternative package managers
yarn create playwright
pnpm create playwright

Running this command will prompt you through a few quick configuration choices:

  • Choose between TypeScript or JavaScript: TypeScript is the default and strongly recommended.
  • Name of your Tests folder: Default is tests (or e2e if you already have a tests folder).
  • Add a GitHub Actions workflow: Adds a CI workflow file to run tests on every push and pull request.
  • Install Playwright browsers: Installs the browser binaries (Chromium, Firefox, WebKit). Default is true.

2. What's Installed

Playwright generates a clean project layout with ready-to-run example tests and configuration:

my-playwright-project/
├── playwright.config.ts                 # Master configuration file for runner, projects & options
├── package.json                         # Project dependencies and test run scripts
├── package-lock.json                    # Exact dependency lockfile
├── tests/
│   └── example.spec.ts                  # Basic end-to-end test spec to get started
└── tests-examples/
    └── demo-todo-app.spec.ts            # Comprehensive TodoMVC real-world testing example

The playwright.config.ts file specifies options for your tests, including where tests are located, test timeouts, browser configurations, base URLs, and reporter outputs.

3. Writing Your First Test

The generated tests/example.spec.ts demonstrates how to use the test and expect primitives with auto-waiting web-first assertions:

import { test, expect } from "@playwright/test";

test("has title", async ({ page }) => {
  await page.goto("https://playwright.dev/");

  // Expect a title "to contain" a substring.
  await expect(page).toHaveTitle(/Playwright/);
});

test("get started link", async ({ page }) => {
  await page.goto("https://playwright.dev/");

  // Click the get started link.
  await page.getByRole("link", { name: "Get started" }).click();

  // Expects page to have a heading with the name of Installation.
  await expect(page.getByRole("heading", { name: "Installation" })).toBeVisible();
});

Core concepts in this test:

  • { page } fixture: Playwright creates an isolated browser page for each test automatically. No manual browser opening or closing needed.
  • Auto-Waiting: Actions like click() and fill() automatically wait for elements to be visible, stable, enabled, and clickable before interacting.
  • Web-First Assertions: Assertions like expect(page).toHaveTitle() and expect(locator).toBeVisible() automatically retry until the condition passes or timeout is reached.

4. Running Your Tests

By default, Playwright runs tests across all 3 browsers (Chromium, Firefox, WebKit) in headless mode (no browser window opens, output renders in terminal):

# Run all tests across all configured projects (Chromium, Firefox, WebKit)
npx playwright test

# Run tests with the browser visible (Headed Mode)
npx playwright test --headed

# Run tests on a specific browser project only
npx playwright test --project=chromium

# Run a single specific test file
npx playwright test tests/example.spec.ts

# Run tests that match a specific title
npx playwright test -g "has title"

5. HTML Test Reports

After your tests finish running, Playwright automatically generates an interactive HTML test report. You can open and inspect it in your browser anytime:

# View the HTML test report
npx playwright show-report

The report provides a complete breakdown of every test run: which browser project ran, execution duration, test steps, failure screenshots, video recordings, and attached traces.

6. Running Tests in UI Mode

For a rich developer experience during test creation and debugging, launch Playwright's interactive UI Mode:

# Launch the interactive UI Mode
npx playwright test --ui

Features of UI Mode:

  • Time-Travel Debugging: Hover over each test step to see full visual DOM snapshots of before and after every action.
  • Watch Mode: Automatically re-runs tests on save when editing test files.
  • Locator Playground: Pick elements directly from the preview window to test and generate resilient locator queries.
  • Network & Console Tabs: Inspect HTTP requests, responses, and browser console messages at every step in time.

7. Installing & Managing Browser Binaries

Playwright requires browser binaries to run tests. If you skipped browser installation during initial setup or need to reinstall them:

# Install default browsers (Chromium, Firefox, WebKit)
npx playwright install

# Install a specific browser only
npx playwright install chromium

# Install browsers AND operating system dependencies (required for Linux CI / Docker)
npx playwright install --with-deps

Browser Cache Directory:

  • Windows: %USERPROFILE%\AppData\Local\ms-playwright
  • macOS: ~/Library/Caches/ms-playwright
  • Linux: ~/.cache/ms-playwright

8. Updating Playwright

Keep Playwright updated to the latest version to get access to new browser features, performance improvements, and bug fixes:

# Update @playwright/test to latest
npm install -D @playwright/test@latest

# Download matching new browser binaries
npx playwright install --with-deps

9. Key Interview Questions on Playwright Setup

  1. What makes Playwright Test different from traditional Selenium WebDriver?
    Playwright communicates with browsers over persistent WebSocket connections using internal debugging protocols (CDP for Chromium), allowing real-time event streaming, automatic waiting, and zero-overhead browser context creation. Selenium communicates via HTTP requests per W3C specification with explicit driver executables.
  2. What is a BrowserContext and why does Playwright use it?
    A BrowserContext is an isolated, incognito-equivalent session inside a single browser process. Creating a context takes only milliseconds and uses minimal memory. Playwright runs every test in a separate, pristine context, ensuring 100% test isolation without the performance penalty of relaunching full browser processes.
  3. Why are Playwright assertions called "web-first"?
    Because they are designed specifically for the asynchronous nature of the web. Assertions such as await expect(locator).toBeVisible() do not perform a one-time check; they continuously poll the DOM until the condition is met or the timeout is exceeded, eliminating race conditions.
  4. What does npx playwright install --with-deps do on CI?
    It downloads the browser binaries and installs all missing OS system-level libraries (such as graphics, font rendering, and audio packages on Linux/Ubuntu) needed for headless browser execution.
