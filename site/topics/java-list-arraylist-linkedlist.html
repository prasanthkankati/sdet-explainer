5.2 List: ArrayList vs LinkedList

Ordered duplicate-allowing List implementations, ArrayList 1.5x resizing vs doubly-linked LinkedList nodes, time complexities, and Selenium findElements().

The List<E> interface maintains insertion order, permits duplicate elements and null entries, and supports positional zero-based indexing. Selecting between ArrayList (backed by a contiguous dynamic array) and LinkedList (backed by doubly-linked node objects) depends on access patterns, memory footprint, and insertion positions.

Before you start

Prerequisite: 5.1 Collections Hierarchy & Generics (Type Safety)

Where it fits

Selenium's driver.findElements(By) returns a List<WebElement> (specifically an ArrayList under the hood), and product catalog validations store ordered titles and prices in List structures.

Key points

  1. List<E> preserves insertion order, allows duplicate values, and supports indexed methods (get(i), set(i, e), indexOf(e)).
  2. ArrayList is backed internally by a contiguous Object[] elementData array with an initial default capacity of 10 (allocated lazily upon adding the first element).
  3. When an ArrayList reaches capacity, it allocates a new array 1.5x larger using oldCapacity + (oldCapacity >> 1) and copies elements via Arrays.copyOf().
  4. ArrayList.get(index) runs in constant O(1) time, whereas inserting or removing in the middle requires shifting trailing elements in O(n) time.
  5. LinkedList implements both List<E> and Deque<E> using doubly-linked Node<E> objects storing item, prev, and next references; random get(index) requires traversing nodes in O(n) time.
  6. driver.findElements(By) returns an empty list (size() == 0) when no elements match—unlike driver.findElement(By), which throws NoSuchElementException.

How it works

  1. Call List<WebElement> cards = driver.findElements(By.cssSelector(".card")); to capture matching DOM items safely without exception.
  2. Notice findElements() returns a List backed by an array; iterating or reading cards.get(0) executes in O(1) time.
  3. If the list grows dynamically beyond 10 elements, ArrayList expands capacity by 50% automatically (10 -> 15 -> 22 -> 33).
  4. For immutable test expectations, construct List.of("A", "B") (Java 9+) rather than mutating a shared array-backed list.

Using ArrayList capacity growth, Selenium findElements(), and Java 9+ immutable List.of():

package dev.java.collections; // Declares package

import org.openqa.selenium.By; // Imports By locator
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import java.util.ArrayList; // Imports ArrayList implementation
import java.util.List; // Imports List interface

public class ListComparisonDemo { // Demonstrates ArrayList usage in Selenium
    static List<String> extractVisibleTitles(WebDriver driver, By locator) { // Extracts DOM text safely
        List<WebElement> elements = driver.findElements(locator); // Returns empty list if 0 matches (no exception)
        List<String> titles = new ArrayList<>(elements.size()); // Pre-sizes ArrayList to avoid resizes
        for (WebElement el : elements) { // Iterates elements in DOM order
            String text = el.getText().strip(); // Captures trimmed visible text
            if (!text.isEmpty()) { // Skips empty text nodes
                titles.add(text); // Appends text in O(1) time with zero resize churn
            } // Ends empty guard
        } // Ends iteration
        return List.copyOf(titles); // Returns unmodifiable defensive copy (Java 10+)
    } // Ends extractVisibleTitles
} // Ends class

Common mistakes

  1. Iterating a LinkedList with an indexed for (int i = 0; i < list.size(); i++) list.get(i) loop; calling get(i) on a LinkedList walks from the head/tail on every step, turning a linear loop into quadratic O(n^2) time.
  2. Calling driver.findElements(By).get(0) without checking !list.isEmpty(); when 0 elements appear, findElements() returns an empty list and get(0) immediately throws IndexOutOfBoundsException.
  3. Passing null into Java 9+ List.of(...) or attempting List.of("a").add("b"); List.of() rejects null elements with NullPointerException and rejects mutation with UnsupportedOperationException.
  4. Using legacy Vector instead of ArrayList; every Vector method synchronizes unconditionally and doubles capacity (2x), wasting both CPU locks and RAM.

Interview questions

Basics

Compare ArrayList and LinkedList on internal structure, access speed, and memory usage.
ArrayList uses a single contiguous Object[] array, giving O(1) indexed lookup (get(i)) and low per-element memory overhead while paying O(n) cost to shift elements when inserting or deleting in the middle. LinkedList wraps every element in a separate Node object holding prev and next references, consuming roughly 3x–4x more memory and requiring O(n) traversal for get(i) while offering O(1) insertion/removal at both ends.

How does driver.findElement(By) differ from driver.findElements(By) when an element is missing?
driver.findElement(By) expects at least one matching node and immediately throws NoSuchElementException (after any active implicit wait) if none exist. driver.findElements(By) returns a List<WebElement> containing all matching elements, or a clean empty list (size() == 0) without throwing an exception when zero elements match.

Are ArrayList and LinkedList thread-safe?
Neither is thread-safe. Concurrent structural modification from multiple threads causes lost elements or ConcurrentModificationException. For thread-safe lists across threads, use CopyOnWriteArrayList (for read-heavy listener lists) or synchronize explicitly around shared mutations.

How it works

Explain how ArrayList grows dynamically when its internal array fills up.
When constructed via new ArrayList<>(), Java initially shares a zero-length empty array and lazily allocates capacity 10 upon the very first add(). Once adding an 11th element overflows capacity, ArrayList.grow() computes newCapacity = oldCapacity + (oldCapacity >> 1) (1.5x growth: 10 -> 15 -> 22) and copies existing references into the newly allocated Heap array via Arrays.copyOf().

Why is ArrayList faster than LinkedList even for repeated sequential scans and middle edits in practice?
ArrayList elements sit contiguously in RAM (actually their object references sit sequentially in one array), enabling hardware CPU cache lines to prefetch adjacent slots effortlessly. LinkedList scatters individual Node objects randomly across the Heap, causing frequent CPU cache misses during pointer chasing.

What is the difference between list.remove(1) and list.remove(Integer.valueOf(1)) on a List<Integer>?
List<E> overloads remove(int index) and remove(Object o). Calling list.remove(1) invokes the primitive int overload and deletes the element at index 1, whereas calling list.remove(Integer.valueOf(1)) invokes the Object overload and removes the first occurrence of value 1.

Real situations

When writing a Selenium helper that checks whether an optional modal banner appeared without failing the test, how does List<WebElement> help?
Use List<WebElement> banners = driver.findElements(By.id("promo-modal")); and check if (!banners.isEmpty() && banners.get(0).isDisplayed()). Notice that if implicit wait is set to 10s, findElements() still waits up to 10s when absent—so keep implicit wait at 0s and rely on explicit waits.

When collecting text from 200 product cards via List<WebElement> cards, why pre-size new ArrayList<>(cards.size())?
Passing cards.size() to the ArrayList(int initialCapacity) constructor allocates the exact array size in one shot, eliminating repeated 1.5x array copies (10 -> 15 -> 22 -> 33 -> 49 -> 73 -> 109 -> 163 -> 244) and wasted array garbage.

How do you implement a FIFO test-queue or undo stack cleanly in Java?
Although LinkedList implements Deque, the official Java documentation recommends ArrayDeque<E> for both stacks and FIFO queues because a resizable circular array beats node-per-element allocation in speed and Heap memory.

Troubleshooting

Why does List<String> list = List.of("a", "b"); list.set(0, "c"); throw UnsupportedOperationException while Arrays.asList("a", "b") allows set()?
List.of() constructs a strictly immutable unmodifiable collection introduced in Java 9 that forbids add, remove, set, and null elements. Arrays.asList() returns a fixed-size mutable wrapper backed by the original array, allowing set() while forbidding add and remove.

Why does list.subList(1, 3).clear(); unexpectedly remove elements from the original parent list?
List.subList(from, to) does NOT copy elements into a standalone new list; it returns a live backed view over a slice of the original list. Any mutation on the subList reflects directly in the parent list, and structural edits directly on the parent list afterward throw ConcurrentModificationException on the subList.

Why did driver.findElements(locator).get(0).click() throw IndexOutOfBoundsException: Index 0 out of bounds for length 0?
The page had not yet rendered the element or the locator matched zero nodes, so findElements() returned an empty list of length 0. Use WebDriverWait with ExpectedConditions.numberOfElementsToBeMoreThan(locator, 0) before calling .get(0).

Design choices

Why is ArrayList the default choice over LinkedList in 95% of Java and SDET applications?
Most lists in tests and business code are populated sequentially at the tail and iterated or indexed randomly, where ArrayList's contiguous memory layout delivers vastly higher CPU cache locality and lower memory overhead. Only choose LinkedList (or preferably ArrayDeque) when frequent O(1) insertions/deletions at both the head and tail dominate.

Why should Page Objects return unmodifiable lists (List.copyOf(result)) when exposing scraped UI rows?
Returning an unmodifiable defensive copy prevents test assertions or utility helpers from mutating Page Object internal lists inadvertently while protecting against accidental null insertions.

Why was legacy Vector effectively replaced by ArrayList and CopyOnWriteArrayList?
Synchronizing every single get() and size() method on Vector imposes unnecessary lock contention even for single-threaded usage and still fails compound check-then-act sequences (if (!v.isEmpty()) v.get(0)). Modern code uses local ArrayList for isolated threads or CopyOnWriteArrayList for concurrent shared reads.

Quick answers

  1. What is the default initial capacity of ArrayList? 10 (allocated lazily on the first add).
  2. By what factor does ArrayList grow when full? 1.5x (oldCapacity + (oldCapacity >> 1)).
  3. What is the time complexity of ArrayList.get(i) vs LinkedList.get(i)? O(1) for ArrayList; O(n) for LinkedList.
  4. What does driver.findElements(By) return if zero elements match? An empty List<WebElement> (size() == 0), never NoSuchElementException.
  5. Does List.of() allow null elements? No; it throws NullPointerException.
  6. Which interface allows ArrayList to signal O(1) indexed access? java.util.RandomAccess.
