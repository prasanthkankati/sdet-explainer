5.2 List: ArrayList vs LinkedList

1. Definition

ArrayList stores references inside a dynamic array that grows by 1.5x for instant O(1) indexed lookup, whereas LinkedList chains doubly-linked nodes for fast head/tail edits at the cost of O(n) index walks.

2. Memory hook

Default to ArrayList (O(1) get(i), 1.5x grow); LinkedList chases pointers node by node!

  • Internal capacity: ArrayList defaults to capacity 10 on first add() and grows by newCap = old + (old >> 1) (1.5x).
  • Why indexed for fails on LinkedList: calling linked.get(i) inside a loop walks from head/tail each step (O(n^2) slow!).
  • Arrays.asList vs List.of: Arrays.asList throws on add/remove (allows set & null); List.of is strictly unmodifiable and forbids null.

3. ArrayList Contiguous Array vs LinkedList Node Chain

Memory Layout Inside Heap
CPU cache prefetches contiguous ArrayList slots quickly; LinkedList nodes jump randomly in RAM.
ArrayList: Object[] block[0 | 1 | 2 | 3] -> instant jump list.get(2) in O(1)
LinkedList: Doubly-linked Nodes[prev|item0|next] <-> [prev|item1|next] -> walks links for index i

5. Code example: capturing Selenium product names safely in ArrayList

import java.util.*;

public class ListDemo {
    public static void main(String[] args) {
        List<String> expectedTabs = List.of("Downloads", "Documentation", "Projects"); // immutable Java 9+
        List<String> actualTabs = new ArrayList<>(10); // dynamic array sized for fast index read

        actualTabs.add("Downloads");
        actualTabs.add("Documentation");
        actualTabs.add("Projects");

        System.out.println("Index 1 = " + actualTabs.get(1));        // O(1) direct jump
        System.out.println("Matches expected? " + actualTabs.equals(expectedTabs)); // true (same order)
    }
}

6. Execution flow, step by step

  1. List.of(...) creates a compact immutable baseline list (zero add, set, or null allowed).
  2. new ArrayList<>(10) allocates a single backing array ready for 10 elements before resizing by 1.5x.
  3. Adding three strings fills slots 0, 1, and 2 in order, preserving duplicates and insertion sequence.
  4. actualTabs.get(1) computes the offset immediately in O(1) time without walking prior elements.
  5. actualTabs.equals(expectedTabs) passes true because any two List implementations match when size and order match element for element.

8. Why it matters

Choosing ArrayList by default avoids scattered node memory overhead and gives instant random access on 95%+ of real list workloads.

SDET link: driver.findElements(By.cssSelector(".product-title")) returns a List<WebElement>; extracting strings with new ArrayList<>() preserves exact UI order so you can assert sorted prices and check order equality cleanly.

9. Quick test

What exception does List.of("A", null) throw? NullPointerException — Java 9+ immutable factory collections forbid null elements.
