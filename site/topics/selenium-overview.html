Selenium Overview

Is Selenium for you? See an overview of the different project components.

Selenium is not just one tool or API; it comprises many tools. It is an umbrella project for a range of tools and libraries that enable and support the automation of web browsers.

It provides extensions to emulate user interaction with browsers, a distribution server for scaling browser allocation, and the infrastructure for implementations of the W3C WebDriver specification that lets you write interchangeable code for all major web browsers.

WebDriver

If you are beginning with desktop website or mobile website test automation, then you are going to be using WebDriver APIs. WebDriver uses browser automation APIs provided by browser vendors to control the browser and run tests. This is as if a real user is operating the browser. Since WebDriver does not require its API to be compiled with application code, it is not intrusive. Hence, you are testing the same application which you push live.

IDE

IDE (Integrated Development Environment) is the tool you use to develop your Selenium test cases. It’s an easy-to-use Chrome and Firefox extension and is generally the most efficient way to develop test cases. It records the users’ actions in the browser for you, using existing Selenium commands, with parameters defined by the context of that element. This is not only a time-saver but also an excellent way of learning Selenium script syntax.

Grid

Selenium Grid allows you to run test cases in different machines across different platforms. The control of triggering the test cases is on the local end, and when the test cases are triggered, they are automatically executed by the remote end.

After the development of the WebDriver tests, you may face the need to run your tests on multiple browsers and operating system combinations. This is where Grid comes into the picture.

Where it fits

Selenium forms the foundational execution engine in test automation architecture, translating high-level test assertions written in Java into native browser commands dispatched to Chrome, Firefox, Edge, and Safari.

Key points

  1. Selenium is not a single tool; it is an open-source suite composed of WebDriver, Selenium Grid, Selenium IDE, and Selenium Manager.
  2. WebDriver drives browsers natively using browser vendor automation APIs and conforms to the official W3C WebDriver standard.
  3. Selenium Manager is a built-in binary tool that automatically detects browser versions and downloads the matching driver binaries.
  4. Selenium Grid allows parallel test execution across multiple remote machines, virtual environments, and container platforms.
  5. Selenium IDE is a Chrome and Firefox browser extension used for recording, playing back, and prototyping automated scripts.
  6. Selenium does not include a test runner or reporting tool; it integrates with Java testing frameworks such as TestNG and JUnit 5.

How it works

  1. The test engineer writes browser automation steps in Java using the Selenium client bindings.
  2. Selenium Manager checks the local system, identifies the installed browser version, and resolves the matching driver executable.
  3. The driver executable launches on a local port and starts a browser session adhering to the W3C WebDriver protocol.
  4. Test commands (navigation, element discovery, clicks, text input) are transmitted as HTTP requests to the driver endpoint.
  5. The driver translates each W3C command into native internal browser operations and returns execution responses to the test script.
  6. Upon test completion, driver.quit() destroys the browser session and terminates the driver process.

Minimal Java WebDriver execution snippet:

package dev.selenium.overview; // Declares the package structure

import org.openqa.selenium.WebDriver; // Imports the core WebDriver interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports the ChromeDriver class

public class SeleniumOverviewExample { // Declares the demonstration class
    public static void main(String[] args) { // Entry point of the application
        WebDriver driver = new ChromeDriver(); // Initializes driver and launches Chrome via Selenium Manager
        try { // Starts guarded execution block
            driver.get("https://www.selenium.dev/"); // Navigates to the official Selenium website
            System.out.println("Page Title: " + driver.getTitle()); // Prints the current document title to standard console
        } finally { // Starts teardown block
            driver.quit(); // Closes the browser and terminates the driver process cleanly
        } // Ends teardown block
    } // Ends main method
} // Ends class

Common mistakes

  1. Assuming Selenium is a desktop automation or performance testing tool; fix by using Selenium strictly for web browser rendering and UI functional tests.
  2. Manually downloading browser drivers and configuring system PATH variables; fix by relying on the built-in Selenium Manager to resolve drivers automatically.
  3. Using Selenium IDE recordings directly in enterprise production test suites; fix by writing structured, maintainable code using WebDriver and the Page Object Model.
  4. Omitting driver.quit() at the end of execution; fix by placing quit() inside a finally block or test runner teardown hook.

Interview questions

Basics

What is Selenium and what components constitute the project suite?
Selenium is an open-source umbrella project for automated web application testing across different browsers and platforms. The suite consists of Selenium WebDriver for programmatic browser automation, Selenium Grid for scaling parallel execution across distributed nodes, Selenium IDE for rapid record-and-playback prototyping, and Selenium Manager for automated driver binary management. In an enterprise automation pipeline, test scripts are written in Java using WebDriver APIs and run in parallel on Selenium Grid.
How does Selenium WebDriver differ from Selenium IDE?
Selenium WebDriver is a programmatic code library that allows developers to write robust, maintainable, object-oriented test automation scripts in languages like Java. Selenium IDE is a browser extension limited to recording user interactions in the DOM and replaying them without enterprise logic. For example, WebDriver supports complex loops, custom database connections, and Page Object Models, whereas Selenium IDE is designed only for quick smoke test prototypes.
Which programming languages and browsers does Selenium officially support?
Selenium officially provides client language bindings for Java, Python, C#, JavaScript, and Ruby. It supports all modern browsers including Google Chrome, Mozilla Firefox, Microsoft Edge, and Apple Safari through browser vendor-maintained drivers. For instance, a Java automation suite can run the same test method on both ChromeDriver and GeckoDriver without altering business logic.

How it works

Explain the internal architecture and communication flow of Selenium 4 WebDriver.
Selenium 4 communicates directly with browser drivers using the standardized W3C WebDriver protocol over HTTP and WebSocket. When a Java test command like driver.findElement() executes, the Java client serializes the request into a standard JSON payload and sends an HTTP POST request to the local driver binary endpoint. The driver binary receives the W3C command, invokes native browser internal APIs, and returns an HTTP response containing execution results to the client.
What is Selenium Manager and how did it change test setup in Selenium 4?
Selenium Manager is an integrated cross-platform command-line utility built in Rust that automatically detects the installed browser versions on the host system and downloads the matching driver binaries. Prior to Selenium Manager, engineers had to manually download ChromeDriver executables, keep versions aligned with Chrome browser updates, and configure system PATH variables or third-party libraries like WebDriverManager. With Selenium Manager, executing WebDriver driver = new ChromeDriver(); automatically resolves the correct driver binary without any third-party tools.
What role does Selenium Grid play in an enterprise CI/CD pipeline?
Selenium Grid distributes test sessions across multiple machines, operating systems, and browser versions to enable high-volume parallel execution. In a CI/CD environment like Jenkins or GitHub Actions, a test suite sends commands to the Grid Router/Hub, which forwards sessions to available Node containers. For example, a suite of 200 tests can run concurrently across 10 Docker nodes, cutting total execution time from hours to minutes.

Real situations

How do you decide whether to run tests on a local browser or through Selenium Grid?
Local browser execution is ideal during test development, script authoring, and quick debugging where immediate visual feedback is needed. Selenium Grid is required when executing regression suites in continuous integration, running cross-browser matrix tests, or executing multiple tests in parallel. For example, an engineer authors a test locally in IntelliJ with Chrome, and the CI server runs the entire 500-test suite across a Kubernetes-backed Selenium Grid cluster.
When should a team use Selenium IDE instead of Selenium WebDriver?
Selenium IDE should be used for rapid exploratory prototyping, reproducing bug sequences reported by manual testers, or demonstrating proof-of-concept workflows without writing code. WebDriver must be chosen for any production automation project requiring maintainability, CI/CD integration, assertions, and test data management. For instance, a manual tester can record a bug reproduction step sequence in Selenium IDE and export it as a Java JUnit script for the automation team.
Can Selenium automate desktop applications or native mobile apps?
Selenium is strictly engineered for web browser automation and cannot automate native desktop or mobile applications directly. However, the W3C WebDriver standard established by Selenium forms the foundation for tools like Appium, which automates native iOS and Android apps, and WinAppDriver for Windows desktop apps. For example, a team automating an Android app uses Appium client bindings, which inherit the same syntax and commands as Selenium WebDriver.

Troubleshooting

What causes a SessionNotCreatedException and how is it resolved?
SessionNotCreatedException occurs when the browser driver binary cannot establish a new session, most commonly because the driver version is incompatible with the installed browser version. In Selenium 4, this is resolved by allowing Selenium Manager to automatically fetch the matching driver version rather than hardcoding local driver binary paths in System.setProperty. For example, if Chrome updates to version 130 while an old ChromeDriver 128 is forced via system properties, removing the manual path allows Selenium Manager to supply the correct version 130 binary.
Why must driver.quit() always be called, and what happens if it is omitted?
driver.quit() closes all open browser windows, terminates the remote session, and cleanly kills the background driver process executable. If it is omitted or if driver.close() is called instead, the driver executable continues running in memory, consuming system RAM and CPU. For example, in an automated regression run on a CI runner, omitting driver.quit() leaves dozens of orphan chromedriver.exe processes running until the machine runs out of memory.

Design choices

Why does Selenium WebDriver not include its own assertion library or test runner?
Selenium follows the single-responsibility principle by focusing purely on browser automation and leaving test organization to dedicated testing frameworks. This design allows engineers to integrate Selenium seamlessly with industry-standard runners like TestNG, JUnit 5, or Cucumber. For example, a Java test uses Selenium to interact with web elements, while TestNG handles Assert.assertEquals(), @DataProvider annotations, and execution reporting.
Why was the JSON Wire Protocol replaced with the W3C WebDriver standard in Selenium 4?
The legacy JSON Wire Protocol required the Selenium client to encode commands and the driver to decode them, leading to inconsistencies and flakiness between different browser vendors. By making W3C WebDriver an official web standard, browser vendors implement the specification directly within their drivers, eliminating translation overhead and improving stability. For example, actions and window management execute natively across Chrome, Firefox, and Safari without intermediate translation discrepancies.

Quick answers

What is Selenium?
An open-source suite of tools and libraries for automating web browsers.
What is WebDriver?
A W3C standard API that drives browsers natively through vendor drivers.
What is Selenium Manager?
A built-in utility in Selenium 4 that downloads and configures matching driver binaries automatically.
What is Selenium Grid?
A distributed server infrastructure for running browser tests in parallel across remote machines.
What is Selenium IDE?
A Chrome and Firefox extension for recording, playing back, and prototyping test cases.
Does Selenium provide test assertions?
No; Selenium handles browser control, while frameworks like TestNG or JUnit 5 provide assertions.
How do you terminate a WebDriver session cleanly?
Call driver.quit() inside a teardown or finally block.
