2.2 Write Your First Selenium Script

The eight fundamental components of every Selenium WebDriver script from session startup to teardown.

Every Selenium test script follows a predictable eight-step lifecycle to interact with a web application. The script starts a browser session, navigates to a URL, queries browser metadata, establishes a synchronization strategy, locates DOM elements, performs user actions, reads element state, and terminates the session.

Before you start

Prerequisite: 2.1 Install Selenium Library

Where it fits

These eight steps form the core execution body of every automated UI test method across smoke, sanity, and regression suites.

Key points

  1. Step 1 (Start Session): WebDriver driver = new ChromeDriver() launches a browser instance and binds a W3C session.
  2. Step 2 (Navigate): driver.get("https://...") loads the target web page and waits for the document readyState to reach complete.
  3. Step 3 (Browser Info): driver.getTitle() and driver.getCurrentUrl() retrieve document-level metadata.
  4. Step 4 (Wait Strategy): Synchronization ensures elements exist in the DOM before interacting with them.
  5. Step 5 & 6 (Find & Act): driver.findElement(By...) locates a WebElement so methods like sendKeys() and click() can act on it.
  6. Step 7 & 8 (Read State & End Session): getText() extracts rendered text for assertions, and driver.quit() closes all windows and kills the driver process.

How it works

  1. Instantiate ChromeDriver() to start the local driver server and open a fresh Chrome browser window.
  2. Call driver.get() with the target URL to navigate to the web page under test.
  3. Configure a wait timeout using driver.manage().timeouts().implicitlyWait(Duration.ofMillis(500)) or WebDriverWait.
  4. Locate the target input field and submit button using driver.findElement(By.name(...)) or By.cssSelector(...).
  5. Invoke sendKeys() on the input element and click() on the button element, then read the resulting message with getText().
  6. Invoke driver.quit() inside a finally block to close the browser and release operating system resources.

Complete 8-step Selenium 4 Java script:

package dev.selenium.getting_started; // Declares package namespace

import org.openqa.selenium.By; // Imports By locator mechanism
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver implementation
import java.time.Duration; // Imports Java time Duration class

public class FirstScriptExample { // Declares test class
    public static void main(String[] args) { // Main execution entry point
        WebDriver driver = new ChromeDriver(); // 1. Starts the session and launches Chrome
        try { // Guards execution to guarantee cleanup
            driver.get("https://www.selenium.dev/selenium/web/web-form.html"); // 2. Navigates to target web form
            String title = driver.getTitle(); // 3. Requests browser document title
            driver.manage().timeouts().implicitlyWait(Duration.ofMillis(500)); // 4. Establishes wait strategy
            WebElement textBox = driver.findElement(By.name("my-text")); // 5. Finds text input element
            WebElement submitButton = driver.findElement(By.cssSelector("button")); // 5. Finds submit button element
            textBox.sendKeys("Selenium"); // 6. Enters keystrokes into text box
            submitButton.click(); // 6. Clicks the submit button
            WebElement message = driver.findElement(By.id("message")); // 5. Finds confirmation message element
            System.out.println("Result: " + message.getText()); // 7. Requests element text content
        } finally { // Executes regardless of pass or exception
            driver.quit(); // 8. Ends session and terminates driver process
        } // Ends finally block
    } // Ends main method
} // Ends class

Common mistakes

  1. Interacting with elements immediately after click() without waiting for the DOM to update; fix by establishing an explicit or implicit wait before locating dynamic elements.
  2. Calling driver.close() instead of driver.quit() at the end of a test; fix by always calling driver.quit() so background driver processes do not leak memory.
  3. Passing a domain without the protocol scheme (such as driver.get("www.selenium.dev")) which throws InvalidArgumentException; fix by always including https:// or http://.

Interview questions

Basics

What are the eight core steps of a standard Selenium WebDriver script?
The eight steps are: (1) Start the session, (2) Take action on the browser (navigate), (3) Request browser information, (4) Establish a waiting strategy, (5) Find an element, (6) Take action on the element, (7) Request element information, and (8) End the session with driver.quit().

Why do we declare WebDriver driver = new ChromeDriver() instead of ChromeDriver driver = new ChromeDriver()?
Coding to the WebDriver interface applies polymorphism. It allows the rest of the test script to switch seamlessly between ChromeDriver, FirefoxDriver, EdgeDriver, or RemoteWebDriver without changing any method calls.

What happens if you pass a URL without https:// to driver.get()?
Selenium throws an org.openqa.selenium.InvalidArgumentException because the W3C WebDriver navigate command strictly requires a fully qualified URI scheme such as http:// or https://.

How it works

Does driver.get() wait for the web page to finish loading before moving to the next line?
Under the default PageLoadStrategy.NORMAL, driver.get() blocks execution until the browser fires the window load event (document.readyState equals complete), meaning HTML, stylesheets, and synchronous scripts have loaded.

When is a WebElement actually looked up in the DOM?
The DOM lookup happens the exact moment driver.findElement(By...) is executed. If the element is not present in the DOM after any configured implicit wait expires, Selenium immediately throws NoSuchElementException.

What happens internally when driver.quit() is executed?
Selenium sends an HTTP DELETE request to the /session/{sessionId} endpoint of the driver server. The driver closes all associated browser windows, deletes temporary user profile directories, and shuts down its own OS process.

Real situations

When should you use driver.close() instead of driver.quit() in a real test?
Use driver.close() when a test clicks a link that opens a secondary popup tab, verifies the popup content, and needs to close only that popup tab before switching back to the parent window. Always use driver.quit() in the final test teardown.

How do you verify that clicking a submit button navigated the user to the expected confirmation page?
After calling submitButton.click(), use WebDriverWait with ExpectedConditions.urlContains("/submitted") and then assert on driver.getCurrentUrl() and the confirmation element's getText().

Why should driver.quit() be placed inside a finally block or @AfterMethod hook?
If an assertion fails or a NoSuchElementException is thrown mid-test, normal execution aborts immediately. Placing driver.quit() inside finally or @AfterMethod guarantees the browser closes even when the test fails.

Troubleshooting

Why does calling any driver method after driver.quit() throw NoSuchSessionException?
Once driver.quit() executes, the session ID is destroyed and the driver server process is terminated. Any subsequent call on that same WebDriver reference has no active session to communicate with and throws NoSuchSessionException.

Why did driver.findElement() throw NoSuchElementException even though the element is visible on the screen?
The script likely executed findElement() a few milliseconds before an asynchronous AJAX call finished inserting the element into the DOM, or the element resides inside an <iframe>. Add an explicit wait or switch into the frame first.

What happens if driver.close() is called when only one browser tab is open?
The single browser window closes, but the background chromedriver binary process remains running in memory until driver.quit() is called.

Design choices

Why does Selenium separate browser-level actions (driver.get) from element-level actions (element.click)?
Separating browser context methods on WebDriver from DOM node operations on WebElement mirrors the browser architecture itself, keeping the API clean and modular.

Why did Selenium 4 replace long + TimeUnit parameters with java.time.Duration?
Java's standard Duration class (such as Duration.ofSeconds(10) or Duration.ofMillis(500)) is type-safe, self-documenting, and prevents unit conversion bugs between milliseconds and seconds.

Why should production test scripts avoid writing tests inside public static void main()?
A main() method lacks test lifecycle hooks, parallel execution, failure reporting, and assertion tracking. Production frameworks use TestNG or JUnit 5 @Test methods instead.

Quick answers

  1. Which method opens a URL in Selenium? driver.get("https://...") opens a URL and waits for page load.
  2. Which method returns the browser tab title? driver.getTitle() returns the current document title as a String.
  3. Which method finds a single element? driver.findElement(By) returns the first matching WebElement.
  4. Which method types text into an input? element.sendKeys("text") dispatches keystrokes to the element.
  5. What is the difference between close() and quit()? close() closes the current tab; quit() closes all tabs and stops the driver process.
