1.3 Stack vs Heap Memory & Pass-by-Value

1. Definition

The Stack stores short-lived method calls and local variables per thread, while the Heap stores all objects and arrays shared across the program; Java always passes copies of Stack values into methods.

2. Memory hook

Stack = Private scratchpad, Heap = Shared warehouse, Call = Copy the slip.

  • Stack opens a fresh frame when a method starts and wipes it cleanly when the method returns.
  • Heap holds every new object until nothing points to it and the Garbage Collector clears it.
  • Pass-by-value means a method receives a copy of a number or a copy of a Heap address ticket, never the caller's own Stack box.

5. Code example: primitive copy vs reference copy

public class MemoryTrace {
    static void bump(int sec, StringBuilder log) {
        sec = 30;                 // changes only local copy 'sec'; caller stays 10
        log.append("OK");         // follows @H99 copy into Heap and edits shared object
        log = new StringBuilder();// rewires only local 'log' to new @H100; caller unchanged
    }
    public static void main(String[] args) {
        int wait = 10;                              // Stack: literal value 10
        StringBuilder sb = new StringBuilder("Run:");// Stack: sb=@H99 -> Heap object "Run:"
        bump(wait, sb);                             // copies 10 and @H99 into bump's frame
        System.out.println(wait + " | " + sb);      // 10 | Run:OK
    }
}
javac MemoryTrace.java
java MemoryTrace   # Output: 10 | Run:OK

6. Execution flow, step by step

  1. main starts and gets the bottom Stack frame holding wait = 10 and sb = @H99.
  2. new StringBuilder("Run:") allocates the object at Heap address @H99.
  3. Calling bump(wait, sb) pushes a second Stack frame above main with copies sec = 10 and log = @H99.
  4. Setting sec = 30 changes only the child frame's box; calling log.append("OK") walks the copied address to edit @H99 on the Heap.
  5. Reassigning log = new StringBuilder() moves only log to @H100; when bump returns, its frame vanishes and main still prints 10 | Run:OK.

8. Why it matters

Every recursive loop without a base condition blows up the Stack (StackOverflowError), while holding onto huge lists or unclosed objects fills the Heap (OutOfMemoryError).

SDET link: Passing driver into a Page Object constructor (new LoginPage(driver)) copies the Heap ticket into the page so all pages drive the same browser. Setting a local variable d = null never closes the browser.

9. Quick test

If a helper sets its parameter driver = null;, does the caller's driver become null? No — only the copied Stack variable became null.
