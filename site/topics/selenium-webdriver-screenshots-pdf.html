5.3 Screenshots & Print to PDF

Capturing viewport screenshots (TakesScreenshot), element-level screenshots, and printing headless/headed pages to PDF (PrintsPage).

Visual evidence is critical for debugging failed CI/CD test runs and archiving invoice or receipt views. Selenium 4 provides TakesScreenshot to capture the current viewport, WebElement.getScreenshotAs() to capture an isolated DOM element, and PrintsPage.print(PrintOptions) to export any web page directly as a Base64-encoded PDF.

Before you start

Prerequisite: 5.2 Frames, Alerts & Cookies

Where it fits

Screenshots are captured inside TestNG @AfterMethod failure hooks or Extent/Allure report listeners, while Print to PDF is used in document export verification tests.

Key points

  1. ((TakesScreenshot) driver).getScreenshotAs(OutputType.FILE | BYTES | BASE64) captures the currently visible browser viewport.
  2. element.getScreenshotAs(OutputType.FILE) captures a cropped image of only that specific WebElement's bounding box.
  3. OutputType.BYTES or OutputType.BASE64 is preferred for attaching screenshots in-memory to Allure or ExtentReports without writing temporary disk files.
  4. ((PrintsPage) driver).print(new PrintOptions()) renders the current page to a W3C Pdf object, which can be written to disk via OutputType.BYTES.convertFromBase64Png(pdf.getContent()).
  5. FirefoxDriver additionally exposes getFullPageScreenshotAs() to capture the entire scrollable document height from top to bottom.

How it works

  1. For a viewport screenshot, cast the WebDriver reference to TakesScreenshot and call getScreenshotAs(OutputType.BYTES).
  2. For an element screenshot, call getScreenshotAs(OutputType.FILE) directly on the located WebElement.
  3. For PDF generation, cast driver to PrintsPage, configure PrintOptions (such as orientation or page ranges), and call driver.print(printOptions).
  4. Write the returned byte array or File to your target report directory using java.nio.file.Files.write() or Files.copy().

Capturing viewport screenshot, element screenshot, and printing page to PDF:

package dev.selenium.interactions; // Declares package

import org.openqa.selenium.By; // Imports By locator class
import org.openqa.selenium.OutputType; // Imports OutputType target formats
import org.openqa.selenium.Pdf; // Imports W3C Pdf container
import org.openqa.selenium.PrintsPage; // Imports PrintsPage interface
import org.openqa.selenium.TakesScreenshot; // Imports TakesScreenshot interface
import org.openqa.selenium.WebDriver; // Imports WebDriver interface
import org.openqa.selenium.WebElement; // Imports WebElement interface
import org.openqa.selenium.chrome.ChromeDriver; // Imports ChromeDriver
import org.openqa.selenium.print.PrintOptions; // Imports PrintOptions configuration
import java.nio.file.Files; // Imports NIO Files utility
import java.nio.file.Paths; // Imports NIO Paths utility

public class ScreenshotsPdfExample { // Declares class
    public static void main(String[] args) throws Exception { // Main method
        WebDriver driver = new ChromeDriver(); // Starts Chrome session
        try { // Guarded block
            driver.get("https://www.selenium.dev/"); // Navigates to Selenium site
            byte[] viewportPng = ((TakesScreenshot) driver).getScreenshotAs(OutputType.BYTES); // Captures viewport bytes
            Files.write(Paths.get("target/viewport.png"), viewportPng); // Saves viewport PNG to disk

            WebElement logo = driver.findElement(By.cssSelector(".navbar-brand")); // Locates navbar logo
            byte[] logoPng = logo.getScreenshotAs(OutputType.BYTES); // Captures element-only screenshot
            Files.write(Paths.get("target/logo.png"), logoPng); // Saves element PNG

            Pdf pdf = ((PrintsPage) driver).print(new PrintOptions()); // Prints current page to W3C PDF
            Files.write(Paths.get("target/page.pdf"), OutputType.BYTES.convertFromBase64Png(pdf.getContent())); // Decodes Base64 PDF to disk
        } finally { // Teardown block
            driver.quit(); // Closes browser
        } // Ends finally
    } // Ends main
} // Ends class

Common mistakes

  1. Calling getScreenshotAs(OutputType.FILE) and assuming the file is permanently saved; OutputType.FILE writes to the OS temp folder and deletes it on JVM exit unless copied with Files.copy().
  2. Calling TakesScreenshot inside @AfterMethod after driver.quit() has already executed, which throws NoSuchSessionException; always capture the screenshot before calling driver.quit().
  3. Trying to capture a screenshot while an unhandled JavaScript alert is open on screen, which throws UnhandledAlertException.

Interview questions

Basics

Why do you have to cast WebDriver to TakesScreenshot when taking a screenshot?
The WebDriver interface itself does not declare getScreenshotAs(). Concrete driver classes like ChromeDriver, FirefoxDriver, and RemoteWebDriver implement both WebDriver and TakesScreenshot, so casting ((TakesScreenshot) driver) exposes the method.

What are the three OutputType formats supported by getScreenshotAs()?
The three formats are OutputType.FILE (saves a temporary PNG file on disk), OutputType.BYTES (returns a raw byte[] array in memory), and OutputType.BASE64 (returns a Base64-encoded String).

How do you take a screenshot of a single WebElement in Selenium 4?
WebElement extends TakesScreenshot directly in Selenium 4, so you simply call element.getScreenshotAs(OutputType.FILE) or OutputType.BYTES without casting.

How it works

Does ((TakesScreenshot) driver).getScreenshotAs() capture the entire scrollable page or only the visible viewport?
Under the W3C WebDriver specification, getScreenshotAs() on the driver captures only the currently visible browser viewport. To capture a full scrollable page in Firefox, cast to FirefoxDriver and call getFullPageScreenshotAs().

What happens to the File returned by getScreenshotAs(OutputType.FILE) when the Java process finishes?
Selenium creates that File inside the operating system's temporary directory and marks it with deleteOnExit(). You must copy it to a persistent path (such as target/screenshots/) using Files.copy().

How does PrintsPage.print() work in Selenium 4?
Calling ((PrintsPage) driver).print(new PrintOptions()) sends the W3C Print Page command to the browser, which renders the page using its native print-to-PDF engine and returns a Pdf object containing Base64-encoded PDF content.

Real situations

Which OutputType is best when attaching failure screenshots to Allure or ExtentReports in parallel CI runs?
OutputType.BYTES or OutputType.BASE64 is best because the image data stays entirely in memory per thread and is embedded directly into the report without disk I/O collisions or leftover temp files.

How do you include background colors and images when printing a page to PDF with PrintOptions?
Create PrintOptions options = new PrintOptions(); options.setBackground(true); and pass it to ((PrintsPage) driver).print(options). By default, browsers omit background graphics when printing.

Why do element screenshots help in visual regression testing?
Capturing an isolated component (such as a navigation bar or chart widget via element.getScreenshotAs()) avoids false-positive pixel diffs caused by dynamic timestamps or ads elsewhere on the page.

Troubleshooting

Why did TakesScreenshot throw UnhandledAlertException when a test failed?
The test failed while a native JavaScript alert() dialog was open. W3C WebDriver cannot capture the DOM viewport while a modal alert blocks the page; dismiss the alert in a catch block before taking the screenshot.

Why did printsPage.print() fail on older Chrome versions when running in headed mode?
Prior to Chrome 109's unified --headless=new architecture, Chromium only allowed PDF printing in headless mode. In modern Chrome 109+ and Selenium 4, print() works in both headed and headless modes.

Why is an element screenshot blank or cut off?
If the element is inside a scrollable overflow container and partially scrolled out of view, ensure the element is scrolled into view before calling element.getScreenshotAs().

Design choices

Why is java.nio.file.Files.copy() or Files.write() preferred over Apache Commons FileUtils.copyFile()?
Standard JDK java.nio.file.Files is built into Java 11+ and writes byte[] or copies File objects in one line without requiring an extra Apache Commons IO dependency.

Where should automatic failure screenshot capture be implemented in a TestNG framework?
Implement it either inside an ITestListener.onTestFailure(ITestResult) listener or inside the base test class's @AfterMethod(alwaysRun = true) hook before calling driver.quit().

Why should screenshot filenames include a timestamp or thread ID in parallel runs?
If two parallel tests fail at the same millisecond or a data-driven test fails on two iterations, including testName + "_" + System.currentTimeMillis() prevents one screenshot file from overwriting another.

Quick answers

  1. How do you take a viewport screenshot? Call ((TakesScreenshot) driver).getScreenshotAs(OutputType.BYTES).
  2. How do you take a screenshot of one element? Call element.getScreenshotAs(OutputType.BYTES) directly on the WebElement.
  3. Which OutputType is best for ExtentReports or Allure? OutputType.BYTES or OutputType.BASE64 (in-memory, no temp file cleanup needed).
  4. Which interface exports a web page to PDF? PrintsPage via ((PrintsPage) driver).print(new PrintOptions()).
  5. How do you take a full scrollable page screenshot in Firefox? Call ((FirefoxDriver) driver).getFullPageScreenshotAs(OutputType.FILE).
