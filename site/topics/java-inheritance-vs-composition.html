4.5 Inheritance (IS-A) vs Composition (HAS-A)

1. Definition

Inheritance (IS-A via extends) reuses and overrides a single parent class across a strict hierarchy, whereas Composition (HAS-A via a private field) embeds reusable helper objects cleanly without the Diamond Problem.

2. Memory hook

extends = IS-A (1 parent class only); HAS-A field = Composition (swap parts freely!).

  • Why Java forbids multiple class inheritance: if two parents both define run(), calling child.run() hits the Diamond Problem ambiguity.
  • Interfaces solve multiple contracts: a class can extend 1 parent class yet implement many interfaces.
  • Prefer Composition over Inheritance: a Page Object HAS-A WebDriver and HAS-A HeaderBar rather than inheriting unrelated behaviors.

3. IS-A Inheritance vs HAS-A Composition

Framework Architecture Choice
Inheritance fits true BaseTest / BasePage families; Composition builds components flexibly.
IS-A (extends)LoginPage extends BasePage (inherits shared wait helpers & driver)
HAS-A (Composition)CartPage holds private HeaderComponent header; + WebDriver driver;

5. Code example: BasePage IS-A combined with HeaderComponent HAS-A

class HeaderComponent {
    void openCart() { System.out.println("Header clicked Cart"); }
}

class BasePage {
    protected final String envUrl = "https://qkart-qa-web.labs.crio.do/";
}

public class CheckoutPage extends BasePage {      // IS-A BasePage
    private final HeaderComponent header = new HeaderComponent(); // HAS-A HeaderComponent

    public static void main(String[] args) {
        CheckoutPage page = new CheckoutPage();
        System.out.println("Base=" + page.envUrl); // inherited via IS-A
        page.header.openCart();                   // delegated via HAS-A
    }
}

6. Execution flow, step by step

  1. CheckoutPage extends BasePage inherits envUrl directly from one parent class.
  2. Inside CheckoutPage, header holds a separate HeaderComponent object via composition.
  3. If QKart adds a SearchBar component tomorrow, adding a field requires zero deep inheritance edits.
  4. Trying class A extends B, C fails compilation immediately to block the Diamond Problem.
  5. Both patterns complement each other cleanly inside Page Object frameworks.

7. Real-life analogy: biology family tree vs plugging parts into a laptop

Laptop vs TreeJava
Dog is-a Animal inheriting eating behavior from parentInheritance (extends)
Laptop has-a Screen, has-a Battery, has-a Keyboard plugged inComposition (HAS-A fields)
Swapping an SSD drive without redesigning the entire motherboardSwapping composed helper implementations
Confusion if a child had two biological classes overriding the same ruleDiamond Problem

8. Why it matters

Overusing deep 4-5 level inheritance trees creates fragile classes where editing one base class accidentally breaks distant subclasses.

SDET link: Keep inheritance shallow (LoginTest extends BaseTest, LoginPage extends BasePage) and compose shared page widgets (HeaderBar, FooterBar, WaitHelper) via HAS-A fields.

9. Quick test

Should LoginPage extend ChromeDriver? No — a LoginPage is NOT a ChromeDriver; it HAS-A WebDriver passed via constructor composition.
