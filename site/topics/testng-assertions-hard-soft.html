2.1 Hard Assertions vs Soft Assertions (SoftAssert)

Deterministic verification: Assert.assertEquals failure termination semantics vs SoftAssert multi-checkpoint collection and assertAll().

Assertions form the validation core of test automation. Without assertions, test code merely executes actions without determining correctness. TestNG provides two distinct assertion paradigms: Hard Assertions (via org.testng.Assert) and Soft Assertions (via org.testng.asserts.SoftAssert), each designed for specific verification scopes.

1. Hard Assertions: Immediate Termination

Hard assertions immediately throw an java.lang.AssertionError upon failure, terminating the current test method at that exact instruction line. Subsequent statements in the test method are completely skipped.

import org.testng.Assert;
import org.testng.annotations.Test;

public class HardAssertExample {
    @Test
    public void testAuthenticationFlow() {
        boolean isLoginSuccessful = performLogin();
        // If this fails, the method aborts immediately. The profile check is never executed.
        Assert.assertTrue(isLoginSuccessful, "Authentication failed for user");

        String welcomeMsg = getWelcomeMessage();
        Assert.assertEquals(welcomeMsg, "Welcome, Prasanth!", "Welcome banner mismatch");
    }
}

When to use: Critical path gateways where downstream steps are meaningless or will throw secondary exceptions (e.g. failing to login, failing to create an order, or receiving an invalid HTTP 500 status code).

2. Soft Assertions: Multi-Point Validation

In UI verification, a page often contains multiple independent fields (header, footer, profile picture, pricing, copyright year). Using hard assertions causes the test to fail at the first discrepancy without verifying the remaining 5 fields. SoftAssert records failures in memory and continues execution until assertAll() is explicitly called:

import org.testng.asserts.SoftAssert;
import org.testng.annotations.Test;

public class SoftAssertExample {
    @Test
    public void testUserProfileDashboard() {
        SoftAssert softAssert = new SoftAssert();

        softAssert.assertEquals(getHeaderTitle(), "Dashboard", "Header mismatch");
        softAssert.assertTrue(isAvatarVisible(), "Avatar should be displayed");
        softAssert.assertEquals(getUserRole(), "Admin", "User role mismatch");
        softAssert.assertEquals(getFooterYear(), "2026", "Footer year mismatch");

        // CRITICAL: assertAll() aggregates all recorded errors and marks the test failed if any assert failed
        softAssert.assertAll();
    }
}

4. Senior SDET Interview Q&A

  1. What happens if you omit softAssert.assertAll() at the end of a test?
    If assertAll() is omitted, the test will pass even if every single soft assertion failed! TestNG relies on assertAll() to throw the aggregated AssertionError. Omitting it creates a dangerous false-positive test.
  2. Can you share a single SoftAssert instance across multiple test methods?
    No! If a SoftAssert instance is shared across methods, failures from Test A will carry over into Test B, causing subsequent tests to fail falsely. Always instantiate a new SoftAssert inside the method or in a @BeforeMethod.
